# HANDOFF — M13.1  (ADR-0016, H-1 to H-6: a chain in the events file)

Task: every event a host watch writes names the line its run wrote before it by that line's sha256, and `raqib events FILE` checks each run's chain. Read docs/specs/ADR-0016-a-chain-in-the-events-file.md first, then docs/specs/EVENT.md ("The events file", "For a reader of the file", "Keys"), raqib/eventlog.py (`EventLog.say`: how a line is built, compared and appended, `VARY`), raqib/event.py (`check`, `line`) and `cmd_events` in raqib/cli.py.

Scope:
  raqib/event.py (the key `prev`; a function that checks the chains of a file's lines), raqib/eventlog.py (the writer), raqib/cli.py (only `cmd_events` and its parser's help), tools/event_examples.py (only what the examples of a run whose numbering varies need for `prev`), docs/specs/EVENT.md, docs/GUIDE.md (only the row and sentences of `raqib events`), docs/THREAT_MODEL.md (one entry: H-5), tools/rig/check.py and tests/test_rig_check.py and .github/workflows/rig.yml (only X38), tests/test_event_chain.py (new), docs/review/2026-11-20-M13.1-questions.md; and a test of tests/ or a fixture ONLY where it holds, word for word or by count, a line, a list or a number this task changes (named in the questions file; no other assertion weakened).

Exit criteria:
- E1 (H-1, H-6) The key `prev`: the word `first`, or 64 characters of lower-case hexadecimal. `event.check` takes an event with it and one without it, and names any other value as a problem of `prev`. Its place in a line's order is after `n`. EVENT.md's Keys, Required keys (not required: a line of an older build has none), Mapping (the namespace) and "For a reader of the file" say it; the last also says that a reader must allow a key it does not know.
- E2 (H-1, H-2) The writer: a run's first written line holds `prev` `first`; every later line holds the sha256 (hex) of the bytes of the line this run wrote before it, without its newline. A line that could not be written does not move the head. `prev` is not part of what makes a thing "the same again" (VARY). Nothing else of a line changes, and the bound on a pass's work stays.
- E3 (H-3) A heartbeat and a watch's end hold `prev` as any event: a test reads a watch's file and follows the chain from its start to its end through a heartbeat.
- E4 (H-4, H-2) The check, as a function of raqib/event.py over a file's lines and through `raqib events FILE`: for each run (by `watch.run`, in the file's order) one line of the answer: whole with its count of lines; or the first break, by its line number in the file (the line does not name the run's line before it: one before it was removed, changed, added or moved); or a line beside the chain (it names a line of the run that is not the one before it, and the lines between follow each other: not counted as written by the writer, or put there by another hand), by its line number; or not chained (no line of the run holds `prev`). A run that holds `prev` on some lines and not on others is broken. Two runs whose lines alternate in the file are each whole. A line that is no event is no link and is reported as it is today. Exit 1 where any run is broken or holds a line beside its chain; a file of an older build (no run chained) exits as it does today.
- E5 Tests of the check on made-up files: whole; a line removed from the middle; a byte changed; a line added; two lines swapped; the last lines cut (said in the test's own words as NOT seen: H-5); a line beside the chain; two runs alternating; an older build's run beside a chained one; a torn line in a chained run.
- E6 The examples of EVENT.md are made by `python3 tools/event_examples.py --write` and `--check` passes; where a fixture run numbers its events differently from run to run, `prev` is treated as its id, n and about are. raqib/forward.py is not edited and its tests pass unchanged (it sends lines as the file holds them).
- E7 The rig: after the watch, `raqib events` over the watch's events file is run and its output kept; X38 in check.py: MET where the answer says this watch's run is whole and names no break; MISSED otherwise; both systems.
- E8 Words: GUIDE's row of `raqib events`; THREAT_MODEL's entry (what the chain proves and what it does not: no secret; a cut end and a tail written again are not seen from the file alone; what a collector that holds a later line can tell).
- E9 Gate green in the foreground; ASCII outside docs; raqib/host.py, raqib/forward.py and raqib/discover.py are not edited.
Not in scope: a keyed chain; the head in the state file or the report; the forwarder; the version and CHANGELOG.md (the Table's at the merge).
If an exit criterion needs a file outside Scope: STOP and say which file and which line.
