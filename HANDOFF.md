# HANDOFF — M12.1  (ADR-0013 A-1 to A-9, stage S1: the watch as a unit of the system's, on Linux)

Task: `raqib service install | remove | status` for the host watch as a systemd unit of the system's. Linux only. The watch itself is not changed.

Scope:
  raqib/service.py (new), raqib/cli.py (the `service` command only), tests/test_service.py (new), tools/rig/service_run.py (new), tools/rig/check.py (X28 to X30 only), tests/test_service_rig.py (new), docs/specs/SERVICE.md (new), docs/THREAT_MODEL.md, docs/GUIDE.md, tests/test_readme_top.py (only the guide's new or changed lines in its registry), docs/review/2026-11-18-M12.1-questions.md

Exit criteria:
- E1 (A-3) `service.owned_by_root(paths, stat=os.stat)`: for the interpreter (as started and resolved), every existing folder of sys.path, every file and folder of the raqib package, and every folder above each up to `/`: owned by uid 0 and not writable by group or others; the first that is not is returned with why. A symbolic link is checked as itself and as what it points to. Tests over a made-up stat: a world-writable parent three levels up, a user-owned file inside the package, a group-writable site folder, a link to a user's file, and the clean case.
- E2 (A-4, A-7) `raqib service install`: exit 2 with the reason and no write where the platform is not Linux, the caller is not root (no elevation asked), E1 fails (the path said), the interpreter's path holds a character outside `A-Za-z0-9/._+-`, no systemctl is at one of the fixed paths, or a unit of the name exists that does not carry Raqib's mark. Else it writes the unit (root, 0644) by a write beside and a rename, runs systemctl daemon-reload and enable --now (`--no-start`: neither enabled nor started), and says what it did. A second install over Raqib's own unit replaces it. Every system call (the uid, stat, the write, systemctl's run) goes through one object a test replaces: no test writes under /etc or runs systemctl.
- E3 (A-3, A-5, A-6) The unit's text, one constant but for the interpreter's path: the mark `# raqib-service/1`; ExecStart the interpreter with `-I -m raqib watch --host --no-open --no-notify`; Environment HOME=/var/lib/raqib; StateDirectory raqib, mode 0700; Restart on-failure after 5 s; KillSignal SIGTERM, TimeoutStopSec 30; and A-6's directives exactly as ADR-0013 lists them (NoNewPrivileges, ProtectSystem=strict, ProtectHome=read-only, PrivateTmp, PrivateDevices, ProtectKernelTunables, ProtectKernelModules, ProtectControlGroups, ProtectClock, ProtectHostname, LockPersonality, MemoryDenyWriteExecute, RestrictRealtime, RestrictSUIDSGID, RestrictNamespaces, RestrictAddressFamilies=AF_UNIX AF_NETLINK AF_INET AF_INET6, IPAddressDeny=any, IPAddressAllow=localhost, CapabilityBoundingSet=CAP_SYS_PTRACE CAP_DAC_READ_SEARCH CAP_NET_ADMIN, SystemCallFilter=@system-service, SystemCallArchitectures=native, UMask=0077); WantedBy multi-user.target. A test holds the whole text.
- E4 (A-4) `raqib service remove`: as root only; stops and disables the unit, removes the one file if it carries the mark (a unit without it is not touched: exit 2), daemon-reload; the record under /var/lib/raqib stays and its path is said; `--purge` removes that folder too, and only that folder (a test: a state path that is a link, or is not /var/lib/raqib, is refused). No unit installed is exit 0 saying so.
- E5 (A-8) `raqib service status`: no rights needed; installed (the file with the mark), enabled and active by systemctl's own words, the unit's last result where not active; exit 0 active, 1 installed and not active, 3 not installed; where systemctl cannot be run it says so and is 3. Not Linux is exit 2.
- E6 (A-9) tools/rig/service_run.py (run as root by the rig, Linux only): tries an install from a place a user can write and records the refusal (X28); makes root's own venv in a folder it makes root's alone, installs from it, waits for the unit to be active, runs the rig's workload as a second user outside the runner's own tree (systemd-run --uid), reads the service's events for a finding on that user's tree (X29); removes, and records that no unit is left (X30). tools/rig/check.py X28 to X30 from its facts: MET, NOT MET with what is missing, not run on Windows; never raises. Their tests feed made-up facts.
- E7 docs/specs/SERVICE.md: the three commands, the unit's text, what install checks and why, where the record is, what removal leaves. docs/THREAT_MODEL.md (no milestone token): what the service changes (who can stop it, write its record, hide under another user) and what it costs (Raqib's code as root; A-3's check; the two watches). docs/GUIDE.md: the commands. A test holds the sentences that matter.
- E8 Gate green in the foreground; ASCII outside docs; raqib/service.py imports no network module and is imported only inside the `service` command; tests/test_rhythm.py's guards pass unchanged.
Not in scope: raqib/host.py, raqib/forward.py, raqib/app.py, the forwarder's unit, Windows, .github/workflows/, tests/test_rhythm.py.
