# HANDOFF — M10.2  (ADR-0011 Amendment F: the watch writes its events)

Task: the host watch writes `raqib-event/1` lines to a file beside its record while it runs, with a heartbeat. Nothing is sent anywhere. Rulings F-1 to F-9 (E-4 lists what the writer settles).

Scope:
  raqib/eventlog.py (new), raqib/host.py (the pass and what it needs: the trees' rows, the state, the report's EVENTS line, the first lines), raqib/event.py (F-4's and F-5's keys only), raqib/cli.py (`--beat`, `--event-host`, the `events` command), docs/specs/EVENT.md, docs/THREAT_MODEL.md, tools/rig/check.py, .github/workflows/rig.yml (the events file gathered and given to check.py), tests/, docs/review/2026-11-13-M10.2-questions.md

Exit criteria:
- E1 (F-1) raqib/eventlog.py: the writer. It numbers events from 1 in a run, keeps per `about` the last rev and what was said, writes one line (event.line, appended, flushed) only for a new thing or a changed one. Tested without a watch: new, same again (nothing), changed (rev 2), two things; and that an id is never written twice in a run.
- E2 (F-2) The watch's pass, at the end of every round and at the finish, names each entry from the list it is in. Tested through fixture watches (as tests/test_event.py makes them): the file of a watch with a tree, a finding, source findings, a hole, a notifier's hole, a blind spot, notes and knocks: every line passes event.check; the first is the start, the last the end with the report's RESULT word and exit; each finding and source finding of the report has its event; a source finding said before it settled is said again when settled (rev 2, same about); a notifier's hole made before a watch's hole keeps its name; reading the file back, (about -> last rev's event) equals what event.snapshot gives for the final state, apart from id, n, rev and time.
- E3 (F-3) `--beat S` (default 60, at least the round's interval; less is refused as a usage error). On the fake clock: a watch of N rounds writes a heartbeat at each beat and none between; a round in which nothing changed writes nothing but a due beat; a blind spot's count and the lost-words note are said again only with a beat. "watch" is rev 1 at the start and one more for each beat and for the end.
- E4 (F-4) A builder that raises: one hole per thing, naming it and the key; the pass goes on (tested with one entry made unbuildable). A file that cannot be written: one hole, the count in the report and the state, the watch finishes with its report (tested with a path that is a directory). `evidence.cites_left_out`; no event with an empty cites list (event.py, check, EVENT.md, tests).
- E5 (F-5, F-6) `knocked.for` on every knock event whose thing the watch knows; `subject.by` from the tree's row; the host name read once (no network: socket.gethostname or the platform's own), `--event-host`, "unnamed" said at the start. EVENT.md, check and tests follow; EVENT.md gains examples of a notifier's hole and the lost-words note.
- E6 (F-7, F-8) The first lines and the report's EVENTS line (tests/test_host_sources.py pins the count of the first lines: it follows); `raqib events FILE` with its three exit codes, tested on a good file, a file with one bad line, a missing file.
- E7 (F-9) tools/rig/check.py: X16 every line of the events file is an event; X17 a start and an end; X18 an event for each finding the report lists; n/a where the rig gave no events file. tests/test_rig_check.py follows; rig.yml gathers ~/.raqib/host/events.jsonl and passes it.
- E8 docs/THREAT_MODEL.md (no milestone tokens): what the events file holds and does not (EVENT.md is the contract), that it is local and appended, that nothing is sent. Gate green; ASCII outside docs; no new test reads docs/review; no real host, user or address.
Not in scope: sending anything, sinks, raqib/app.py, raqib/ui.py, raqib/watch.py, raqib/notify.py, the rules, README.md, docs/GUIDE.md.
