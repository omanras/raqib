# HANDOFF — M12.4c2a  (ADR-0013 Amendment P: the drive a path is on, and the libraries loaded by name)

Task: `raqib service check` (Windows, 0.12.0) says in its own documents that it does not read what a drive's letter names, nor the system's PATH. Amendment P (the end of docs/specs/ADR-0013-the-service-under-the-system.md) closes both before an install rests on the check. Read Amendments K, L (L-3), N, O and P, then raqib/wincode.py (`check`, `_plain`, `_Walk`, `path_refused`, `System`, the pass words), raqib/winservice.py (`System._win`, `System.read_place`: where the system's calls are declared, by ctypes, at the first call), tests/test_wincode.py (its `Machine` stand-in), tests/test_own_env.py (how a test scans every file of raqib/ by its syntax tree and names what it found, so that a blind scan fails), tools/rig/check.py (`read_check`, X49, X50), docs/specs/SERVICE.md's section "Windows: the check".

Scope:
  raqib/winservice.py (only: one new method of `System` that reads a drive, and the two calls it declares), raqib/wincode.py, tools/rig/check.py and tests/test_rig_check.py (X51), tests/test_wincode.py, tests/test_winservice.py (only a test of the new method's declarations, where that file holds the others'), tests/test_libraries.py (new), docs/specs/SERVICE.md (the check's section), docs/GUIDE.md (the check's paragraph, one sentence), docs/THREAT_MODEL.md (the check's paragraph), docs/review/2026-11-27-M12.4c2a-questions.md; and a test of tests/ ONLY where it holds, word for word or by count, a line this task changes (named in the questions file with every assertion removed; no other assertion weakened).

Exit criteria:
- E1 (P-1, the reading) `winservice.System` gains one method that, given a drive's root (`X:\`), returns what the system says of it: its kind (GetDriveTypeW, the number) and its device's name (QueryDosDeviceW of `X:`, the first name; a buffer of a fixed bound), or raises OSError with the system's number where the device's name cannot be read. Declared with the other calls, used nowhere else; no ctypes in wincode. Nothing else of winservice.py changes.
- E2 (P-1, the rule) In raqib/wincode.py, through the check's system object (a test hands its own): each drive a path of the walk is on is asked once, before any name of it is read - the program's or the interpreter's first, then every root, entry, *.pth line and name of N-1 as it is met - and taken only where the kind is 3 and the device's name is a string that begins with `\Device\`. Refusals, each with its own words, the letter, the kind as a number with the system's word for it (0 unknown, 1 no root, 2 removable, 3 fixed, 4 remote, 5 a disc, 6 a RAM disk; another number said as it is) and the device's name made printable: a kind that is not 3; a device's name that does not begin with `\Device\` (said: a letter given to a folder or a share reads so); a device's name not read (the system's number said); a kind or a name of a type the check does not know. A refused drive is exit 1, nothing of it read. Both roads; the drive of an entry that is not there is asked too.
- E3 (P-1, the words) The pass says the drives it asked - each letter with its device's name - and no more than was judged; "to the drive's letter" stays. SERVICE.md, GUIDE.md and THREAT_MODEL.md move "what the drive's letter names" from not read to what is refused, with what Amendment P measured named so and its not-measured list.
- E4 (P-1, tests with stand-ins) The measured readings as the stand-in's defaults: `C:` kind 3 `\Device\HarddiskVolume3`; then each of: a letter given to a folder (kind 3, `\??\C:\ProgramData`) refused; kinds 0, 1, 2, 4, 5, 6 and 7 refused, each with its word; a device's name not read (OSError 2) refused; an empty name, None, bytes, a kind given as a string or True: refused; an entry of the plain road on a second drive that is a folder's letter: refused, the walk's earlier names read and nothing of that drive; a second drive that is a disk: asked once and said in the pass; the same drive in two letter-cases asked once. The real method: a Windows-only test that `C:\` (or the system drive) reads kind 3 and a name beginning `\Device\`; skipped elsewhere with its reason.
- E5 (P-2) tests/test_libraries.py: a scan of every .py file of raqib/ by its syntax tree that finds every place a library is loaded (ctypes' WinDLL, CDLL, OleDLL, PyDLL, their `windll` / `cdll` / `oledll` forms by attribute and by LoadLibrary, `ctypes.util.find_library`, and each of Raqib's own loader functions that take a name - found by the scan, named in the test with the file and the function, as tests/test_own_env.py names its starts); holds that every name given is a string written in the code, with no path separator and no dot but a final `.dll`, on one list in the test; that no call gives a search mode (`winmode`), and that no file of raqib/ calls `add_dll_directory`, sets `PATH`, or loads by a name worked out at run time; a test that the scan is not blind (a made-up file with each form is found; one with a worked-out name fails). On Windows only: each name of the list is a file in System32. The one call that takes a folder off the search (`SetDllDirectoryW`, ADR-0007 CI-3) is named and allowed as what it is.
- E6 (P-3) `tools/rig/check.py --service-check-drive FILE`: X51 MET where FILE (lines `key: value`: `letter-exit`, `letter-words`) says the check asked through a letter given to a folder ended with 1 and its words name a kind and a device's name that does not begin with `\Device\`; MISSED with words for each thing not found; n/a where none was given. Tests as X49's. The job's wiring is the Table's, after you land.
- E7 Gate green in the foreground; ASCII outside docs; pyproject, raqib/service.py, tests/test_own_env.py and the fixtures unchanged; standard library only; nothing at import; no process started; the AST test of wincode as strict as it is.
Not in scope: installing, removing, the state (M12.4c2b); changing how any library is loaded; .github/workflows and tools/rig/*.ps1; raqib/cli.py; the version and CHANGELOG.md; the ADR.
