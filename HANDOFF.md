# HANDOFF — M10.3  (ADR-0011 Amendment J: the forwarder, over HTTP)

Task: `raqib forward`, a process of its own that reads an events file and sends every whole line to one HTTP collector, at least once and in order, and says its own state. Syslog is the next task: a syslog destination is a usage error that says so.

Scope:
  raqib/forward.py (new), raqib/cli.py (the subcommand and its dispatch, nothing else), tools/rig/collector.py and tools/rig/forward_run.py (new), tools/rig/check.py (X19 to X22), .github/workflows/rig.yml (the steps that run them, on both machines), tests/, docs/specs/FORWARD.md (new), docs/GUIDE.md and README.md (the command), tests/test_readme_top.py (only its lists of rows gain the command's rows: G-11), docs/THREAT_MODEL.md, docs/review/2026-11-13-M10.3-questions.md

Exit criteria:
- E1 (J-1, J-2) The standard library only. A test reads the imports: raqib/host.py, raqib/eventlog.py, raqib/event.py and everything under raqib/hooks/ import nothing of raqib.forward. A redirect is a failed send (tested with a collector that answers 302); a proxy named in the environment is not used (tested: HTTPS_PROXY and HTTP_PROXY set to a dead port, the send still arrives).
- E2 (J-3, J-5, J-11, J-12) Against a collector on loopback inside the test: every whole line arrives in the file's order; the cursor moves only past a batch the collector took (a batch answered 503 is sent again, whole, and nothing after it before it); a line that is not JSON or not an event (`event.check`) is skipped and counted, never sent; a last line with no newline waits and is sent when its newline comes; a file shorter than the cursor, or whose last sent line changed, is read again from its start and counted as a restart; at most 100 lines or 512 KiB to a request; `--from end`.
- E3 (J-4) A batch answered 400 is sent line by line; the line refused alone is counted, its id kept (the latest 50), and passed; 401 and 403 move nothing, and a token file corrected between two tries is read again; 408, 429, 5xx, no answer and a late answer are failed sends.
- E4 (J-6) `--shape raqib`: the body is the lines as the file holds them, byte for byte. `--shape hec`: one envelope per line with time, host, source, sourcetype and the event unchanged, and the header `Authorization: Splunk <token>`; a 200 whose body's code is not 0 is not taken.
- E5 (J-7, J-8) The token only from `--token-file`; a test greps every output, the state, every error's text and the process's own argument list for it; off Windows a token file others can read is exit 2. No argument or environment turns certificate verification off (tested with a certificate the test makes with `openssl` where the machine has it - skipped with the reason where not - against the system's authorities: refused; with `--ca`: taken). Plain http only to loopback unless `--plain`; connect 10 s, answer 30 s (the clock and the timeouts injected in tests).
- E6 (J-9, J-10, J-13) The state file written whole (beside, then renamed) after every batch, every failure and at least once a beat (`--beat S`, default 60), with J-9's keys and nothing of the token or the collector's body; `--status` exits 0, 1 and 3 as J-9 says (each tested, 3 also for a state older than two beats); the waits 1, 2, 4 ... 60 s; `--once` 0, 1, 2; Stop writes the state; a second forwarder of one name is refused while the first one's pid lives.
- E7 (J-14) tools/rig/collector.py (loopback only; the hec shape; checks the token; can be told to refuse, fail and be late) and X19 to X22 in tools/rig/check.py, run by rig.yml on both machines against the events file the rig's watch wrote.
- E8 docs/specs/FORWARD.md (the state's keys, the shapes, what acknowledged means, the one search for silence on the collector's side); the guide's section and the rows; docs/THREAT_MODEL.md says what a forwarder adds (the token, the wire, what the collector learns) with no milestone tokens.
- E9 Gate green, run in the foreground; ASCII outside docs; loopback and documentation addresses only; no test reads docs/review or needs a network beyond loopback.
