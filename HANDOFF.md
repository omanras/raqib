# HANDOFF — M14.1c  (ADR-0007 Amendment BY, BY-1 to BY-7: the round takes the reader's processes)

Task: on Linux a child that begins and ends between two samples becomes its tree's child and is judged by the rules that read a child's name. Read ADR-0007's Amendments BU, BX and BY first (grep for them; the file is very long), then in raqib/discover.py how a round is built (`run`, `PARSERS`, `parse_proc`, `_merge_procs`, `_date_links`, `_acts_core`, `_channel_fields`, `_without_channel`, and every place that asks whether a record is the channel's: grep `"sysmon"`), and in raqib/host.py the live reader, `ProcEvents`, `_host_lines` and `plain_program`.

Scope:
  raqib/discover.py (a parser of the reader's records and its place in `PARSERS`; where a record of the channel is told from a sampled one; the watch's own socket tool recorded as its own), raqib/host.py (only: what `ProcEvents` keeps of an answer's records; the text given to discover; the holes of BY-5; the section's and the notes' words), raqib/procevents.py (only `Helper`: always isolated; a write that cannot block), raqib/own.py (only the image of an interpreter replaced on disk), tools/rig/workload.py and tools/rig/check.py (X36, and X35's words), tests/test_procevents_round.py (new), tests/test_host_procevents.py, tests/test_procevents_helper.py, tests/test_rig_check.py, new files under tests/fixtures/ (no existing fixture's bytes change), docs/specs/PROC-EVENTS.md, docs/GUIDE.md, docs/THREAT_MODEL.md, README.md (only where the sample report is the code's own and changes), docs/review/2026-11-20-M14.1c-questions.md; and a test of tests/ ONLY where it holds, word for word or by count, a line, a list or a number this task changes (named in the questions file; no other assertion weakened).

Exit criteria:
- E1 (BY-1) The watch gives discover one text of kind `procevents` per round: one JSON line per process the helper gave since the last round (`pid`, `ppid`, `exe` or null, `ticks` or null, `began`, `ended` or null, `code` or null; nothing else, bounded as the helper's answers are). `discover.parse_procevents` makes of each a process record as `parse_proc` makes of a sampled one (pid, ppid, its image by the same naming of a program's path, exe, no argv, the start key `boot+<ticks>` where the ticks were read, its time) marked as the channel's own (created, with its time); a line that is not such a line is a problem of the round, never an exception. Tests: each field; an unread exe; no ticks; a bad line; 5000 lines.
- E2 (BY-2) In a Linux round built with these records: a child whose parent is a sampled process that talks is that tree's act and child, with its start; a grandchild through a parent the reader also gave is too; a process the sample also holds (same pid, same start key) is one process; the same pid with another start is another. A round with no `procevents` text is byte for byte the round it was (a test builds both ways over every Linux fixture of tests/). Windows: every existing test passes untouched.
- E3 (BY-2, BY-4) Through the watch: a tree whose root talks at the sample and whose child `curl` (then `shred`) began and ended between two samples gets its HostChild line in the round that reads it, with the program's name through `plain_program`, once; NET-TOOL and DESTRUCT-CMD fire on it as on a sampled child. A child still alive at the next sample is not written twice. A process whose `exe` is unread gives no line and no hole; it is counted in the section. A name that `plain_program` refuses is the existing hole. Tests with a stand-in helper and a stand-in sample.
- E4 (BY-5) A refusal at the first start: the blind spot as before, the round the sample's alone, the result unchanged. After at least one answered ask: late, ended (and its one restart), lost events, `beyond`, a line that is no line -> a hole of the result of a kind of its own (`procevents`), said once per episode with its round, the result INCOMPLETE as any hole makes it. An `ended` heard from the reader never removes a process the sample still holds. Tests for each; the first build's tests that held "the result does not change" follow only where BY-5 changes them (named).
- E5 (BY-6) The socket tool the round starts is in the watch's record when it starts (no "process under the reader's pid that the watch did not start" hole for it: a test with the real `ss` on Linux where it is installed, a stand-in elsewhere). `own` takes an image that ends with ` (deleted)` as the image it was. `Helper`'s command is always `-I` (never `-P` alone); its ask is written without blocking (a full pipe is `ended`, said), and the test of the input that never drains still passes.
- E6 (the words) The section says what is judged (the children of a tree that talks at a sample, by their program's name) and what is not (a tree that lives whole between two samples; a child's own connections; a program not read), with the counts: given to the round, joined to a tree, not read. The note that nothing between two samples is seen on Linux says what is now seen and what is not. GUIDE.md, THREAT_MODEL.md (BY-4's limit: the helper's lines are its word; what a process of the same user could make the watch write, in plain neutral words) and PROC-EVENTS.md follow; a test holds the sentences that matter.
- E7 (BY-7) tools/rig/workload.py on Linux starts one more child that lives under a second (`wget -q -O /dev/null --timeout=5` of the same public host its curl asks, said in a WORKLOAD line with its return code); tools/rig/check.py X36: MET where a NET-TOOL line of the stand-in's tree names `wget`; MISSED where the stand-in ran it and none does; n/a off Linux, where wget is not installed, or where the helper was refused. Tests feed made-up reports.
- E8 Gate green in the foreground; ASCII outside docs; no network; no exploit code and no attack steps anywhere.
Not in scope: connections between samples (M14.2), any rule's YAML, raqib/rules/engine.py, Windows' channel, the version and CHANGELOG.md (the Table's at the merge), ADRs.
