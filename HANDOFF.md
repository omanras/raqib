# HANDOFF — M15.3a  (ADR-0014 Amendment G, AG-1 to AG-3: the autostart places read by Raqib itself, standing alone)

Task: a new module, raqib/autostart.py, that reads Windows' autostart places with the standard library alone and compares two reads. Nothing of the watch changes in this task. Read ADR-0014's Amendment G first, then in raqib/hooks/os_sysmon.py how a registry line names a value and its program (`value_name`, `program_name`, `autostart_value`), and tools/rig/procevents_run.py with its row in tools/rig/check.py (X31) as the model of a module run by the rig.

Scope:
  raqib/autostart.py (new), tests/test_autostart.py (new), docs/specs/AUTOSTART.md (new), docs/THREAT_MODEL.md (one entry: what this read does not see), tools/rig/autostart_run.py (new), tools/rig/workload.py (only: a service made and deleted), tools/rig/check.py and tests/test_rig_check.py (only X37), .github/workflows/rig.yml (only the step that runs autostart_run.py and check.py's new argument), docs/review/2026-11-20-M15.3a-questions.md; and a test of tests/ ONLY where it holds, word for word or by count, a list this task changes (a list of modules, of specs, of the rig's claims), named in the questions file.

Exit criteria:
- E1 `autostart.read(...)` on Windows gives the entries of AG-1's places: Run and RunOnce of every loaded user's hive (HKU by its SID; `_Classes` hives left out; HKCU is not read a second time) and of the machine's, the 32-bit view only where it holds an entry the other view does not hold as the same name and content; the files directly in the user's and all users' Startup folders (`desktop.ini` left out); the services (ImagePath, Start, Type); the scheduled tasks (the registry's tree: a task's actions and triggers); Winlogon's Shell and Userinit. An entry: `place` (run, runonce, startup, service, task, winlogon), `scope` (user or machine), `view32`, `name` (as os_sysmon.value_name gives a value's name: bounded, redacted), `program` (as PERSIST-RUN-KEY's line names the program a value would run; None where the content is not a command or was not read) and a sha256 of its content that never leaves the process's memory but as a hash. No value's text, file's content, SID or user's name is in anything the module returns or prints.
- E2 What the rights do not give is said, never read as empty: per place `refused` (the whole place), `partly` (how many of its keys were refused) or `failed` (another error, with its reason); a place that is not there is empty. `read` never raises, and imports winreg only inside the call. Off Windows it reads nothing and says so in one sentence (Linux's places are ADR-0014 S4).
- E3 `autostart.changes(before, after)`: every entry added, changed (its hash) or removed, each with the entry's fields and `change`; a place refused or failed in either read gives no change and is named as unread. The same entry of one hive seen under two names is one entry.
- E4 `python -m raqib.autostart [--rounds N] [--every S]`: one line of the first read (entries per place, what is refused, the seconds it took), then at each later read one line per change (`CHANGE round 3: added service "name" (would run cmd.exe)`), ASCII; exit 0, 2 for arguments it does not take. It writes no file and opens no socket.
- E5 Tests on a made-up registry and folders given to `read` (no real registry in a test that runs everywhere): every place, the two names of one hive, the two views, each refusal, a name that needs redacting, a value whose program the gate refuses, each kind of change. One test, skipped off Windows, makes the real read: it does not raise, the services place holds entries, and it takes under 5 s.
- E6 docs/specs/AUTOSTART.md: what is read and how an entry is named, what is not read (AG-5's list), what the rights refuse, and Amendment G's measured numbers with what is not measured. THREAT_MODEL: one entry.
- E7 The rig: tools/rig/workload.py's Windows stand-in also makes a service that is never started (`sc create` with a binPath of `cmd.exe /c echo`, start demand) and deletes it after some seconds, saying each in a WORKLOAD line; tools/rig/autostart_run.py runs the module's read beside the stand-in and writes what changed to a JSON file; X37 in check.py: MET where the stand-in's Run value, its Startup file and its service are each an `added` change and later a `removed` one; MISSED otherwise; n/a off Windows. No other claim changes.
- E8 Gate green in the foreground; ASCII outside docs; raqib/host.py, raqib/discover.py, raqib/hooks/ and raqib/rules/ are not edited.
Not in scope: the watch reading it, host lines, the rules (M15.3b); Linux; the version and CHANGELOG.md (the Table's at the merge). The stand-in's acts are harmless and each is undone; no exploit code or attack steps anywhere.
