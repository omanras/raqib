# HANDOFF — M16.1  (ADR-0017 S-1 to S-5: ready content for Elasticsearch and OpenSearch, Sigma rules, the ATT&CK table)

Task: a new folder `siem/` with the files a SOC installs to use Raqib's events in Elasticsearch or OpenSearch, Sigma rules over the events, and a table of the rules' ATT&CK techniques; proved on the rig by real engines. Read docs/specs/ADR-0017-ready-content-for-a-soc.md first, then docs/specs/EVENT.md ("Keys", "Mapping", "For a reader of the file") and docs/specs/FORWARD.md ("The shapes", "On the collector's side"). The Table's probe is on the branch claude/rig-probe (read it with `git show origin/claude/rig-probe:tools/rig/siem_probe.py`, `:tools/rig/sigma_probe.py`, `:tools/rig/sigma-draft/pipeline-ecs.yml` and the job `siem` of `:.github/workflows/agents-probe.yml`): it is a measured draft to start from, not a file to copy whole.

Scope:
  siem/ (new: README.md, elastic/, opensearch/, sigma/, attack/), tools/siem_content.py (new: makes and checks the files of siem/ that are made from the catalog), tools/rig/siem_run.py (new), .github/workflows/rig.yml (only a new job that runs the engines and siem_run.py), tests/test_siem_content.py (new), docs/specs/EVENT.md (only "For a reader of the file": S-4's sentences), docs/GUIDE.md (one short section that points to siem/README.md), docs/review/2026-11-20-M16.1-questions.md; and a test of tests/ ONLY where it holds, word for word or by count, a list this task changes (the guide's sentences, a list of the tree's folders or tools), named in the questions file.

Exit criteria:
- E1 siem/elastic/ and siem/opensearch/: one ingest pipeline (the same text serves both engines) that takes a document whose `message` is one line of the events file and gives ECS as EVENT.md's Mapping names it - every named key to its ECS field, every other key under `raqib`, the whole line in `event.original`, the engine's own arrival time in `event.ingested`, a line that is not a raqib-event/1 event kept as a document that says why (never dropped in silence); and a template for each engine under which no line of any kind is refused (strings as keywords; the parts whose shape differs from kind to kind kept whole: `flattened` in Elasticsearch, `flat_object` in OpenSearch).
- E2 The searches, each as a file with one sentence of what it finds: an alarm; the findings of one rule; a hole of the capture; a watch that ended with a result other than 0; and the search for silence (the hosts whose latest heartbeat arrived more than two of its `watch.beat` ago, by `event.ingested`, never by the event's `time`).
- E3 siem/sigma/: Sigma rules over the events' own keys (`logsource: product: raqib`): a finding that alarms; a hole of the capture; a finding of each class of the catalog's rules that a SOC would route apart (persistence, the network, destruction, secrets, an agent nobody named); a watch that ended incomplete. Each with a fixed id of its own, a level, and ATT&CK tags only where the catalog's rule holds the technique. And the pipeline of names for the ECS fields of E1. Every key a rule names is a key of EVENT.md's Keys table.
- E4 siem/attack/: a table (markdown) of every rule of the catalog with its class, kind, severity and ATT&CK techniques, and a layer for the ATT&CK Navigator (JSON) of the same; both made by `python3 tools/siem_content.py --write` from raqib/rules/catalog and held by `--check` (exit 1 and each difference named), which a test of the gate calls: a rule added to the catalog fails the gate until the command is run.
- E5 tests/test_siem_content.py (no engine): every JSON and YAML file of siem/ parses (the repo's own YAML reader or the standard library; no new dependency); every ECS field the Mapping names is set by the pipeline's text and every key the Sigma rules and their pipeline name is a key of the spec; ids are unique; `tools/siem_content.py --check` passes; siem/ is ASCII and holds no address, host name or person's name; nothing under raqib/ imports or reads siem/.
- E6 The rig (Linux): a job starts Elasticsearch 8.15.3 and OpenSearch 2.17.1 in containers bound to 127.0.0.1, installs the content, and tools/rig/siem_run.py puts EVENT.md's examples and a real short watch's events file through it and prints one row a claim, MET or MISSED with its numbers: X39 no line refused and none kept as an error; X40 every field the Mapping names holds the value the event holds (compared with a mapping computed in Python from the event, for every line); X41 each search of E2 counts what a count made in Python says; X42 the Sigma rules, converted by sigma-cli with the pipeline of names, run and count what a count made in Python says. A claim that is MISSED is reported and does not fail the job (ADR-0012); a tool that could not be installed or an engine that did not start is said as such, never as MET. The stand-in events are the fixtures' and the runner's own: nothing is sent off the machine.
- E7 siem/README.md: for each engine the steps to install the content (the requests, as a person can paste them, to a host and port written as placeholders), the two ways the events reach it (an agent of the engine's own tailing `~/.raqib/host/events.jsonl` as lines; `raqib forward` to a collector), the measured trap of S-4, what was measured and where, and what was not (Splunk, Sentinel, Wazuh, an agent tailing the file, volume). EVENT.md's reader section gains S-4's sentences; GUIDE points to the page.
- E8 Gate green in the foreground; ASCII outside docs; nothing under raqib/ is edited; no new dependency of Raqib (sigma-cli is installed by the rig's job only).
Not in scope: Splunk, Sentinel, Wazuh, OCSF documents (M16.2, M16.3); the forwarder; the version and CHANGELOG.md (the Table's at the merge).
