# M7.6c - thresholds that can be measured: questions and choices (builder)

Task (one line): a changed host threshold can be measured, so it can be
allowed: the host rules' fixtures are generated at the requested values by a
generator inside the package, and each host YAML declares its bounds (A6
holds) - ADR-0008 Amendment B, Q-15.

## What was built (E1-E5)
- E1 `raqib/rules/fixturegen.py` (new): make.py's synthetic generators as
  package code - `rhythm_inventory`, `os_lines`, `synthetic_inventory`, the
  scenario tables parametric in k (`rhythm_scenarios`, `os_scenarios`,
  `os_rounds`) and in the streak (`dark_scenarios`), `arrival_scenarios`,
  `Clock`, `Follow`, `rounds_of`, `source_lines`, `fixture_doc`, `dumps`.
  `generate(rule)` makes the rule's fixtures at ITS OWN eq values (read as
  host.py reads them: `host.rhythm_params`, `host.rule_eq`), in memory, in a
  temporary home removed after each run: `{"positive": [(path, doc)],
  "negative": [(path, doc)], "arrivals": [path], "values", "runs": {path:
  [lines of each round]}, "last_round_only": [path]}`. At the declared
  values every doc is byte for byte the shipped file
  (test_e1_generate_at_the_declared_values_is_the_shipped_files_byte_for_byte).
  tests/fixtures/host/make.py is the thin writer: it keeps only the
  discover-export reader (`inventory()`: `:before`, `:rm`, kimi-gone,
  `host_record`), builds its SCENARIOS from fixturegen at the declared values
  (`DECLARED`, read from the YAMLs), and writes the shipped fixtures, the
  notes and `raqib/rules/hostdata/inventories.json`. Running it changes no
  shipped fixture (git status clean after `python3 tests/fixtures/host/make.py`).
- E1 package data: `raqib/rules/hostdata/inventories.json`, 81629 bytes,
  ASCII, compact JSON: discover.run's inventory of the 7 export rounds the
  generated rules replay (`windows`, `kimi-gone`, `kimi/one-sample`,
  `benign/linux-desktop[:before]`, `benign/windows-desktop[:before]`), the
  catalog path written relative. Listed in pyproject.toml's package-data;
  test_packaging's "every file under raqib/ is in the wheel" holds it.
- E2 `bounds:` in the five host YAMLs. HOST-RHYTHM: k 1..100, w 1..3600,
  r 1..1000, suspect_every 1..1000, relations ["k <= r"]. AGENT-DARK-LIVE:
  streak 2..100, live_window 2..1000, relations ["live_window >= streak"].
  NEW-AGENT, NEW-AGENT-UNKNOWN, HOST-UNWATCHED: `bounds: {}` (nothing of
  them may be set). engine.py: `bounds` is an OPTIONAL key; `bounds_problem`
  refuses an unsound block at load (a key that is not a declared threshold,
  not {min, max}, min < 1 or > max, the YAML's own value outside, a relation
  that is not "a <= b" / "a >= b", names an unbounded threshold, or that the
  YAML's own values break); `Rule.bounds` (None without a block);
  `declared_thresholds(doc)`, `eq_predicates(node)`. overlay.py: BOUNDS and
  ORDER are gone; `thresholds()` are the declared thresholds with bounds;
  `fixed_thresholds()` the rest, listed by `raqib rules` as "name=V (fixed:
  its YAML gives it no bounds)" or "(fixed: its YAML has no bounds block)"
  and refused when set ("... is not editable").
- E3 `overlay.measure`: a rule fixturegen generates (HOST-RHYTHM,
  AGENT-DARK-LIVE) is measured by `measure_generated` on its fixtures made
  at the new values plus the benign arrivals made at them: every positive
  must fire in its run, no negative and no arrival may fire, the fp rate over
  the measured negatives must stay within the declared budget; a failure is
  refused naming the fixture ("k=1: negative-changing-destination fires").
  Same on `--threshold` and at every load (apply()). Any other rule (a
  person's) is measured on its own fixture files as in M7.6. Nothing is
  cached on disk; an in-process memo (`_MEASURED`, 16 entries) keeps a
  set_threshold and the listing's load after it from measuring twice.
- E4 an arrival that fires is refused "...: would fire on a benign desktop"
  (test_redo_a3_a_threshold_under_which_a_negative_fires_is_refused, with a
  doctored run: no value within the bounds makes a real arrival fire).
- E5 `raqib rules --threshold` says what was measured ("measured at k=5 on
  fixtures generated at it: 4 of 4 positives fire; 0 of 7 measured negatives
  fire (2 benign arrivals among the 7 negatives); fp rate 0, budget 0"); the
  panel's threshold edit shows "threshold ok (measured): ..." or "REFUSED:
  threshold refused: <why>" (raqib/app.py RulesPanel.threshold; RULES_INTRO
  says it). README: two lines. cli.py needed no change (it prints what
  overlay says).

## Questions and choices (each recorded, none answered for the Table)
- Q-1 (the run, not the last round). A shipped host fixture holds the LAST
  round's lines, and a host rule fires once per streak. At k=1 the
  changing-destination negative fires in round 2 and its last round says
  `fires: false`; judged on its last round only, k=1 would pass. The
  measurement therefore judges every round of each generated run: a
  positive must fire in some round, a negative in none - except
  negative-dark-then-linked (`fixturegen.LAST_ROUND_ONLY`), whose point is
  the round that clears a streak that fired (in round s it fires exactly as
  positive-never-live does). The shipped files stay last-round (byte
  equality). check-rules still judges the files as before. Is the run the
  Table's unit of measure for generated fixtures?
- Q-2 (what is shipped). The guidance said "a minimal copy of the arrival
  fixtures". The arrival fixtures are host LINES, and every host line
  carries the thresholds it was made with (rhythm.k/w/r, streak,
  live_window): under any changed value the shipped lines can never match,
  so measuring on them would be vacuous. I shipped the arrivals' INPUT (the
  exports' inventories, which discover makes from the real exports) and
  replay them through HostWatch at the new values; at the declared values
  that replay is the shipped file (tested). Also: the directory is
  `raqib/rules/hostdata/`, not `raqib/rules/fixtures/`, because a directory
  named `fixtures` beside the module `raqib/rules/fixtures.py` is one
  `__init__.py` away from shadowing it. Both are departures from the
  guidance's letter: the Table's to confirm.
- Q-3 (W inside the generator). make.py's gaps were fixed (a host child 5 s
  after the talk round; an os talk 3 s before its act), so any w < 5 failed
  every host positive for the generator's sake, not the rule's. The gaps are
  now min(5, w) and min(3, w) (identical at w=30). No generated negative
  puts an act just OUTSIDE W (that is a new fixture in the YAML's list, out of
  this Scope): w is measured on "the rule still fires on its shapes and
  nothing benign fires", not on "it stops firing past W". A pair for W is a
  candidate for the Table.
- Q-4 (values the bounds admit and the measure refuses). k=1 (any single
  talk-then-act), and k >= r-1: an os source's act is read one round after
  its time (host.py's read of the per-tree file), so the k-th cycle of the
  host-talks/os-acts shape needs r >= k+2. Both are refused with the fixture
  named, so nothing is allowed on faith; but the bounds say "k 1..100, k <=
  r". Should the Table tighten them (k min 2; a relation "k <= r - 2" needs
  arithmetic the relation grammar does not have), or keep the bounds as the
  outer fence and the measure as the inner one?
- Q-5 (streak min 2). At streak 1 the negative "dark one round short of the
  streak" has no round, so the value cannot be measured; the YAML's bound
  starts at 2 (live_window too, as it may not be below the streak).
- Q-6 (live_window). No fixture of AGENT-DARK-LIVE exercises the window
  (positive-never-live is never live; the live-then-dark runs are host.py's
  NOTES under tests/fixtures/host/notes, N-2). A changed window is measured
  as "the rule's positives still fire and its negatives and arrivals do not"
  - true at every value - but its own effect (a shorter window knocks
  sooner after a live tree) is not. Allowed, not refused: is that "on
  faith"? A parametric pair (dark inside the window: no fire; past it: fire)
  would add fixtures to the YAML's list (out of this Scope).
- Q-7 (suspect_every) is a watch parameter, not a condition of the rule (the
  `any` with `exists: false`): no fixture depends on it, so its measure is
  the rule's unchanged result. Recorded.
- Q-8 (no built-in bounds). The guidance said the built-ins become a
  fallback for a rule whose YAML has none, "which then is not editable":
  such a fallback would bound nothing, so BOUNDS and ORDER are removed and a
  rule without a block lists its declared thresholds as fixed. HOST-UNWATCHED's
  none_rounds (eq 2) is declared but fixed: host.py counts it with its own
  UNWATCHED_ROUNDS and never reads it from the YAML, so a changed eq would
  never match (said in its YAML comment).
- Q-9 (a person's rule). A user rule with a bounds block is editable and
  measured on its own fixture files under rules.d (M7.6 A-3 unchanged): its
  files carry the old value, so a change is refused unless the person ships
  fixtures that hold at it (test_e5_a_user_rule_without_bounds_...). No
  generator for a person's rule. HOST-class user rules stay refused (A-6).
- Q-10 (cost). A measure at the declared-scale values takes 0.1-0.3 s here;
  k=100 with r=1000 about 7 s (1000+ HostWatch rounds); streak 100 about
  1 s. It runs on `--threshold` and at every load of an overlay with a
  changed threshold (each watch start, each panel reload). Acceptable for
  v1? The in-process memo removes the second measure of one command only.
- Q-11 (raqib/rules reaches host.py). fixturegen (in raqib/rules/) imports
  raqib.host, raqib.discover and raqib.notify inside its functions; with
  platform "fixture", a fed inventory, a fake Sysmon check and a disabled
  notifier, HostWatch reads nothing live and starts no process. The A1 test
  in tests/test_rules.py was a substring match and tripped on the data key
  "sockets" (a fake ss row's count); it now matches the banned names as
  words. Recorded for the Table's eye: the test is weaker by exactly that.
- Q-12 (CI install job, gate.yml not in Scope). Met as M7.6 did, by pytest:
  test_e5_an_installed_layout_sets_measures_and_resets_with_no_checkout runs
  `raqib rules --threshold HOST-RHYTHM k 4`, a refused k=1 and `--reset`
  from the wheel's files alone (test_packaging.site_layout, `python -I`, cwd
  outside the checkout, no tests/); and
  test_e5_a_wheel_installed_in_a_clean_venv_sets_measures_and_resets builds a
  real wheel offline from a copy of the package files (this Python's
  setuptools, `--no-build-isolation --no-index`), installs it with pip into a
  fresh venv and runs the venv's `raqib` from outside. It ran here (3.6 s);
  it skips, named, where setuptools or ensurepip is missing (the CI pytest
  job installs only pytest; setup-python's interpreter usually has pip and
  ensurepip, setuptools is not certain). The gate.yml step itself is the
  Table's to add.
- Q-13 (bounds grammar). Keys are the thresholds' short names (the field's
  last part, as `raqib rules` names them); a short name two fields share is
  not a threshold. Relations are "a <= b" or "a >= b" only. `relations` is a
  reserved key of the block (no threshold may be called that).
- Q-14 (counts). HOST-RHYTHM's measure counts 7 negatives (its 5 and the 2
  arrivals, E4) where check-rules counts 5; AGENT-DARK-LIVE's arrivals are
  unmeasured for it (no footprint line, C-1a) as before. The README section
  test now expects 6 lines (two added).
