## 2. ZF-1: `_one_name` read as Windows would treat each name
- **Trailing dot or space:** refused (849).
- **Only dots and spaces** (".", "..", "...", ". ."): refused by the same test.
- **Device names:** the base is taken up to the first dot, then its trailing spaces are dropped and it is upper-cased
  (851). That matches how the system finds a device in the last part of a path, as I read its documented and
  reimplemented behaviour (not measured). So "con", "Nul.txt", "aux.tar.gz", "con .txt" and "CON  .x" are all refused.
- **COM/LPT:** `isdigit` takes 0-9 and the superscripts ¹²³. It also takes any other Unicode digit, which
  over-refuses. That is safe.
- **Leading space (" CON"):** handed. Windows does not treat it as a device either, so this is consistent.
- **Control characters:** handed. They are not rewritten: the call names that exact name or fails (123).
- **Wildcards:** handed. The system refuses them in a name and does not expand them in DeleteFileW, RemoveDirectoryW
  or FindFirstFileW's folder part. This is from the system's documents, not measured.
- **8.3 aliases:** the listing gives long names (cFileName). A long name can at most coincide with an alias in the
  same folder, which is still inside the place.
- **No later part of a path can end in a dot:** every folder entered was itself a listed name that passed `_one_name`.
- **Result:** I found no form handed that the system would turn into another name, the folder itself, the folder above
  or a device. Not measured.
- **The other way:** none of Raqib's own names is refused. That covers `.raqib` (empty base), `host`, `sources`,
  `service.txt`, `service.before.txt`, `rounds.jsonl`, `rounds.jsonl.watch.json`, `events.jsonl(.N)`,
  `inventory.json`, the atomic-write temp `.raqib-host-*.tmp` (host.py:578), and names made of a time stamp, a pid and
  a hash. tests:962-966 and the TREE runs guard this direction.

## 3. ZF-2: what `held` answers, and what stops the removal
- **What stops it:** exactly `isinstance(held, dict) and held["held"] == "fresh"` (966). That is the exact complement
  of `_wait_for`'s return at winservice.py:1065.
- **Same call, same path:** it is the same call, winservice.System.held, which calls host.holder(home=place,
  wall=time.time) (winservice.py:420-424). It is handed the judged string itself: got[1], the same `ntpath.join(root,
  "Raqib")` that prepare builds (winservice.py:561).
- **State file unreadable** (open refused, not ASCII, not JSON, torn, not an object): "unreadable", and the place is
  removed.
- **No host mode, or finished:** "none", and the place is removed.
- **Unfinished with a heartbeat that cannot be parsed:** "unparsed", and the place is removed. The watch itself
  refuses to start over such a state (host.py:2519-2523).
- **Nested too deep or too large:** RecursionError or MemoryError is caught (963-965): nothing is touched, exit 1.
- **Heartbeat far in the future:** the age is negative, so it reads fresh. The place is kept, exit 1, and stays kept
  until the wall clock passes the heartbeat.
- **Read before any removal:** yes, on the one road that removes (959-970). It is not asked on the absent, refused or
  unread roads, and the tests check that.
- **No writes:** holder writes nothing (host.py:513-542: one open for reading, then json.load).

## 4. ZF-3: the retry on 32
- **Where it applies:** only inside the place. The place's own folder is excluded (925). It runs only where `result ==
  REMOVED` (1013), which needs exit 0 with no handle-close failure.
- **The bound:** 20 s per removal, so N held names wait N x 20 s, and N grows with the record (ZE-5 gives no bound on
  its size).
- **Whether one bound is needed:** ZF-3's reason is one lingering process whose handles close together, and one
  deadline serves that. Per removal, the command's length and ZE-5's window between reading and removing (measured
  under 0.1 s) grow with the number of names held. `held` is not asked again during that time. This is for the Table
  to decide.
- **Where the code would hold it:** a deadline in `_purge` beside `done` (889-890), set by `_removal` at the first
  IN_USE from `system.clock` (869). Each later `_removal` then asks again only while `now < deadline` (878).
- **Can it spin?** Yes, with a stand-in whose sleep does not move its clock, or a clock that answers a constant or
  NaN: `now - first >= IN_USE_BOUND` is then never true. The real `time.sleep` and `time.monotonic` move. `_wait` has
  the same property (529-550).

VERDICT: NEXT

1. **medium (A3, for the Table).** wininstall.py:966 takes "unparsed" and "unreadable" as clear to remove, and
  tests:844-849 pin that. The watch's own rule D-6 says an unknown state is not clearance (host.py:2519). An
  "unreadable" state can also come from a live writer's `os.replace` at the moment it is read (host.py:584-590). This
  is built as E2 is worded ("held fresh"). **To make it right:** the Table rules whether unparsed (and unreadable)
  means the place is held or not known (exit 1, nothing removed).
2. **medium/low (for the Table).** wininstall.py:862-880: the 20 s bound is per removal, so N x 20 s in all. It widens
  ZE-5's window, and `held` is not asked again during it. SERVICE.md:826-827 and the GUIDE's "up to 20 s" can be read
  as a total. **To make it right:** one deadline for the whole purge, held in `_purge` (889) and checked in `_removal`
  (878); or the documents say "each".
3. **low (rule 4).** wininstall.py:869-879: a clock or sleep that fails ends the wait silently. The line then says
  "error 32 ... once" as if the wait had been made. These roads are untested. **To make it right:** say the wait's
  failure in the left line, and add tests with `fail={"sleep": [...]}` and `fail={"clock": [...]}`.
4. **low (field).** ZF-2's "(measured: the one command removed both)" was measured on a2c6905, which never asked
  `held`. That the state reads finished right after the service's own remove is not yet measured. If it does not, X56
  will read 1. **To make it right:** read it at X56 and the first field moment.
5. **low (A5).** On the read again, an error 5 (for example, a folder still pending deletion) is said through
  place_judged's "an administrator is needed" (492-493 via 978) to an administrator. The branch has no test. **To make
  it right:** add a test where the read again raises 5, and the Table rules the words.
6. **low (A5).** RECORD_HELD (147-149) says "still watches, or was ended without its end ... ask again when it has
  ended". A heartbeat ahead of the clock, or an infinite staleness, holds the place with no end. The runner's own
  words add "or a heartbeat ahead of the clock" (winservice.py:1076-1077). **To make it right:** add those words.
7. **low (A5).** wininstall.py:56-58 says "each left with its target's file". The shell's folder has no target (its
  own file was left), and for the link inside the place the rest was removed. **To make it right:** say each case as
  SERVICE.md:839-843 does.
8. **low.** `_removal` has no count bound, so a clock that does not move spins forever. **To make it right:** also
  stop after IN_USE_BOUND / IN_USE_EVERY asks.
9. **low (tests).** No test lists a refused name as a folder (0x10) or a reparse point (0x410). No test covers a

10. **low (suspicion only).** There are now two judgements of a Windows name: wincode._part_refused

  on purpose), and on wildcards and control characters. `_one_name` only refuses more than wincode does, so it is
  safe. Recorded.
11. **low.** tests:1181-1187: `ntpath.os.unlink` or `sys.modules["os"]` would pass all three os checks. This goes

12. **low (A5, older text).** wininstall.py:12-13, "This module itself was not run on a real machine", now contradicts
