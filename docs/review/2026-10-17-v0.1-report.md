## 4. Question files and the readings taken

Every design question went to `docs/review/2026-10-17-<task>-questions.md`;
the most conservative reading was taken each time. In brief:

**M0.1** — Q1 the hello spec lived in `tests/e2e/` while `e2e/` was out of
scope (moved to `e2e/` in M2.1). Q2 exact pins; vitest 4 rejected (npm
peer resolution fails). Q3 JSX through esbuild, no Babel preset. Q4 no
`toFixed`: decimal.js configured never to print exponents.

**M0.2** — Q1-Q9 row, amount, problem, YAML and serializer choices made
from `reference/` alone; Q1-Q4 and Q6-Q8 superseded in M0.3 by the CLI's
own behaviour; Q5 (`classes` default list) and Q9 (serializer style;
CSV round trips byte for byte, YAML semantically) stand.

**M0.3** — Q1 the reference engine's source on branch `qayd` was read,
never written. Q2 the loaders follow the CLI exactly (problem shape,
codes, every faulty field, one line per CSV record, every policies.yml
problem fatal). Q3 YAML 1.1 as PyYAML reads it, with documented
differences (parse-error wording, keys always strings, `!!set` family
refused). Q4 `null` is an absent file, `""` an empty one. Q5 a household
the CLI cannot read is never green: no policies, every fatal problem a red
finding. Q6 the oracle is compared without any normalisation; the wider
suites normalise only the YAML parse-error wording. Q7 1215 recorded CLI
runs committed, replayed by the gate. Q8 the CLI's synthetic test fixtures
copied. Q9 one drawdown message keeps Python's trailing zeros; documented,
not emulated. Q10 the engine API the screens use, fixed before the UI tasks.

**M1.1** — Q1 an eighth screen, Files, for import and export. Q2 refuse
only what the CLI could not read at all; import the rest and let the
engine judge it. Q3 absent files and the empty state. Q4 two tabs: whole
files, last write wins, BroadcastChannel or `storage` event, reload with
a banner. Q5 a later refused write moves the tab to memory with the
banner; an open silent for 4 s counts as unavailable. Q6 Arabic counts
written "label: n". Q7 the hello spec kept passing.

**M1.2** — Q1 `hold` green, every other verdict red (a silence never looks
milder than a breach), the verdict word always on the chip. Q2 the

**M1.3** — Q1 forms change one YAML block item, never re-serialise a whole

**M1.4** — Q1 the default period is the quarter of the as-of date (never

## 5. Deviations from the ADRs

App ADR (`docs/specs/ADR-0001-app.md`):
- §2 Import offers one input per file, several files at once (matched by
  name) and paste; there is no folder picker. Selecting the five files of
  a folder at once does the same job.
- §3 An eighth screen, Files, holds import and export (M1.1 Q1).
- §3 The as-of "date picker" is an ISO text input with a Today button, so
  dates stay ISO with Latin digits in both languages (M1.2 Q4).
- §3 Review: the screen's headings and column names are translated and
  two charts have tables beside them (M2.2 Q3); the copied or downloaded
  page is the CLI's own, in English (M1.4 Q3).
- §6 The gate also checks that `release/qayd.html` equals a fresh build
  (M2.2). It does not grep for unary `+x` on amounts, which the ADR lists;
  `parseFloat(`, `Number(` and `toFixed(` are grepped as before.

Engine ADR and reference CLI (`reference/spec/ADR-0001-qayd-engine.md`):
- YAML parse errors are worded by js-yaml (file, line and code agree);
  mapping keys are always strings; `!!set`, `!!omap`, `!!pairs`,
  `!!binary` are refused (M0.3 Q3).
- BAD-ENCODING never reaches the engine: bytes that are not UTF-8 are
  refused at import (M1.1 Q2).
- One drawdown reason prints a computed zero-or-negative peak without
  Python's trailing zeros (M0.3 Q9).
- §8 `init` is "Load the sample household"; `review -o FILE` is Copy as
  HTML / Download. Exit codes are not shown as numbers; the summary line
  and the fatal message are the CLI's.

## 6. Open items

- **M2.3** (an outside user runs `release/qayd.html` on their own numbers
  and files one issue) is open until it happens; it is not a builder task.
- **Exported page contrast**: in the CLI page's light theme `hold` 4.25,
  `missing` 4.17, `stale` 3.25 and `warn` text 3.25 are below 4.5:1. To be
  fixed in the reference engine, then ported.
- **Failure model, open in each case**: persistent storage not requested;
  no "last exported" reminder; an unsaved raw edit replaced by another
  tab's write without warning; a kept as-of date that is not today not
  flagged; a loosening policy edit asks nothing and leaves no trace; the
  reversal chain not followed; a dropped download in a sandbox cannot be
  detected.
- **Browsers**: only Chromium is tested. Firefox and Safari (and their
  `file://` storage rules) are unverified.
- **Small leftovers**: `vitest.config.ts` still excludes the now-empty
  `tests/e2e`; the colour tokens `--unknown-bg` / `--unknown-fg` are
  defined but used by no rule; the gate has no unary-plus check (section
  5). None affects a verdict.
- **Commander**: the next HANDOFF (`docs/handoffs/<next>.md`) and the
  merge of `claude/qayd-web-v0.1` into `qayd-web` are the commander's.
