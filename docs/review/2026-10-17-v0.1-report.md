## 4. Deviations from ADR-0001

Where a HANDOFF exit criterion and the ADR disagreed, the HANDOFF was
followed and the ADR difference is listed here. Where the ADR was silent,
the reading is in the question files above and is not repeated unless it
changes an ADR statement.

1. **Section 7, logsource compatibility.** ADR: "every key the rule sets
   must be equal in the corpus declaration". Implemented: `product`,
   `category`, `service` only; `definition` and other keys ignored
   (M1.2 Q1). Reason: `definition` is free text in Sigma; requiring
   equality would make nearly every rule `no_corpus`.
2. **Section 9, JSON of `export`.** ADR: every JSON output is
   `{"version": 1, "rules": [...], "green": bool}`. Implemented for
   `export --json`: `{"target", "query", "backend_version"}` as HANDOFF
   M2.1 E1 prescribes (M2.1 Q1). The four other commands keep the ADR
   shape and add `"command"` (and `"rules_dir"`, `"corpus"` for check/
   corpus) -- a superset.
3. **Section 9, text line of `corpus`.** ADR: `<status> <id> <title>`.
   Implemented for the `corpus` command: `<status> <id> fp/10k=<n>
   budget=<b> events=<e>` as HANDOFF M1.2 E4 prescribes; `check` and
   `test` keep `<status> <id> <title>` and add one indented summary line
   (`fp/10k=... corpus=...`) after the citations.
4. **Section 8, exit code 3.** ADR: 3 when "a corpus file unparseable".
   Implemented more broadly: any corpus file without a valid header,
   empty, unreadable, over the size limit, or with a line that is not one
   JSON object, and a missing corpus directory, give exit 3 (the affected
   rules are also `unknown`, as HANDOFF M1.2 E1/E3 require).
5. **Section 3, stricter than listed.** The loader rejects more than the
   ADR enumerates: duplicate YAML keys, rule files over 1 MiB, unknown
   keys under `x-mizan`, a `condition` list, non-canonical UUID
   spellings, uppercase levels, an empty `x-mizan.corpus` list. Each is
   `invalid` with the field named; none is silent (M0.1 Q1-Q11).
6. **Section 5, inside one selection.** The ADR specifies three-valued
   logic between selections; the matcher additionally makes `Unknown`
   dominate inside one selection and `evaluate_rule` compiles every
   referenced selection before looking at any event, so a rule that uses
   an unsupported feature is `unknown` on every event even when the
   three-valued table would have short-circuited it (M0.2 Q1, M0.3 Q1).
   This is a strengthening of A4, not a relaxation.
7. **Section 4, event-side numbers under gt/gte/lt/lte.** The ADR speaks
   of numbers; strings that are exactly a JSON number literal (`"2048"`)
   are also compared as numbers (M0.2 Q5). Everything else is False.
8. **Section 2, modules.** No module was added or removed. `report.py`
   also holds the `Result`/`Citation` types and `combine`; `loader.py`
   also holds `find_rules`; `fixtures.py` also holds the JSON Lines reader
   used by `corpus.py` and `match_file` for the `match` command.
9. **Section 9, `match`.** The ADR does not define green for `match`;
   implemented: exit 0 when every line was judged (M1.1 Q5).

No ADR amendment was written: amendments are the commander's (the ADR
says they are appended, never edited in place, and the builder's scope
never included `docs/specs/`).

## 5. Open items

Engine (each needs a handoff; none blocks v0.1):
- YAML alias expansion in rule files is unbounded under the 1 MiB cap
  (THREAT_MODEL section 6, M2.2 Q4). Proposed: refuse aliases in the
  strict loader.
- Regular expressions from rules have no execution-time bound against
  crafted events (M0.2 open item, THREAT_MODEL section 6).
- Duplicate rule ids across a directory are not detected (M1.2 open,
  THREAT_MODEL section 8).
- `.yaml` files are not scanned by `check` (M1.1 Q8 / M1.2 Q9).
- No cap on the number of match citations for a match-everything rule on
  a large corpus (M1.2 open).

Policy and evidence (THREAT_MODEL sections 1-5, 7):
- Near-miss and minimum-count requirements for sidecars live only in the
  example set's test, not in `fixtures.judge`.
- Budget caps per level and the "budget raised to pass" pattern are not
  enforced; budgets of the example set are measured + headroom (M1.3 Q1
  asks the commander which convention to adopt).
- Corpus provenance, minimum size and diversity are not measured; the
  shipped corpora are synthetic.
- Evasion fixture sets per technique do not exist.

  merge into `mizan`; the builder did not merge (CONSTITUTION, roles).
