## 5. Deviations from ADR-0001

None of these changes a constitutional article; each is recorded in the
question file named.

1. **§2 Member substitution after start** is not implemented: the ledger
   type `member.substituted` is reserved, no route uses it (M0.2 Q9).
   After start nobody can leave or be replaced in v0.1.
2. **§2/§3 Storage of contributions.** Reports, confirmations and waivers
   are ledger entries; `contributions` holds one obligation row per
   (round, member) and the tables are indexes of the ledger, not the
   record (M0.3 Q1, M1.4 Q1). No draw tables (M1.3 Q1).
3. **§3 Audit table** is append-only by trigger, like the ledger (stricter;
   M0.3 Q3).
4. **§4 API: routes added** beyond the ADR's list: `GET /api/auth/csrf`,
   `POST /api/auth/logout-all`, `PATCH /api/auth/me`, `GET
   /api/auth/sessions`, `POST /api/auth/sessions/:id/revoke`, `POST
   /api/auth/password`, `POST /api/auth/recovery-codes`, `GET
   /api/circles/:id/invites`, `POST .../invites/:inviteId/revoke`, `GET
   /api/invites/:token`, `POST /api/circles/:id/leave|cancel`, `GET
   /api/circles/:id/draw`, `GET /api/circles/:id/overview`; the organizer
   may report for a member through the contributions route. All are in
   the matrix and audited (M1.1 Q7, M1.2 Q1-2, M1.3 Q7, M1.4).
5. **§2 Draw timing**: the ADR computes the order "when all have revealed,
   or at the reveal deadline"; here the organizer finalizes then (route
   `draw/finalize`, as the ADR's API lists), early close/finalize only
   when everyone has acted, a start date on or after the reveal deadline
   is required, and only the start date may change while drawing (M1.3
   Q2, Q5).
6. **§5 Client placement**: invitations and start are on **Members**, not
   Settings; Settings holds rules, start date and cancel; an **Activity**
   tab shows the audit log (M2.2).
7. **§6 CSRF form**: a token in the `x-csrf-token` header that is an HMAC
   of the session (or, before sign-in, of a pre-session cookie), not a
   separate double-submit cookie; equivalent binding (M1.1 Q3). Cookies
   are `__Host-` prefixed in production; sessions also have a 90-day
   absolute expiry (S2.1).
8. **§7 Logging** field is `durationMs` (ADR: "duration").
9. **§8 Configuration** adds `HOST` (default 127.0.0.1), `TRUST_PROXY` and
   `CLIENT_DIR`; production also requires an `https://` BASE_URL
   (stricter; M0.1 Q6, M0.3 Q6).
10. **§9 Deployment**: the backup uses SQLite's online backup API through
    better-sqlite3 rather than the `sqlite3` shell's `.backup` (same
    mechanism; M3.2 Q3); added `deploy/restore.sh`, `dbtool.mjs`,
    `healthcheck.mjs`, `smoke.sh`, `Caddyfile`, `env.example`.
