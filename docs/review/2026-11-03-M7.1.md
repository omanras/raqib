## Findings
P1 (must-fix, A3) the DNS name list is capped silently: hostwin.py:354 drops every name after
   DNS_NAMES_MAX (20000) with no error and no hole, unlike the process cap (hostwin.py:279-281) and
   the TCP failure paths; a flooded cache hides the names an agent's endpoint would join on.
P2 (should-fix, resource) cached_records frees the record list only when status == 0
   (hostwin.py:388-389); DnsQuery_W can hand back a list with a non-zero status (a negative answer
   with its SOA, a CNAME chain with no A), which is then never DnsRecordListFree'd. Leaks per name
   per sample; M7.2 runs this for as long as the watch runs. Free whenever head is non-NULL.
P3 (should-fix, Q-3, A6) with CommandLine empty live (hostwin.py:420), names_of (discover.py:1459-1470)
   loses argv[0..1]: Claude Code run as node.exe ...\node_modules\@anthropic-ai\claude-code\cli.js is
   named "node" only, so a ~/.claude footprint no longer links (discover.py:2150-2156) and is
   AGENT-DARK beside a live candidate, and the B-7/D-5 hand-off falls to `os`. Not covered by
   NOT_READ's wording (hostwin.py:88-91), which names `--type=` and argv footprint paths only.
P4 (should-fix, E4/A6 evidence) the live-shape equivalence is tested on the two Kimi positives only
   (test_hostwin.py:310-341). The act_root fp_budget is measured by --check on the CSV negatives with
   their CommandLine (G-1b `--type=` helpers, benign/windows-desktop); no test runs a negative through
   the fake API, so the 0-of-2 measurement is not shown to hold for a live run.
P5 (should-fix, E4) the CI step asserts only exit != 2 for the replay (gate.yml:160-161); nothing
   compares replay.json to live.json (self, candidates, act_roots, records) on a real host. The
   equality is proven only against the fake API (test_hostwin.py:523-528).
P6 (should-fix, A3/A5) the LiveRefused wrapper (discover.py:1172-1178) covers hostwin.collect as
   well as Api(): any AttributeError or OSError raised by a bug inside the reader is reported as
   "the API cannot be loaded" and exit 2, hiding the real cause.
P7 (should-fix, E3) on Windows the reader's launchers are not in its tree: the console script
   raqib.exe and, in a venv, the redirector python.exe are the parents of os.getpid()
   (discover.py:1174), so they are ancestors (self_line, discover.py:1634-1636), not self_tree. They
   can be counted as acts of a talking ancestor or as an act-root's "command below the shell"
   (discover.py:2025-2034). The CI step checks only `me` (gate.yml:146-150). On Linux the launcher
   is the same process; this is new with Windows.
P8 (note, A4) OpenProcess on every pid every sample (hostwin.py:296) is read-only but not silent on
   the host: Sysmon event 10 / object-access auditing and EDRs log handle opens (lsass included),
   and DnsQuery_W calls may appear as the reader's Sysmon 22 / DNS-Client ETW events, a source
   discover itself reads. "nothing written" (hostwin.py:34-36, README) holds for Raqib, not for the
   host's logs. Unverified on a host.
P9 (note, Q-2) NO_WIRE_QUERY "nothing is sent on any network" (hostwin.py:29-30, 57, README) rests on
   the API's documentation; the call goes to the DnsCache service by local RPC, whose behaviour
   (TTL refresh, hosts file, negative caching) is not observed. No CI check can show the wire silent.
P10 (note, A3) a process that exits between the Toolhelp snapshot and OpenProcess is counted as
   "denied" (hostwin.py:418-419, hole text :493-494); a pid reused in that gap gives another
   process's path and CreationDate to the snapshot's name and ppid (no check that the path's
   basename equals szExeFile). Denied pids also appear twice: hostwin's hole and discover's G-4
   hole (discover.py:1783-1786), which the test asserts (test_hostwin.py:443-444).
P11 (note, scope) discover.py:704-712 changes parse_win_process (a parser, not "live path, --save"):
   any win-process CSV, including a PowerShell export given with --from, now honours a
   "# raqib-snapshot ... self=PID" line, so an edited export can name any tree "the reader" and
   exclude it from evidence (same trust as proc.txt's "self", discover.py:522). doctor gains a
   function and a prober argument through checks()/run() (doctor.py:323-347, 409, 443), more than
   "one line" of code though one line of output.
P12 (note, A3) an AF_INET6 failure makes the whole win-tcp-k source an error (hostwin.py:428-434),
   so the run is incomplete; Linux treats a missing IPv6 table as a hole only (D-2). Table's choice.
P13 (note, A3) a cache entry with a NULL name is skipped without a count (hostwin.py:352), and a
   name longer than NAME_MAX (1024 units) is truncated silently (hostwin.py:220).
P14 (note) "T seconds apart" is T after the end of each sample (hostwin.py:489-490), not start to
   start; sample_times in run.json records the truth (A5). README/--every help say "apart".
P15 (note, Q-9) doctor says OK for macOS (doctor.py:326-327) where discover reads only the homes
   and ends incomplete (exit 3).
P16 (note) test_hostwin.py:213 returns 9701 commented as DNS_INFO_NO_RECORDS; that constant is 9501
   (9701 is DNS_ERROR_RECORD_DOES_NOT_EXIST). The reader treats any non-zero alike, so no effect.
P17 (note, Windows versions) DnsGetCacheDataTable is undocumented (hostwin.py:116-117); whether it
   returns FALSE or TRUE with a NULL head on an empty cache is unverified; FALSE gives "no names"
   (safe side). Real path first runs in CI 41702279079.
P18 (note, ADR-0007 decision 3) no cwd is read live (A4), so M7.2's "hooks into the project that
   tree's cwd names" has no input on Windows from this reader.
