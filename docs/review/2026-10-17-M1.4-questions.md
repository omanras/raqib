# M1.4 — questions for the commander (not answered locally)

Each entry: the question, the most conservative reading taken, where it
shows in the tree. Nothing here changes the exit criteria.

## Q1. "Default the current quarter": current by the clock or by the as-of date?
The app already has one notion of "now": the as-of date (default today,
set on the dashboard, kept in the store). The review's default period is
the quarter that contains the as-of date, taken once when the screen
opens; with the as-of date left at today that is the current quarter.
Reading taken: the review never looks at the clock on its own, so the
same files and the same as-of date give the same review on every machine.
`src/ui/review.tsx` (`periodOf(asOf, "quarter")`).

## Q2. Which as-of date a review is judged at
The CLI judges a review at the period's end when that end is before
`--as-of`, else at `--as-of`. The port does the same (`reviewAsOf`), with
the app's as-of date in the place of `--as-of`. A future period therefore
shows only the months up to the as-of date (2026-Q4 as of 2026-10-17 has
one column, 2026-10, cut at 2026-10-17), as the CLI does.

## Q3. "Copy as HTML" is the CLI's page, in English
E3 asks for the same sections with theme tokens on `:root`; the app ADR
asks for "the same self-contained page the CLI writes". The copied and
downloaded page is that page byte for byte (`renderReviewPage`, checked
against 17 pages recorded from the reference CLI in
`tests/ui/review.test.ts`), so it is in English whatever the interface
language, and it carries the CLI's own palette, not the app's. The
on-screen sections are translated (headings, column names); engine texts
inside them (verdict reasons, declared policy text, finding reasons, the
chart titles and legends inside the SVG) stay in English as everywhere
else in the app. An Arabic export page would be a new artefact the
reference does not define; not built.

## Q4. The review differential lives in tests/ui/, not tests/differential/
`tests/differential/` is outside this task's Scope. The recorder
(`tests/ui/review/generate.py`, run by hand against branch qayd, not by
the gate) and its output (`tests/ui/review/cli-reviews.json`) sit next to
the unit tests. Eight households (the sample and seven variants: a
breach, a currency with no rate, no rates file, a tight snapshot age, an
HTML-hostile note, no snapshots, a refund) and seventeen period/as-of
pairs, all byte-equal.

## Q5. The SVG is placed as markup
The charts are the engine's own SVG strings (every text escaped like
Python's `html.escape`, no script, no event attribute, no external
reference), placed with `dangerouslySetInnerHTML` so the screen and the
exported page draw the very same pixels. Their colours are the CLI's
tokens (`--grid`, `--income`, `--expense`, `--bar`, `--band`, `--mark`,
`--unknown`), now also defined in `src/ui/styles.css` for light, dark by
system and dark by choice, with text in `currentColor`.

## Q6. Two number details of the drawing
- Geometry is the only place a JS number is used (pixel positions, not
  money); it is formatted like Python's `'%.1f'` from the exact binary
  value, half to even (`f1`). Amounts printed in the charts come from
  Decimal (`money`).
- decimal.js keeps a negative zero where Python's Decimal arithmetic
  gives `0` for the empty expense sum of a month (`measures.ts` negates
  the sum). The value is equal and prints as `0`; only a pixel computed
  from it could print as `-0.0`, so `px()` maps a zero to +0 before
  formatting. The engine's measures are unchanged (no new measures, as
  the HANDOFF requires).

## Q7. A household that cannot be read
When the household is fatal (a policies problem or a file-level problem)
the review is not built and the screen says why, as the dashboard does;
the CLI exits 3 with no page in that case.
