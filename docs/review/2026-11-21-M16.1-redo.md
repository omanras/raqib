# Review packet: M16.1 REDO (4aaa17c)
VERDICT: REDO   (a recommendation, not an approval)
The field run is strong. On both engines every claim was MET, with positives, near misses, odd lines and timed reads.
Four things should still be fixed before merge:
- X41 can still say MET when nothing was judged (every read "not sure"), and a test holds that behaviour.
- Two kinds of line pass the pipeline's check but an engine will very likely refuse them, so they would be lost:
  a key longer than the engine's term limit, and a number too large for a double. I suspect this; it was never fed.
- siem/README.md:39-41 says more than the pipeline does.
- The bound of runs-no-end drops the runs most likely to have been killed first, and the page does not say so.

## MUST FIX BEFORE MERGE
1. tools/rig/siem_run.py:578-591 (judge_deadlines) and tests/test_siem_content.py:624.
   Problem: a group that is "not sure" is not judged, and ok stays True. If the runner is slow and every group is
   not sure, the silence and runs-no-end rows say MET with nothing compared. The test at :624 asserts exactly
   that (True with "2 not sure"). Verified by reading.
   What a SOC would miss: on a slow push, X41 says MET without anything having been checked.
   The field run had 0 not sure, so this path has never run on an engine.
   Smallest change: a read with any not-sure group is not MET (say n/a with the reason), and the test at :624
   expects that.
2. siem/*/pipeline.json:25 (the walk function) and tools/rig/siem_run.py:196-227 (typed and walk).
   Verified by reading: the check bounds the length of values only, not of key names. Type 'f' accepts any Double,
   including Infinity.
   Suspected: two lines the check calls events that the engine then refuses, so they are lost (against SA-5):
   (a) A top-level unknown key over 32766 bytes is listed in raqib.unknown_keys (template.json:134-136, a keyword
       with no ignore_above). That is an immense term, so the line is refused. A long key below a part kept whole
       (for example inside evidence.cites items) makes the flattened path plus value too long in the same way.
   (b) watch.beat or rule.fp_budget written as 1e400 parses to Infinity. The double fields
       (template.json:148-150 and :158-160) refuse values that are not finite.
   R3's "a text longer than 8000 characters" does not cover key names as written.
   Smallest change: in both copies of the pipeline and in check_of, bound a key's length (small enough that path
   and value together stay under the term limit) and require a finite number for 'f'. Add both lines to ODD so
   the rig measures them.
3. siem/README.md:39-41 and siem/*/pipeline.json:2.
   Problem: the page says the pipeline "sets host.name and removes no other field a shipper set ... on an event and
   on an error document alike". Verified by reading, the pipeline does less than that:
   - On an error document it does not set host.name (Q2).
   - On an event with no summary it removes `message`, the shipper's line (pipeline.json:46 `ctx.remove('message')`).
     The rig's own X40 expects that removal.
   - It replaces a `host` that is a text (Q10), and @timestamp and event.*.
   - The test named test_r3_no_field_a_shipper_set_is_removed (tests/test_siem_content.py:145-153) checks only
     the `remove` processors, so it does not catch these.
   Smallest change: say exactly which fields are set or replaced and that `message` is removed; rename or narrow
   the test.
4. siem/README.md:149-151, siem/*/searches/runs-no-end.json:2 and :34-44.
   Verified by reading: the multi_terms has no order, so it keeps runs by count. Ended runs count toward the 10000
   for as long as they are kept. Past 10000 runs, the runs with the fewest lines are cut first, and those are the
   likeliest killed. Nothing in the answer says a cut happened (sum_other_doc_count is not read).
   What a SOC would miss: killed runs, once it holds more than 10000 runs (for example 50 hosts with a daily
   restart over 200 days).
   Smallest change: the sentence and the page say which runs fall outside the bound and how to see that a cut
   happened. The order itself is Q5 for the Table.
5. siem/README.md:50-69. This is a regression from 4599659.
   The REDO removed the only pointer to error documents ("Search for them: event.kind: pipeline_error"), and no
   shipped search lists them. A line that is kept but cannot be read is a finding (CLAUDE.md rule 4, A3).
   A host whose lines all become error documents is either listed as silent or, if it never sent a good line,
   never appears anywhere. Smallest change: restore the sentence and say both of these cases.

## SHOULD FIX (may be a recorded debt)
- Q10 (suspected). The template maps `host` as an object (template.json:63-69). An error document that keeps a
  shipper's `host` as a text (old Logstash, syslog input in legacy mode) is then refused and lost. The same holds
  if `event` or `error` is a text: the on_failure `set` fails. Not fed on the rig.
- Hosts that share a watch.host are one bucket to silence: "unnamed" (EVENT.md:118-119), or two machines with the
  same name. A dead host is masked by a live one. runs-no-end still separates them by run. README:142-148 does
  not say so.
- README:118-125 (what the content trusts):
  - A forged `watch` end takes a run off runs-no-end for good, not for two beats.
  - watch.beat has no upper bound, so "two of that beat ... and no longer" (:122-123) can mean decades.
  - Above about 4.6e15 s the deadline wraps negative (silence.json:40). That line then counts for nothing, which is
    the safe side.
- tools/rig/siem_run.py:401-417 and :818-830. A connection error or a body that is not JSON halfway through ends
  the runner with a traceback and no rows. rig.yml:216 echoes the exit and the job stays green. Each claim should
  say n/a with the reason.
- siem_run.py:615. X39 checks only that an error document has some reason, not which reason. X39 compares the
  engine with check_of, which is the same rule written twice. The per-label outcome is held only by the unit test
  (tests :156-170). Nothing requires every line of the real watch's file to be an event.
- siem_run.py:587-589. The order check uses the engine's own deadlines. A listed host that was never fed is not
  checked: the engine's keys are not checked to be a subset of the fed groups.
- README wording:
  - :115 "a cardinality of the two" was never run, and cardinality is approximate.
  - :155 "as the two searches above do": those searches read event.ingested but set no window.
  - :159 names Watcher. I suspect it needs a paid licence, and that Kibana's query rule counts documents rather
    than buckets. Neither was checked; say only "not measured".
- docs/review/2026-11-21-M16.1-redo-questions.md:85-87 says an error document has no event.ingested.
  pipeline.json:69-74 sets it.
- Stale titles: siem/attack/rules.md:1, tools/siem_content.py:51 and :77 still say "the catalog's rules".
- rig.yml:202 and :204 pin the images by tag only. :212 pins the four packages but not their dependencies.
- Text length is counted differently: Python counts code points (siem_run.py:225), Painless counts UTF-16 units
  (pipeline.json:25). They disagree for characters outside the BMP. The result is a false MISSED, not a loss.
