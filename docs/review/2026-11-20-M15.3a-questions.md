# M15.3a - questions and choices (the builder, 2026-11-20)

Task: ADR-0014 Amendment G, AG-1 to AG-3: raqib/autostart.py, the autostart places read standing alone.
Nothing here is answered locally; each choice below was made only where the HANDOFF left it open, and can be
ruled otherwise.

## Design questions for the Table

1. **A task's program.** A task's body (`Actions`, `Triggers`) is binary and is hashed as it is; its
   `program` is None. The program a task would run is inside `Actions` (a versioned binary record holding a
   UTF-16 path). Should M15.3b parse it, and by which ruling of its format?
2. **Userinit's comma.** `Userinit` usually reads `C:\Windows\system32\userinit.exe,`; through
   PERSIST-RUN-KEY's gate its first word ends with a comma, which `common.HEAD_NAME` does not take, so its
   `program` is None. Strip a trailing comma for Winlogon's values, or keep the one gate?
3. **An unquoted path with a blank.** `C:\Program Files\x\y.exe /q` is named `Program`, as PERSIST-RUN-KEY's
   line names it (its first word). Windows itself tries `C:\Program.exe` first, so the name is not wrong, but
   it names no real program of an ordinary install. Keep the one gate?
4. **A Startup file's program.** None (a file's content is not a command). Should the file's own name be the
   program where it passes the gate (a `.cmd`, an `.exe` put there), or a `.lnk`'s target be read?
5. **The `key` of an entry.** A plain sha256 of (place, hive, view, full name); for a user's Run value the hive
   is `HKU\<SID>`, so `key` is a hash over a SID (never the SID). The content's `sha256` is plain too, as the
   HANDOFF says. Should either be salted per process, so that a hash cannot be matched outside it?
6. **Keys refused in part, differently in two reads.** Where a place is `partly` in both reads but the keys
   refused are not the same (a hash of the refused keys is kept), the place gives no change and is `unread`:
   otherwise an entry under a key refused in one read alone would read as added or removed. The finer choice
   (compare all entries but those under a key refused in either read) needs the refused keys' paths kept; it
   was not made. Which?
7. **X36.** check.py has claims up to X35; the HANDOFF names X37. X37 is used as named; is X36 reserved?
8. **The rig's step.** The stand-in runs in the watch's step; a step of its own cannot read beside it. So
   tools/rig/autostart_run.py starts a second run of the stand-in as its own child, in its own step after the
   watch has ended (X32 to X34 are not touched by it). The stand-in therefore runs twice on Windows, each run
   undoing its acts. Should M15.3b's rig read beside the watch's own run instead?
9. **The rig's artifact.** autostart.json is not copied into the uploaded `rig-out` (that is the gather step,
   outside "only the step that runs autostart_run.py and check.py's new argument"); the step prints the
   stand-in's lines and check.py's row says what was seen. Add it to the gather step at the merge?
10. **The Linux job.** The step that runs autostart_run.py was added to both jobs, so X37 is said as n/a on
    Linux rather than absent (as X31 is said on Windows). Keep?

## Choices the HANDOFF did not make

- `read(registry=None, folders=None, platform=None, clock=None, disk=None)`. `registry` has two methods,
  `subkeys(root, path, view32)` and `values(root, path, view32)` (root `HKU` or `HKLM`); on Windows with none
  handed in, `winreg` is imported inside `read` and wrapped (`WinRegistry`: `KEY_READ` with
  `KEY_WOW64_64KEY` or `KEY_WOW64_32KEY`; an enumeration ends at error 259). `disk` lists a folder's files and
  hashes a file in chunks. Off Windows with no registry handed in nothing is read.
- The result: `{"read", "said", "platform", "seconds", "entries", "places"}`; `places[p]` is `{"state":
  read|partly|refused|failed, "entries", "keys_refused", "reason", "refused_sha256"}`. A place with no
  refusal and no error is `read` (the HANDOFF names only the other three).
- An entry carries a seventh field, `key` (question 5), by which `changes` knows it.
- `HKU\.DEFAULT` is left out (it is `S-1-5-18`'s hive under another name); only `HKU` subkeys that are a SID
  are read.
- A value's content hash is over its registry type and its data (so the text "1" and the number 1 differ); a
  file's over its bytes; a service's over ImagePath, Start and Type; a task's over Actions and Triggers.
- The 32-bit view's value is dropped where the 64-bit view holds the same name (case-insensitive) and the same
  content hash; the same name with other content is a second entry, `view32` true.
- A service key with no `ImagePath` is not an entry.
- A task's path in the tree (`\Folder\Task`) is its name; a refused folder of the tree is not walked and counts
  once; a task whose body is refused is an entry with `sha256` None and counts as a refused key.
- A Startup file whose content is refused is an entry with `sha256` None, counted as refused; a file gone
  between the listing and the read is skipped; a folder that is not there is empty; `APPDATA` or `ProgramData`
  not set makes `startup` `failed`.
- A failure's reason is its error's kind and number alone (an error's text can hold a path).
- A clock that fails gives `seconds` None ("in an unknown time"); `read` does not raise.
- A changed entry carries `was`, the hash it had.
- The command: `--rounds` default 1, `--every` default 5; `--rounds` below 1, `--every` below 0 or not finite
  exit 2. Change lines add "of the user"/"of the machine" for run, runonce and startup, and ", 32-bit view";
  a place unread in a later comparison is one `UNREAD round N:` line (silence is said).
- tools/rig/autostart_run.py reads every 1 s while the stand-in runs and once after, gives it 240 s, writes no
  hash, and keeps the stand-in's WORKLOAD lines. X37 matches the stand-in's three names case-insensitively,
  and needs a `removed` change in a later read than the first `added` one.
- The stand-in's service is `RaqibRigService`, made with `sc.exe create ... binPath= "cmd.exe /c echo" start=
  demand` in `behaviour` and deleted by `sc.exe delete` in `undo`, each said in a WORKLOAD line; it is never
  started.
