# M10.3 - questions for the Table (the forwarder over HTTP, ADR-0011 Amendment J)

## STOP: the gate is red on one guard test, and only a change to that guard can make it green

`tests/test_rhythm.py::test_redo_k11_the_network_guard_covers_every_module` (an AST guard, ADR-0007 REDO K-11)
lets `urllib`, `http.client`, `socket` and `ssl` be imported only by `raqib/suspect/backends.py`,
`raqib/hooks/proxy.py`, `raqib/ui.py` and `raqib/hooks/common.py`. The forwarder must send over HTTP(S) (J-1,
J-2, J-8): `raqib/forward.py` imports `http.client`, `ssl`, `socket` and `urllib.parse`, and the guard fails:

    AssertionError: ('raqib/forward.py', {'http.client', 'socket', 'ssl', 'urllib.parse'})

The gate (run in the foreground) is otherwise green: `1 failed, 3945 passed, 76 skipped`. The HANDOFF says "Do
not change a guard test to pass", and the only change that passes is the guard's own: an entry
`"raqib/forward.py": {"http.client", "socket", "ssl", "urllib.parse"}` in its `allowed` map (the module that
owns the forwarder's network, as `hooks/proxy.py` owns the proxy's). Importing them by another spelling to
escape the AST would defeat the guard, and the network code cannot live in an allowed module (`hooks/` is the
capture path, which J-1 keeps from knowing the forwarder). Q0: does the Table add `raqib/forward.py` to that
guard's `allowed` map (and say so in its docstring)? With that one entry the rest of this commit is meant to
land as it is; everything else of E1 to E9 is built and its tests pass.

## The choices made where Amendment J's words did not decide

Built as the nearest thing Amendment J's words allow; each point below is a choice made where the words did not
decide, or a limit met. None is answered here.

1. **The guide's section (E8).** The guide cannot gain a heading or a sentence outside a table row:
   tests/test_readme_top.py holds every guide heading to the old README's (`test_e3_every_old_heading_...`) and
   every guide sentence to the old README's or GUIDE_NEW (`test_e3_every_sentence_...`), and this task may only
   add rows to its lists. The forwarder's guide text is therefore three rows of the guide's Commands section
   (GUIDE_ROWS): the command, `--status`, and the hec shape with the one search for silence and the Windows
   token-file sentence. Does the Table want a section "Forward the events" in a later task (a change to the
   guard test's GUIDE_NEW)?
2. **README's "the rest" row** is held to 120 characters; with `forward` named it was 129. The commas between the
   names were dropped and the link's text is "all" (it still links docs/GUIDE.md#commands only).
3. **Two keys beyond J-9's list.** `from` {start, offset}: J-12 says "the state says from which offset", and no
   key of J-9 can (the cursor moves). `beat`: J-9's status judges "more than two beats" and "longer than a
   beat", and only the forwarder knows its `--beat`. `schema` is J-9's own ("schema raqib-forward/1"). Keep?
4. **The cursor's sha256 and EVENT.md.** EVENT.md: "a file ... whose bytes before the cursor changed, is not the
   file that was read". J-5 rules how: the sha256 of the last line sent. Built: the sha256 of the line that ends
   at the cursor (the last line passed - sent, refused alone or skipped), so the check is at the cursor itself.
   A change to bytes before that line is not seen (said in docs/THREAT_MODEL.md and FORWARD.md). Hashing the
   whole prefix would see it at the price of reading the file again at every pass.
5. **`--batch N` (1 to 100, default 100)**, an option J did not name: J-11 says "at most 100 lines", and the rig's
   X21 needs two batches out of a watch's file of a few dozen lines to kill a forwarder between them.
6. **The raqib shape and a token.** J-6 names a header for hec only. Built: with `--token-file`, the raqib shape
   sends `Authorization: Bearer <token>`; without it, no Authorization header. hec requires `--token-file`.
7. **A line over 512 KiB.** No request may carry it (J-11). Built as J-6 rules a line too long for a datagram:
   refused locally, counted, its id kept, passed - never cut.
8. **`--once`.** One try per batch, no wait and no second try. Exit 1 also where a line was refused alone (a
   refused line is not taken); skipped lines (not events) do not make it 1. A missing events file is exit 2.
9. **The URL.** User information is a usage error (a password in an argument would be a secret on the process
   list). A query is sent (HEC takes `?channel=`) but never stored in the state or printed.
10. **`plain`** is true for every http destination, loopback included (J-8: "and then the state and every status
    say plain"); the status says "plain: not encrypted".
11. **`--status` without NAME** says every state in ~/.raqib/forward and exits with the worst (3, then 1); no state
    at all is 3. "Nothing waits longer than a beat" is judged as: `behind` above 0 while `last_ok` is more than a
    beat older than `written` (J-9 has no key for when lines began to wait).
12. **One name, one forwarder (J-13).** The pid is held in `~/.raqib/forward/<name>.pid`, made with O_EXCL (two
    started at once cannot both take it); a pid whose life cannot be told is refused, a dead one's file is
    replaced. A name whose state names another file, destination or shape is a usage error (its cursor is not
    the new destination's).
13. **A missing events file** while running: `failing` with the word `file`, tried again as a failed send.
14. **raqib/cli.py's docstring** does not list `forward` (Scope: "the subcommand and its dispatch, nothing
    else"); argparse lists it in `raqib --help`, and the guide has its rows.
15. **The rig.** tools/rig/forward_run.py runs the forwarders with HOME set to a new directory, so their states are
    the rig's and not the runner's; the token is made up per run. On Windows X20's forwarder is ended by
    TerminateProcess (its state already says what X20 reads). check.py gives X19 to X22 only with `--forward`
    (the old rows and counts of tests/test_rig_check.py stand), and a `--forward` file that is missing makes all
    four MISSED.
