VERDICT
REDO (narrow). The AK-1 road itself is sound. But this build adds a road where an os tree's own host-record file
  failing to write ends its os source while the follow keeps running unjudged (R-1). And the AK-8 property holds in
  the tests only because four of the six cases use an os follow that reads nothing, and the two that read are judged
  in the same poll as the host lines.

MUST-FIX
R-1 (SILENCE; rare: a transient append failure on the -host file, e.g. an AV/indexer lock on Windows, or an adversary)
- Where: host.py:3384-3388 sets src.host_error and src.error on the os source. Next round, host.py:3020 failed_os is
  true, and host.py:3024-3025 calls _attach_host (3203-3216).
- What goes wrong: _attach_host never stops the old follow (only _attach_os does, 3229-3234). The orphaned follow:
  - keeps appending to the untagged os file, which no feed reads now;
  - is never stopped at the end (stop_sources only iterates self.sources, 3761);
  - its wevtutil helpers are neither ended nor said (_helper_holes, 3783).
- After that the tree is host for the rest of the watch, because a host source is kept.
- The words are false: "its os source ended with a hole: cannot append to ...-host.jsonl" (3431) and "the source is
  attached again next round" (3387), while it is still running and is replaced by host.
- Why it is new: before M7.14 an os source had no host file whose failure could end it.

SHOULD-FIX
S-1 (MORE SAID / WORDS; common whenever the follow reads)
- The tree's single FIRST-FINDING (host.py:3743-3755) can be spent by an os-line act judged in an earlier poll: tick
  polls between rounds (1848), and the follow's pass ends between rounds.
- Case: curl2's event 1 is read by a pass before round 3. The os act knocks FIRST-FINDING. Round 3's HostChild
  NET-TOOL finding is then "not notified: severity medium". Without Sysmon, that same finding is the FIRST-FINDING.
- So both the host-line finding's notice and the KNOCKS rows differ. Same case with a tree there at the start: curl
  born after the start and before round 1 gives a live os line and the knock, while its HostChild is history.
- No knock is lost: the tree knocks once either way.
- The tests do not see this:
  - test_host_follow_returns.py:318-331 settled_follows judges both files in one poll.
  - 401, 416, 441, 474 use Script(fail_from=1) and 424 uses raises=True, so the follow reads nothing.
  - host_said's rows filter (350-351) includes the os rows, so a reading follow in the at-start case would fail the
    property as the test computes it.

S-2 (WORDS; common where AF-1/AG-1 happens, as on the commander's machine) - E4 unmet in this case (the builder's Q12)

  round 2 in -host (host.py:3239). file_seq is per path (3325), so seq restarts at 1.
- Effect: FIRST-FINDING's "seq N" (notify.py:217-220) and NET-TOOL's summary "at seq {seq}" (terminal line, listing)
  differ from the watch without Sysmon.
- No HostChild is doubled or lost (carry_host), and history is equal.
- No property test covers AG-1. test_e1_aj1_not_touched_host_rhythm only checks act_twins.

S-3 (MORE SAID, history so no knock; needs an adversary)

  Feed whose epoch is 0 again (host.py:3240, 1042), and it re-reads the post-restart lines.

  report.
- told_twice (709-715) and the tests' host_said also read pre-restart epoch-0 entries through the post-restart lines
  (line numbers reused).
- Without Sysmon a host source is never re-attached, so none of this happens.
