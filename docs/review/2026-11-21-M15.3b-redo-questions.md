## Design questions for the Table

1. **A key made under a part read before, but unread when it is first seen.** AJ-1 makes a part the base does
   not hold its base when first read, none said. Read alone, that would pass over a service planted while its
   own key was refused or cut by the deadline at the read that first listed it (its parent, the services' key,
   was read before). The code keeps, for a part seen and not read, whether it was born under a part the base
   held: such a part is new, and its entries are `added` when it is first read (AI-1); a part seen unread from
   the watch's first read, or under a part never read, is a base taken late. Test:
   `test_aj1_a_key_made_under_a_part_read_before_and_unread_at_first_is_said_as_added`. Is that the ruling's
   meaning?
2. **How a late base is said.** Once per read and per place, in `take`'s `late` (`{place: {"parts",
   "entries"}}`), not as a change in `changes`; the command says it as one `BASE round N:` line. A hive's part
   counts nothing itself; its keys count under `run`/`runonce`. Should M15.3c write it as a host line of its
   own?
3. **A hive under a listing taken late.** A hive listed for the first time after the users' hives could not be
   listed is a base taken late (its keys under `run`/`runonce`), not a `hive loaded` (M15.3b said loaded).
   AJ-1 read over AI-6 there. Keep?
4. **A hive loaded while one of its keys is not read.** The hive loaded is said at once, with the count of the
   entries of its keys read now; a key of it not read (its RunOnce failed or was cut) is taken as a base late
   when it is first read (AJ-5). M15.3b compared the hives only where Run and RunOnce were both read; that gate
   is gone.
5. **The bound of 1000.** It is put on a key's values and a folder's files (what one part holds), not on the
   subkeys of the services' key or of a folder of the task tree: each of those is its own key, under the
   deadline, and a bound there would keep a machine with more than 1000 services from ever reading them whole.
   Right?
6. **A place the deadline cuts.** It keeps what it reached (`partly`; keys not reached are parts not read,
   files listed and not reached are entries with their content not read); a place not reached at all is
   `unread`. A Startup file listed and not reached, when it is first read, is said `read` (its content), not a
   change. Keep?
7. **The rotation.** The Watcher turns the first step at each `read()`, whether or not the read is then taken.
   A read made without a watcher begins with the first step. Run and RunOnce are one step (one hive listing).
8. **A link.** A symbolic link or another reparse point to a folder is listed as a link too (an entry, not
   opened), not left out as a folder is. A cloud file's placeholder is a reparse point: it is a link, its
   content not read, the place `partly` for as long as it is there. Right?
9. **A Startup file not found when opened** is an entry with its content not read (`not found when opened`),
   the place `partly`; a file gone between the listing and its open is therefore said `added`, content not read,
   at the read that listed it, then `removed`. Keep?
10. **`Watcher(salt=...)`.** The command, given a reader (a test's), takes the process's own salt so that it
    can take reads made without a watcher. The parameter would let two watchers share a salt; it is said in the
    docstring as the command's alone. Hide it further (a private factory)?
11. **X37 and the held file.** MET now needs the first read that listed the held file to be the held one
    (`held` true, content `not read`) and `held.removed` true. A run where the held read was cut by the
    deadline is MISSED, though the module did nothing wrong. Keep it strict?

## Choices the HANDOFF did not make

- `read(..., begin=0)`; the result carries `begin` (the step it began with) and `salt_id`. STEPS are `run`
  (Run and RunOnce), `startup`, `service`, `task`, `winlogon`.
- The deadline is looked at before each place, before each Run key and view, before each Startup folder and
  file, before each service, before each key of the task tree. A key not reached gets the reason `the read's
  deadline (N s) passed before it was reached`; a place not reached keeps `... passed before it was read`.
- A part not read whole for the bound is `read` false; its first 1000 entries are still given in the result
  (the Watcher compares nothing of it). WinRegistry asks at most 1001 values of a key; Disk lists at most 1001.
- `sure`: the extensions are compared without case; the comma list of Winlogon is split outside quotes; a
  list of one names its program (`userinit.exe,` names `userinit.exe`, sure).
- An entry has a new field, `list` (true for a Winlogon list of more than one); the change line says
  `(a list of programs)` in place of the program.
- The long form: `\\?\` + the folder made whole by `ntpath.normpath` + `\` + the listed name; a folder that
  already begins with `\\?\` is kept as it is. Off Windows (tests) the plain join is used unless a test asks
  for the long form.
- A link is told by `DirEntry.is_symlink()` or `FILE_ATTRIBUTE_REPARSE_POINT` in the listing's own data
  (`stat(follow_symlinks=False)`); a plain file by `is_file(follow_symlinks=False)`.
- An open's other error is said by its kind and number (`OSError (22)`), as a failed place's reason is.
- `_windows_drive_kind(kernel32=None)`: 4 remote; 2, 3, 5, 6 local; 0, 1 and a path with no drive letter not
  known (not read).
- A read of another salt: `take` returns `refused` (the words of AJ-6), no change, no unread, and the base and
  the pending parts are untouched; the command prints `REFUSED round N: ...`.
- share_opener closes the fd (and so the handle) where `os.fdopen` raises (the review's F13).
- The rig: `facts["partly"]` holds the reads that read a place in part, apart from `facts["unread"]`;
  `facts["late"]` and `facts["refused"]` are kept too. X37's words say `unread: ...; read in part: ...`, and
  read a place in part out of an older `unread` record by its words (`in part`). The held file is let go once.

## Tests of tests/ changed, each with why

tests/test_autostart.py:
- `test_every_place_is_read_with_its_entries`: the set of an entry's fields gains `list` (AJ-3's new field).
  Nothing else changed.
- `test_ai4_the_deadline_says_each_place_it_did_not_reach_as_not_read` is removed and replaced by
  `test_ai4_aj2_the_deadline_cuts_between_keys_and_no_place_is_starved` (with
  `test_aj2_a_place_cut_while_it_is_read_keeps_what_it_reached`). Why: AJ-2 changes what it held - a read
  begins with a turning step, so "run read, winlogon unread" no longer holds for a fixed order, and a place cut
  while it is read keeps the entries it reached, so "no entry of a cut place" holds only for a place not
  reached. Carried over: the places not reached are `unread` with the deadline's reason and have no entries;
  `first_line` says `; not read: `; `take` gives no change and names every place not read whole in `unread`.
  Not carried over: the deadline of 12 s and the clock of one second a call (the new test's clock moves only
  when the slow key is read).
- `test_ai8_a_name_that_may_not_be_what_runs_is_said_so`: a Winlogon list of two now names no program (was
  `userinit.exe`, not sure) and its line says `(a list of programs)` (was `(may run userinit.exe)`): AJ-3
  reverses it.
- `test_ai9_the_hashes_are_salted_by_the_watcher_and_never_left_unsalted`: `"salt" not in said.lower()` is
  replaced by `a._Watcher__salt.hex() not in said`. Why: a read now carries the field `salt_id` (AJ-6), whose
  name holds the word. The new assertion holds the salt's own value out of what leaves; it no longer forbids
  the word itself.
- `test_the_rig_run_holds_a_file_across_one_read_and_writes_what_each_read_said`: the first read's task place
  is held whole again (R7); its holder counts how often it is let go, and the test holds once (AJ-7).
- `test_the_spec_says_what_is_not_read_what_is_refused_and_what_was_measured`: phrases added for every item;
  in the THREAT_MODEL part, "Closed (ADR-0014 Amendment I): an entry that first appears while its place or its
  key is unread" became "**Closed** (ADR-0014 Amendments I and J). An entry that first appears while a place or
  a key", because the entry now closes both amendments' ways round. No phrase of the spec was removed.

tests/test_rig_check.py (X37 only):
- `test_x37_names_every_other_change_by_its_kind_and_place`: the MET words of the held file are now "the held
  file added in read 2 while held, its content not read, and removed after" (were "the held file added in read
