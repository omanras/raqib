## Questions

1. **Where the packed runtime does not say where its modules are.** K-5 rules the case where the runtime says its
   modules are outside the program's folder. Where `sys._MEIPASS` is absent (a packer other than PyInstaller),
   the check refuses ("the packed runtime does not say where its modules are"). Meanwhile: refused.
2. **The packed runtime's sys.path.** Only the program's folder, whole, is walked (with the modules' folder inside
   it). The entries of a packed program's `sys.path`, and whether its runtime reads PYTHONPATH or a `._pth` file,
   are not read. Meanwhile: not walked; nothing about them is said.
3. **Two names of one folder that differ only in case** (a folder that tells case apart). The set of names
   already walked is compared without case, as the prompt rules, so a second such name would never be read.
   Meanwhile: refused, with its own words.
4. **Names Windows would open as another thing.** A part ending in a dot or a space, and a device's name (CON,
   PRN, AUX, NUL, COM0-9, LPT0-9, CONIN$, CONOUT$, any extension; the superscript digits too), in the program's
   path, the modules' path or a listed name: refused unread. Not measured.
5. **"Longer than the system opens plainly."** Taken as a whole path of more than 259 characters (MAX_PATH less
   its end: `PLAIN_MAX`). The limit of one name (255) is not checked apart. Meanwhile: as said.
6. **How long a name or a text said may be.** The runner cuts a value of a state at 80 characters (`_printable`)
   and 40 marked (`_read_said`); an entry of the measured texts with an app's capability SID is about 115
   characters, and a path can be 259. Meanwhile: made printable as the runner makes it (a character that is not is
   `?`) and cut at 200 characters (`SAID_MAX`), the cut marked `...` (AJ-3).
7. **Flags and words outside the measured texts.** An entry's flags are taken only from OI, CI, NP, IO, ID (an
   audit flag, SA or FA, or another, is refused); rights in hex of at most eight digits; the list's flags only P,
   AI, AR. Meanwhile: anything else refused as not read.
8. **The order below the root.** The folders above are read first, from the drive down; then the root, and below
   it breadth first, names in the order the listing gives them (not sorted). Which of two refusals below the root
   is said first follows that order.
9. **A short (8.3) name of the modules' folder.** `ntpath.normcase` does not expand a short name, so a
   `sys._MEIPASS` given in that form would be refused as outside the program's folder. Not measured.
10. **X49 and the job's own folder.** X49 asks the refusal of the copy in the job's own folder to name a path of a
    drive and a role. On x64 that copy is expected to be refused at `D:\` (owned by NS, as a folder above); on
    ARM64 there is no `D:\` and where the job's folder is was not measured here. A refusal with no role (the path's
    form, the modules' place, the walk's bound) is MISSED by X49. For the Table's wiring.
11. **Words left as they are.** The threat model's earlier sentence "nothing yet checks that the code the service
    runs is the system's and the administrators' alone" (the runner's item) and SERVICE.md's runner section ("a
    refusal where the code it would run is not the system's alone ... are M12.4c's") were not changed: the scope
    gives one paragraph of the threat model and a section of the spec. The new paragraph says the check exists and
    that nothing asks it before a service runs. cli.py's module text (`service install [--no-start] | remove
    [--purge] | status`, held by test_service.py) was not changed either: only the action's help says `check`.
12. **E5 on a real machine.** The test that reads `C:\Windows\System32\kernel32.dll` and its folders by the real
    reader is skipped on Linux, where this builder ran; it was not run by the builder on Windows.
