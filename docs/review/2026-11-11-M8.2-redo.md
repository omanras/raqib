## Findings
**R1 (must-fix; E-3, Q-4): a lower-case program name with a suffix is now refused.**
- `check_program` keeps the typed name only when it contains a capital (ruleform.py:209-211). The examples keep the program as typed (290, 387-389), and that typed name goes into the Bash fixture line (457-460).
- Values "curl.exe" (likewise terraform.exe, x.bat, -bash) give names ["curl"] and the prefilled example "curl.exe". positive-bash.json's command_head "curl.exe" is not in ["curl"], so `validate_rule` returns positive-missed and the form refuses beside "Must fire on". The first build passed this, because its example was "curl".
- Q-4's ruling ("as typed and as lower-cased") is not held. test_ruleform_redo.py:138 asserts the old names and never runs a Test of them.

**R2 (must-fix; E-6): Remove on a refused-at-load row can delete another rule.**
- A row's id is a folder name or a loose file's stem (overlay.py:569-571). `_folder_of` returns the first folder whose name in upper case matches (1242-1246).
- Case (a), any OS: a loose rules.d/MY-TF.yaml next to the loaded rules.d/MY-TF/.
  - The refused row "MY-TF" gets a Remove. It deletes the loaded rule's folder and its overlay entry; the loose file stays.
  - The two rows share their rule_widgets and rule_vars keys, and both show the confirmation (app.py:4048-4106).
  - `taken_ids` holds "MY-TF.yaml", not "MY-TF" (overlay.py:1192), so the form itself can create this state.
- Case (b), Linux: rules.d/MY-TF (loaded) and rules.d/my-tf (refused).
  - "Add rule file..." can create this, because add_rule ignores folder names (overlay.py:1156).
  - `sorted()` puts "MY-TF" first, so Remove on the my-tf row deletes the loaded rule.

**R3 (must-fix; E-6): a failed Remove says something false and can switch an off rule back on.**
- `_delete_tree` can fail before deleting anything: a link inside the folder or a realpath mismatch (overlay.py:1205-1206, 1214-1215), or a first `os.remove` that fails (on Windows, a file held open).
- By then the overlay entry is already dropped (1280-1282), and the message ends "(it is refused at load and listed with Remove)" (1289-1291).
- That is false: the folder is intact and loads. With its entry gone, a rule the person had switched off judges again at the next watch. The window shows "REFUSED: MY-X removed: ...".
- test_ruleform_redo.py:170 sets the rule off, fails before any deletion, and asserts this wording.

**R4 (should-fix; E-2, A3): a person's rule's "could not judge" note is now hidden on old os lines.**
- host.py:2791-2793 drops the partial notes of every rule in host_rules on an os source with lines written before M7.8.
- host_rules now includes a person's program rule. That rule reads input_meta.image on os lines (ruleform.py:413-414) and cannot judge such a line.
- The note shown instead, PRE_M78_NOTE (host.py:296-298), names only NET-TOOL and DESTRUCT-CMD. So the person's rule's "could not judge N lines" is said nowhere; before this delta it was.
- A `--add` rule that names HostChild loses a partial note of any cause there.

**R5 (should-fix; E-2): "On your records" treats os-source files as host-line files.**
- `record_files` marks every file under host/sources as host lines (ruleform.py:736). But the os source writes its per-tree file there too, and the watch judges that file with every rule (host.py:826, 2579-2588).
- For a path, host or tool rule, such a file is skipped and reported as "host source file not judged: a watch gives host lines only to a rule that reads HostChild lines" (ruleform.py:783-786, 824-826). That is false, and the line count M leaves out lines a watch would judge.
- Firings are unaffected for those three forms.

**R6 (should-fix; E-9, A3): links are refused silently, and the sweep fails silently.**
- `record_files` skips, without counting, a linked ~/.raqib or traces (737), a linked subfolder (744) or file (747), and any lstat error (723-724).
- When nothing else was read, the text says "no trace or host source file under ~/.raqib this rule would read yet" (831-833). fixture_file says why it refuses; this does not.
- ~/.raqib is checked as the parent of traces, but not above host/sources.
- The sweep discards `_unstage`'s reason when it cannot remove a folder (587-589). It has no age bound, so it deletes a concurrent Test's form-* folder (another window, or `raqib rules --new`).

**R7 (should-fix; E-6): Remove refuses what Add and staging accept, and some Remove buttons can never succeed.**
- Remove refuses a linked ~/.raqib or rules.d (overlay.py:1262-1265).
- Add does not: `add_rule`'s fixture_file checks only below rules.d (1159, 527-540). Staging checks only rules.staging (ruleform.py:585).
- So with ~/.raqib on another disk through a link, the form adds a rule that neither the window nor the terminal can remove.
- A refused row that is a loose .yaml file with no folder, or a folder that is not an id even upper-cased ("backup", "my_old"), gets a Remove that always refuses (overlay.py:1257-1258, 1268-1269).

**R8 (should-fix; E-8): the report does not say how a person's rule was measured.**
- The start lines and the report's user-rule lines are unchanged: "user rule X (origin: user) from S" (overlay.py:939, 1013).
- MEASURED appears only in the YAML description, Test's words and the form's header.

**R9 (should-fix; E-10, E-11): tests and words P15/P16 named are not all done.**
- P15's "running watch": test_ruleform.py:335-341 still passes `running=True` with no watch, and no Tk test has `c.watching()` true.
- No test asserts "testing...".
- cli.py:25 still says "its two fixtures", and cli.py:11's usage line has no --dry-run for --remove.
- No junction or reparse-point test exists. The symlink tests skip on windows-latest, so the Windows link refusals are not exercised.

**R10 (should-fix; words): statements the delta made false.**
- The path form's evasion "~/.aws matches only paths written with ~, never /home/me/.aws" (ruleform.py:113-114) is written into every ~ rule, which now also holds the home.
- The module docstring still says program names are "lower-cased as discover.image_name does" (21-23).
- The help says host lines are "judged by NET-TOOL and DESTRUCT-CMD" (cli.py:127-128).
- A ~ place whose home cannot be carried, whose home is longer than 260 characters, or that is written `~user/...` is held as typed only, and nothing is said (ruleform.py:243, 270). That is P4's failure back, now silent.

**R11 (note; E-1): on_records can fail a passed Test, one claim is wrong, and one test asserts nothing.**
- `on_records` runs inside step after `res.ok` is set (ruleform.py:697-704). An exception there turns a passed Test into "the form could not write this rule", so an information-only step becomes a gate with wrong words.
- The refused header says "nothing was written in rules.d" (app.py:3953). That is also shown after add_rule wrote fixtures and then failed (overlay.py:1177-1181).
- test_ruleform_redo.py:86's staging assertion is vacuous: both failures it provokes happen before staging. No test makes a failure after `_new_stage`.

**R12 (note; E-2c; question): a person's hand-written rule now shares the host-line poll with NET-TOOL.**
- A `--add` rule naming HostChild now runs in the same host-line poll as NET-TOOL.
- `engine.evaluate` has no per-rule guard or time bound (engine.py:797-823), and a hand-written rule may carry any regex (593-598). A pathological regex on a host line's string field would stall the poll, and NET-TOOL's judgement of that feed with it.
- This is not new for trace and os feeds. I found no predicate that raises. The form offers no regex (ruleform.py:409-436).

**R13 (note; tests): two tests are weaker than they look.**
- test_ruleform_redo.py:103-111 compares against the old id list recomputed in the same process. With the selection already asserted equal at :94, it cannot fail, and no finding is pinned.
- test_e3 was loosened to `fired >= 2` (test_ruleform.py:260).
- `_write_records` is defined twice (220 and 238); the first is dead.

**R14 (note; E-10 guard): the allow-list has gaps.**
- Imports are compared by module name (test_ruleform.py:403), so `import os as o; o.system(...)` passes.
- Calls through a bound name (`f = shutil.rmtree`) are unchecked.
- ("os", "utime") is allowed but unused (391).
- Calls into overlay and host are unchecked, except add()'s.

**R15 (note; E-7): USER is enforced only by the form.**
- `ruleform.CLASS_OF` is the only enforcement. `validate_rule(user=True)` refuses only HOST (overlay.py:603), so `--add FILE` of class SCOPE, NET or USER is accepted, and nothing stops a package YAML from declaring USER.
- Other readers of the class word:
  - `check_finding` (engine.py:1033).
  - The row, report table, page and start lines print the word.
  - The suspect layer sends it as a free string (suspect/core.py:133). SCHEMA does not enumerate classes, so USER cannot break a suspect call.
  - The gate counts kinds, and `kinds_off` counts package kinds.

**R16 (note; E-4): the person's home path reaches the report and the page.**
- The default title ("... ~/.aws, /home/<user>/.aws", ruleform.py:366-367) reaches `report.rule_table` (report.py:61-62), the Rules row and the page. The description's example also carries it.
- It does not reach the suspect layer, and no fixture in the tree holds it (the tests compute it from a temporary HOME).

**R17 (note; fit): the screenshots are not of this commit, and the form's header can go stale.**

- After a passed Test, editing a field disables Add while the header still reads "The test passed: the rule can be added" (3895-3908). This predates the REDO.
