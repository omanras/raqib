  `index.default_pipeline` were not run against Elasticsearch or OpenSearch. The rig's job `siem` is their first
  run. What differs from the Table's measured draft and is therefore unmeasured:
  - Painless the draft did not use: `instanceof` checks, `for (def k : [...])` over a list literal, `throw new
    IllegalArgumentException(...)`, `Map.remove`, `isEmpty`, `ctx.remove('message')`.

    arrival on an error document.
  - `index.default_pipeline` in the template (the runner sends the lines without `?pipeline=`, so X39 and X40
    hold it).
  - `_search/template` with an object `source` (rule.json, silence.json) in both engines; static `params` in a
    `bucket_selector` script, read with `Long.parseLong(params.now)`.
  - `exists` and `term` on `raqib.result.exit` inside `flattened` / `flat_object`, and the query string
    `raqib.result.word:INCOMPLETE` over them.
- **sigma-cli was run here, not against an engine.** In a throwaway virtual environment in the session's scratch
  folder (sigma-cli 3.1.0 from the package registry; not in the tree, not a dependency of Raqib), every rule of

  - `(event.action:(finding OR source\-finding)) AND event.kind:alert` (alarm)
  - `(event.action:(finding OR source\-finding)) AND rule.category:DESTRUCT` (and NET, PERSIST, SECRET alike)
  - `event.action:hole`
  - `(event.action:(finding OR source\-finding)) AND rule.id:NEW\-AGENT\-UNKNOWN`
  - `event.action:watch AND raqib.state:end AND raqib.result.word:INCOMPLETE`
  The rig installs the newest sigma-cli for Python 3.12 (4.x when this was written); its pySigma may treat
  `set_value` and `map_string` differently.
- **The rig's job has not run.** Its YAML follows the probe's job `siem` (the same images, flags and loopback

## Design questions

- **Q1. Named keys leave the namespace.** The pipeline moves each named key out of `raqib` (no `raqib.time`,
  `raqib.id`, `raqib.alarm` ...); the probe's draft kept the whole event under `raqib` as well. E1 says "every
  other key under raqib" and EVENT.md "a key maps to a named field or to the namespace". Is that the ruling? A
  SOC that wanted `raqib.alarm` as a boolean has `event.kind` instead.
- **Q2. The search for silence needs a time.** Neither engine gives a `bucket_selector` script the time of the
  search. silence.json is a search template whose parameter `now` (epoch milliseconds) is the time of the check
  (an alerting tool's scheduled time). Other ways: a deadline stored at ingest (a field outside the Mapping),
  runtime fields (Elasticsearch) and derived fields (OpenSearch), which differ, or each engine's own alerting
  monitor (not one content for both). Which?
- **Q3. Which beat.** The search judges a host by the longest `watch.beat` its heartbeats said (`max`), since
  "the latest heartbeat's beat" needs `top_metrics`, which OpenSearch does not have. A host whose beat was made
  shorter is judged by the longer one. Acceptable?
- **Q4. A watch that ended in order.** A host whose watch ended (its watch end written, no heartbeat after) is
  listed as silent two beats later, as FORWARD.md says of a stopped watch. Should the search leave out a host
  whose latest event is a watch end? Not done.
- **Q5. Hole or blind spot.** hole.json and raqib_hole.yml select every `kind` hole, holes and blind spots alike
  (as the probe did); `raqib.hole.class` says which. Should "a hole of the capture" be `hole.class` hole only?
- **Q6. alarm in Sigma.** `alarm: true` becomes `event.kind: alert` by pySigma's `set_value`, which sets every
  value of `alarm` to `alert`: a rule written with `alarm: false` would be converted wrong. The test holds that
  the rules name `alarm` only as true. Should the pipeline of names refuse `alarm: false` instead?
- **Q7. One Sigma rule a class.** The rules of a class are one Sigma rule; its level is the highest severity of
  the class's rules and its tags the union of their techniques (NET: T1021, T1105, T1048, level high, though
  NET-TOOL is medium). Or one Sigma rule per catalog rule?
- **Q8. One job, two engines.** E6 says "a job starts Elasticsearch 8.15.3 and OpenSearch 2.17.1". The job is a
  matrix of two runs, one engine each on 127.0.0.1:9200, as the probe measured, not both in one run.
- **Q9. What is an error document.** Beyond the probe, a line of `raqib-event/1` whose named keys are not of
  their kind (an `id` that is not a string, a `subject.pid` that is not an integer, a part that is not an
  object) is kept as an error document with its reason rather than refused by the template. Is the list of
  checks the right one?
- **Q10. The layer's versions.** raqib-layer.json names only the layer format (4.5), not an ATT&CK or Navigator
  version.

## Choices the HANDOFF did not make

- Layout: siem/elastic/ and siem/opensearch/ each hold `pipeline.json` (the same bytes), `template.json` and
  `searches/*.json` (the same bytes in both; a test holds both sameness); siem/sigma/rules/*.yml,
  siem/sigma/pipeline-ecs.yml; siem/attack/rules.md and siem/attack/raqib-layer.json.
- Names: the pipeline `raqib-event-1`, the template `raqib-events`, the indices `raqib-events*`.
- A search file is `{"finds", "request", "body"}`; rule.json (parameter `rule_id`) and silence.json (`now`) are
  search templates.
- The template: `date_detection` false; `long` for `raqib.n`, `raqib.rev`, `process.pid`, `event.severity`;
  `double` for `raqib.watch.beat` and `raqib.rule.fp_budget`; `message` and `error.message` text;
  `event.original` neither indexed nor in doc values (as the probe).
- Not set (the probe set them; S-1 says the Mapping and nothing else): `event.module`, `event.dataset`,
  `rule.name`, `observer.vendor`, `observer.type`.
- A `severity` that is not one of the five words stays `raqib.severity`, with no `event.severity`.
- Sigma: technique tags only, no tactic tags; no `date` key (the repo's YAML reader reads a date as an error);
  `logsource` product raqib alone; status experimental; fixed version-4 UUIDs; the selections name `kind`,
  `alarm`, `rule.class`, `rule.id`, `state`, `result.word`.
- The pipeline of names maps every key of EVENT.md's Keys table to the first field of its ECS column (a test
  reads the table); `severity` by `map_string` to the number.
- siem_run.py: the words MET, MISSED and n/a; exit 0 whatever the claims (2 for a wrong usage); every claim
  MISSED where the engine refuses the content; X39 also sends two lines that are not events to a second index
  and wants each kept with its reason; X41 counts the heartbeats too and asks the search for silence at three
  times (the runner's clock, just past the earliest host's two beats, just past the latest's), comparing the
  hosts; X42 counts in Python by the rules' own selection (the subset they are written in: one selection,
  `condition: selection`, `startswith`).
- The rig's job runs no curl to a public host (the probe did): nothing is sent off the machine.
- The guide's section is a `###` at the end of its "More", not a `##` heading (in "Watch the host" it broke three tests that count that section's lines: test_field_run, test_host_sources, test_rhythm): a new `##` heading would need
  README.md's More to link it (tests/test_readme_top.py, test_e1_more_links_every_heading_of_the_guide), and
  README.md is not in Scope.
