## FINDINGS

**N1. Medium, false statement.** `raqib/host.py:381-382`, `docs/GUIDE.md:418`, `docs/THREAT_MODEL.md:713-714`.
- When it is said: in the round where the third kept read is applied (`channel_rounds >= CHANNEL_KIND_ROUNDS`,
  host.py:3616-3620), if 11 is not among the reads' cumulative `kinds_read`. It is said once per watch
  (`_note_once("channel-kind-11")`). Failed reads do not count toward the three.
- The kinds are read from the whole channel, so a config that logs file creation narrowly, on a quiet machine, can
  give no event 11 in three rounds (30 s by default). The sentence is then said while a tree's file in the Startup
  folder would still be logged and judged.
- It is never withdrawn. If an event 11 comes after round 3, the final CHANNEL line (host.py:4824-4830) prints "kinds
  read: ... event 11" next to "no event 11 read so far: no file a tree makes is seen".
- The three older sentences all say "may be unseen". This one says "is seen" and "have nothing to read" and only
  hedges inside the parenthesis.

**N2. Medium, false statement.** `raqib/host.py:385-387`.
- The sentence gives two readings: the configuration logs no registry value, or none was set under a key it logs. In
  the second reading PERSIST-RUN-KEY does have something to read once a tree sets a Run value.
- ADR-0014:153 records that under the public configuration the stand-in's five values were the only events 13 in 91
  seconds. On such a fresh machine the question, asked before the values were set, would likely find none (inferred;
  the question itself was not measured). The blind spot would say "nothing to read here", and the rule would then fire
  five times.

**N3. Medium, false statement.** `PERSIST-AUTOSTART.yaml:11` and `PERSIST-RUN-KEY.yaml:11` still say "not said yet",
  which this task made false. `tests/test_registry_lines.py:535` holds the second. Neither file is in Scope, and the
  questions file does not name either; it should have.

**N4. Low, silence.** What the engine does with `{field: input_meta.initiated, eq: true}` (`NET-ADMIN-PORT.yaml:31`):
- **Key missing:** UNKNOWN (engine.py:594-598, 704-708). The line is unknown only where nothing else in `all` is
  false. Then the partial note says it (engine.py:870-874). A public, non-listed-port or ssh-by-git line is judged
  false and needs no note.
- **null:** `_same(None, True)` is False (engine.py:714-716). The line is judged "not initiated", silently.
- **true:** matches. **false:** no match.
- **A string** (even "true"), **or 1:** False, silently, because the match on bool is strict. os-sysmon never writes
  one; `initiated()` gives only a bool or nothing.
- `exists: true` would not help. `exists` returns a plain bool and counts null as absent (engine.py:633-636), so the
  whole `all` is still False: judged, and still silent. No single condition in the engine turns null into unknown.
- The smallest honest fix is words (must-fix 4). Treating null as unknown is a design question for the Table, since E5
  forbids engine edits.
- Reach is near zero: only lines from the M15.1/M15.2 builds whose Sysmon wrote no Initiated. But the old evasion line
  was the only sentence that said this, and it was deleted.

**N5. Medium, changed result in an error path, unsaid and untested.**
- A question that times out ends its helper and records it on the channel's own `Helpers` (os_sysmon.py:1031).
- The next round's read carries that record (os_sysmon.py:1403) and the watch makes it a `channel-helper` hole named
  "round N+1" (host.py:3604-3605). Any such hole makes the result incomplete, exit 3 (host.py:4680-4682). The hole
  also reads as round N+1's own read, which it was not.
- If there is no next round, `ChannelOwner.close` sets `said` past the record (os_sysmon.py:1264) and no hole is made;
  only the blind spot's reason carries the text. So the result differs by run length.
- `test_e3_an_error...` uses a stand-in error that never touches the helpers, so this path is not tested through the
  watch.

**N6. Medium, possible changed result, unmeasured.**
- The question runs inside the round 1 reader, after `discover.run` and the commit (host.py:519-525). It can take up
  to ROUND_TIMEOUT 10 s plus HELPER_GRACE 2 s plus 2 s (os_sysmon.py:958-959, 1234), about 14 s.
- The reader's deadline is 2 x T, which is 20 s by default (host.py:286-287, 1646). A late reader is a `reader-late`
  hole and a knock (host.py:2218-2225), so the result becomes incomplete. A smaller `--every` makes this likelier.
- An answer of "none" probably requires reading the whole channel, newest first, which is exactly the case that
  matters. This is believed, not measured.

**N7. Low, silence, a design question.** `own["asked"] = True` is set before the call (host.py:522). A failed first
  question is never asked again, and the whole run says "not known". Neither Q-6 nor the documents say so.

**N8. Low, design.** `registry_held` returns None, so nothing is said and the inventory carries nothing

## TO MEASURE ON A REAL WINDOWS MACHINE

1. **How long the question takes.** Time `wevtutil qe Microsoft-Windows-Sysmon/Operational /q:*[System[(EventID=13)]]
  /rd:true /c:1 /f:xml` on three channels: (a) one that holds event 13; (b) a full channel of default size whose
  configuration logs no registry event; (c) a large channel (raised max size).
   - Under about 2 s: N6 is moot.
   - Over about 5 s: round 1 can be late (a reader-late hole and exit 3).
   - Over 10 s: "none" becomes "not known" exactly where it matters, and round 2 gets a channel-helper hole (N5).
2. **What wevtutil does with an empty result.** Run the same question on a config that logs no event 13 and note the
  exit code and output.
   - Exit 0 with empty output: `held: false` is right.
   - A non-zero exit: it is said as "not known".
3. **A fresh runner under the public configuration.** Run the watch's round 1 before the stand-in sets its five Run
  values.
      - If round 1 says `held: false` and PERSIST-RUN-KEY then fires five times, the second reading of must-fix 2 is
     confirmed in the field.
4. **Quiet-machine file events.** Under the public configuration and under the rig's, count the event 11s in the first
  three rounds before any act.
   - If there are none and PERSIST-AUTOSTART later fires on the stand-in's Startup file, must-fix 1 is confirmed.
5. **Initiated in real events.** Over a run's net lines, count those with no `initiated` key. Expect 0, which bounds
  AE-1's reach.
6. **Decoding.** Check that the question's output decodes as the round's does (a `<Event` is found). Otherwise N9
  applies.
