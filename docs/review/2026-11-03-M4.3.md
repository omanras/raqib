### Builder readings (within the rulings; recorded, not settled here)
- **No start line.** A session with no session_start line but git keys on
  another line is unknown ("no session_start line"). One with no git keys
  anywhere is not judged (J-3). A session_start without keys decides: the
  session is not judged even if its close has keys.
- **"no repo" on one side only** is unknown: the null on the other side is
  for another reason (J-3).
- **Edits around start and close.** Edits before the first session_start
  are not triggers. Edits after the last close are unknown ("no close
  came"). A session with no close is unknown.
- **Unknown triggers.**
  - An edit pre whose post never came, under the start cwd, is an unknown
    trigger. It is not reported when the value moved, or when a true
    trigger fires the session (H-3's reading).
  - An edit whose path is missing or cannot be placed is not a trigger
    (J-4 "others"; hole named).
- **Malformed values.** A git value not in the hook's shape (not 40-hex or
  64-hex) is treated as null: it is never compared.
- **SHA-256 repositories.** A 64-hex head is "unreadable" (J-2's 40-hex
  shape); the hole is named.
- **Reading the index.** It is read once, in 1 MiB chunks, up to
  64 MiB + 1 bytes, with the budget checked after each chunk. An lstat size
  over 64 MiB is "index too large" before any read.
- **What "relative" means for a gitdir (J-6).** All of these are checked
  lexically, before any call on the path:
  - no leading `/` or `\` (this covers UNC and device prefixes);
  - no `:` anywhere (drives and NTFS streams);
  - no NUL;
  - no Windows device-name component.

  `..` is resolved lexically. Every component below the common ancestor of
  cwd and the gitdir is lstat'ed. A Windows junction (a name-surrogate
  reparse tag) counts as a link.
- **Per-rule constants.** STATUS and FP_BUDGET are per-rule dicts, because
  there are two rules. FIXTURES also lists `unknown` and `not_judged` files,
  which the tests assert. check() measures a negative only when J-3 left
  the session judged and the rule wrote no partial note. Positives are
  measured whatever the status, as fixtures.check_rule does.
- **README.** The sentence reads "5 silence rules, 1 cross-source rule ...
  and 11 more: 9 YAML rules ... and 2 tree anchors", so J-11's 5 + 1 + 11
  holds with code rules.
- **eval.** rule_findings now runs the tree anchors (J-1 names eval). eval
  never ran cross.py. No eval event carries git keys, so the baseline does
  not change.
- **Task names.** The THREAT_MODEL cites "ADR-0002 Amendment J", not the
  task name: tests/test_docs.py:67 holds every task cited there to a
