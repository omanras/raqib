### B-1: the stop path traced
The path is the same for (i)-(iv) once the stop is asked. The handler is set and the nap raises AskedStop (cli.py:371-389). For Ctrl-C, KeyboardInterrupt is raised anywhere in the main thread. Then, in order:
1. The except clause calls `hold`, so "stopped" is queued.
2. conclude runs:
   - Project watch: finish writes watch.json, then unregister marks the row (watch.py:1484-1498).
   - Host watch: finish runs stop_sources, which closes the channel (host.py:3459-3480), then writes the state; then unregister (host.py:4120-4129).
3. release writes the held words, then close(running) runs.
4. The final report is written.
5. cmd_watch's finally: `out.flush()` (guarded), `_quiet_if_dead` for stdout and stderr, then restore. main returns the code; `sys.exit(main())` (raqib/__main__.py:8).

How each case ends:
- **(i) A terminal that takes the words:** the same words in the same order as a079336. The code is the report's (0 / 1 / 3).
- **(ii) A hung-up tty:** every write and flush gets EIO, and `_Said` swallows it. The line-buffered BufferedWriter keeps its bytes. `_quiet_if_dead` sees the flush fail, dup2s os.devnull onto fd 1, and the flush then succeeds. Python's last flush succeeds, so there is no 120 and no traceback.
- **(iii) A closed pipe:** Python ignores SIGPIPE, so writes raise BrokenPipeError and are swallowed. Block-buffered: the same dup2 path as (ii). Unbuffered (PYTHONUNBUFFERED=1): FileIO keeps nothing, the flush succeeds, there is no dup2, and the exit is clean.
- **(iv) A stream closed mid-watch:** ValueError is swallowed. `_quiet_if_dead` gets ValueError from fileno and replaces sys.stdout with os.devnull. Python's last flush skips a closed stream.

Other checks on this path:
- `_quiet_if_dead` is reached on every path through the finally: a normal return, an Exception from host.conclude (host.py:4122 is unguarded and predates the delta), and KeyboardInterrupt.
- It never closes a stream. It never touches the caller's `out`. It touches sys.stdout or sys.stderr only when their flush fails.
- The window never reaches it, because app.py:1581 and 2188 call loop and conclude directly with no on_stop.

## Findings

**F1 must-fix (a test that cannot pass on Windows CI): `test_b1_must_not_touch_a_terminal_that_takes_the_words_gets_them_as_before_in_their_order[PROJ]` fails on windows-latest with Python 3.11 and 3.12.**
- The test runs the same watch twice, under `tmp_path/"now"` and `tmp_path/"before"`, and asserts the two texts are equal (test_first_run.py:847-858).
- It normalises only `str(base)`, which on Windows has backslashes (:836-838).
- `raqib watch PROJ` prints the install's hook command (install.py:449, through watch.py:1374 `out=out`).
- On Windows that command is `windows_command`, whose `windows_word` turns `\` into `/` (install.py:168-169, 182-186, 192-195; `WINDOWS = os.name == "nt"` at install.py:59).
- The trace in that command is under HOME/USERPROFILE: base/"home" (test :749-750, watch.py:1110-1113).
- Case: the "now" text holds `C:/.../now/home/.raqib/traces/proj-<hex>/...` and the "before" text holds `C:/.../before/home/...`.
  - Neither matches the backslash `str(base)`.
  - `proj-[0-9a-f]+` and `\d+` normalise the hash and the digits but not "now" against "before".
  - So `texts[0] == texts[1]` fails at :858.
- Linux passes because posix_command keeps the path as it is.
- Why it matters:
  - The gate runs all of tests/ on Windows (tools/gate.py:285, gate.yml:51-53), so the windows jobs go red.
  - This is B-1's MUST NOT TOUCH test.
  - E7 requires the tests to pass on the windows jobs.
- The [--host] case prints no hook command and likely passes.
