## Design points (for the Table; none answered locally beyond the choice recorded)
- Q-1 run.json. The HANDOFF says "run.json gains a note"; tests/fixtures/discover/linux has
  no run.json. Adding one changes discover.read_dir's path (sources and labels come from it;
  without it ss.txt is ignored with a hole), so the inventory and the five fixtures would
  change beyond the path, against E2. The note went where this export already says what it
  is: proc.txt's snapshot "note" (its JSON meta line, the field the capture wrote) and
  footprints.txt's header line, line counts unchanged. A run.json for this export is a
  Table decision.
- Q-2 "differ only in the path" and the cut. A cited line longer than LINE_TEXT_MAX is
  bounded (start ... end); the path is 2 characters shorter, so the cut shows 2 characters
  more ("15:..." -> "15:38..."). The E2 test accepts exactly that: such a string must equal
  bounded(the redacted export line) where the old was bounded(the old line).
- Q-3 Allowances beyond alice and bob. The tree holds more illustrative homes than the
  HANDOFF names; each is allowed only under the paths listed in ILLUSTRATIVE
  (test_thresholds.py), and the test fails if an allowance stops being used:
  carol, dan (SCOPE-CWD-ROOT fixtures and their generator), dev (tests/fixtures/eval,
  tests/fixtures/tree), a and x (catalog comments of SCOPE-CWD-MOVED/ROOT), Public
  (C:\Users\Public, a Windows built-in; catalog comment and the windows footprints export) and
  **ubuntu** - `/home/ubuntu` in the REAL linux export's footprints: the stock account of the
  sandbox image, not the sandbox's user. E1 names only the sandbox home, so it was left as
  captured (A8). Should it be redacted too, or the allowance kept?
- Q-4 Code is not scanned. raqib/discover.py (a docstring: "/home/claude/x.py does not run
  as claude") and raqib/rules/engine.py (docstrings: C:\Users\Bob, x) carry example homes;
  they are code, outside Scope, and not package data. Whether the pattern test should also
  cover raqib/*.py docstrings is for the Table.
- Q-5 Future captures. capture.py's main() does not yet redact homes on capture (only the
  one-off --redact-home). Folding redact_home() into capture (all /home/<name> but the image's
  stock accounts?) is a design choice left to the Table.
