## Findings
**T1 (must-fix; G-3 FOR; a false statement): "read: every file" is said beside a file that was read only in part.**
- Cause:
  - `on_records` counts `big` before the not-host check (ruleform.py:961).
  - The not-host branch then `continue`s (964-966) before `out["cut"]` is set (970).
  - `whole` (1041) reads `cut`, `more_files`, `walk_cut` and `not_read`, but not `big`.
- Case:
  - Inputs: ~/.raqib/traces/a/raqib.log.jsonl holds one Bash `ls` line; ~/.raqib/host/sources/x.jsonl holds more than 4 MB of HostChild lines; the rule is a path, host or tool rule.
  - What happens: "on your records: would have fired on 0 of 1 line in 1 file; read: every file (the newest 20 files, at most 20,000 lines in all and 4 MB of each); 1 file of host lines not judged: ...; 1 file read only in its last 4 MB; information only, never a gate".
  - Why it is wrong: G-3 says "every file" only when nothing was bounded, and the line itself names a bounded file.
- This is plausible: host source files grow over a long host watch.
- Test gap: `g3_for_each_bound_met_is_said` (redo3:231-240) uses only judged trace files.

**T2 (should-fix; G-2 MUST NOT TOUCH, A8): the package refusal's words changed, and the record says they did not.**
- `place_of` raises `REMOVE_PACKAGE` (overlay.py:1376) inside `remove_rule`'s inner try. The handler (1427-1430) appends ": nothing removed" to any check refusal that lacks those words.
- `raqib rules --remove NET-TOOL` now prints "...switch it off instead (raqib rules --set NET-TOOL off): nothing removed".
- The refusal, exit 2 and nothing deleted are all as before, so this is not a must-fix.
- But the test checks only containment (redo3:175), and the questions file says "the exact words as before; REMOVE_PACKAGE as before".

**T3 (note; G-6 words): a non-OSError while deleting drops what is gone from both lists.**
- `_delete_tree` turns only OSError into `_Stopped` with `gone` (overlay.py:1328-1329). For any other exception, `gone` is only the rule file (1469), and `left` keeps only what still exists (1470).
- Case: the test's own case (redo3:380-391). Six fixture files are deleted, then `rmdir` raises ValueError. The words read "gone: <MY-X.yaml>; what remains: <folders>", and the six files are in neither list.
- The test checks only "gone: " and "what remains: ".
- In practice only a programming error reaches this, since `os.remove` and `os.rmdir` raise OSError.

**T4 (note; window): one row's error leaks into every later refused row.**
- `unlisted` is reused across the loop (app.py:2270-2274, 2277-2278).
- Case: `is_link(A)` raises. Rows A, B and C then all say "<A> cannot be read (...): Remove is not offered", and B and C lose their Remove.
- It is reachable only by a race: `user_entries` has already lstat'd every "other" entry (overlay.py:1235).

**T5 (note; G-2 and G-6): a link named exactly as a package id is said as a package rule, not as a link.**
- Exact matches skip links (overlay.py:1372), and the package refusal (1375-1376) comes before the link words (1381-1384).
- Case: rules.d/NET-TOOL is a symlink and the person runs `--remove NET-TOOL`. The words are `REMOVE_PACKAGE`. Nothing is deleted. The window's row says `BY_HAND_LINK`.
