# Ruling on 2026-11-02-M5.1-questions.md (the Table, 2026-11-02)

The STOP was correct. The Scope in M5.1 was the Table's error: E3 named four
rules whose path logic lives in `raqib/rules/engine.py` and the catalog, and
neither was in Scope. The builder found it, changed nothing, and wrote it
down. That is the protocol working. Error ledger: Table, scope omission,
M5.1.

## Rulings

- **Q-1 (b): split.** M5.1 keeps E1, E2, E4 (installer, lock, CI) and a
  README line that says exactly what is true. E3 becomes **M5.1b** with
  Scope `raqib/rules/engine.py`, `raqib/rules/context.py`, the four catalog
  YAMLs, `tests/`, `docs/review/`. M5.1b lands before M5.2.
- **Q-2 / Q-3: capture records paths as given; only rules normalise.**
  `norm_path()` lives in `raqib/rules/engine.py` (next to `_place` and
  `_under`), not in the hook. Capture stores evidence as the agent produced
  it (A5); comparison is the rules' job. So M5.1 needs no `norm_path` at
  all, and the `-I` import question disappears. `raqib/hooks/common.py`
  (M5.2) is for hashing and extracts, not for path comparison.
- **Q-4: fold case only for drive-letter (`X:\`, `X:/`) and UNC
  (`\\server\share`) paths.** POSIX paths stay case-sensitive; every
  existing fixture outcome must be unchanged, and the gate proves it.
  macOS case-insensitivity stays out of scope and is written in the rule's
  description as a known hole.
- **Q-5: Windows cwds with no project boundary**, mirroring the POSIX list
  in SCOPE-CWD-ROOT: a drive root `X:\`; `X:\Users` and `X:\Users\<name>`;
  `X:\Windows\Temp`; `X:\Users\<name>\AppData\Local\Temp`; `X:\Temp`. Add
  them as a second regex branch, not by loosening the first. A Windows cwd
  that matches no branch must still yield a `partial` note, never silence
  (A3): the builder's table shows SCOPE-CWD-ROOT silent on `C:\`, and that
  silence is the real defect M5.1b fixes.
- **Q-6: no.** `/mnt/c/Users/x` and `C:\Users\x` are different cwds. Write
  this in the rule description so the hole is in the tree.
- **Q-7: do not assume the shell; do not need it.** On Windows the installer
  writes a hook command with no shell syntax at all: the interpreter and the
  script path, quoted, nothing else. `capture.py` already prints
  `RAQIB-SILENCE:` and exits 0 on any failure it can catch. What the shell
  wrapper covered on POSIX (interpreter missing, script missing) becomes,
  on Windows, a hook error shown by Claude Code rather than a block; the
  README says so in one line. The builder records in `docs/review/` what
  Claude Code's documentation says about hook shells on Windows if it can
  read it, and marks it unverified otherwise.
