# M12.4c2b1 - the builder's questions (ADR-0013 Amendment T, T-1 to T-4)

The builder's questions, with what was built in the meantime and why. None is answered here; each is the
Table's.

## What was built

- `raqib/winservice.py`: one new method of the system object, `System.own_check()`, which imports
  raqib/wincode.py at its call and returns `(bad, counts, drives, words)` from
  `wincode.check(wincode.System(), drives)`. `Runner._serve` now runs: START_PENDING (5 s); the place; the text
  file and its first line; START_PENDING again with `CHECK_WAIT_HINT` (60000 ms), unless a Stop already came;
  `Runner._own_code()` (the check, its seconds read on `System.clock`); RUNNING; the AH-2 wait; the watch.
  `EXIT_NOT_ALONE = EXIT_BASE + 15` has its words in `EXIT_WORDS`. `_status` takes an optional wait hint.
  `run()`'s branch for an interrupt with no watch result never turns a 15 into 0.
- The text file for a pass: `raqib service run: its own code, checked at this start by this process (ADR-0013
  T-1), in S.SS s: raqib service check: the code a service would run is the system's alone: <the check's words>`.
  For a refusal, the same head, then `raqib service check: NOT the system's alone: NAME, WORDS; no watch is begun;
  the system is told the service's own exit 536870927 (0x2000000F: ...)`. An exception (its trace first) and an
  answer of a form not known get their own words and `; what was not read is never the system's` before the
  `no watch is begun`.
- `tools/rig/check.py --service-refused FILE`: X52 (`read_service_refused`), with tests in
  tests/test_rig_check.py modelled on X48's and X51's.
- Docs: SERVICE.md (the runner's section, the 15 row, one sentence of the check's section), GUIDE.md (the
  check's paragraph, where it says the service), THREAT_MODEL.md (the runner's and the check's paragraphs).

## Questions

1. **T-1's FOR cannot be fully true of the runner.** T-1's FOR says "the service is never the road by which a
   user's file runs as the system". But when the runner asks the check, the code doing the asking has already
   run as the system: the interpreter, its site, the `import` lines of its *.pth files and Raqib's own modules up
   to the runner (N-2), or the packed program and its runtime. So the check at the start keeps a user's tree from
   being *watched*. It does not keep it from *running*. Built: the documents say so in those words (SERVICE.md,
   GUIDE.md, THREAT_MODEL.md), and they say that keeping such a tree from running at all is the install's
   (M12.4c2b2). The FOR's own words are in the ADR, which is the Table's.
2. **The method's answer has four parts.** HANDOFF E1 asks for one method "that gives what `wincode.check` gives
   with the drives it asked". The runner also has to write the pass's sentence as `raqib service check` prints
   it. That sentence is made by `wincode.plain_words` or `wincode.checked_words`, and wincode may be imported
   only inside that one method. So the method also returns the words. The two line heads, "raqib service check:
   the code a service would run is the system's alone: " and "...: NOT the system's alone: ", are written again
   in winservice as `PASS_SAID` and `REFUSED_SAID`. A test holds them word for word against
   `wincode.cli_check`'s output. Is a four-part answer acceptable, or should wincode get a function that makes the
   line (wincode was not to change in this task)?
3. **The wait of 60 s, and the check-point.** At the slowest rate measured (1.9 s for about 10000 names), WALK_MAX
   (200000) comes to about 38 s. That was not measured. 60 s is above it with room, and it matches the runner's
   other bound, HELD_WAIT_MAX. `System.set_status` always passes a check-point of 0. The second START_PENDING
   therefore goes out with check-point 0 and a new wait. The system's documents say a service in a long start
   raises the check-point. Changing that would change `set_status`, which is more than the one new method, so it
   was not done. Whether the manager takes the new wait without a higher check-point was not measured. Should the
   check-point be raised (here as a REDO, or in M12.4c2b2), and is it measured first?
4. **A Stop during the check may never reach the runner.** START_PENDING accepts no control (AF-2, unchanged).
   The system's documents say a Stop is then refused to its caller ("cannot accept control messages at this
   time"). That was read, not measured. If it holds, an administrator cannot stop the service through the
   manager while the check walks, for up to the 60 s wait. The behaviour E2 asks for (a Stop during the check is
   obeyed after it: 0 where it passed, 15 where it refused) is built and tested with the stand-in. On a real
   machine it may be a path the system never takes. Should START_PENDING accept a Stop while the check runs?
5. **A Stop that came before the check.** It does not skip the check (T-1: "at every start"). The second
   START_PENDING is not told after the Stop's STOP_PENDING. The system is told 0 where the check passed (no watch
   is begun) and 15 where it refused. The other choice is to skip the check once a Stop came, and tell 0.
6. **Which exceptions count as "out of the check".** `Exception` and `KeyboardInterrupt` raised in
   `System.own_check` are refusals (15), with their trace. The Stop's interrupt is raised only while the watch's
   call runs (AF-4), so a KeyboardInterrupt here is never a Stop. Other BaseExceptions (SystemExit,
   GeneratorExit) are not caught there and end as the runner's own (23). Should they be 15 as well?
7. **"An answer of a form the runner does not know".** It is defined strictly. A pass is
   `(None, dict, list, str)`. A refusal is `((str, str), dict, list, None)`. Anything else, including a pass
   carrying a refusal's name or a refusal carrying words, is 15, said by its type and its repr cut to 200
   characters.
8. **The cut.** HANDOFF E2 asks for each part to be "made printable and cut as the runner cuts". Each part (the
   name, the words, the pass's words, an exception's words) has every character that is not printable replaced
   by `?`, and is cut at `CHECK_SAID_MAX`, 4000 characters, with the cut marked `...`. The runner's other cuts
   (80, 40) would lose a refusal's words. wincode already cuts each name it says to 200. Its longest words, read
   in its source (a name the interpreter looks for, inside a *.pth line's entry), are around 1200 characters.
9. **X52's `refused-exit`.** The HANDOFF names this key without its value. It was built as the service's exit
   number as the system gives it (`sc query`'s WIN32_EXIT_CODE, `Win32_Service.ExitCode`): 1066, the
   service-specific error, which means the number is the service's own. It is read in decimal or as 0x
   hexadecimal. If the job writes something else under that key (the start command's exit, for one), the reader
   needs to change. The job's wiring is the Table's.
10. **15 used again.** The spec said "15 is not used: the closing it named is gone". Amendment T rules 15 for the
    check, and the spec now says both. A system log that still holds a 15 from a build before Amendment F would
    now read with the new words. No released version is known to have told 15. That was not checked against the
    changelog, which is outside Scope.
