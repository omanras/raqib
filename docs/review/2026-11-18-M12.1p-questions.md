# M12.1p - STOP (ADR-0013 Amendment C, AC-1: `raqib watch --host --no-page`); the question for the Table

The builder built the task whole in its worktree and did not land it. One clause of E4 cannot be met inside
the task's Scope. Nothing below is answered locally (CLAUDE.md rule 6). The tree at this commit is HEAD
(96e578c) plus this file.

## Q1. E4's `--refresh` clause needs a line outside the Scope of raqib/cli.py (the blocker)
E4: "`--no-page` with `--port` or `--refresh` is a usage error that says why." The Scope of raqib/cli.py is
"only: the option `--no-page` of `watch`, its usage line and help".

- The file and the line: raqib/cli.py line 577,
  `w.add_argument("--refresh", type=_refresh, default=ui.REFRESH_DEFAULT, metavar="N",`.
- Why it blocks: without `--refresh`, argparse sets `args.refresh` to `ui.REFRESH_DEFAULT` (5). With
  `--refresh 5` it sets the int 5 that `_refresh("5")` returns. That is the same value, and in CPython the same
  object (a small int). So no check in `_watch_host` can tell `--no-page --refresh 5` from `--no-page`. An
  argparse mutually exclusive group cannot either: it compares a given value to the default by identity.
- Measured in the builder's tree: with the check `args.refresh != ui.REFRESH_DEFAULT`,
  `raqib watch --host --no-page --refresh 9` is exit 2 and says why. `--no-page --refresh 5` is not refused:
  the watch starts.
- What the Table may rule (the builder chooses neither):
  (a) Widen the Scope of raqib/cli.py to line 577: `default=None`. The two readers of `args.refresh` already
      take None as the default. `watch.command` hands it to `watch.start` (raqib/watch.py line 1363), and
      `host.command` hands it to `host.start` (raqib/host.py line 5142). Both read None as
      `ui.REFRESH_DEFAULT`, so a page still reloads every 5 s and the help's "(default 5)" stays true.
      `raqib app`'s own `--refresh` (line 642) is a separate option and need not change.
  (b) Amend E4 to "`--refresh` with a value other than the default's". `--refresh 5` then passes with
      `--no-page`, and it changes nothing, because no page reloads.

## Q3. Choices the build made where the HANDOFF is silent (for the Table to strike or keep)
- Where the start says `raqib watch --host: no page is served (--no-page): no port is opened`: where the page
  would have been served, after the start's `hole:` lines and before a registry hole line.
- With no page, the loop says no line of how the watch ends. The page line used to carry "Ctrl-C ends the
  watch". The start's round line still says "until Ctrl-C", and the stops line of M9.1 is said as before.
- `--no-open` is accepted with `--no-page`: nothing is opened anyway. Should it be a usage error too?
- `host.start(no_page=True)` does not use its `port` argument (the command line refuses `--port`). It keeps
  `refresh` in the state (`refresh_seconds`), because `watcher.page()`, called by a test (E3), uses it.
- `Running` takes `no_page=False` as a keyword. `close` skips the server only where `running.no_page` is
  true. A `Running` built with a server of None and no `no_page` (the older tests' fakes) closes as before.

## Q4. What only the field can show
- On a Linux host: `raqib watch --host --no-page`, then `ss -ltnp` shows no listener of the watch's pid, and
  a user without rights finds nothing on 127.0.0.1:8765. The next task (the unit's ExecStart, and
  RestrictAddressFamilies=AF_UNIX AF_NETLINK) is where an AF_INET socket the watch still makes would show up.
  With `--no-page` the build opens none of its own, but the notifier, the host's name and the readers were not
  measured under that restriction here.

## Ruled, and landed
Q1 was ruled (a) by ADR-0013 AC-13 (the Table, commit 2379810). The scope of raqib/cli.py gained line 577:
`watch`'s `--refresh` defaults to None, and `_watch_host` refuses `--no-page` with any `--refresh`, the
default's 5 included, in either order. Without `--no-page` a page still reloads every 5 s by default. The
starts read None as `ui.REFRESH_DEFAULT`; tests/test_host_nopage.py holds the host watch's default through
the command line, and tests/test_dashboard.py holds the project watch's. `raqib app`'s own `--refresh` is
not touched. AC-13 kept the choices of Q2 and Q3 as they are. The task landed as
`landed: M12.1p the host watch without its page`.
