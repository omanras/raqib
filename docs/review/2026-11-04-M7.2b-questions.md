## Design points settled (Q-1..Q-9): the Table may overrule any

- **Q-1 Attachment order and when.** When a tree (candidate or act-root) first appears in a round,
  `_attach` gives it one source: (c) hooks, only under `attach_hooks` and only for a Claude Code tree
  with a usable cwd; else (a) os when the Sysmon check (doctor.check_sysmon, read once at the start)
  says the channel exists; else (b) host. A source that ended with a hole (an os follow that raised,
  a host file that could not be appended, nothing attachable) is attached again the next round the
  tree is in; an os source that failed falls to the host source then (not to os again), said on the
  tree. A source is not re-attached for a tree that is gone and back (same key, same source).
- **Q-2 What "Claude Code tree" means.** The catalog's hook images (claude) with no Claude Desktop
  path pattern (discover's own hand-off rule, applied to the exe and argv where read), or node whose
  argv (read only from a /proc snapshot's JSON line, which the tree cites) has a `.../claude-code/
  .../cli.js`. On Windows live argv is not read (A-3), so node is never recognised there: said.
- **Q-3 Where hooks are refused even with the flag.** No cwd read (Windows always, H-4), not
  absolute, not a directory here, under ~/.raqib, the home directory itself (its
  `.claude/settings.json` is the person's settings for every project; writing hooks there would be
  a write the person did not point at), or a filesystem root. Each is "hooks: not attached (<why>)"
  on the tree and a `hooks-not-attached` hole (only under the flag: without it the reason is "no
  --attach-hooks" and no hole, since nothing was asked). A failed install is the same.
- **Q-4 The trace of attached hooks.** `watch.choose_trace(installer, cwd, None, home)` exactly as
  `raqib watch` with no --log: the earlier install's trace if outside the project, else
  ~/.raqib/traces/<name>-<hash>/raqib.log.jsonl. The hooks' trace is judged incrementally (Feed:
  watch.Tail + trace._parse) by the silence rules, the catalog with no context and CROSS-SOURCE;
  its lines already there at attach are history.
- **Q-5 Hooks and the host lines together.** A tree with hooks also keeps its host lines (HostChild,
  HostConnection) in the per-tree file: the host's record is the anchor the agent does not write,
  so it stays beside the agent's own hooks. Recorded; the Table may want hooks alone.
- **Q-6 The YAML shapes.** NET-TOOL: one more branch in its top-level `any`: source host, tool
  HostChild, command_programs has_any the same list. DESTRUCT-CMD: `tool: Bash` moved inside a new
  `any` beside the host branch (same list). Consequence (C-1a): DESTRUCT-CMD has no top-level `eq`
  gate any more (NET-TOOL never had one), so its two benign negatives that hold no Bash line
  (docs-lookup, file-tools log) now count as measured: 8 -> 11 measured, 0 unmeasured. They are
  judged on every line and do not fire, so the measure is honest, but the Table may prefer the
  gate kept (`gate_of` reading an `any` of `eq`s is a fixtures.py change, out of scope here).
  DESTRUCT-CMD's summary now starts with `{tool}` instead of the literal "Bash" (no host line is
  labelled Bash). HostConnection lines are not judged by NET-TOOL: its endpoint rules are for a later
  task (recorded in its evasion).
- **Q-7 Silence over host lines.** silence.findings drops lines of source host before grouping by
  session: one exemption, by source. A session mixing host and other lines is judged on its other
  lines.
- **Q-8 History and knocks of sources.** A source finding whose cited lines all end at or before the
  feed's history mark is history: listed, not knocked, not an alarm. The mark is: the file's size at
  attach; for a tree there at the start (first round = the history round), also its first round's
  host lines; for an os follow of such a tree, everything its first pass appended (the channel's
  past). SILENCE-OPEN and SILENCE-HALF of a source are listed at the end only ("pending at the
  end"), never knocked live (later lines take them back; B-1's settlement is not rebuilt here). Other
  findings knock once under "<RULE> pid N". A live source finding makes the watch's result ALARM
  (exit 1); a source hole makes it INCOMPLETE (3) unless a finding.
- **Q-9 HOST-UNWATCHED.** Fires on a candidate's HostTree line with `source: none` and
  `none_rounds: 2` (two rounds in a row with nothing attached), once per tree; `none_rounds` counts
  consecutive rounds the tree was seen with no source. Only "none" is unwatched: an attached but
  silent source (an os follow whose Sysmon logs nothing of it) counts as a source; its silence is
  its own RAQIB-SILENCE lines. Since (b) needs only ~/.raqib/host/sources/, "none" means that
  directory could not be had; its fixtures make that so with a file in its place. Act-roots are
  listed with their source but not judged (holes in the YAML).

## Other choices recorded

- The per-tree file is ~/.raqib/host/sources/<run>-<pid>.jsonl for os and host lines (the HANDOFF's
  path); host lines' session is `host-<pid>`, their seq runs per file, and each cites its round, its
  sample, the run and `tree_seq`, the seq of its HostTree line in rounds.jsonl, which holds the cited
  record lines' text (C-6). In the source file a cite is (src, line, text_sha256): hashes only (E2).
- `os_sysmon.follow` (API only): run() in a loop until a Stop, each pass appending only events with an
  EventRecordID above the last appended one (`build(after_record=, info=)`), each silence written
  once per follow, `on_pass(n, top)`. run() and the CLI are unchanged.
- `install.py`: no change was needed; `install_project`, `absolute`, `installed_traces` are used as
  `raqib watch` uses them.
- Stop: `finish()` sets every os follow's Stop and waits up to 5 s for them together; one still in a
  pass is a `source-out` hole. A tree that leaves the round stops its os follow.
- The HostTree line carries `source`, `source_word` (no path, so the fixtures do not depend on the
  home), `none_rounds` and `hooks` ("hooks: not attached (<why>)" or "hooks: project P").
- The window: a checkbox "attach hooks to Claude Code projects" (off), read when "Watch this host"
  starts; the host table gains "source" and "findings" columns. The page: the same two columns and a
  "Source findings" section, and one line saying whether hooks are attached.
- CI (install job, host step): every tree in the report has a `source:` line whose kind is one of
  host/os/hooks/none, and "none" never outnumbers HOST-UNWATCHED; the report says hooks are not
  attached. On the runners that is the host source (checked locally: CLEAN, both trees `host`).
