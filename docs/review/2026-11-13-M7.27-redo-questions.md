# M7.27 REDO - questions and notes for the Table (2026-11-13)

Built against ADR-0007 Amendment BI (BI-1 to BI-4). No design question blocked the build; each
item below is a decision the builder made inside BI's words, surfaced for the Table.

## 1. BI-3, the third `_act_roots` self_tree walk (~ discover.py:2975) is armor, not a rule

BI-3 asks for a test that fails when any one of the three `self_tree` walks in `_act_roots` is
reverted. Two of the three are load-bearing and the test covers them (confirmed by reverting each
once):

- `ancestors(procs, pid, self_tree)` for the act-root's talking ancestor (~2984): reverting it
  makes the act-root R's `talking_ancestor` the talker above the reader -> the test fails.
- `ancestors(procs, r["pid"], self_tree)` for `inside` (~3005): reverting it makes R's `inside` the
  second act-root above the reader -> the test fails.

The third - `ancestors(procs, q, self_tree)` building each act's `via` (~2975) - cannot be
isolated, and this is structural, not a gap in the test. The acts `q` fed to that walk are
`[s] + below(s)`, and `below()` already drops every `self_tree` member and never descends through
one; the shell `s`'s parent IS the act-root (the chain is keyed by `s["ppid"]`). So no member of
the watch's tree can ever sit strictly between an act `q` and its act-root, and the walk's result
is identical with or without the `self_tree` argument. Reverting it changes nothing in any sample
(verified empirically: the act's `via` is unchanged). It is the mirror of the candidate-side
`via` walk in `_acts_core` (~2379), where the "root" is a talker that can be many levels up with
members in between, so that one DOES need the exclusion and IS exercised.

Decision (per the Table's standing guidance relayed this session): kept the argument with a
one-line comment `# BH-4: redundant here - below() already drops self_tree; kept defensively, no
isolating test (ADR-0007 BI-3)` rather than removing it. Reason: it keeps the three walks
symmetric and self-documenting, and it stays correct if `below()` or the chain construction is
ever changed to admit a member between an act and its act-root; the comment prevents a future
reader from "fixing" the asymmetry or re-opening this question. If the Table prefers the argument
removed as dead code, that is a one-line change and the gate stays green either way.

## 2. BI-2, the no-image fallback does not re-open the silent hole

A recorded entry with no image of its own falls back to proving by pid and time alone, as before
BI-2. This is only reached where the launcher's `args[0]` gives no usable name. The two programs
the watch actually starts - `wevtutil` (os_sysmon.py, args[0] = the absolute wevtutil.exe path)
and the notifier (notify.py, args[0] = an absolute program path, guarded by `os.path.isabs`) -
always have a real `args[0]`, so a real recorded helper always carries an image and is proven by
pid, time AND image. A no-image entry is therefore not expected in practice; should one ever occur,
it is proven by pid and time as before (it is not hidden more and not named more than the old
behaviour). The start lines in os_sysmon.py and notify.py were NOT changed (they already pass a
Popen whose `.args[0]` is a real path, which `own.started` now reads); this stays within BI-2's
"MUST NOT TOUCH: what is started".

## 3. BI-2, a held pid whose image the sample could not read is kept, not forgotten

`own.alive` does not prove such a pid this sample (it is named, not hidden, as BI-2's MUST NOT
TOUCH requires) and also does NOT forget it, since the read may be transient - the same caution
BI-1 applies to an unreadable Linux process. A pid taken again under a different image (read) IS
forgotten, because the helper that held it has ended. This keeps BI-1's and BI-2's "do not drop a
possibly-alive helper" in one place.

## 4. BI-2, the sample's image on each platform

- Windows (hostwin.process_text): the snapshot's `szExeFile` (the Toolhelp32 image basename, taken
  atomically) is the sample's image. A pid reused in the gap between the snapshot and OpenProcess
  is already dropped as REUSED by date; the atomic snapshot name is what the rest of the sample
  judges the pid by, so proving by it is self-consistent.
- Linux (discover.snapshot_proc, `_proc_image`): the exe link where read, else `argv[0]`, else the
  status Name. `own._base` takes the lower-case basename of either (it also splits a Windows path),
  and the record's image is normalised the same way, so the comparison is a case-insensitive
  basename match on both platforms.
