## 4. New bugs and silent assumptions

**4.1 [high, SILENCE] The private_key regex backtracks catastrophically** (capture.py:112-114).
- The header-line group `(?:[A-Za-z][A-Za-z-]{0,30}: [^\r\n]{0,200}(?:\s|\\[rn]){1,4}){0,8}` is ambiguous on a single line: `[^\r\n]{0,200}` can swallow later "Name: " fields and spaces.
- A line of many "a: " tokens can therefore be split across up to 8 iterations in roughly 66^8 ways. Every split then fails at `[A-Za-z0-9+/=]{40}`.
- **Trigger, by reading (not run):** about 1-2 KB made of a PEM header ("-----BEGIN " + "PRIVATE KEY-----"), a newline, then 200-600 repetitions of "a: " on one line. The scan should run until SIGALRM. That signals interrupt `re` is my reading of CPython, not verified here.
- **Effects:**
  - the post line is lost, leaving one RAQIB-SILENCE line on the hook's stderr and a SILENCE-HALF in the trace;
  - the agent waits 8 s;
  - SECRET-OUTPUT never sees that output.
- The agent can produce this output itself: Write echoes the content (M1.2-questions.md:204-206), so a Write followed by a Read is enough.
- test_capture.py:646 puts one header field per real line, which does not exercise the ambiguity.

**4.2 [medium, SILENCE] The work under the lock is not capped and grows with the log** (capture.py:482-485, 340-364).
- Every event reads the whole shared log and JSON-parses every line of its own session. Over one session that is quadratic.
- With a 5 s lock wait and parallel calls queued behind the lock, a long-lived log turns into RAQIB-SILENCE for every event: holes in the trace, not stalls.

**4.3 [medium, SECRET/A2] The placeholder rules can acquit real secrets inside capture** (capture.py:125-130, 290-312).
- **url_credentials** keeps the user name in the part it checks (:297). A real password is dropped when the user name contains "test", "secret", "your", "fake", "sample" or "dummy". It is also dropped when user:pass has fewer than 8 distinct characters, for example "root:" + "toor".
- **sk_api_key** must mix digits and both cases (:309-311). By my recollection, not verified, at least one widely used provider issues "sk-" + 32 lowercase hex. Such keys count as placeholders.
- **Greedy kinds** (sk, slack, gitlab, github_pat, stripe) pull adjacent token characters into the match. A token followed directly by "test", "TEST" or "XXXX" is dropped.
- **Nothing raises on the suppression.**
  - SECRET-OUTPUT ignores placeholder_kinds (SECRET-OUTPUT.yaml:12), and no note is written.
  - The report shows output_meta only on lines a finding cites (report.py:50-52).
  - So "the suppression is visible" (M1.2-questions.md:101-102) holds only for someone reading the raw trace.

**4.7 [medium, A3] SCOPE-CWD-ROOT matches four fixed patterns against the raw cwd string** (SCOPE-CWD-ROOT.yaml:12).
