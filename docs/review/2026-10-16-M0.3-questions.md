## Open questions (not answered)

- **Q1 The watched agent can edit its own trace.** By default the log is
  `raqib.log.jsonl` in the directory Claude Code runs hooks from, which is the
  project the agent works in. Nothing stops it from rewriting or truncating
  the trace. `--log PATH` can move the trace outside the working tree, but the
  agent still runs as the same user. Should the default move (for example to
  `~/.raqib/<project>.jsonl`)? Should a rule flag tool calls whose
  `input_meta.path` is the trace or `.claude/settings.json`, meaning the
  agent touched its watcher?
- **Q2 SessionStart `source` and SessionEnd `reason` are dropped.** A-3 lists
  the fields of a session line, and the builder kept to that list. `source`
  (startup, resume, clear, compact) would let a rule tell a resumed session
  from a new one. Should it be recorded?
- **Q3 Stop fires once per turn.** In a multi-turn session the first `stop`
  closes it for SILENCE-OPEN (M0.2 E2), so an open session is caught only
  when no turn ever finished. This is consistent with M0.2's wording; is it
  the intent?

## Assumptions made (confirm or overrule)

- **Matchers:** tool events use `"*"` (all tools); SessionStart, SessionEnd
  and Stop have no matcher (all sources).
- **Recognising Raqib entries:** a command that contains
  `raqib/hooks/capture.py` is Raqib's. A re-install replaces any such entry
  (a stale path, a wrong matcher, or duplicates) with exactly one group, and
  keeps the other hooks that shared a group with it.
- **Hook command:** `python3 '<absolute path>/raqib/hooks/capture.py'`, which
  relies on `python3` being on PATH. `--log` puts `RAQIB_LOG=<absolute
  path>` in front of it.
- **Unreadable settings:** invalid JSON, a non-object, or a `hooks` value of
  the wrong type exits 1 and leaves the file byte-for-byte unchanged. An
  empty file counts as `{}`. Writes are atomic (temp file plus rename).
- **error_class (A-4):** a leading exception name (`TimeoutError: ...`,
  `Error: ...`, `pkg.CustomException: ...`), or the `type`/`name`/`class` of
  a structured error, capped at 64 characters. Anything else is `"failure"`.
  No message text is stored. `is_interrupt` is not recorded.
- **Session lines** get the next seq, like a pre. They never pair with or
  close a tool call.

## Not verified
