## 5. B-3, determinism
- `line()` (event.py:264-266) is deterministic for one input: sorted keys, compact separators, ASCII,
  `allow_nan=False`. Floats print as the shortest repr (0.25 stays 0.25).
- None is dropped at the part level but kept inside lists (F11).
- Lone surrogates, which Windows names can carry, are escaped as `\udXXX`: deterministic, but some parsers reject
  them.
- Two entries in one call never share an id. Across calls they do (F2, EVENT.md:151 and 167).
- `check()` with a wrong `n` tests only that n >= 1 and that `id` equals `run:n` (event.py:301-307). It cannot see a
  repeated or skipped n.
- `ledger()` restarts at 1 on every call. Its end call reuses the heartbeat's n for the watch end.

## 10. The builder's questions (what the code does now; no choice made for the Table)
- **Q1, tree summary.** A tree event has no `summary`, and `check()` refuses one. A consumer's OCSF and ECS `message`
  is empty for every tree event.
- **Q2, pending at exit.** The state is emitted as "pending at exit", and `check()` accepts it. The order matches host
  `_word` for every entry the watch makes today (section 4), but neither treats "not settled" (F3). A SIEM mapping
  that knows B-2's four states meets a fifth.
- **Q3, knocked.event.** Only knock events carry it. A knock row also has no reference to its finding (`ref` and
  `tree` are dropped, host.py:1825), so a consumer can join a finding to its knock only through the round and the body
  text.
- **Q4, subject.named.** A tree event carries a boolean, a tree's finding carries a string. `ledger()` emits trees
  before findings, so in an Elasticsearch index with dynamic mapping the boolean is mapped first, and each NEW-AGENT
  finding's "unknown" or "named" is refused at indexing: the finding is lost. [SILENCE, likely in ES]
- **Q5, evidence.record.** It is never emitted, but documented with kinds "none yet". The `sample` field of findings
  and dark notes is dropped.
- **Q6, time.** Entries with an `at` use it; the start uses `started`; trees, plain notes, the heartbeat and the end
  use the caller's time.
  - A tree row does hold a time of its own, `first_seen` (host.py:2002).
    - In run B the finding is said at 10:00:10 (EVENT.md:103) and its tree at 10:00:30 (EVENT.md:127). A consumer
    sorting by time sees the tree after its own finding.
