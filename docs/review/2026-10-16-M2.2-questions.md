# M2.2 evaluation harness: questions and assumptions

Task: HANDOFF.md (M2.2). Built:
- `tests/fixtures/eval/events.json`: 50 events, 25 benign, 20 suspicious and
  5 deceptive, written by `tests/fixtures/eval/generate.py`. A test checks
  that the file is byte for byte what the generator writes.
- `raqib/eval.py` and `python -m raqib eval`.
- `tests/test_eval.py`.
- The real rules baseline: `docs/review/2026-10-16-M2.2-baseline.md`.
  - Rules: FN 9, FP 6, errors 0.
  - They miss 4 of 20 suspicious events and 5 of 5 deceptive ones.
  - They flag 6 of 25 benign events.

## Open questions (not answered)

- **Q1 Who labels.** The events and their labels were written by the
  builder, who knows the catalog (A7). Benign events that trip a rule and
  deceptive events that dodge every rule were both chosen on purpose. Should
  a second person relabel the set, or add events, before it decides a model?
- **Q2 What a model sees.** In the model row, the model sees the rule
  findings in its window, as `raqib suspect` runs it.
  - So "model" alone is not a blind model, and "rules+model" is the row that
    answers what the model adds (E3).
  - Should there also be a blind row, with no findings in the prompt?
- **Q3 Ties and cost.** Rows are ranked by FN, then FP, then errors (the
  plan). Cost and latency are not measured. Should they break ties?
- **Q4 Window size.** Every event is shorter than the default window (40
  lines), so each event is one window. Real sessions span many windows, and
  the harness does not test that.

## Assumptions made (confirm or overrule)

- **An error is a miss** on a suspicious or deceptive event (A3). On a
  benign event it is not a false positive, but it is counted under
  `errors`, which ranks after FN and FP.
- **The rules row is flagged by any finding**, SILENCE included (HANDOFF E3).
  Notes, such as `not-evaluated`, do not flag an event. Every event carries
  the same context (scope src, tests and docs; root /work/app), so
  DRIFT-FILES runs on all of them.
- **A model row is flagged** when any window raises suspicion at or above
  `--threshold`. Answers below it are dropped (A2), never counted as "clean".
- **Exit code 0** once the events are scored, even when a candidate had
  errors: the errors are a column of the table. Bad input exits 2.
- **Event format** is `{"version": 1, "events": [{id, label, description,
  lines, context?}]}`. Each event is one complete session in capture's
  current shape (output_meta with `scan`).

## Not verified

- **No real model was evaluated.** No ANTHROPIC_API_KEY was available, and
  no Ollama server ran in this container. The model rows rest on canned
  answers. The real ranking of candidates is still to be done by someone
  with a key or a local model.
- **Mutants:** 11 eval mutants were run ad hoc in scratch copies.
  - The one survivor (gap_seconds not passed through `evaluate`) was killed
    by a stronger test.
  - The harness is not in git.
