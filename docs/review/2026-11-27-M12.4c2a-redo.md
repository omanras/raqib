**Q-1 as an adversary, from the code (certain).**
- Taken only when all of these hold: `type(kind) is int` and `kind == 3`, `isinstance(name, str)`, and `fullmatch` of
  a flagless pattern whose literals match exactly and whose `[0-9]` is U+0030 to U+0039.
- Every other case is refused: a trailing newline, other Unicode digits, other case, bytes or None, bool or IntEnum or
  float or str for the kind, and a NUL with more after it.
- The answer is cached per letter folded to upper case (368-370, 376). A refusal is a truthy tuple and is returned for
  every later path. A take is per letter and never shared.
- The drive is asked before any name of it is read:
  - The only read of a name is 409, after `_drive` at 398. The 396 cache holds only names already read.
  - Listing (457) comes only after a read, and `*.pth` bytes (759) only for a file taken.
    - Every path read begins with its own `X:\`: path_refused, `_entry_said` and `_root_said` check the entry points;
    `_above` and joins of part-checked names (462) keep the drive.
  - The REDO changed `drive_refused`'s arguments; every caller now passes two (wincode.py:375 and the tests).
- The pass names only drives taken (377-378) and prints only when nothing was refused (917-919).

**Can a letter name exactly that form and not be a volume's root?**
- Known from Windows' documentation, not verified here:
  - A letter is a symbolic link in the object namespace, and QueryDosDeviceW's first string is its current target.
  - `X:\a` is opened through that same link as `<target>\a`.
  - `\Device\HarddiskVolumeN` is a volume's device made by the volume manager.
    - So a letter whose target is exactly that name is that volume's root, and an alias letter is that root too: a
    second letter the system gives a volume, or one a user defines in his own session with exactly that raw target.
    - `\Device\HarddiskVolumeShadowCopyN` is refused, because digits must follow "Volume" directly. A name in other
    case names the same volume but is refused, which errs toward refusal.
- Likely: a plain user cannot make an object named `\Device\...`. Those come from drivers, which only an administrator
  can load. So the form names a real volume. I know of no letter of that exact name that is not a volume's root. Not
  verified on a machine.

**Ways "to the drive's letter" can still be less than the system's alone, though the root is a volume's.**
1. The asker's session may name the letter otherwise than the system's account does. This is said, and M12.4c2b closes
  it.
2. The letter can change between the two calls of the ask and the reads by path. This is said only as "a reading at
  one moment" (the first review's finding 17). M12.4c2b's ask as the system narrows it.
3. The volume can be changed beneath its file system: raw writes, an attached image's backing file, a disk served from
  elsewhere. This is said only in part (finding 10).

A folder mounted as a volume is refused as a reparse point. A letter given to a disk's own root (`\??\C:\`) is refused
  by form; Q4 errs toward refusal.
