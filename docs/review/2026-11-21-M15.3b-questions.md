# M15.3b - questions and choices (the builder, 2026-11-21)

Task: ADR-0014 Amendment I, AI-1 to AI-10: the autostart read made fit for the watch, in raqib/autostart.py
alone. Nothing here is answered locally; each choice below was made only where the HANDOFF left it open, and can
be ruled otherwise.

## Design questions for the Table

1. **The salt of a read made without a watcher.** E7 says `read` without a watcher "takes a salt of its own".
   A salt made new at every such read would make `changes(read(), read())` say every entry removed and added,
   and E1 says `changes` is unchanged. So a read without a watcher takes the process's own salt, random, made
   once at its first need, never written. Two watchers (and two processes) still differ. Is a salt per read
   wanted instead (and `changes` then only for reads of one watcher)?
2. **A place the deadline cut.** A place the deadline did not reach, or cut while it was read, is `unread`
   whole (its entries not given), not `partly` with the keys it did reach. The finer one would keep the keys
   read before the cut. Is the coarse one right for the watch, where a place larger than the deadline (thousands
   of services) would then never be read?
3. **`changes()` and the new state.** `changes()`'s own code is unchanged; its helper `unread()` now names the
   new state `unread` (a place cut by the deadline, or with no key readable for a bound) so that such a place
   gives no change, as AG-2 says. `changes()` compares `sha256` alone, so a task whose triggers alone changed is
   no change to it (the Watcher says `rescheduled`). Keep?
4. **A hive never listed before.** A hive the base never listed is `hive loaded`, also on the first listing
   after the users' hives were refused (AI-6 read over AI-1 there): its entries become the base and are not said
   as added. And the hives are compared only where Run and RunOnce were both read (whole or in part); a hive
   loaded while one of them is not read is said when both are. Which rule wins where the two meet?
5. **A hive's change.** `hive loaded` and `hive unloaded` have place `hive` (not one of the six places), name
   `a user's hive`, and `key` the salted hash of the hive's part; `entries` counts Run and RunOnce together.
   Should M15.3c's line carry them under `run`?
6. **Both a task's actions and triggers changed.** One change, `changed` (what it would run changed), with
   `was` the actions' former hash; not `changed` and `rescheduled` both.
7. **`sure` (AI-8).** "An unquoted text with a blank after a separator" was read as: an unquoted text whose
   first word holds a separator (`\` or `/`) and is followed by a blank. So `C:\Tools\a.exe --x` is not sure
   (Windows would try `C:\Tools\a.exe --x.exe` were `a.exe` not there), and `cmd /c rem x` is sure (its first
   word holds no separator, though `/c` does). Every service whose ImagePath is an unquoted path with arguments
   (`C:\Windows\system32\svchost.exe -k netsvcs`) is therefore `may run`. Is the reading right, or should only a
   blank inside what could be a longer path (a later word holding a `\`) count?
8. **Winlogon's list.** A Winlogon value is split on commas outside quotes; its first item is the program named
   (so the usual `userinit.exe,` now names `userinit.exe`, sure; M15.3a named none), and more than one item is
   not sure. For a list of two, the line names the first program, `may run`, though the second may be the one
   that matters. Name all of them, or none?
9. **A Startup folder whose drive's kind is not known** (no drive letter, or `GetDriveTypeW` not to be had) is
   not read and says so (`whether it is on a share is not known`), rule 5 before completeness. A folder of the
   Startup path that is itself a link to a share is not seen as one (only the folder's own drive is asked). Off
   Windows (a test's read) a folder is local unless it is a UNC path.
10. **An entry whose content is not read now** keeps, in the base, the content it last had, and nothing is said
    (AI-2 says only the first read of a content). A content changed and changed back while it could not be read
    is never said; one changed while it could not be read is said `changed` when it is read again.
11. **The rig's held file.** autostart_run.py holds it (CreateFileW, share mode 0, CREATE_NEW) across read 2,
    lets it go before read 3 and removes it before read 4, before the stand-in starts: the held file's three
    reads are its own, not beside the stand-in. X37 needs it `added` at the first read that lists it; its
    content's `read` and its `removed` are in the words, not required. Require them?

## Choices the HANDOFF did not make

- The watcher is `autostart.Watcher(deadline=5.0, **given)`: `read()` (the module's read with its salt) and
  `take(result)` (the changes of that read against its base: `{"changes", "unread", "first"}`). `given` is what
  `read` takes besides. Its salt is a private attribute; its `repr` is `<autostart.Watcher>`.
- The base is kept per part: a part is a key or a folder (the HKU listing, each hive, each Run key and view,
  each Startup folder, the services' key and each service, each key of the task tree, Winlogon), named by a
  salted hash and holding its parent. A part absent from a read is gone only where its nearest ancestor that
  the read holds was read; then its entries are removed (or, under a hive unloaded, counted in that one change).
  `read` returns `parts`; every entry carries `part`. A place `refused`, `failed` or `unread` keeps all its
  parts; a part not read keeps what it held.
- The hashes are HMAC-SHA256 under the salt (32 random bytes): a content over its type, its length and its
  first 64 KiB; a file over its length (`fstat`) and its first 64 KiB, read no further; `key` and `part` over
  where they are. `refused_sha256` is salted too.
- `keys_refused` now counts every key not read (refused, below the depth bound, on a share, share unknown,
  not opened with every sharing), so the Table's AH-2 test holds as it was; `keys_why` counts them by reason.
  A place with no key read and a reason other than refusal is `unread`, with the reasons.
- The opener: `share_opener(kernel32, osfhandle, last_error, invalid)` (CreateFileW, GENERIC_READ, share
  0x7, OPEN_EXISTING, FILE_ATTRIBUTE_NORMAL; msvcrt.open_osfhandle with O_RDONLY|O_BINARY; a Windows error
  number becomes FileNotFoundError, PermissionError (5, 32, 33) or OSError). On Windows it is made inside the
  call by ctypes; where it cannot be, no Startup file is opened. Off Windows (a test's read) the default opener
  is Python's `open(path, "rb")`.
- The deadline is checked before each place and at each key of a loop (a hive, a Startup file, a service, a
  task key); `read(deadline=None)` reads with none.
- The machine's two views are always two entries; the user's hive is read in the 64-bit view alone.
- The kinds are `added`, `changed`, `rescheduled`, `read`, `removed`, `hive loaded`, `hive unloaded`. The
  command says a `read` as `content read`, an added entry with no content as `, content not read`, a hive's as
  `(a user's hive, N entries)`; `UNREAD round N:` now also names a place read in part, with its keys' reasons.
- The stand-in says `the startup file's delete failed (Kind)` where the delete raises another OSError than
  FileNotFoundError, and `the startup file was not there to undo` (no kind) where it was not there.
- X37 holds the three acts as before, no WORKLOAD line with `the startup file's delete failed`, the held file
  made and said `added` by the first read that listed it; its words add `the held file added in read N, its
  content ...` and `other changes: <kind> <place> <count>, ...` (or `none`). The facts' changes carry `sure`
  and a hive's `entries`, never a hash.
