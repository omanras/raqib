# M2.2 — questions for the commander (not answered locally)

Each entry: the question, the most conservative reading taken, where it
shows in the tree. Nothing here changes the exit criteria.

## Q1. How contrast was measured
Two ways, both WCAG 2 relative luminance. (a) Every foreground/background
token pair the stylesheet uses, in light and dark, from the hex values in
`src/ui/styles.css`; the table is in the README (Accessibility). (b) In
the built page, on every screen, in both themes and both languages, with
every form and `<details>` open: the computed colour of every element
with its own text against the first opaque background behind it. No text
is below 6.09:1 in light or 7.09:1 in dark (the links and secondary
buttons). Non-text marks (focus ring, chart bars and band lines, button
borders) are all at or above 4.17:1, against the 3:1 they need. Disabled
buttons (opacity 0.55) are exempt and were not counted.

## Q2. The exported review page keeps the CLI's palette
"Copy as HTML" and "Download" give the reference CLI's page byte for byte
(M1.4). In its light theme the white text of four labels is below 4.5:1:
`hold` 4.25, `missing` 4.17, `stale` 3.25, and the `warn` class text 3.25
(dark theme: all at or above 5.83). Reading taken: the page stays equal to
the CLI's; the shortfall is documented in the README and belongs to the
reference engine, to be fixed there and then ported. The app's own screens
use the app's palette, which passes.

## Q3. What the accessibility pass changed in src/ui/
- The new-policy form's heading was an `h4` directly under the screen's
  `h2`; it is now an `h3` (an edit form, inside its group's `h3`, keeps
  its `h4`).
- Placeholders had the browser's own grey, which nothing measured; they
  now use `--fg-soft` (8.21:1 light, 7.82:1 dark on inputs).
- The spending and allocation charts of the Review screen had no table:
  an SVG with `role="img"` reads as its title only, so the amounts were
  not available to assistive technology. Each now has a table with the
  same numbers beside it (category and amount; class, value, share and
  band), as the income and expense chart already had. Two strings added
  (`rev.share`, `rev.band`) in English and Arabic.
- Reduced motion: the app has no transition or animation; the existing
  `prefers-reduced-motion` rule stays as a guard.
Labels, roles and tab order were already clean on every screen
(`e2e/a11y.spec.ts`, M2.1), and stay so with these changes.

## Q4. Tests for this task
`e2e/` and `tests/` are outside this Scope, so no spec was added for the

## Q5. release/qayd.html: byte-equal, no stripping
The build is deterministic: two consecutive builds are byte-identical,
the output holds no hash (the stylesheet and script are inlined, so no
file name survives) and no date (the version comes from package.json).
`tools/gate.sh` therefore compares `release/qayd.html` with the fresh
`dist/index.html` byte for byte with `cmp`, and is red when the file is
missing or differs. Consequence: every later commit that changes the app
must refresh the release (`cp dist/index.html release/qayd.html`); the
gate's message says so. Whether a build on the CI runner equals the local
one is shown by the CI run of this commit (see the v0.1 report).

## Q7. The failure model's open items are not built
Each case in `docs/FAILURE_MODEL.md` ends with what is open: persistent
storage is not requested, an unsaved raw edit is replaced by another tab's
write without a warning, a kept as-of date that is not today is not
flagged, a loosening edit of a policy asks nothing, the reversal chain is
not followed, a dropped download cannot be detected. Each would be a new
feature; none is in this task's scope.
