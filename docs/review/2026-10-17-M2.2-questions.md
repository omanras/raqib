request (any branch), on `ubuntu-latest` with Python 3.11 and 3.12,
`permissions: contents: read`, no secret, two pip packages (PyYAML,
pytest). The workflow file lives on the `mizan` line of history only, so
branch `main` (Raqib) is unaffected. The builder also ran the suite and
the self-check on Python 3.11, 3.12 and 3.13 locally: 295 passed /
6 skipped on 3.11 and 3.12 (the four pySigma tests skip without the

Question: should CI add a third job that installs pySigma and its two

offline.

## Q4. Threat model: a gap found while writing it
`docs/THREAT_MODEL.md` section 6 records that YAML alias expansion
("billion laughs") is not bounded: `yaml.safe_load` expands anchors, and
the 1 MiB cap on rule files bounds the source, not the expansion. This is
an engine change (loader), out of this task's scope; proposed fix for a
later handoff: refuse aliases in rule files in the strict loader (a Sigma
rule has no legitimate use for them), with a fixture and a test. Same
section lists regex backtracking (no timeout in Python `re`) and
unbounded value lists as open.
