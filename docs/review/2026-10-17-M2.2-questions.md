# M2.2 quickstart, failure model, CI - design questions

Readings taken by the builder where the handoff left room.

1. **"From a fresh clone of branch `qayd`"** cannot be literally true
   before the commander merges: the v0.1 code lives on
   `claude/qayd-v0.1`. The README says `qayd`, as it will be after the
   merge; the transcript (`docs/review/2026-10-17-M2.2-quickstart.md`)
   cloned `claude/qayd-v0.1` from github.com and says so in its header.
   Question: should the README name the builder branch until the merge?

2. **`~/money` and `$EDITOR` in an unattended run.** The transcript uses
   a fresh directory in the sandbox for `~/money`, leaves the shipped
   policies untouched and appends four October rows with `printf` in
   place of the two editor steps; `--as-of 2026-10-17` pins today so the
   run is reproducible. Citation lines longer than twenty `file:line`
   tokens are replaced by a count, marked inline; nothing else is edited.

3. **The README quickstart runs every command from the clone with
   `--dir ~/money`**, so no installation and no `PYTHONPATH` is needed.
   There is no `setup.py`/`pyproject.toml` in v0.1 (not in any handoff);
   installing the package is an open item.

4. **CI** (`.github/workflows/gate.yml`) runs `bash tools/gate.sh` on
   every push and pull request, on `ubuntu-latest`, with Python 3.11 and
   3.12 (`fail-fast: false`), after `pip install pyyaml pytest`; no
   secret. The gate was run locally with the sandbox's Python 3.11 and
   3.12 as well as 3.13 (210 tests pass on each). The workflow lives on
   the Qayd branches only; branches `main` and `mizan` are untouched.

5. **Failure model.** `docs/FAILURE_MODEL.md` covers the eight cases the
   handoff lists plus malformed lines, duplicates, a routine done late,
   and future-dated rows; "a policy loosened to pass" is stated as not
   detected (A2: a policy is a declaration) with version control named
   as the real control and an `AMENDED` finding as a v0.2 candidate.

6. **An open display item** seen in the transcript: a computed limit
   such as `3695.678618181818181818181818 OMR` (an average over eleven
   months) is printed at full Decimal precision in the text output.
   JSON should stay exact; rounding the text to the currency's precision
   is a `report.py` change outside every remaining scope, so it is left
   for the commander.
