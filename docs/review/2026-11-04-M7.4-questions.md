## Design choices (recorded; the Table rules)

- **Q-1 The rule's id is HOST-RHYTHM, not RHYTHM.** engine.RULE_ID requires
  `[A-Z][A-Z0-9]*(-[A-Z0-9]+)+` (a hyphen); engine.py is out of Scope, and the
  id must equal the file name. HOST- matches HOST-UNWATCHED's family (class
  HOST, the rules of `raqib watch --host`). The README row, the findings, the
  page, the window and the band say HOST-RHYTHM; the HANDOFF's word "RHYTHM"
  is kept in the docstrings. Alternative for the Table: widen RULE_ID to allow
  a bare word, and rename.
- **Q-2 E2 path: computed field on HostTree lines, not a YAML window.** The
  engine has no construct for windows over lines (aggregate is distinct values
  per session, require is before/after in one session). As HOST-UNWATCHED uses
  `none_rounds` computed by host.py, host.py computes `input_meta.rhythm` on
  every HostTree line: {k, w, r, cycles, destination, rounds, talks, acts,
  act_basis, fires, streak_fired, beats}. The YAML matches `rhythm.fires: true`
  plus `rhythm.k eq 3`, `rhythm.w eq 30`, `rhythm.r eq 10`; host.rhythm_params()
  reads those three `eq` values from the loaded rule and computes with them, so
  the YAML is the one source of truth and a line computed with other thresholds
  cannot match (tests `test_e2_the_thresholds_are_the_yamls_and_the_code_reads_them`,
  `test_e2_a_yaml_with_other_thresholds_drives_the_watch`). The module constants
  RHYTHM_K/W/R are the fall-back when the rule is missing (a host-rule hole) and
  a test holds them equal to the YAML's.
- **Q-3 What a beat is, exactly.** talk = each remote host:port in the tree's
  `talks` of the round (new or still established; the inventory's talks are
  outbound connections in TALK_STATES). act = a child of the tree (discover's
  `acts` of how "process") first seen in this round, never in the tree's first
  round (its children then were there already). Its time is the child's start
  time where the reader gives an ISO UTC one (hostwin's GetProcessTimes), else
  the round's time (Linux, a note once; an export's local CreationDate is not
  guessed as UTC, a note once). cycle to D = one talk beat to D in round m and
  an act of round e >= m at time a with m.at <= a <= m.at + W; one talk beat
  pairs with one act round at most (a talk then three rounds of children is one
  cycle), each act round counts once per destination (a burst of children is
  one turn). K cycles to the same D within the last R rounds fire, once per
  streak; the streak ends when R rounds pass with no cycle (a note says so).
- **Q-4 Unknown trees only.** HOST-RHYTHM matches `input_meta.named: false`
  (ADR-0007 decision 4: "the unknown is judged by rhythm"). A tree the catalog
  names is NEW-AGENT's (a test: a named tree with 3+ cycles does not fire).
  Benign-image trees are unknown and are judged (the rhythm is the tree's, not
  its name's); the YAML lists that a benign IDE or updater has the same rhythm
  (a medium finding, not a verdict). History trees are judged too: a tree there
  at the start that keeps a think-act cycle under the watch is a fact of the
  watch, not of history. The Table may prefer otherwise.
- **Q-5 Budget: what the benign desktops measure.** fp_budget 0.0, measured on
  6 negatives: 4 fake-round fixtures (K-1 cycles, changing destination, acts
  between rounds, no talk) and the two NEW-AGENT benign arrivals. The arrivals'
  trees are seen in ONE round after arriving, so they measure only that a
  desktop's first rounds give no cycle; they do not measure an IDE that polls a
  server and builds for hours. That is the real false-positive source, named in
  the YAML; a recorded desktop of many rounds is the fixture it needs (later).
- **Q-6 E1 bytes.** Linux: discover.read_conn_bytes runs `ss -tinp` by
  run_ss (absolute path from SS_PATHS, minimal environment, no PATH; the AST
  guard `test_e6_discover_opens_no_socket...` still holds: one subprocess call,
  in run_ss). The bytes are summed per (pid, remote) and recorded on each
  HostConnection line as `bytes: {sent, received, sockets}`; when not given,
  `bytes: "not read"`. A missing ss, a failed run, or an ss that prints no
  bytes_* for any socket is a named hole (a note of the run, said once per
  distinct text); sockets with no owner shown are counted, not attributed.
  Windows: no bytes (GetExtendedTcpTable), WIN_BYTES_HOLE once per run. Bytes
  are recorded, not judged (ADR-0004 layer 3's "large POST bodies" is not a
  threshold yet: a later rule; recorded in the YAML's holes).
  These are notes of the run, not holes of the watch (they would turn every
  Windows and every ss-less Linux watch to exit 3); the same choice as
  LINUX_HOLE. The Table may rule them holes instead.
- **Q-7 E1 HostConnection is now one line per talk beat per round** (new:
  true or false), not one per new remote: the source file is the tree's
  record of both beats, and the suspect layer sees the repetition. NET-TOOL and
  DESTRUCT-CMD do not read HostConnection lines; the M7.2b fixtures were
  regenerated by make.py (their HostTree lines gain `rhythm`, the HostChild
  children gain `started`, the HostConnection lines gain `new` and `bytes`).
- **Q-8 E3 the suspect call.** `--suspect BACKEND` (ollama[:MODEL],
  anthropic[:MODEL], fake:FILE) and `--suspect-threshold X`; the window's field
  "suspect unknown trees" (empty = off). Every R rounds (round % R == 0) one
  SuspectCall thread runs raqib/suspect/core.run over each UNKNOWN, non-benign
  tree whose host source file has lines not yet handed over: its last
  DEFAULT_WINDOW (40) lines and the source findings citing them. Same schema,
  same validate() (A2: below the threshold is dropped; A5: cited seqs must be
  in the window, else an error line), same backends. API added to core.run:
  optional `system`, `line_fields`, `meta_keys` (defaults unchanged) so the
  host lines go with their own prompt (SUSPECT_PROMPT) and allow-list: seq,
  phase, tool, ts, input_sha256, input_meta.command_programs. The remote
  host:port is not sent (only its hash); no cite text, no path. Never two calls
  at once (a call still out at the next turn is a hole "suspect-held"); a call
  not back within 120 s is a hole "suspect-late"; an error line is a hole; at
  Stop the call has 5 s. Raised suspicion: an entry on the tree (cited seqs of
  its source file), knocks once per tree (SUSPECT, its own rate-limit id), an
  alarm of the watch (exit 1). "benign" (below threshold) is counted on the
  tree as "N window(s) below the threshold: no finding (A2)", never a
  clearance. Named and benign trees are never sent in v1 (no option asks for
  them; the HANDOFF said "never ... unless asked": not built, recorded).
- **Q-9 Only network call, proven by AST.** `test_e3_the_backend_call_is_never_on_the_capture_or_discovery_path`:
  host.py imports nothing of raqib.suspect at module level; the backend is
  built only in `suspect_backend` and called only in `SuspectCall._run`;
  live_reader names no suspect; discover.py, hostwin.py, capture.py and
  os_sysmon.py import no raqib.suspect, urllib, http, socket or anthropic. The
  existing guards (discover's E6, os_sysmon's E1) still hold.
- **Q-10 Exit codes.** As C-10: HOST-RHYTHM and a raised suspicion are
  findings (1); a suspect call failed or late is a hole (3 unless a finding);
  "benign" changes nothing.
