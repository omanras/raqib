# M0.2 — questions for the commander (not answered locally)

The reference engine's source is not on this branch; its behaviour was
read from reference/spec/*.md, reference/examples/ and reference/oracle/.
Where the documents leave a choice, the stricter reading was taken (A3)
and is listed here with where it lives in `src/engine/`.

## Q1. What is a "row": trimming, blank lines, quoting
Fields are taken as written (no trimming: " 2026-09-01" is a bad date,
like Python's csv module would give). Blank lines are skipped (a file's
trailing newline is universal). RFC 4180 quoting is honoured on input;
output quotes only fields that need it. A quoted field spanning lines
takes the line where the record starts. (`csv.ts`)

## Q2. Amount text
Only plain decimal text is an amount: `-300.000`, `3.50`, `1200`, with
an optional sign. Thousands separators, exponents, `Infinity`, `NaN`
and surrounding spaces are `BAD-AMOUNT` (the FAILURE_MODEL names the
thousands separator as malformed). Currency codes must be three capital
letters. Rates must be positive. (`text.ts`)

## Q3. Problem codes and shape
The oracle has `problems: []` only, so the shape of an entry is not
witnessed. Taken: `{code, file, line, cite, reason}` with codes
BAD-HEADER, EMPTY-FILE, BAD-COLUMNS, BAD-DATE, BAD-AMOUNT, BAD-CURRENCY,
BAD-QUANTITY, BAD-VALUE, BAD-RATE, UNKNOWN-ACCOUNT, UNKNOWN-CATEGORY
(FAILURE_MODEL), UNKNOWN-CLASS, BAD-YAML, BAD-FILE, BAD-BASE-CURRENCY,
BAD-ACCOUNTS, BAD-CATEGORIES, BAD-CLASSES, BAD-SNAPSHOT-AGE,
NO-SNAPSHOT-AGE, BAD-POLICIES, UNKNOWN-POLICY, DUP-ID, BAD-DECISION,
BAD-STATUS, BAD-POLICY, BAD-CLOSES (FAILURE_MODEL). DUP-ROW is a
finding (warn), not a problem, and is produced in M0.3 from `dupNotes`.

## Q4. `snapshot_max_age_days` absent
Not defaulted (A2: declared, not inferred): problem NO-SNAPSHOT-AGE and
the config carries null; M0.3 makes holdings-based policies `unknown`.

## Q5. `classes`
The spec says classes are declared in policies.yml with a default list.
Taken: optional top-level `classes:`; absent means the default seven.
The serializer writes `classes:` only when it differs from the default.

## Q6. YAML line numbers
js-yaml gives no node positions. Taken: the line of each `- ` item is
found by scanning the text at the sequence's column (column 0 for
decisions, the `policies:` block's indent for policies); when the count
does not match the loaded items (flow style, odd layout) the line is
null and a cite would be `decisions.yml` without a line. The example
files cite exactly as the oracle (decisions.yml:2, 10, 18, 26).

## Q7. YAML scalars are text
Loading uses the failsafe schema: `value: 10` arrives as "10" and
becomes Decimal("10"); `date: 2024-10-01` stays text (the default
schema would build a JS Date). The serializer keeps numbers and ISO
dates plain so PyYAML reads them as before, and quotes anything else
that YAML could misread (`"yes: no"`, `"a, b"`, `"1"` as an id).

## Q8. Decisions and policies that cannot be read
A decision with a bad date, review_by or status is a problem and is
left out of the list (it cannot be judged); a policy with an unknown
type/measure/limit/match/band is kept with status `unknown` and the
reason (the spec says the verdict is `unknown`). Extra keys inside
`measure`, `match` or `band` make the declaration unknown; extra keys
on the policy itself are ignored but kept in `raw` for the serializer.
A cap/floor/kill whose measure is an amount (sum, holdings) with a
percent limit, or a percent (share, drawdown) with an amount limit, is
unknown ("do not compare").

## Q9. Serializer style
Policies: block top level, flow lists, flow maps inside each policy,
keys in the order id, type, title, measure, limit, match, band, period;
comments are not preserved. Decisions: the eight keys in the spec's
order, one block per decision, `[]` for none. Both round-trip the
example semantically (tests), not byte for byte (the leading comment
line is lost). Ledger, holdings and rates round-trip byte for byte.
`appendLedgerLine`, `appendHoldingLines` and `appendDecision` add to
the existing text without rewriting earlier lines (A6).
