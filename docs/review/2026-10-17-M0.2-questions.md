# M0.2 matcher — design questions (returned, not answered locally)

Each question names the reading the builder took. The rule applied
throughout: where ADR-0001 section 4-5 is explicit, its literal text is
implemented even where Sigma practice differs; where it is silent, the
reading that makes a wrong answer *loud* (a failing fixture or `unknown`)
is preferred over the one that could hide it. Every reading has a test in
`tests/test_matcher.py`.

## Q1. `Unknown` inside one selection
ADR section 5 says an unsupported modifier makes the *rule* `unknown`
(A4). The three-valued table of M0.3 (Unknown and False = False) would let
an unsupported modifier hide behind a sibling field that is False.
Reading taken: inside one selection `Unknown` dominates; a selection
with any unsupported feature is `Unknown` whatever its other fields say.
The three-valued logic applies only when the condition combines whole
selections (M0.3). Test: `test_unsupported_modifier_dominates_the_selection`.

## Q2. A selection that is a list of mappings
Sigma allows `selection: [ {a: 1}, {b: 2} ]` (OR of mappings). ADR
section 5 names only mapping selections and lists of strings.
Reading taken: `Unknown("... a list of mappings is not supported")`.
Non-string scalars in a keyword list are also `Unknown`.

## Q3. Keyword search over non-string values
ADR section 5: "any string value anywhere in the event". Section 4 says
non-string values compare as their JSON text under field comparison.
Reading taken: literal section 5 -- keywords are searched in string values
only; a numeric `EventID: 4688` is not found by the keyword `4688`, and
keys are never searched. A rule author who expected otherwise sees a
failing positive fixture (loud), never a silent pass.

## Q4. Event-side arrays and objects under a field comparison
Sigma backends usually treat an array field as "any element matches".
ADR section 4: "values that are not strings are compared as their JSON
text".
Reading taken: literal -- an array or object event value compares as its
compact JSON text (keys sorted, no spaces); so `Tags: alpha` does not match
`["alpha","Beta"]` but `Tags|contains: alpha` does. The alternative was not
taken.

## Q5. Numeric modifiers on non-numeric event values
ADR section 4 covers numbers under gt/gte/lt/lte only.
Reading taken: an event value that is a number, or a string that is
exactly a JSON number literal (`"2048"`), is compared as a number; a
boolean, null, array, object or any other string is simply not greater or
smaller than anything (False). The rule-side value must be a finite number
or the field is `Unknown`.

## Q6. `windash`
ADR section 5: "also match / for -". Sigma 2.x also lists en dash, em dash
and horizontal bar variants.
Reading taken: each `-` in the rule value matches `-` or `/` in the event
(every permutation, implemented as a character class); a `/` in the rule
value stays a `/`; the non-ASCII dash variants are not implemented.
`windash` combines with plain, `contains`, `startswith`, `endswith` only;
with `re`, `cidr`, numeric or `exists` it is `Unknown`.

## Q7. `re` sub-modifiers
ADR names `re` and `i`. Sigma 2.x also has `m` and `s`.
Reading taken: `m` and `s` are unsupported modifiers (`Unknown`); `i`
without `re` is `Unknown`. The engine is Python `re`, not PCRE; a pattern
that is valid PCRE but invalid for Python is `Unknown` with the error.

## Q8. `exists`
Reading taken: `exists: true` is satisfied by a key that is present with a
null value (presence, not non-nullness); the value must be a single YAML
boolean; `exists` takes no other modifier.

## Q9. `null`
Reading taken: `field: null` matches an absent field or a null value, as
the ADR says, and may appear inside a value list; `null` under any
modifier (or `windash`) is `Unknown`. A literal string `'null'` matches a
JSON null through the JSON-text rule of section 4.

## Q10. Modifier hygiene
Reading taken: a repeated modifier (`contains|contains`), two comparison
kinds together (`contains|startswith`, `gt|lt`), an empty field name, an
empty value list, a nested mapping as a value, a non-string field key: all
`Unknown`, each naming the field.

## Q11. Dotted paths
Reading taken: the exact key wins; otherwise the whole name is split on
dots and walked through nested objects only (array indices are not
addressed). A partial mix (`"a.b"` key holding an object with `c`) is not
resolved.

## Open item (not a question for this task)
A regular expression from a rule can backtrack catastrophically on a
crafted event (A7: logs are untrusted). Python's `re` offers no timeout;
the 1 MiB line limit of section 4 bounds the input but not the time. Left
open for the threat model (M2.2).
