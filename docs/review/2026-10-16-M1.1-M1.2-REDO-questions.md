## Fixed (commit `landed: M1.1+M1.2 REDO 2 ...`)

- **4.1 [high] private_key backtracking: confirmed, then fixed.**
  - Measured before the fix: a PEM header, a newline and `"a: " * 50` (150
    characters) took 25 s in one `search`.
  - The pattern now ends every PEM line at a newline, real or JSON-escaped
    (`\n`). A header value cannot hold a newline or a backslash, so each line
    can be matched one way only.
  - Four adversarial inputs, 54-100 KB each, are now in
    `test_m12_scan_time_is_linear`: name-colon runs, many header lines,
    escaped lines and URL colons. Each scanned in under 1 ms here.
  - Encrypted PEM (Proc-Type, DEK-Info), PGP blocks and escaped newlines are
    detected (mutant e).
- **4.3: placeholder checks look at the secret only.**
  - url_credentials checks the password, never the user name, and skips the
    distinct-character test. `testuser:<random>@` and a short real password
    such as `to` + `or` now count.
  - An `sk-` key needs digits and letters, any case, so lowercase-hex keys
    count.
  - Tests sit on both sides of the 8-distinct boundary (mutant f), cover
    letters-only `sk-` (g), and a jwt with sub 1234567890 but another name
    (i).
- **4.5: a secret inside `input_meta.path` is replaced by
  `[redacted:<kind>]`.** The path keeps its place, so SCOPE-PATH still
  works.
- **4.12:** an empty quoted first word (`'' x`) gives no head.

  mixed-case boundary is tested (mutant j).
- **F12 residual:** a tool_response or error that is null counts as absent,
  so the post gets `scan: "none"` and no secret_kinds.
- **F10 residual:** strings are scanned in document order, keys before
  values, so a capped scan really covers the start of the output, as the
  README says.
- **F9 residual:** a test now checks that hashing happens before the lock
