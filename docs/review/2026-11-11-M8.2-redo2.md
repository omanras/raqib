## Findings
**S1 (must-fix; Windows; F-3): test_redo2_f3_for_two_folders_a_case_apart cannot pass on windows-latest.**
- Line 177 `other.mkdir()` makes "my-tf" beside "MY-TF". On NTFS, which folds case, that raises FileExistsError before the skip at 178-179 is reached.
- Both Windows gate jobs will error.
- The questions file's "No test depends on the system that runs it except the link tests" and "F-3 MET" are therefore false (A8).

**S2 (must-fix; data loss; F-3): `--remove NAME.yaml` deletes a rule folder.**
- `place_of` strips the suffix (overlay.py:1335) and matches folders by that stem when there is no exact match (1345-1347).
- Case: the loaded MY-TF/ exists and no loose MY-TF.yaml does (for example the second run of `raqib rules --remove MY-TF.yaml`).
  - What happens: it returns "MY-TF" and deletes MY-TF/ with its overlay entry, without asking.
  - Why it is wrong: the person named a file, and the help says "the one whose id is NAME in any case" (cli.py:30-31, 283-285).
- The suffix also skips the package check (1338: `stem == name`). `--remove NET-TOOL.yaml` takes a folder NET-TOOL by folding.
- The several-matches refusal suggests `raqib rules --remove <folded[0]>` (1350-1352). In F-3's own case that is the loaded rule's folder.
- No test runs a suffixed NAME whose file is absent.

**S3 (must-fix; false statement; F-7 FOR): "on your records" misstates what it read.**
- (a) "read: every file (...)" is chosen on `cut` and `more_files` only (ruleform.py:1013-1017). It is printed beside "N file(s) not read: a link" or "the walk stopped at 10,000 entries: some files were not looked at" (998-1002).
  - Case: one readable trace plus a linked traces/x/ gives "...in 1 file; read: every file (...); 1 file(s) not read: a link".
- (b) With no file judged, `more_files` (the 20-file bound met) is never said (1003-1006).
  - Case: 25 files whose newest 20 hold host lines, with a path rule, gives "no file was judged ...; 20 host source files not judged". The 5 older traces are not mentioned.
- (c) A whole folder (a linked traces/ or host/, a linked or unreadable subfolder; 875, 880-881, 890) is said as "1 file(s) not read". A traces/ file holding host lines is called a "host source file" (998).

**S4 (must-fix; false statement; README): README.md:80 describes the superseded Remove.**
- It says Remove "drops its lines in `rules.yaml`, then deletes its folder". F-4 reversed that order (overlay.py:1396-1408).
- It says every rule refused at load "has a Remove button". A non-id place has none (app.py:4145).

**S5 (should-fix; must-fix if CI shows link_dir took the junction path; F-5, F-11): junctions inside a rule folder.**
- `os.walk(topdown=False, followlinks=False)` (overlay.py:1274) excludes only `DirEntry.is_symlink()`, so it walks into a junction. `_tree_plan` therefore meets the junction's contents before the junction itself.
- Same drive: the refusal reads "...\linked\precious.txt resolves outside ...". test_redo2_f5_must_not_touch (redo2:331, `match="is a link: nothing removed"`) then fails.
- Another drive: `os.path.commonpath` raises ValueError (1280). That is not an OverlayError, so it escapes `remove_rule` (1380). The terminal (cli.py:536) prints a traceback, and the window's `_do` (app.py:2212) lets it reach Tk with no words. Nothing is deleted in either case.
- Where the runner can make symlinks, `link_dir` (redo2:64-80) never makes a junction, so F-11's "tested where the job can make a junction" is unmet there.

**S6 (should-fix; words; F-4): a failed Remove's words.**

- If the overlay write fails, the remaining entry is not listed among "what remains".

**S7 (should-fix; vacuous test; F-5): test_redo_e6_a_link_below_rules_d_is_refused passes on its tmp path.**
