## The cost

The new ENVIRON rows hold whole statements, so an ordinary edit unrelated to the environment or to libraries will
  change them:
- Most fragile: doctor.py `checks`, the `lines = [...]` row holding all five checks' calls. Adding a check, or any
  argument change to any of the five, changes the row.
- Fragile:
    - host.py `start` and watch.py `start`, each with `notifier = notify.Notifier(...)` (any new or changed keyword at
    that call) and `return Running(...)` (any field added to Running). That is four rows.
- Moderate: autostart.py `default_folders` return (the whole dict comprehension), autostart.py `_sure`'s `value =
  next(...)`, and watch.py `open_page`'s `env.update(...)`.
- Stable: app.py `why = self.opener(url, environ)`, app.py `problem = display_problem(environ)`, and watch.py `root,
  why = notify.windows_root(environ, isdir)`.
- Also by design: any new statement in those functions that hands `environ` on changes ENVIRON. This is S-3's intent.
- `_bound_otherwise` is file-wide: one good-faith binding of a name `re` anywhere in a file (a parameter, for example)
  brings back every `re.compile` row of that file at once. That change is visible but noisy.
- On the other side, MENTIONS loses 31 rows that changed with every new regular expression or line of help, which is
  what S-4 was for.
- Risk for the Table to weigh: if unrelated ENVIRON changes (a new doctor check) become routine, a reviewer may learn
  to pass ENVIRON changes unread. S-1 relies on that reading.
