# M10.2 - questions (the watch writes its events; ADR-0011 Amendment F)

Where F-1 to F-9 left a choice, the builder did the nearest thing their words allow and asks here.

- Q1 (F-3, a tree's record line). A tree's event holds `evidence.seqs` (its HostTree line of the latest round)
  and that round's cites; both move every round, so a tree would be said again every round and "a round in
  which nothing changed writes nothing" could not hold. As built, a tree is said again at once when anything
  outside its evidence changes (named, benign, history, knocked, by), and its evidence alone waits for a beat
  (and the end), as F-3 rules for a blind spot's count and the lost-words note. Is a tree's evidence a third
  thing of F-3's kind, or should a tree's event carry its first line only?
- Q2 (F-3, the end). The last pass (at the finish) says a blind spot's count, the lost-words note and a tree's
  evidence again where they changed, as a beat does, so that the file read back equals `event.snapshot` of the
  final state (E2). Is the end a beat for these?
- Q3 (F-4, a line not written). Its number `n` is used all the same (a collector sees the gap), and the thing
  is not taken as said: the next pass tries it again, under a new number. So "not written" counts lines (each
  attempt), not things. Is that the count meant?
- Q4 (F-4, the holes' kinds). "event-not-built" (one per thing, its detail "<about>: <the key's problem>"),
  "events-unwritable" (once) and "events-failed" (a pass that raised, once). Like every hole of the watch they
  make the result INCOMPLETE. Is an events file that cannot be written meant to change the exit?
- Q5 (F-3, `--beat`). The default is 60 s or the round's interval if that is longer (`--every 120` alone is not
  refused); only a `--beat` given shorter than `--every` is a usage error. The window (raqib/app.py, out of
  scope) gets the same default from HostWatch.
- Q6 (an event's time on a later rev). A thing said again keeps its entry's own time (as `snapshot` does); the
  rev says it changed, not when. Should a later rev carry the time of the pass?
- Q7 (F-8). `raqib events FILE` exits 1 for a file that holds no event (rule 4: an empty log is a finding),
  though "every line is an event" is true of no lines. And an id said twice in one file (keyed by watch.host and
  id) is a problem of the line that says it again.
- Q8 (F-5, an act's knock). A knock of an act (V-1) names the copy on the tree it was knocked on
  (`source-finding:i`), else that tree ("tree:<word>"). A knock whose thing the watch does not know has no
  `knocked.for`.
- Q9 (F-9). X17 counts as "outlasted a beat" a watch whose start and end are more than two beats apart (a
  watch a little longer than one beat may end before its first heartbeat is due); the beat is read from the
  report's EVENTS line.
- Q10 (E6, the first lines). tests/test_host_sources.py's `len(lines) == 15` counts docs/GUIDE.md's "Watch
  the host" paragraphs, not the watch's first lines (GUIDE.md is out of scope and unchanged). The first lines
  are pinned, in order, by tests/test_first_run.py's FIRST_LINES, which follows; the events line is the third
  after the record and the state, the host's name the fourth.
- Q11 (F-8, outside Scope). README.md's Commands table must name every subcommand of the parser
  (tests/test_readme_top.py); README.md and docs/GUIDE.md are not in M10.2's Scope, so `events` is not in the
  table. The test now allows exactly that one missing name, and fails again once the table names it (then the
  exception is to be removed). The Table to add `events` to README.md's table and to docs/GUIDE.md's commands.
- Q12 (F-6). The host's name is read with platform.node() only: tests/test_rhythm.py's network guard forbids
  a `socket` import outside the modules that may reach the network, and platform.node() is the platform's own
  name of the machine (no lookup).


## REDO (ADR-0011 Amendment G), 2026-11-13: why this REDO is a STOP

- QR1 (G-11, E6: the guide's Commands table cannot name `events` by the documents alone). README.md's table now
  names `events` in its "the rest" row, and tests/test_readme_top.py (restored to main's) passes by its own rule:
  every parser command is named, and nothing else. The guide's Commands table does not name it. A row
  "| `raqib events FILE` | <the command's help text> |" in docs/GUIDE.md makes
  tests/test_readme_top.py::test_e3_every_sentence_of_the_old_readme_is_in_the_readme_or_the_guide_word_for_word
  fail: that guard allows the guide no piece that is not the old README's, except those its GUIDE_NEW lists
  (E-3's NEW_ROWS, which must also be README rows, and README's eight command rows are pinned). Making it green
  needs the guard changed (GUIDE_NEW gains the row), which the HANDOFF forbids. The Table's to rule: add the
  row to GUIDE_NEW (and say its words), or rule that README's row suffices. Also: README's "the rest" row with
  `events` was 125 characters (the limit is 120); its link now reads "[guide]" where it read "[in the guide]".
- QR2 (G-4, the suppressed test). The end's `result.suppressed` is tested on a NONE-SEEN host watch with
  overlay.suppressed replaced by a count (the report and the end both read that one function), not with a rule
  turned off in a real overlay: no host rule fires on the fixture's clean watch. The Table may want a fixture.
- Everything else of E1 to E5 and E7 is built and tested on disk (focused tests green); see the commit.
- Left open by this REDO (named, not done): G-12's "the host-name line among the first lines" is still pinned
  only through host.event_lines (host.start prints those lines right after the record and state lines; no test
  reads start's own output for it yet).
