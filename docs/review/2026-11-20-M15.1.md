## FINDINGS

### A. Ways the rules can be wrong

**F1 (should-fix). NET-ADMIN-PORT misses SMB lateral movement, and no evasion line says so.**
- Where: raqib/rules/catalog/NET-ADMIN-PORT.yaml:9-16; docs/GUIDE.md:417; docs/THREAT_MODEL.md:619.
- What is wrong: Windows' SMB client runs in the kernel. Sysmon event 3 for an outbound 445 connection names System
  (pid 4), not the process that asked for it. That covers `net use`, a copy to `\\host\share`, `sc \\host`, `schtasks
  /s`, `reg \\host` and PsExec-style tools. None of these is a process of the tree, so nothing is judged. This is the
  main sub-technique of T1021 (T1021.002).
- How I know: GUIDE.md:417 says "whatever program opened the socket (PowerShell's own included)". The evasion list
  names no system-side opener. The System attribution is known Windows behaviour; it was not measured on the rig.
- What would close it: an evasion line, plus "of the tree" in the two docs.

**F2 (should-fix). Another machine reached by its link-local address is excluded and not said.**
- Where: NET-ADMIN-PORT.yaml:10.
- What is wrong: SSH or RDP to a neighbour by its fe80::/10 or 169.254/16 address reaches another machine's login
  port. The rule excludes it by A-4. A-4 gives a reason for loopback only ("WSL, a forwarded port").
- How I know: line 10 reads "only a private address that is neither loopback nor link-local is judged (a machine
  reached on the internet, or over IPv6 by a global address, is not)". It names link-local only as part of the scope's
  definition, never as a way round.
- What would close it: an evasion line (MF2) and the Table's reason (QT-3).

**F3 (should-fix, A3). An unread Initiated or address is skipped with no note.**
- Where: NET-ADMIN-PORT.yaml:29-30; raqib/hooks/os_sysmon.py:253-257 and 605; tests/test_behaviour_rules.py:201.
- What is wrong: `initiated` null or `dest_scope` null meets `eq` and gives false, not unknown. The line is not
  judged, there is no partial note, and os-sysmon writes no silence line for the unread field. The fixture
  negative-not-admin.json holds a private-22 line whose Initiated is dropped, and the test fixes `notes == []`.
- How I know: the builder states it (C-4: "nothing fires, no partial"). HANDOFF E1 asked for null, so the builder
  followed the HANDOFF.
- Reach: real Sysmon always writes Initiated, so reach is low. The silence is still an A3 matter (QT-1).

**F4 (should-fix). PERSIST-AUTOSTART evasions that are not listed.**
- Where: PERSIST-AUTOSTART.yaml:9-14 and 36.
- What is wrong:
    - **Hooks paths not in normal form.** The regex needs exactly one separator between each segment and a leading
    separator. `...\Startup\.\x.cmd`, `...\Startup\\x.cmd`, `...\Programs\..\Programs\Startup\x.cmd` and a path
    relative to any folder above Startup (for example `Microsoft\Windows\Start Menu\Programs\Startup\x.cmd` with a cwd
    under `AppData\Roaming`) all miss. Sysmon's own paths are normalised, so the os branch is not affected.
    - **A file already in the folder changed in place.** Opening and writing an existing file is not a Sysmon file
    creation. A hooks Edit is caught; a Bash or program write is not.
  - **A hard link made in the folder.** I believe this is not an event 11; not verified.
    - **A write by a file tool of another name** (an MCP server's write tool, another agent's patch tool whose paths
    are inside its text).
    - **A write from WSL into /mnt/c.** The Windows-side creation belongs to WSL's file server, not to the tree. Not
    verified. A hooks Write with a /mnt/c path does fire.
- How I know: by hand against the regex `(?i)[\\/]microsoft[\\/]windows[\\/]start
  menu[\\/]programs[\\/]startup[\\/](?!desktop\.ini$)[^\\/]+$`. Line 13 names "a path relative to it" and 8.3,
  junction, symlink and mount-point forms; it does not name the cases above.
- What would close it: evasion lines (MF6), or a Table ruling that hooks paths be normalised.

**F5 (note). The regex has no anchor on the left, so it fires on any path that ends in the folder's segments.**
- Where: PERSIST-AUTOSTART.yaml:36; docs/GUIDE.md:416.
- Right to fire: another machine's Startup through an admin share (`\\host\C$\Users\...\Startup\x`), `\\?\` forms, WSL
  `/mnt/c/...`, the Default and system profiles, an offline image under a mount folder.
- False positives: a copy, mirror or dotfiles repo laid out like a profile (for example
  `C:\src\dotfiles\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\hotkeys.ahk`), and backup or restore
  tools.
- `C:\work\Microsoft\Windows\Start Menu\Programs\Startup\x` fires. That follows from the rule's own words, but the
  docs say "a user's or all users'", which is narrower than what the regex does.

**F6 (note).** On the builder's C-4 choice (a null `image` fires): I agree it is right. A missed act becomes a false
  positive, and that matches the engine's null semantics and NET-TOOL's handling of an unreadable parent. No fixture
  holds it: every NET-ADMIN-PORT fixture export contains the root's start, so a firing line with `image` null is never
  tested.

**F7 (note). What `dest_scope` calls "public" is wider than the word.**
- Where: os_sysmon.py:238-250.
- What is wrong: "public" means "not in PRIVATE_NETS". That includes 0.0.0.0, ::, multicast, broadcast, 240/4,
  198.18/15, documentation ranges, IPv4-compatible `::a.b.c.d`, 6to4 and fec0::/10. NET-ADMIN-PORT is unaffected; a
  later rule reading `dest_scope: public` as "the internet" would be wrong.
- 100.64/10 (carrier-grade NAT) is "private". The YAML description (line 20) and the os_sysmon docstring (242-243) say
  so; GUIDE.md:417 and THREAT_MODEL.md:619 do not. Tailscale-style overlay addresses in that range will fire.

**F8 (note). The capture's names are sound on real Sysmon.**
- Keyed by ProcessGuid, the names come from the process's own start over the whole pass (os_sysmon.py:623-625). They
  cannot be wrong; they can only be null.
- Keyed by pid alone (lines 626-630; exports with no ProcessGuid) they can be wrong in two ways:
  - a stale pid key kept across passes, when a new holder's event 1 was missed;
  - a pid reused inside one pass, overwritten in walk order before a late-sorted event 3 of the old holder.
- An agent cannot reach either: it cannot remove ProcessGuid from Sysmon's own records.
- "ssh started by git" can be borrowed only through a real or renamed git parent. The evasion at line 15 says so.
- `tree_copy` (host.py:820-823) carries `starts` across a reattach.

**F9 (note). `common.redact` cannot make the rule miss on any real path.**
- No secret class admits a backslash, except private_key's literal `\n`, which needs a PEM header in the path. The
  classes that admit `/` need their keyword and are stopped by the space in "Start Menu".
- The replacement `[redacted:kind]` holds no separator. A redacted user-name or file-name segment keeps its place, and
  the rule fires.

**F10 (note). Ports.** No fixture uses 23, 135 or 5900; the port list is held only by reading the YAML. Port 139 (SMB
  over NetBIOS) is not in A-4's list (QT-4).

**Inbound connections cannot fire.** `initiated()` returns True, False or None, and `eq: true` is type-strict
  (`_same`).

**`dest_scope` and `dest_private` always agree.** Loopback and link-local are subsets of PRIVATE_NETS, and "private"
  requires `dest_private`. I checked by hand: 127/8, ::1, 169.254/16, fe80::/10 (with zone), 10/8, 172.16/12,
  192.168/16, 100.64/10, fc00::/7, the IPv4-mapped form of each, and malformed input giving null.

**False positives a real desktop would produce (none measured):**
- NET-ADMIN-PORT:
    - git over SSH where ssh's parent is not git: `core.sshCommand` or `GIT_SSH_COMMAND` run through sh, or
    `GIT_SSH=plink` (TortoiseGit), to a LAN git server;
  - VS Code Remote-SSH;
  - scp, rsync, sftp, Ansible, Fabric or paramiko deploys to LAN hosts;
  - `Enter-PSSession`;
  - `Test-NetConnection -Port 445` while fixing a share;
  - user-mode SMB libraries;
  - SSH or RDP to a local Hyper-V, WSL2 or Docker VM at its 172.16/12 or 192.168 address;
  - Tailscale or CGNAT peers;
  - this machine's own LAN address (said);
    - a Windows service host knocked as an unknown agent (ADR-0014 Consequences), if it is given an os source: its
    domain RPC to 135.
- PERSIST-AUTOSTART:
  - per-user installers or "start at login" settings run by the agent;
  - profile mirrors or dotfiles repos (F5);
  - possibly a folder created directly in Startup, if Sysmon logs folder creation as event 11 (not verified).

**F18 (note).** README: two lines changed, `RULES (A6 fp_budget): 24` and `(24 rows ...)`. The HANDOFF says "the
