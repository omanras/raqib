## 3. Bugs and silent assumptions

### 3a. yamlite.py: accepted but read differently from YAML
- **Y1 [high] A quote inside a plain scalar swallows a comment.**
  - yamlite.py:116 opens a "quote" whenever `"` or `'` follows `-`, `:`, `[`, `{` or `,` (spaces skipped), even in the middle of a plain scalar. A ` #` after it is then kept as value text.
  - Examples:

    | Input | yamlite reads | YAML reads |
    |---|---|---|
    | `summary: a - "b # c"` | `a - "b # c"` | `a - "b` |
    | `regex: =["'] # note` | `=["'] # note` | `=["']` |

  - This silently changes `regex`, `glob`, `prefix`, `eq` and `summary` values, and nothing downstream catches it.
- **Y2 [medium] Plain keys are never type-resolved and never checked for ambiguity** (yamlite.py:211-217; flow keys :347-353).
  - All of these match `PLAIN_KEY` and come back as strings: `on:`, `yes:`, `true:`, `null:`, `1:`, `1.0:`, `.5:`, `017:`, `2026-10-16:`. PyYAML reads them as bool, None, int, float or date keys.
  - This contradicts yamlite.py:15-20.
  - Today it is contained only because every mapping the engine reads has a closed key set (engine.py:139-141, 157, 169, 219-221). That turns these cases into "unknown field" errors.
- **Y3 [medium] Unicode whitespace and control characters.**
  - yamlite.py:79 splits lines with `str.splitlines()`, the same pattern M0.2 S13 removed from trace.py. `\x0b`, `\x0c` and `\x1c`-`\x1e` start new lines, where PyYAML rejects these characters.
  - yamlite.py:84-90 use `str.strip()`/`rstrip()`, which also remove NBSP and U+3000:
    - `key: v ` is read as `"v"`; YAML reads `"v\xa0"`.
    - A line ` b: 1` is read as key `b` at indent 0; YAML reads key `"\xa0b"`.
  - Raw ESC, NUL and DEL inside scalars are accepted; PyYAML rejects them.
  - Nothing in the gate enforces ASCII for `raqib/` (M0.2 P6).
- **Y4 [low] The digit-separator guard (yamlite.py:33) misses an underscore after the dot.**
  - `1.5_0` and `1._` come back as strings. PyYAML 6.0.1 reads them as floats (1.5 and 1.0); YAML 1.2 reads strings.
  - These are exactly the 1.1/1.2-ambiguous scalars that yamlite.py:19-20 says are errors.
- **Y5 [low] Inputs PyYAML rejects but yamlite accepts** (my reading of PyYAML's scanner; not run):
  - `key: ]x` and `key: ,x` (yamlite.py:43, 231-233);
  - `[a,#b]`, read as `["a", "#b"]`, where PyYAML starts a comment;
  - `{regex: colou?r}`, where PyYAML breaks a flow plain scalar at `?`;
  - `--- foo`, read as the string `"--- foo"`. This one is contained, because it is not a mapping.

### 3b. Matcher semantics
- **MS1 [medium] `not` inverts "cannot evaluate".**
  - Every predicate that cannot be evaluated returns `False`: a missing field, an unplaceable path, or bad context. `not` (engine.py:203-205) turns that into `True`.
  - So `{not: {field: input_meta.path, outside: cwd}}` fires on every line without a path or cwd.
  - The docstring (engine.py:31-33) states that such predicates are false, but not that `not` inverts this.
- **MS2 [low] `prefix` and `glob` are plain string operations.**
  - `prefix` is a string prefix (engine.py:257), so a path rule built on it has the sibling-prefix error (`/work/p` matches `/work/p-secrets`). `outside` avoids that error.
  - `glob` uses fnmatch, where `*` also matches `/` (engine.py:258).

### 3c. Paths in outside / outside_any
- **PA1 [high, A3] The scope root is supplied by the watched session.**
  - SCOPE-PATH's root is the line's own `cwd` (SCOPE-PATH.yaml:13; engine.py:264-267), and capture takes it from the hook payload (capture.py:230-232).
  - A session started from `/` or `$HOME`, or a shell whose cwd moves, makes every path "inside".
  - test_rules.py:269 `("/anything", "/", False)` locks in the `/` case.
  - Claude Code did block `cd /tmp` in the `-p` run (M0.3-questions.md:122-125). The rule does not depend on that, and nothing reports a cwd change.
  - No fixture has cwd `/`, cwd `$HOME`, or a cwd that changes within a session.
- **PA2 [medium, A3] Normalisation is lexical only** (`posixpath.normpath`, engine.py:317).
  - A symlink inside cwd that points outside normalises to an in-scope path. Examples: `cwd/ln -> /etc` with a Read of `cwd/ln/shadow`, or `cwd/link/../x` where `link` is a symlink.
  - Neither engine.py:31-33 nor the questions file (:70-72) states this assumption.
- **PA3 [medium, A3] Unplaceable paths give `False` with no note** (engine.py:264-267, 277-281, 311-316).
  - Cases: a relative cwd, a missing cwd, an empty or non-string path, or any unplaceable root in the context list.
  - test_rules.py:270-272 lock these cases in.
- **PA4 [low] `~` and `//` give false positives, not silences.**
  - `~` paths are never joined to cwd. So `~/proj/x` is "outside" `/home/u/proj`, and a relative file named `~notes` is treated as absolute.
  - `normpath("~/../..")` yields the relative path `..`.
  - `//work/p/a` keeps both leading slashes and fires against cwd `/work/p`.
- **PA5 [medium, A3] Some file access never reaches `input_meta.path`.**
  - Capture fills `input_meta.path` only from `file_path`, `notebook_path` or `path` (capture.py:109-113).
  - Glob or Grep with an absolute or `../` `pattern` and no `path` carries no path, so SCOPE-PATH is silent. `negative-inside.json:8` records exactly such a Grep (`input_meta: {}`) as a clean negative.
  - Bash file access (`cat ~/.ssh/id_rsa`) and MCP file tools fall outside the tool allowlist (SCOPE-PATH.yaml:12).

### 3e. Summary rendering
- **SU1 [medium] Truncation can make an escape look in scope.**
  - Each value keeps only its first 77 characters plus "..." (engine.py:426-427).
  - SCOPE-PATH prints the raw, un-normalised path (SCOPE-PATH.yaml:9).
  - So `/work/example/<70 chars>/../../../../etc/shadow` renders as an in-scope-looking prefix. The seq citation is still correct; the summary text misleads.
- **SU2 [low] Template text is not sanitised.**
  - Values taken from the trace are sanitised (engine.py:424-425); the template's own text is not.
  - yamlite accepts raw control characters and `\x1b`/`\u202e` escapes (yamlite.py:44-45, 277-282). A rule file can therefore put terminal escapes or bidi overrides into every summary.
  - Without `summary`, the title is used as the template, and its placeholders are not validated (engine.py:87, 175-179).
- **SU3: no raw content can leak today.** Only trace fields can be referenced, and those are hashes plus `input_meta`. Up to 80 characters of `input_meta.path` are copied into findings.

### 3g. A6 budget logic: ways a rule can pass while over its budget
- **A6-1 [high] Rules that need context score as clean on the benign corpus.**
  - `fires()` runs the rule with the fixture's own context (fixtures.py:59-61).
  - Benign `.log` files and plain JSON lists have context `{}` (fixtures.py:38, 45), and `outside_any` returns `False` without context (engine.py:276-278).
  - So such a rule can never register a false positive on the benign corpus. `evaluate()` writes a note for the same case (engine.py:341-345); the runner counts it as a pass.
- **A6-2 [medium] Malformed lines in JSON fixtures can never fire.**
  - JSON fixtures are not passed through `trace.parse` (fixtures.py:39-48).
  - `run_rule` drops uncitable lines (engine.py:357).
  - So a malformed or misspelled line in a negative or benign file is never counted as a false positive.
- **A6-3 [medium] fp_rate is files that fired divided by files** (fixtures.py:71).
  - A rule that fires on every line of a benign session counts once.
  - The two real traces (test_rules.py:18-21) contain only `echo`, `ls`, `cd` and `whoami` plus session events, so no catalog rule can fire on them. They still enter the denominator, which lowers every rate from 1/4 to 1/6.
- **A6-4 [medium] Budgets were chosen against a corpus written in the same commit.**
  - questions.md:40-41 says "The budget was set to the measured routine rate".
  - The measured rate is 0.167; the budgets are 0.25 (NET-TOOL.yaml:7, DESTRUCT-CMD.yaml:7).
  - NET-TOOL.yaml:6 cites "package fetches", which neither the corpus nor the rule can see (see Q2).
- **A6-5 [low] `fp_budget: 1` is valid** (engine.py:152). A rule with that budget can never be over budget.
- **A6-6 [low] The default `benign=()` measures own negatives only** (fixtures.py:64). The benign corpus is applied only because the test passes it in.
- **A6-7 [medium, A7] SCOPE-PATH's 0/6 comes from sessions that never leave cwd.** The corpus has none of the routine reads outside cwd that a real session makes: `/tmp` scratch files, `--add-dir` directories, `~/.claude` files.
- **Observation: one "benign" trace raises high silence findings.** `blocked-calls-claude-code-2.1.301.log`, in the benign corpus, raises two SILENCE-HALF (high) findings (test_install.py:405-406).
