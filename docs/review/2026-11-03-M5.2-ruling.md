# M5.2 ruling (the Table, 2026-11-03) - on 721126a and its review (R1-R17, Q-1..Q-10)

Table checks: one commit over 721bb55; CI 41583717701 six jobs success
(api.github.com; R2 answered); scope clean; TLS context verified by the
Table (create_default_context, never off). Verdict: REDO. Rulings =
ADR-0003 Amendment A (the ADR is accepted; amendments follow).

- A-1 (R4, A4, A3) Recording never breaks relaying: every recording step
  on the request and response side runs under a catch-all that writes one
  RAQIB-SILENCE line ("record failed: <class>") and lets the bytes pass;
  request bodies over 64 MiB are relayed unrecorded with a silence line;
  a sender-chosen chunk size is bounded. Tests for RecursionError, a
  list-valued index, MemoryError-shaped failures.
- A-2 (R5, E3) `tool` and `tool_use_id` are bounded: printable ASCII, at
  most 64 / 128 characters; anything else is replaced by "sha256:<16 hex>"
  with `tool_hashed: true` on the line. Tests.
- A-3 (R7, R10, Q-1, Q-2) Sessions and pairing follow the CONVERSATION:
  the session id of a proxy line is the conversation key = sha256 over the
  model name and the canonical JSON of messages[0] (system/first message).
  session_start is written on a key's first sight; a response with no tool
  call (finish_reason stop / end_turn) writes `stop`; proxy shutdown writes
  session_end for every open key. Pairing is per key: a result closes the
  oldest open pre with that id IN ITS KEY; a result with no open pre in its
  key is a new seq (half). Ids repeated across conversations never cross-
  pair; numbered ids (Kimi-style) pair within their conversation. `--cwd
  DIR` sets the cwd on proxy lines (default: the proxy's own, said in the
  README). Tool names are written as sent; SCOPE-PATH's name list is a
  named hole for other agents (M5.4).
- A-4 (R11, Q-8) Results that predate the proxy in a conversation (seen in
  the key's first request with no pre) are written as ONE `history` line
  per key ("N tool results predate the proxy", cites) and not as halves;
  few-shot example calls fall under the same line. Named as fp source.
- A-5 (R13, Q-6) A re-sent result whose output hash differs from the
  posted one writes a RAQIB-SILENCE-class line "result for <id> re-sent
  with a different hash" (trace problem -> alarm); the original post stays.
- A-6 (R8, Q-10) The listener refuses a request whose Host is not the
  listen address or that carries an Origin header (403, one silence line);
  refused-request silence lines fold to one per 60 s with a count;
  THREAT_MODEL names: forged posts suppress real ones, browser senders,
  the API key travels in the clear to whatever binds the port (README: set
  base_url back when the proxy stops; prefer a fresh port per run).
- A-7 (R9, A3) capture.py with a missing/broken common.py writes its
  RAQIB-SILENCE line into the trace (argv log path) as well as stderr;
  doctor's common.py check is a later task (recorded).
- A-8 (R6, R14, R15) Connection: close is documented; HTTP/1.0 clients get
  no stale Content-Length when the proxy re-frames; an Upgrade request is
  refused (501 + silence line), never relayed stripped; TRACE and other
  unhandled methods 405 + silence line; an SSE `error` event, an abandoned
  stream and a non-100 1xx each write a silence line; README/THREAT_MODEL
  corrected (header values in silence lines, 127/8, --allow-plain-upstream,
  pre-M5.2 lines, how to watch a proxy trace: `raqib watch --log TRACE
  --no-install` if that flag exists, else the README says `raqib ui --serve`).
- A-9 (R17) The proxy keeps an in-memory index of open pres per key (trace
  read once at start, then appended); no per-request re-read.
- A-10 (R3) A golden hook line from 721bb55 is committed as a fixture; the
  test asserts the new line equals golden + `,"source":"hook"` placement.
- A-11 (R12) Tests for the listed paths. A-12 (R16) SSL_CERT_FILE/DIR noted
  in THREAT_MODEL; HTTPS_PROXY ignored, recorded (Q-9: no). A-13 (Q-4) a 5xx
