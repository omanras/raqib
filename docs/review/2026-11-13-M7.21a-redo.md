## 4. Item 3: BM-1 windows
- **Start:** the window is StartTraceW's return to 457 (see E2).
  - OpenTraceW's return to 474 leaves `_trace` unset. The session is still stopped; only the consumer handle leaks.
    - 412-418 is safe in practice: the real `atexit.register` is a C call, so a pending interrupt lands after the
    registration.
    - An interrupt landing between 418 and 419 leaves the hook registered with the flag False. A later `stop()` will
    not unregister it, so the Reader is held until exit, where the hook is a no-op.
- **Stop:** `stop()` unregisters the hook (612-614) before ControlTraceW(stop) (619).
    - A second Ctrl-C landing at the end of the unregister call, or in `properties()`, leaves a running session, no
    hook, and a `stop()` that does nothing (609-610, state "stopping").
    - The same happens when the stop fails ("may still run"): the hook is already gone. This is said, but nothing
    retries at exit.
- **No double stop:** the hook cannot run after a clean stop. If it did, `stop()` would return [].
- **Silent undo:** on the BaseException path, `_undo()`'s problems are discarded (409). After that, `refused` is None
  and `lost.why` reads "the reader is not started" (582).

## 5. Item 4: BM-2

  only in tests, and there `ownpid` is the real pid, so 183 stays a refusal.
- **Unstated assumption:** the "nobody else's" premise holds only if process N alone creates `raqib-net-N`, and
  nothing enforces it. `Reader(pid)` takes any pid (371-373), and so does `etw_read.main(pid=...)`. If a process Z
  builds `Reader(N)`, then process N starting its own reader stops Z's live session.
- **Tried exactly once:** yes (tests:804).
- **Said, but not as done:** the said line claims "stopped and the start tried once more" before the stop is tried
  (448-449). A non-zero rc from 451 is said nowhere (A5). Only a raise is said, at 452-453, and that branch is
  untested.

## 8. Silent assumptions and A3/A5 (item 9)
1. **A notice-only loss prints as no loss.** The last line shows `lost=events:0,buffers:0` (etw_read.py:109), and the
  reader keeps `why` None with notices > 0. BM-6 says either makes the counts unknown. A3.
2. **One word, two counts.** `other=` in the tool's last line is the sum of `other_ids` (etw_read.py:111).

3. **`said:` noise.** One `said: other:` line is printed per other id (etw_read.py:101-102), and the docstring calls
  them problems (9-11). On a live machine that is a dozen alarm-channel lines per run, against BM-5's intent.
4. **`unread` is not only the four ids.** It still holds "a NULL record" and "not read: X" (523, 527), against BM-5's

5. **The BM-2 field check cannot reach the retry.** Questions D (81-83) asks for "a new reader that is given the same
  pid number". That is refused with 183, which is exactly what test 788 asserts, and the tool has no CLI pid. The BM-1
  check "SIGINT in its start window" (77-78) is a millisecond window.
6. **Overclaim.** "Every change is an addition around them" (questions:8) does not cover the callback's reordering
  (542-545).
7. **Inaccurate test comment.** "0 is no pid" (tests:291) is false on Windows (the System Idle Process). It is

8. **Untested tool prints:** notices (etw_read.py:95-96) and beyond (103-104).

## Verdict: REDO
- **R1 (BM-1/E2):** the session begun at etwnet.py:443 (and 454) is not undone when the interrupt is raised at
  StartTraceW's return, before 457. No test has a session present when the StartTraceW-step interrupt arrives.
- **R2 (BM-1):** `stop()` unregisters the exit hook (612-614) before stopping the session (619). An interrupt in
  between leaves a session with no hook and an inert `stop()`. No test.
- **R3 (E3):** the tool's printing of `said` (etw_read.py:79, 92) has no test, and no tool test can reach the own-pid
  branch.
- **R4 (BM-2, A5):** "stopped" is said before the stop is tried (448-449), and a refused stop's rc (451) is said
  nowhere.
- **Also:** the false "Field-checked" comment (etwnet.py:70); undo problems discarded on the BaseException path (409);
  and, for the Table, the notice-only `lost=events:0,buffers:0` line and the partial-set trust in leftovers (688-695).
