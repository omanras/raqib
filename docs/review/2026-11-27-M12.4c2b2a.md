## Findings

1. raqib/winmanager.py:313-314, called at 380-381 for every state but RUNNING. Exit 0 is said as "exit: 0, stopped
  with no failure" for states 2, 3, 5, 6 and 7 too, so a starting, stopping, pausing or paused service is said to be
  "stopped". The runner tells START_PENDING with a win32 exit of 0 (raqib/winservice.py:683-686). If the manager hands
  that back unchanged, Raqib's own long start (T-2) will read "state: 2, starting", then "exit: 0, stopped with no
  failure", then "a start may be long". That breaks V-3's "nothing is said that was not read", and V-3 gives "0 as
  stopped" only for a stopped service. tests/test_winmanager.py:205 pins the wrong line for every state that is not
  RUNNING. Smallest change: keep "stopped with no failure" for state 1 only; in any other state that is not RUNNING,
  say "exit the system holds: 0" with no word, or say no exit. Change :205 to match. This is Q6's road.

2. raqib/winmanager.py:318-325 and 380-387. For a service of the name WITHOUT the mark, the runner's own words are
  still said: the exit 1066 with a number in EXIT_WORDS goes through winservice.told, 15 says "the whole refusal is in
  its text file: service.txt", and a starting service gets the T-2 line ("before the watch the runner checks its own
  code ..."). All three are written before the `if not ours` return, so a service that is not Raqib's is read as
  Raqib's runner. That goes against V-2: "nothing else is read as Raqib's". No test covers it: the unmarked test
  (tests/test_winmanager.py:146-166) uses only exit 0 and checks only for "ACTIVE" and "NOT AS INSTALLED". Smallest
  change: where the service is not marked, say the own number as a plain number ("N (0xN)") and leave out the
  service.txt line and the T-2 line. Add one test with no mark, 1066 with own 15, and state 2. This was not filed as a
  question.

3. tests/test_winmanager.py:389-435, the part most likely to be wrong. No test holds the three structures' `_fields_`
  (raqib/winmanager.py:96-111), and no test runs the real methods' own logic. Each of these would pass every test
  here: a field dropped (dwServiceFlags gone, so the struct is 32 bytes and QueryServiceStatusEx refuses it on
  Windows), two fields swapped (dwProcessId and dwWin32ExitCode), or making()/description() passing needed.value
  without room(). Today the code is right as text. What would hold it:
   - (a) an AST check of each `_fields_` list as text, the way DECLARED holds argtypes and restype;
      - (b) an AST check that making and description each call `room(` with `api.ctypes.sizeof(api.config)` or
     `api.ctypes.sizeof(api.description)`;
      - (c) optionally, a test that sets `System()._api` to a namespace of real ctypes (Structure, byref, sizeof,
     create_string_buffer and cast all exist on Linux) with fake adv callables, so the two asks, the cast, the LPWSTR
     reads and a NULL lpDescription returning None all run on Linux.
   All three are inside tests/test_winmanager.py.

4. tools/rig/check.py:1480-1483 and 1493-1546 (X53). The claim's name says "with no rights", but no key in FILE says
  who asked. A job that asks status as an administrator gets the same three answers, and X53 would be MET. The probe
  measured a caller with no rights, and this command must be shown under the same condition. This is MET as the
  HANDOFF words E5. For the Table's wiring: add a key the job writes (for example `asked-by` or `asked-elevated: no`)
  and have X53 read it. Until then X53's MET does not show "no rights".

5. raqib/winmanager.py:232-235 (`_said`). "Printable" here is Python's isprintable: controls, format characters (bidi
  marks included) and line separators become "?", which holds against breaking a line or forging `RESULT:`. But
  printable letters of any script pass through. A command or account read from the manager can therefore hold
  look-alike letters, so a path reads as "C:\Program Files\..." when it is not. tests/test_winmanager.py:104 asserts
  every line is ASCII, but no input holds a non-ASCII letter, so that assertion holds only for its inputs. Smallest
  change: escape non-ASCII as \uXXXX in `_said` (lines stay ASCII and the text can still be recovered), and add one
  test with a non-ASCII letter in the command. Or the Table rules that printable is enough.

6. raqib/winmanager.py:414-416. Any exception out of `_read` is said as "what the service manager answered cannot be
  read here". That includes a fault of the command's own (a write that failed, a bug in its own lines). It names the
  manager for what may not be the manager's. Smallest change: "an answer this command cannot read, or a fault of its
  own (%s)".

## For the field

The code was read as text and never run against a real manager. A run on Windows, asked as a user with no rights (not
  elevated), must show:
1. `ctypes.WinDLL("advapi32", use_last_error=True)` loads, and all six names resolve. QueryServiceStatusEx is the
  export with no W.
2. OpenSCManagerW(NULL, NULL, 0x1) gives a handle. OpenServiceW(.., "RaqibWatch", 0x5) gives a handle, or fails with
  exactly 1060 where there is none. Note how OpenServiceW answers for a service marked for removal: V says this is not
  measured, and the code says any number it gets with NOT KNOWN.
3. QueryServiceStatusEx(level 0, 36 bytes) returns TRUE. dwProcessId is not 0 while running and 0 when stopped.
  dwServiceSpecificExitCode reads 536870927 (0x2000000F, unsigned) with dwWin32ExitCode 1066 for 15. Never started is
  state 1 with 1077.
4. What dwWin32ExitCode reads in START_PENDING (the runner's long start) and in STOP_PENDING. This settles finding 1.
5. QueryServiceConfigW(NULL, 0) returns FALSE with exactly 122, and the bytes it names are between
  sizeof(QUERY_SERVICE_CONFIGW) (64 on a 64-bit process, by the code's own sizeof) and 8192. The second ask with
  exactly those bytes returns TRUE.
6. lpBinaryPathName is word for word what the job made: the quoting, the single spaces, no trailing space, no
  %variables% left. The code accepts only `"<path>" service run` and `"<path>" -I -m raqib service run`, matched
  whole.
7. lpServiceStartName (Q2): the code takes only "LocalSystem", in any case. Read it for a service made with no account
  named, the way the job and the later install make it.
8. QueryServiceConfig2W at level 1: the first ask (NULL, 0) returns 122 with the bytes needed. For a service with NO
  description, the code assumes 122 with at least sizeof(SERVICE_DESCRIPTIONW) (8 on 64-bit), then lpDescription NULL.
  Anything else is said as NOT KNOWN with what was answered. Also read the bytes a description of the job's length
  needs.
9. CloseServiceHandle returns TRUE for both handles, the service's first.
10. The lines as the job keeps them (a PowerShell 5 redirect is UTF-16; the reader is tested for it), and X53 MET at
  the three moments asked as a plain user (finding 4).

## Silent assumptions

- The runner's words, the text-file line and the T-2 line are said for a service that is not Raqib's (finding 2).
- "Printable" is taken in Python's sense (letters of any script kept) while the tests assert ASCII (finding 5).
- Any exception in `_read` is said as the manager's (finding 6).
- The place's list is said for 15 as if read (finding 9).
- The service's type is taken from QueryServiceConfigW. The state's dwServiceType is read and never used or said.
- For a service not Raqib's, its command, path and account are read and said (bounded and printable). V-3 allows it,
  but it was not filed.
- A failure of OpenServiceW for a service marked for removal (not measured) is said only as a number with no words, as
  NOT KNOWN.
- The description's two asks are taken to behave like the making's. V records 122 and the bytes for the making only;
  the builder lists this as field item 4 but not as a question.
- "No file is written": the code writes none, but importing winservice at the call can let the interpreter write a
  bytecode cache where the folder is writable. This is not said.
- X53: a repeated key is silently taken as the last one (inherited from `_run_lines`).
