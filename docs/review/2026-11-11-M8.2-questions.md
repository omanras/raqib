## Q-1 The class word of a person's rule (USER) needs raqib/rules/engine.py (out of scope)
Found: `engine.compile_rule` refuses any class not in `engine.CLASSES` ("class: must be one of
SCOPE|NET|..."), so a YAML with `class: USER` never loads; `engine.check_finding` also refuses a finding
whose class is unknown. Downstream nothing else depends on the word: the report (`report.rule_table`,
its RULES table), the page (`ui.py`, the rule table) and the window (`rule_items`' "class X" meta) print
`r.cls` as text; `host.py` filters only `HOST`. So USER is a two-line change in engine.py (add it to
CLASSES, with a comment) plus a test - outside this task's scope.
Built meanwhile: `ruleform.CLASS_OF` gives each form the nearest class the engine knows - program,
path, tool: SCOPE; host: NET - never HOST (A-6) or CROSS. Origin `user` already marks a person's rule
in every listing. Asked: add USER to engine.CLASSES (a later task with engine.py in scope), and then
switch CLASS_OF to it; or keep the nearest class.

## Q-2 fp_budget of a generated rule
Built: 0.1 (as SCOPE-PATH). The fixture runner measures the rule on its own negatives only (all must
stay quiet: fp_rate 0), so the number is what the report shows, not a gate here. Asked: 0.1, 0, or a
field of the form.

## Q-3 Places must be whole paths
Built: a place starts at /, ~, a drive or a UNC share; a relative place is refused ("not a whole
path"), because `under_any` would place it against the line's cwd (each project differently) and the
person rarely means that. `..` parts and `[ ]` sets are refused; `*` and `?` make a pattern (`glob`,
matched case-sensitively as written). A place written with ~ matches only paths written with ~: said
as an evasion in the YAML. Asked: allow relative places (meaning "inside each project")?

## Q-4 What the program form matches
Built: exactly NET-TOOL's three lines (Bash command_head / command_programs, host HostChild
command_programs, os process input_meta.image), with the names lower-cased as discover.image_name does
(Curl.EXE -> curl). On a Bash line the name is matched as written, so `curl.exe` typed in Git Bash is
not matched: said as an evasion. Asked: also match `<name>.exe` on Bash lines?

## Q-5 "K of M lines": what K counts
Built: K is the distinct (session, seq) pairs the findings cite in each file (a pre and its post are one
act), M the lines read; F the files read; "(N of them with a line)" the files with a firing. Bounds,
said in the line: the newest 20 .jsonl files under ~/.raqib/traces and ~/.raqib/host/sources, the last
4 MB of each, 20,000 lines in all; links are not followed; nothing is written.

## Q-6 The staging place
Built: `~/.raqib/rules.staging/form-XXXX/` (tempfile.mkdtemp), its parent checked by
overlay.fixture_file (no link) before it is made; removed after every Test and Add, and
`rules.staging` itself removed when empty. A crash between the two leaves a form-* folder that the next
Test or Add does not sweep (another window may be using it). Asked: sweep form-* folders older than an
hour?
