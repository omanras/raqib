## 2. Exit criteria unmet
- E3, the "once" half: the evidence is missing. In test_eventlog.py:804-805 the assert reads `assert len(problems) ==
  2 and sorted(...) == [...] or problems`. Python reads this as `(A and B) or problems`, so it passes whenever
  `problems` is not empty. B can never be true anyway: `p[1][:23]` is at most 23 characters and the literal "hole: the
  list was not s" has 24. Lines 806-810 check that each problem is present but never count them, and `log.not_built ==
  1` counts things, not list failures. A list failure said at every pass (4 problems over the 3 passes), or knock:2
  said at every pass, still passes. The code does it once (eventlog.py:270-274, `self.failed`); the test cannot catch
  a regression.
- E4, "checked before every append": the evidence is missing. The only test with a fragment (test_eventlog.py:845-852)
  puts a failed pass between the fragment and the next line. The previous build's code reset `self.whole = False` on a
  failed write, so it would also have mended here. The test cannot tell H-4 apart from G-6 (b). Grep finds no other
  test that touches `mended`. The code does check before every line (eventlog.py:171-178).
- E7: the section is there, but EVENT.md now contradicts itself. Line 110 (G-7 bullet) still says "A last line that is
  not whole JSON is a torn write". Line 132 (H-8) says "A last line with no newline is still being written: wait for
  its newline". THREAT_MODEL.md was updated; EVENT.md:110 was not.
- E8/H-9 ("each made able to fail"): not met for the per-entry-failure test, see E3.
- E1, E2, E5, E6, E9: met as far as I read them; the gaps in their tests are in section 9.

## 3. H-1: what the writer keeps, kind by kind
- READS (eventlog.py:47-57) against each builder (event.py:236-344):
    - finding: tree, pid, image, agent, path, named, run, round, cycle_rounds, cited_seq, cites, severity, summary,
    rule_id, class, kind, notice. Complete.
  - source finding: complete, including judged_on, history, pending, benign_note, settled (source_state).
  - note: text, live_tree, agent, path, run, round, cited_seq, cites. Complete.
    - tree: key (key[2] is the start), pid, image, named, benign, history, candidate_by, line_seq, cites, knocked.
    Complete.
  - hole: class, kind, detail, count, last, rounds, round, notice. Complete.
  - knock: body, round, status, called, event, title, limit_id, for. Complete.
  - Nothing outside the entry changes an event: `rules`, `record` and `facts` are fixed; the time is VARY.
  - I found no SILENCE key.
- What the pass adds is in the kept values. same_as goes through `more` (eventlog.py:353). "for" is popped by `row()`
  before `values()` (379-383). "by" is on the row as candidate_by (host.py:1930).
- Nested values: `_frozen` (eventlog.py:61-68) copies dicts, lists and tuples recursively, so a cite list or a key
  changed in place does not compare equal. Leaves are kept by reference only when they are scalars; a set or other
  object cannot reach the line anyway (JSON).
- The tree core (TREE_READS_CORE, eventlog.py:58) holds key, pid, image, named, benign, history, candidate_by,
  knocked. That is exactly what TREE_CORE says at once (everything but evidence), and it covers knocked, benign,
  history, named and by. Complete.
- Notes: grep finds three `self.notes[...] =` sites (host.py:3743, 3762, 3878), each followed by `notes_replaced.add(i
  + 1)`. The indexes are 0-based, so +1 is right. No other mutation of self.notes exists in host.py, and a dark note's
  dict is made together with its text and not changed later (host.py:1813-1823).
- SILENCE, low (notes): `notes_replaced` is emptied at host.py:1932, before the arguments of `ledgers` are evaluated
  (1935-1939). If `watch.lost_note(self.out)` or `self.notifier.holes` raises, the replaced places are lost and those
  notes wait for the next beat.
- SILENCE, low (trees): a tree whose name was read but whose `values()` raised is renamed "tree:?"
  (eventlog.py:331-332). Every unreadable tree shares that one name in `unbuilt`, so a second one makes no hole.
- Test E1 (a) (test_eventlog.py:609-653) checks the right direction: where the event differs, the kept values must
  differ.
    - A key reached through a nested path: caught, through replacing the whole top-level value and changing the first
    element of a list.
    - A key only some entries hold: caught only if one of the 8 longest pooled entries of that kind holds it
    (618-620). It asserts `seen >= 5` per kind, never per key, so which builder keys were actually exercised is not
    shown.
  - A value mutated in place: tested for list values only (643-652); `_frozen` covers dicts too.
    - TREE_READS_CORE is never driven. Dropping "knocked" from it would hold a tree's knock until the finish

## 4. H-2: the pairs
- `self.said` only grows (eventlog.py:187). Once the kept half has any line, the folded half stays folded; before that
  it is said unfolded. From the writer there is at most one flip (alarm true, then a later rev with alarm false and
  same_as). Kept halves come first (`first=kept`, 345-353). The writer never leaves an act without an alarm.
- MORE SAID, low (pairs failure): in a pass where `told_twice` raises, `same = {}` (host.py:1911-1922). Every folded
  half gets a new rev with alarm true, the next pass folds it again, and that adds a rev each time. For one round the
  act has two latest revs with alarm true. The events-failed hole is said only once for the watch's life, so later
  flips carry no hole.
- MORE SAID, low (write fails mid-pass): the kept half's line lands and the folded half's refold write fails in the
  same pass. Two latest revs with alarm true until the next pass. If the refold is "not built", `kept` stores the
  values and both alarms stay.

## 5. H-3 and H-4
- Guards: an entry's read, `more` and `values()` are inside the per-entry try (eventlog.py:309-318). Lists (305-324),
  trees (325-342), `_start` (260-265), dark (358-361) and changed (362-365) are each guarded. I found no exception in
  `ledgers` that ends the pass. The beat is in its own guard after the pass (host.py:1973-1975) and `next_beat` moves
  first (229-230), so no due beat is skipped. `_events_guard` keeps everything from the round. What can still end a
  pass is in host.py before `ledgers` (the arguments above); that was already so, with one hole for the watch's life.
- The end check costs, per line, the existing open/close plus about 3 lseeks and one 1-byte read. Read permission was
  already needed ("a+b" before too).
  - If the check fails it is an OSError inside the same try: "not written", counted, retried at the next pass.
    - If the file is unlinked between that open's check and its write (POSIX), the line goes to the unlinked inode and
    is counted as written. SILENCE, very low.
    - A writer that appends between the check and the write can still be glued to (window of microseconds; one host
    watch per home keeps Raqib itself out of it).
- Trace: file unwritable for rounds 1-3, a beat in round 2, writable from round 4.
  - Tick 1: start, n=1, fails (one events-unwritable hole).
    - Each later pass and the heartbeat try the start again first, then every thing; each attempt uses an n. The
    heartbeat in round 2 uses watch rev 2 and fails.
    - Round 4, in order: start (rev 1, n=K, time t0); trees rev 1 (first_seen); findings rev 1 (their at); source
    findings (kept halves first); hole:1 events-unwritable rev 1 (its at); notes (note_again plus new); knocks. The
    next heartbeat is rev 3. Nothing is said twice; n has the gap 1..K-1.
  - Losing heartbeat rev 2 matches H-4: a heartbeat is a point in time, and the gap shows in rev and n.
- MORE SAID, low: "the start before anything else" is attempted, not guaranteed. A failing `_start` does not stop the
  pass (260-265) or the heartbeat (215-220). After a failure on one line only (one open refused, e.g. a sharing
  violation on Windows), a thing or the heartbeat lands before its run's start, and EVENT.md:139-141 is then false.
- A failed later rev of a tree's evidence, of a blind spot's count or of the lost-words note waits for the next beat
  or the finish, not the next pass (G-2/F-3 hold them). At the finish there is no next pass.

## 6. H-5
- The finish writes the state, then the end, then the state again (host.py:4161-4164). The end cannot be written twice
  (`not self.events.ended`). In a normal finish it is not lost, unless `result()` or `overlay.suppressed` raises
  before `events.end` (as before).
- Second write fails: the end holds the first word, the report says INCOMPLETE. EVENT.md says this case.
- First write fails, second succeeds (MORE SAID, low, not in EVENT.md): `_write_state` clears `state_error` on success
  (host.py:4629). The end says INCOMPLETE (exit 3) while the report, and `result()` (host.py:4231), say the real word.
  EVENT.md's "what fails after the end" covers only the other direction. The end's write itself is never retried; a
  finished run whose end failed reads as "stopped or killed" (EVENT.md:141-142).

## 8. H-7 and H-8: what a sender's builder would still have to guess
- `snapshot(same=)` is as described (event.py:391-426) and the doc matches it.
- (a) Tailing: what to do when the file shrank or was replaced (EVENT.md says only "someone else"). The file is never
  rotated, so it grows without bound.
- (b) At least once: dedup by (watch.host, id) is given. Whether torn lines (or their count) are sent is not said.
- (c) Resume: that the cursor is a byte offset (lines of many runs, never rewritten) is implied, not said. What to do
  when the cursor is past the end of the file is not said.
- (d) Never a torn line: "wait for its newline" is true only while some watch runs. A killed watch's fragment is ended
  only by the next watch's first line, so with no next watch the sender waits forever. How long to wait is not said,
  and line 110 contradicts it.
- (e) A killed watch: "older than two of its beats" by which clock? If by the last line's `time`, a live run whose
  last line is a first saying (an old first_seen or at) reads as killed until its next heartbeat: MORE SAID. Two more
  cases are not said: a run with no start line at all, and a finished run whose end could not be written, which reads
  as killed.
- Statements not true of the code: "still being written" (fragment after a kill or a short write); "before anything
  else the watch could write" (section 5). The other H-8 statements hold as I read the code.
