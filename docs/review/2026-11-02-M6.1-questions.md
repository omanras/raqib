## Questions
- **Q-1 Which findings knock.** ADR-0005 says "a new finding of severity
  high". So SECRET-OUTPUT and the four silence rules knock, and
  DESTRUCT-CMD (rm, dd, mkfs), NET-TOOL and the SCOPE rules, all medium,
  are only printed, in watch.json and on the page. Should medium knock
  too, or should DESTRUCT-CMD be high?
- **Q-2 Two knocks for one silence.** When a live window closes, two
  notifications go out: SILENCE-LIVE closed, and SILENCE-GAP for the same
  gap once both lines are in one session (the demo shows both). They have
  separate rate-limit keys. Should SILENCE-GAP stay quiet when a live
  window covers it?
- **Q-3 Silence that is not capture loss.** A window opens whenever no
  line arrives for the limit: before the agent starts, while it waits for
  you after a stop, and after its session_end. That follows A3 and the
  batch SILENCE-GAP, which also counts waiting time. The rate limit keeps
  it to one knock per minute. Should a window after a stop or a
  session_end be marked, or not knock (M6.2's AGENT GONE)?
- **Q-4 Live silence is per trace, not per session.** If one session
  hangs mid-call and another keeps writing, no window opens. The hung
  call's SILENCE-HALF is pending, so it is not notified. It shows when its
  post arrives (SILENCE-GAP) or at exit. Add a per-session live window?
- **Q-5 An earlier trace inside the project.** Watch replaces those hook
  entries with the default trace outside the project, says so in a note,
  and leaves the old file alone. A --log inside the project is refused.
  The other choice was to refuse in both cases. Is moving acceptable?
- **Q-6 notify-send's argv.** The command built here never holds the text:
  /bin/sh reads it from the file and execs notify-send. notify-send takes
  text only as arguments, so its own argv, which /proc shows to every
  user, holds the cleaned text (event, project name, seq) for the moment
  it runs. ADR-0005 already treats the toast as world-readable. Keep the
  sh wrapper, or pass argv directly, since no shell parses it?
- **Q-7 Delivery blocks the poll.** Delivery is synchronous, with a 10 s
  limit. PowerShell starts in about 1 s, so each Windows toast holds the
  tail for about that long. No line is lost; a window may close late. A
  notifier that does not exit is left running, not signalled (A4), and
  each one is a hole. Move delivery to a thread?
- **Q-8 Re-run cost.** The rules re-run on the whole record list whenever
  lines arrive (O(n) per poll that has new lines; nothing runs on a quiet
  poll, which a test checks). That is fine for the traces seen so far.
  Per-line rules could later run on new records only; the aggregate and
  silence rules need the whole list.
- **Q-9 No scope.** Watch takes no --scope or --handoff (E1 names none),
  so DRIFT-FILES is "not-evaluated" and a clean watch ends INCOMPLETE
  (exit 3), never CLEAN. Should watch read `<project>/HANDOFF.md` when it
  exists, or take --handoff?
- **Q-10 New event names.** SILENCE-LIVE, TRACE-HOLE and RAQIB-SILENCE are
  watch events, not catalog rules: no YAML, no fp_budget, no fixture
  files. Each has positive and negative tests in `tests/test_watch.py`
  (lines closer than the limit open no window; RAQIB-SILENCE inside a
  path is not a marker). Should they enter the report's rule table?
- **Q-11 The page band.** "raqib/ui.py (serve hook only)" became one
  keyword, `render(..., band=None)`. Without a band the page is unchanged
  byte for byte (tested); make_server and the CSP are unchanged. M6.2
  builds the real band and the refresh.
- **Q-12 The installer is loaded by path.** watch loads
  `tools/install_hooks.py` from the checkout with importlib. M6.3's
  packaging must ship it, or move the API into the package.
- **Q-13 Opening the page.** Linux runs /usr/bin/xdg-open or
  /bin/xdg-open with PATH=/usr/local/bin:/usr/bin:/bin, so a browser
  planted in ~/.local/bin is not used. macOS runs /usr/bin/open. Windows
  runs %SystemRoot%\explorer.exe with the URL. None of them is waited on,
  and none runs under CI. Is explorer.exe acceptable, or should it be
  os.startfile (no program path, but the B-1 test bans the name)?
- **Q-14 A fold left at exit.** A count still folded when Ctrl-C comes is
  not sent as a notification. It is in the final report ("N still
  waiting") and in watch.json. Should it be flushed on exit?

New points met in the REDO:
- **R-1 The notify-send wrapper (B-5).** B-5 names it among the script
  files. It is not a file: the tree passes it inline (`sh -c` and the
  in-code constant), so nothing on disk can be swapped. Writing it to a
  file in order to hash it would add the check-then-run window that
  toast.ps1 and notify.applescript still have. That window remains for
  those two: a swap between the sha256 check and the program's read is not
  seen.
- **R-2 The epoch in the key (B-2).** The key is (epoch, rule, session,
  cited seqs, summary). The epoch keeps a finding read after a truncation
  from being merged with the same-looking finding of content that is gone.
- **R-3 History of a running session (B-3).** A finding is history only
  when every line of every seq it cites was in the trace at the start. So
  a pre from before the start whose post comes after the start gives a
  live, knocking finding (tested).
- **R-4 History SILENCE-HALF and SILENCE-OPEN (B-1 with B-3).** These
  settle like the others when a window opens, but never knock (notice
  "history: not knocked").
- **R-5 Heartbeat cost (B-4).** watch.json is rewritten on every poll, every
  0.5 s, with the whole inventory. Fine for the traces seen so far; a
  separate heartbeat file would be cheaper if the inventory grows large.
- **R-6 B-6 on Windows.** The HANDOFF.md root there is a drive path, which
  the engine reports as bad-context until M5.1b. So a Windows watch with a
  HANDOFF.md ends INCOMPLETE, not CLEAN. The CLEAN test is POSIX-only.
- **R-7 The port fallback (B-7).** It applies to an explicit --port too:
  any bind error on the requested port gives a free port and a WARNING.
  Before the REDO this exited 2. A port number out of range is still a
  usage error (exit 2).

New points met in REDO 2:
- **R-8 D-2 and the aggregate rules.** An aggregate finding (DRIFT-FILES,
  SCOPE-CWD-ROOT, SCOPE-CWD-MOVED) is settled when first seen. Under D-2 it
  is never handed over, so each time it grows (a new cwd, a new file
  outside the scope) it is a new finding. It is printed again; the older
  entry stays in watch.json with present false. These rules are all
  medium, so nothing extra knocks.
- **R-9 D-5 and the window.** D-5 speaks of a live *settling line*. A
  pending finding settled by the live silence window has no settling line,
  so it stays history when all its cited lines are history. Without that,
  every watch started on a trace whose last session never closed would
  knock that old SILENCE-OPEN about one gap after the start. A finding
  settled by a live stop or session_end is live (D-5, tested).
