## 2. `_own_code`, road by road

## Findings
1. **Low (a Table reading, or a small fix).** winservice.py:894-907 against 978-983 and 985-990; the words at 71-72
  and 882-883; test:1502-1513.
      - *What is wrong:* the first failure of a raising that is in flight at the check's end is written by the thread
     before 15 is set. ZC-1's order, and E1's literal test sentence, are not held for it. The outcome cannot change.
     No test covers it.
      - *What would make it right:* the Table reads U-3 as the main thread's lines and the words say so; or the window
     is closed. For example, the main thread holds `raise_lock` from just before `checked.set()` until after 907;
     nothing in that span takes `self.lock`. Either way, add a test whose held raising fails first on a refusal.
2. **Low.** winservice.py:886, 895-896 and 905 (with 458-464), against 807 and 827.
   - *What is wrong:* the steps between the thread's begin or the check's end and the number are not guarded.
     - A clock exception at 886 leaves `checked` unset and the thread running (new).
          - A BaseException at 895-905 (the clock, the head, `_form_said`'s repr) leaves 15 unset. A refusal then goes
       out as 23, or as 0 through 807, and the thread is never waited for or said. The lost join is new.
     - Unreachable in the field.
      - *What would make it right:* bring 886 under the try whose `finally` sets `checked`. Make the clock read and
     the head unable to raise (fall back to the NaN road). Have `_form_said` catch BaseException.
3. **Low.** winservice.py:978-983 against 1005-1007 and 1015-1017.
      - *What is wrong:* the count and the first's line are two separate holds of `raise_lock`. If the bound passes
     between them, the first failure is counted but never said, and the count's line says "after the first: at least
     0" about a first that is not in the file.
   - *What would make it right:* count, check `raise_late` and write the first line in one hold.
4. **Low.** test:1590 and 1606.
      - *What is wrong:* the comment "RUNNING only once the held call returned" is not shown. `m.points` records each
     status when its call begins, so the order would be the same without the wait.
   - *What would make it right:* log the held call's return and assert that RUNNING's entry comes after it.
5. **Nit.** winservice.py:890-894.
      - *What is wrong:* on the exception road `checked` is set only after `format_exc`, so a raising can begin after
     the check has ended, against ZC-1's "at once".
   - *What would make it right:* set `checked` first in the except clause as well.
6. **Nit.** winservice.py:1004-1006 against 911-916.
      - *What is wrong:* an end that raises before 1006 leaves `raise_late` False, so the thread may write after the
     check's line.
   - *What would make it right:* set `raise_late` in the 911 handler.
7. **Nit (Table, A3).** ZC-4's "as every exception's are" against winservice.py:745, 767, 833 and 637, which keep raw,
  unbounded words. Either a task for them, or ZC-4's words narrowed.
8. **Nit.** winservice.py:958-960: "whoever waits sees it stop" is not measured. Words such as "the check-point told
  stops here" would say only what is known.
