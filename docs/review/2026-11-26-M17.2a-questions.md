  `[executable, WORD]`; else exactly the list of before, byte for byte. `word(argv, stderr=None)`: None where the
  first argument is not WORD; `[WORD]` alone -> `main(["--serve"])` (SIGINT ignored, ends with its input); WORD

- `raqib/cli.py`: `from raqib import procevents`, and the first statement of `main` hands its arguments
  (`sys.argv[1:]` where none are given) to `procevents.word`; a non-None answer is returned before the output is
  set up or the parser is made. Nothing else of cli.py changed.
- `raqib/host.py`, `raqib/own.py`: not changed. `helper_started` already records the helper by
  `basename(sys.executable)` (own.started, from the Popen's args[0]) and, where `sys.executable` is a link of
  another basename, by the real file's name too; for a packed program both are the packed program's file, which
  is what a /proc sample reads. E2's tests hold it with a made-up frozen state (below).
- `tools/rig/pack.sh` (new): PyInstaller pinned 6.11.1 (checked; exit 2 otherwise), `--onedir --name raqib
  --collect-all raqib --exclude-module tkinter`, run inside its work folder so a checkout's own `raqib/` is never
  packed in place of the installed one; prints the packed program's path alone.
- `tools/rig/check.py`: `--packed FILE`, `read_packed` -> X47. `.github/workflows/rig.yml`: the Linux job only,
  one step after the autostart step: installs `pyinstaller==6.11.1`, packs, runs the packed
  `watch --host --rounds 4 --every 3 --no-open --no-page` with a home of its own (`$RUNNER_TEMP/packed-home`, so
  the plain watch's events file, read by later steps, is not touched), and the check step gets `--packed`;

## Questions

### Q1. The test of the modules that name procevents
The HANDOFF lets a test change only where it holds, word for word or by count, a line this task changes. The
builder took `test_e9_only_the_watch_imports_the_reader` for one (it holds the list of files naming the module,
and cli.py's new import is this task's line), extended its list and added the `{"word"}` assertion. Is that the
Table's reading, or should the entry reach the word another way (raqib/__main__.py and the console script are out
of the Scope; a word kept in cli.py itself would be a second copy of the constant)?

### Q2. The word's spelling
`__raqib_procevents_helper__` was chosen by the builder: no leading dash (no option a parser could take), no
command's shape, and unlikely ever to be typed. The Table may want another; it is one constant (`procevents.WORD`),
held by one test literally (`test_cg1_packed_...`) and by the spec's paragraph.

### Q3. What counts as packed
`sys.frozen` truthy (PyInstaller and cx_Freeze set True; py2exe sets a string, held by a test). A packer that does
not set `sys.frozen` (Nuitka marks a compiled program otherwise) would take the `-I -c` road, and its helper would
end as the packed one did before this task: the watch says it (two ends, then final), so it is no silence, but it
is not built for. Only PyInstaller 6.11.1 was measured. Should the road be keyed on more than `sys.frozen`?

### Q4. What the packed helper loads (BW-5's counterpart)
Not packed, the helper is given the watch's import path entry for entry and runs `-I`. Packed, it is given no path
and loads Raqib from the packed program's own folder; the environment is the watch's, inherited (as the plain
helper's is, which `-I` does not read). Measured once here that PYTHONPATH, PYTHONSTARTUP and the working folder's
modules are not loaded; what the packer's own runtime reads of the environment at its start (its own variables,
the library search path for the libraries it carries) was not measured. Should the packed helper be started with
an environment of its own (empty, or only what the packer needs), and is that to be measured first? docs/
THREAT_MODEL.md (out of this Scope) still says the helper is started "with the watch's own interpreter, always
`-I`"; the packed road is not said there.

### Q5. X47 and a refusal of the reader
X35 makes a refusal for want of a right of this user (EPERM, EACCES) n/a; the HANDOFF names X47's n/a as off Linux
and no file given only, so X47 makes every refusal MISSED, with its words. The rig's plain watch hears on that
machine as the runner's user, so a packed one refused there would be a difference worth a MISSED. Is that meant?

### Q6. How X47 tells the packed program in a tree
By the image of a tree's line in TREES SEEN equal to `PACKED_NAME` (`raqib`, pack.sh's NAME, any case). A tree of
another program named `raqib` would be MISSED too; on the rig there is none. X47 does not read the sources files
nor the count of the watch's own processes (PE_OWN), which was 0 in every run here: the helper's own fork comes
before its reader starts, so the reader does not give it; a helper started again would be given and left out by
the record (E2's test holds that). Is the tree line enough for the claim "its helper is not a tree of the
watch's", or should X47 also read the round's sources?

### Q7. X47 holds no floor of what was heard
X35 holds the processes that began against the stand-in's children; the HANDOFF's X47 holds the asks, the ends and
the trees only, and the rig's packed watch runs with no stand-in (here it said "processes that began: 0" with
nothing started, 48 with twenty short programs). Should the packed watch run beside a workload and X47 hold a
floor, as X35 does?

### Q8. The cost of a packed helper
A packed helper is the whole packed program: it loads Raqib's entry and every module cli.py imports before it
takes the word (34.4 MB here, against 14.9 MB for the plain helper, which imports the reader alone; 424 ms from
start to a stop). The plain `python -m raqib WORD` costs the same imports (44.4 MB). Amendment CG measured the
watch's peak memory with its children packed at 34 to 39 MiB. Is that cost accepted, or should the entry take the
word before cli.py's imports (that needs a packed entry other than `raqib.cli.main`, which the HANDOFF's road
does not name)?

### Q9. pack.sh's name
The probe named the folder `raqib-agent`; pack.sh names it `raqib` (so the packed program's image is `raqib`, as an
installed package's would likely be, and X47's PACKED_NAME follows it). The Table may rule the name of M17.2's
packages otherwise; pack.sh and check.py hold it in one place each, and a test holds that they agree.
