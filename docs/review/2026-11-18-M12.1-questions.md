## REDO 3 (ADR-0013 Amendment C, AC-2 to AC-11)

1. WALK_MAX = 200000 entries. Measured read-only on the builder's machine: 47065 paths in 0.87 s for its Python;
   the rig's install checked 2546.
2. PTH_MAX = 1 MiB: a longer `.pth` file is refused, read whole or not at all.
3. `.pth` lines by site.addpackage's own rule (skip `#`, blank, `import ` and `import<tab>`; rstrip), joined
   lexically against the sys.path entry, as site's makepath does. Every entry's `.pth` files are read, those of
   entries taken from `.pth` lines too; each entry is walked once.
4. A missing path stops the walk quietly at FileNotFoundError or NotADirectoryError, the folders above it
   checked: a missing entry, a missing `.pth` target, a dangling link under an entry. owned_by_root alone (AB-3)
   still refuses a path that cannot be read.
5. The unit's folder, systemctl and ss are checked as themselves (their links, the folders above), not walked
   below: walked whole, `/etc/systemd/system` meets masked units, links to /dev/null (mode 0666).
6. All four SS_PATHS are checked, the missing ones as far as they exist, because the watch takes the first that
   exists.
7. Over Raqib's own unit: `enable` then `restart`; a fresh install `enable --now`; both then wait START_WAIT and
   show every SHOW property. `--no-start` over Raqib's own unit asked ActiveState alone (REDO 4: the one show
   after the reload).
8. After the start, install said a NOT AS INSTALLED line but kept exit 0 where active, by E4's letter (REDO 4,
   AD-3: now exit 1, and the RESULT says it).
9. Status, not active and not as installed: `RESULT: INSTALLED, NOT ACTIVE, NOT AS INSTALLED` (exit 1).
10. `remove` needs systemctl in both branches; with none it is refused (exit 2), since nothing can be asked.
11. The rig's run checks the platform first (Windows facts stay n/a), then `--throwaway` (its reason written as
    `not_run`), then root. Facts with `not_run` and no platform count as Linux, so MISSED. id, useradd,
    systemd-run and journalctl are run by their whole paths.
12. X28's place is `ROOT_PLACE/raqib-x28-*/open` (parent 0755, place 0777); the check also requires the facts to
    show mode 0777 read back, a parent of uid 0 with no group or other write, and the place inside that parent.
13. X29's systemd word: `systemctl show raqib-watch.service --no-pager` whole, and `journalctl --no-pager -b -o
    cat _PID=1`, a line counted only where it names "raqib-watch" and holds one of JOURNAL_WORDS. An empty show,

## REDO 4 (ADR-0013 Amendment D, AD-1 to AD-7)

1. "systemd holds no unit of the name" is LoadState `not-found` with ActiveState `inactive` or `failed`, for
   remove, status and install alike. Install refuses anything else: the letter's active, activating and reloading,
   and also deactivating, refreshing, and a unit loaded or masked from any place.
2. Status with no file: `RESULT: NOT INSTALLED BY RAQIB, YET A UNIT OF THE NAME IS ACTIVE` where ActiveState is
   active, activating, reloading, deactivating or refreshing, else `... IS LOADED`; the LoadState, ActiveState
   and FragmentPath are said above it. A show that gives no answer, or no systemctl: `RESULT: NOT INSTALLED BY
   RAQIB, NOT KNOWN WHETHER A UNIT OF THE NAME RUNS` (exit 3). A file without the mark is not asked of
   (`NOT INSTALLED`, as before).
3. UNIT_MAX = 16384 bytes; status reads at most UNIT_MAX + 1 by the same non-blocking, regular-file-only read
   as the mark. The interpreter is the first word after the first `ExecStart=`; a file that is not ASCII, or whose
   ExecStart names no path of the safe characters, is "a different text".
4. Status takes the interpreter from the file, so a file naming another program in the interpreter's place, its
   text otherwise Raqib's, reads as installed; a test holds that, and the documents say it among what does not
   show.
5. The check after the reload (AD-3) is made under `--no-start` too; it is one show (LoadState, ActiveState,
   FragmentPath, DropInPaths, NeedDaemonReload), whose ActiveState also gives `--no-start`'s line that a running
   watch keeps its text. A show that gives no answer there is exit 1, not started (`how systemd loaded it NOT
   KNOWN`). NeedDaemonReload=yes is NOT AS INSTALLED in install's checks as in status's.
6. PYTHONHOME and PYTHONPLATLIBDIR count as set when present, even empty.
7. A `.pth` byte check refuses a UTF-8 BOM too (0xef is outside the bytes allowed); a file that passes is decoded
   as ASCII and split as before (only LF, CR and CRLF can be in it then, which every site splits alike).
8. `remove`, after the reload, asks the removed unit's ActiveState; a show that gives no answer is said and the
   exit stays; `failed` runs `reset-failed raqib-watch.service`, said, its failure said and the exit unchanged.
9. The rig reads the main process's /proc status right after the unit is waited for until active, its MainPID
   by `systemctl show --property=MainPID --value`. X29 is MET only with a pid, CapBnd equal to 0x80004 as a
   number (16 hex digits or fewer), Seccomp 2 and NoNewPrivs 1. CapEff is recorded, not judged.
10. JOURNAL_WORDS is `unknown|ignor|invalid|not support` (the last also matches "not supported").

## Q1. Choices made where the HANDOFF is silent
- Exit codes beyond E2 and E4's: an install that wrote the unit but whose systemctl failed is exit 1, and so is a
  removal whose systemctl or file removal failed. Each is said and left as it is. Exit 2 stays "refused, nothing
  written or touched".
- `remove --purge` checks the state folder before anything is touched. It refuses a folder that is a link, is
  not a folder, or is not owned by uid 0 (the last is beyond E4's letter, on the side of refusing). It removes
  by shutil.rmtree only where that is fd-based (`avoids_symlink_attacks`), so a link inside is never followed.
- A second install over Raqib's own unit replaces the file and runs `enable --now` as E2 says. A watch that is
  already running keeps its old unit until `systemctl restart raqib-watch.service`; the install says so. Should
  a replacing install restart it?
- The interpreter's path must also be a plain whole path (no empty part, `.` or `..`), besides E2's characters.
  The walk of ownership refuses a path that is not absolute.
- sys.path's relative entries (`''` or the folder `-m` starts in) are made whole against the install's folder
  and checked. So `sudo python -m raqib service install` run from a folder a user owns is refused; run it from
  `/`, or by the venv's `raqib` script.
