# M0.1 — questions and readings taken

Builder: cloud session, branch `claude/dawr-v0.1`. Each item is a design
question that was not answered locally; the reading taken is the most
restrictive one and is stated so the commander can overrule it.

1. **`tsconfig.*.json` in Scope vs. the scope guard.** The guard
   (`.claude/hooks/scope-guard.sh`) matches Scope entries as literal
   prefixes, so `tsconfig.server.json` was refused. Reading taken: the
   server build config lives at `server/tsconfig.json` (inside `server/`,
   which is in Scope) and `npm run build:server` uses it. The root
   `tsconfig.json` type-checks shared/, server/, client/, tests/ and the
   three config files in one program (`npx tsc -p tsconfig.json --noEmit`).

2. **Dependencies for later tasks.** `package.json` and the lockfile are in
   Scope only for M0.1 (later Scopes do not list them). Reading taken: every
   runtime dependency of the fixed stack is declared now: fastify 5,
   @fastify/static, better-sqlite3, zod, pino; dev: typescript, vite,
   @preact/preset-vite, preact, vitest, @playwright/test. No other library
   will be added later without a HANDOFF that lists package.json.

3. **better-sqlite3 prebuilt.** better-sqlite3 12.11.1 installed from its
   prebuilt binary on Node 22.22.0 (SQLite 3.53.2); no compile, so the
   `node:sqlite` fallback is not used.

4. **Versions chosen for a clean audit.** `npm audit` reported high/critical
   advisories for @fastify/static <= 10.1.1 (path traversal / route guard
   bypass) and vitest <= 4.1.10 (tinypool, @vitest/mocker). Reading taken:
   @fastify/static ^10.1.6 and vitest ^5.0.5; `npm audit` reports 0
   vulnerabilities (prod and dev).

5. **Playwright version.** Pinned exactly to 1.56.1, the release whose
   Chromium revision (1194) is the one preinstalled under
   `PLAYWRIGHT_BROWSERS_PATH`. CI runs `npx playwright install --with-deps
   chromium` for the same revision; locally it is never run.

6. **Listen address.** ADR §8 names PORT only. Reading taken: `HOST`
   defaults to `127.0.0.1` (most restrictive); the container (M3.2) sets
   `HOST=0.0.0.0` explicitly.

7. **Request ids.** A client-sent `x-request-id` is ignored; the server
   always generates its own (16 base64url chars) so a client cannot inject
   values into operator logs or audit rows.

8. **Static files.** Served with `wildcard: false` (only files that exist
   in `client/dist` at startup are routable, no filesystem lookups by
   arbitrary path), `dotfiles: deny`, no listing. Hashed `/assets/*` are
   `immutable`; everything else is `no-cache`. Every non-`/api` GET/HEAD
   falls back to `index.html` (history router, `/join/<token>` links).

9. **CSP.** `style-src 'self'` without `'unsafe-inline'`: the build emits
   one stylesheet and the client uses no inline style markup. If a later
   screen needs it, that is a new question, not a silent widening.

10. **Runtime assets.** `npm run build:server` runs
    `server/scripts/copy-assets.mjs`, which copies `server/**/*.sql|txt|json`
    next to the compiled JS, so M0.3 migrations and M1.1's bundled
    password list are found by `npm start` without touching package.json
    again.

11. **Logging options.** Fastify 5.12 deprecates the top-level
    `disableRequestLogging` / `requestIdLogLabel`; the app uses
    `logController` instead. Built-in request logging is off; one line per
    request is written by an `onResponse` hook with the route pattern (not
    the raw URL), status and duration.
