# M0.1 — questions for the commander (not answered locally)

Each entry: the question, the most conservative reading taken, where it
shows in the tree. Nothing here changes the exit criteria.

## Q1. `e2e/` is not in Scope, but E3 asks for one Playwright test
Scope lists `tests/` and not `e2e/`; CLAUDE.md "Layout" puts Playwright
specs under `e2e/`, and `tools/gate.sh` runs Playwright only when
`e2e/*.spec.ts` exists. Reading taken: the hello spec lives at
`tests/e2e/hello.spec.ts` (inside Scope) and `playwright.config.ts`
matches both `e2e/**/*.spec.ts` and `tests/e2e/**/*.spec.ts`, so
`npx playwright test` is green now (run by hand: 1 passed, Chromium
1194) and the gate's own Playwright step starts in M1.1 when `e2e/`
enters Scope. Vitest excludes `tests/e2e`.

## Q2. Exact dependency versions
The stack is fixed by name, not by version. Reading taken: exact pins
(no ranges) so `npm ci` is reproducible: typescript 5.9.3, vite 7.3.7,
vitest 3.2.7, preact 10.29.8, decimal.js 10.6.0, js-yaml 4.3.2
(+ @types/js-yaml 4.0.9), vite-plugin-singlefile 2.3.3,
@playwright/test 1.56.1 (the version whose Chromium build, 1194, is the
one preinstalled under PLAYWRIGHT_BROWSERS_PATH), @types/node 22.20.5.
vitest 4.x was tried first and rejected: npm 10.9.4 fails to resolve
its peer set ("Cannot read properties of null (reading 'edgesOut')").
TypeScript 7 and js-yaml 5 were not taken (new majors, untested here).

## Q3. JSX without @preact/preset-vite
The preset would pull Babel and prefresh. Reading taken: esbuild's
automatic JSX runtime with `jsxImportSource: "preact"` in both
vite.config.ts and tsconfig.json; no extra package.

## Q4. `toFixed` is banned in src/engine by the gate
decimal.js prints large or tiny values in exponent form from
`toString()`; the usual fix is `toFixed()`, which the gate forbids.
Reading taken: the Decimal clone sets `toExpNeg`/`toExpPos` so that
`toString()` never uses exponent notation; `fmt()` returns "0" for
any zero (including "-0.000") and otherwise `toString()`, which drops
trailing zeros like the oracle's amount strings ("120", "10900").
