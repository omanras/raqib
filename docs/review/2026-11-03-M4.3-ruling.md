# M4.3 ruling (the Table, 2026-11-03) - on the STOP 107f241 (Q-1..Q-13)

The STOP was right. Rulings = ADR-0002 Amendment J. Scope widened to
raqib/rules/tree.py (new), raqib/rules/trace.py, tools/gate.py, raqib/cli.py
(run_rules, check-rules), raqib/eval.py, raqib/report.py.

- J-1 (Q-1) HEAD-UNMOVED and INDEX-UNTOUCHED are CODE rules in
  raqib/rules/tree.py (the cross.py pattern): RULE_KINDS anchor, class
  DRIFT, medium, STATUS, FP_BUDGET 0.1, FIXTURES; gate, report, cli,
  eval and check-rules read tree.* as they read cross.*.
- J-2 (Q-2) trace.py in Scope: FIELDS gains git_head, git_index_sha256,
  git_error; strict_problem checks their shapes (40-hex/null, 64-hex/null,
  closed set/null).
- J-3 (Q-3) Not judged, no note: a session whose start line has no git
  keys (pre-M4.3, proxy, os) or "no repo" at both ends. Unknown (partial
  note): null for any other git_error on either side when the session has
  ok edits (a capture gap, A3).
- J-4 (Q-4, Q-5, Q-6) Start = the session_start line; close = the last
  stop or session_end of the session. A cwd that differs between start
  and close = unknown. Triggers = ok Edit/Write/MultiEdit/NotebookEdit
  whose path places under the start line's cwd; others are not triggers
  (hole named).
- J-5 (Q-7) The closed git_error set is accepted; the first failure is
  named; the three keys are always present on boundary lines.
- J-6 (Q-8, rule 5) A `gitdir:` path is followed only when it is relative
  and resolves under the cwd's drive/root and is not UNC (`\\`, `//`) or a
  device path; otherwise git_error "gitdir" and nothing is opened. No
  symlink is followed at any component (lstat check on `.git`, the gitdir,
  HEAD, the ref, packed-refs, index).
- J-7 (Q-9) Unborn branch = "no ref"; missing index = "no index"; a linked
  worktree's commondir is not read in v1 (hole named).
- J-8 (Q-10) One monotonic budget per git_state call (50 ms); each file
  read once with a size cap (1 MiB for HEAD/ref/packed-refs; index read as
  64 MiB + 1 bytes); the Windows tick and the deadline are recorded.
- J-9 (Q-11) v1 hashes the raw index bytes; "git status refreshes the
  index" is a named false-negative source for INDEX-UNTOUCHED; parsing
  index entries is a later task.
- J-10 (Q-12, Q-13) Both rules may fire on one session (two facts);
  unknown fixtures asserted by tests; the draft holes accepted plus J-4,
  J-7, J-9; common.py's docstring names git_state as its one file reader.
- J-11 README Seventeen (5 + 1 + 11); ADR note rows + "Ratio after M4.3:
  4 : 7 : 6."; kinds anchor=6; THREAT_MODEL paragraph.
