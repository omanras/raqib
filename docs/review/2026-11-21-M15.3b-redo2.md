4. [read] AUTOSTART.md:192-198 and THREAT_MODEL.md:933-939: "within one turn of six reads" says more than the code.
   It is true for one slow key (a user's Run, RunOnce or Startup folder) with at most six hives. It is false in
   three cases:
   (a) More than six hives. The users turn by `begin % n` (:566), so the hive just after the slow one in sorted
       order comes first only once every n reads.
   (b) Two slow keys of one user, its own Run and its own RunOnce.
       - RunOnce is then reached only in reads whose number is 1 mod 6 (:88, :785).
       - Those reads turn the users by `begin % n`. Where n shares a factor with 6, only some turns ever occur.
         With an even n, the turn is always odd.
       - Example. A machine has four hives: S-1-5-18, -19, -20, and the user's -21-... (the usual set as far as I
         know; not measured here). Sorted, the user's hive is last. Then S-1-5-18's RunOnce is never read whole,
         for good. It is said `in part` each read.
       - This is the builder's Q3.
   (c) A slow key inside the task or service step, where nothing turns (:646, :673). The same holds for the
       user's Startup folder, which always comes after the machine's (:587). The keys after the slow key are never
       reached first. [suspect: whether a plain user can make a task key slow.]
   - Smallest change (words, by hand): state the premise and the bound, and list (b) and (c) as levers that are
     left until the Table rules Q3.
