## Choices made locally (each is the Table's to confirm or overturn)

Q-1 Bounds. The catalog YAMLs declare no bounds and are not in Scope, so
the bounds are built into `raqib/overlay.py` (BOUNDS, AT_LEAST): k 1..100,
w 1..3600 s, r 1..1000 rounds, streak 1..100, live_window 1..1000 and never
below the rule's streak (a streak above the live window is refused too). A
"declared threshold" is an `eq` on a field of BOUNDS with a positive int,
declared once in the rule: today HOST-RHYTHM k/w/r and AGENT-DARK-LIVE
streak/live_window. NEW-AGENT's benign list (ADR-0008 Problem) is not an eq
value and is not editable here. The Table's later task: a `bounds:` block in
the YAMLs (and the loader reading it), which would replace BOUNDS.

Q-2 Which commands apply the overlay. `raqib watch`, `raqib watch --host`,
`raqib app` (every watch it starts loads the overlay afresh, so a panel
change applies to the next watch) and the `raqib rules` listing. `raqib
rules TRACE`, report, ui, suspect, eval and check-rules judge or measure
the catalog as its YAMLs declare it (the overlay is the watches', and
check-rules measures the package's rules against their fixtures, which a
changed threshold would break). Alternative: apply it to the trace
commands too, said in their output (report.py is not in Scope).
The CI pair (`raqib rules` + a `--set` / `--reset` pair) is a test that
runs `python -m raqib rules` in a child process
(tests/test_overlay.py::test_e2_the_ci_pair...), which the gate runs in CI;
.github/workflows/gate.yml is not in Scope and was not touched. If the
Table wants it as a workflow step, that is a one-line change there.

Q-3 "not judged by <id> (off): M lines". M = the lines the rule's gate
admits (fixtures.gate_of: its eq on tool and source; every line when it has
none). In addition the rule is run anyway on those lines (engine.judge,
whatever its status) and the report says "it would have fired F time(s),
citing C line(s)" - never a finding, never a knock. A rule off that needs
context the watch does not have (SCOPE-PATH without a scope) has its lines
counted and says that its firings are not counted. Project watch: counted
over the trace content read (re-counted at each judge, as the rules are);
host watch: summed over the rounds' lines and every source file's lines.

Q-4 The exit code. Read as "the overlay does not change how the exit code
is computed": a rule off judges nothing, so it neither raises an alarm nor
makes the watch incomplete. In the project watch report.py already treats
the engine's "disabled" note as not incomplete. In the host watch a rule
disabled in its YAML stays a "host-rule" hole (exit 3), as before; a rule
the overlay turned off is NOT a hole (it would turn every host watch with a
rule off into exit 3) and is said in the start lines, the state, the band
and the RULES OFF section instead. Alternative reading: the exit code
should be 1 when an off rule would have fired; that would make "off" not
off for CI, and is the Table's to rule.

Q-5 Refusals at load. A malformed file (not yamlite, wrong shape: a plain
off, a status other than "on"/"off", a non-integer threshold, an unknown
key) is ONE hole and nothing of it applies. In a sound file an entry that
names an unknown rule or field, a non-eq field, an eq that is not a
declared threshold, a value outside its bounds, or "on" for a rule its YAML
disables, is refused whole (its status too), said at the start of every
watch and in the report, and the other entries apply. Alternative: refuse
the whole file on any refused entry.

Q-6 "on" for a rule whose YAML says `status: disabled` is refused (A6: a
rule over its budget is disabled, not tuned live). The person can only
turn off what the package keeps on.

Q-7 `raqib rules` already exists (`raqib rules TRACE` writes findings).
TRACE is now optional: with no TRACE it lists and changes the rules; the
change flags with a TRACE, or the TRACE options without one, exit 2.
`--set`, `--threshold`, `--add` and `--reset` are mutually exclusive (one
change per run); `--json` prints the listing as JSON.

Q-8 rules.d. `--add FILE` validates with engine.load_rule and
fixtures.check_rule, the fixture paths relative to the file's directory,
and copies the YAML as rules.d/<ID>.yaml and its fixture files under
rules.d at the same relative paths; nothing is copied when anything is
refused, and a fixture path that exists there with other content is
refused. Every load re-validates every rules.d/*.yaml the same way
(fixtures relative to rules.d): a file refused there is said, not
dropped. The verdict must be ok (or disabled); the package's benign
corpus is not used (an installed raqib has none). An id may not be a
catalog rule's or another user rule's. A user rule of class HOST does not
join the host watch's own rules (host.RULES is fixed). There is no
`--remove`: a user rule is turned off with `--set`, or its file deleted by
hand (E2 names no remove).

Q-9 The engine's switch, unchanged. A rule off is compiled with `status:
disabled` and its source names the overlay ("the overlay <path> (off since
<t>; rule file <yaml>)"), so engine.evaluate's existing note reads "status:
disabled in the overlay ... (A6)"; evaluate is not touched (only
load_catalog is: `load_catalog(directory, overlay=None, user_rules=None)`;
without them the catalog is read exactly as before, which the gate and
check-rules use). The result is an `overlay.Catalog`, a list with
`.overlay`.

Q-10 host.py reads AGENT-DARK-LIVE's streak from the YAML (the eq on
input_meta.streak, STREAK_FIELD), as it already read the live window and
K/W/R; before, the "dark after a live tree" note used the constant
DARK_ROUNDS. The constant stays the default when the rule is missing.

Q-11 "N rules off" counts every rule that judges nothing: the overlay's
and those disabled in their YAML (none today), each with who turned it off.

Q-12 The panel (E4) is plain Tk: a "Rules" button in the header, the table
as text, a rule id field with On / Off / Reset, a threshold field and value
with Set, and "Add rule file..." (a file picker); the result or the
refusal is the band and the last line. Per-row checkboxes and the look are
M7.6b. The header's "N rules off" is the overlay as the next watch will
load it; a running watch's own is in its badges (band_items).

Q-13 `since` is the UTC wall time the entry was last written (by --set,
--threshold, or the panel), kept in the overlay file.

Q-14 The page (ADR-0008 decision 5) shows the overlay through the band's
"N rules off" badge only (ui.band_items, also under host_band); a page
section listing the overlay is left for the look pass.
