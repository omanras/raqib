## Findings
S1 (must-fix; R-3, I-6, A3) host.py:2789-2798. The knock is decided by the I-6 state of the tree whose feed
   is read first; the `moved` branch (2792-2794) never knocks; _poll_sources walks the sources in insertion
   order (2688), so the outer tree is usually first. (a) Outer tree A has spent its FIRST-FINDING; nested B
   acts; A's entry says "not notified: severity medium", B's moves in with "knocked once, by tree pid A: not
   notified": the act knocks zero times and B's first live finding never knocks. (b) A's copy is history,
   B's live (A there at the start, its first pass reading events after the start, Feed.history 767-768): B's
   entry is an alarm, never knocked, its notice "history: not knocked". (c) B's copy history, A's live: the
   `if history` branch (2784) runs before the move, so the act is a live alarm on A and history on B.
   test_redo_r3 covers only an outer tree with no earlier finding, polled first.
S2 (should-fix; R-1, E6, A3; the Table's) An agent inside a benign program's own process is now judged by
   nothing: discover gives each process to its nearest talking ancestor (discover.py:1949-1967); an IDE's
   extension host is the IDE's own binary, image `code` under Program Files or /usr (endpoints.yaml:192, 197,
   206); its tree is benign (host.py:1632), so its shell's curl, ssh and rm give no finding on either source.
   Before R-1 they were judged on its os or host source. THREAT_MODEL.md:553-556 names only the person's own
   programs.
S3 (should-fix; R-1 against K-10) HOST-RHYTHM still takes a benign tree's host children as beats
   (host.py:2210-2219) and its finding knocks (1799), so BENIGN_WORD "its acts are not judged" (287), the
   report's "(benign: X, not knocked)" (3045) and THREAT_MODEL.md:552-557 are untrue for a benign tree that
   cycles. The builder flagged it.
S4 (should-fix; R-2, A3) host.py:1179, 2735-2738, 2754, 2299. "Before the start" compares Sysmon's UtcTime
   with the wall clock read when HostWatch was built; the watch's own times are monotonic (1417, 1608). After
   a step back of D seconds (a time sync, a resumed VM, an agent allowed to set the clock) every act in the
   next D seconds is history: never knocked, never an alarm, never a beat. THREAT_MODEL.md:544-549 is silent.
S5 (should-fix; R-5, P-2; a question: the kernel's behaviour is not in the code) A Linux tree's start time is
   recomputed in every snapshot from /proc/stat's btime (discover.py:1093, 1295, 1318), which moves when the
   wall clock is stepped: every key (pid, image, started) then changes at once (host.py:450, 1660), each
   living tree is a new tree (NEW-AGENT again, a new file) and its old key is gone - P-2's symptom on Linux.
S6 (should-fix; tests, CI) Seven tests in tests/test_acts_judged.py leave a CountingFollow thread
   ("raqib-host-os-5888") in stop.wait(60) (line 146) after they return, into the Tk tests: from 416dfa4
   test_e4_a_quiet_tree_that_talks_again_... (224) and test_e3_a_source_of_lines_before_m78_... (434); added
   by the REDO test_redo_r2_... (535), test_redo_r4_with_the_connections_unread_... (587, both parameters),
   test_redo_r5_where_the_start_time_is_unread_... (606, 610). Two more end their thread by the gone round's
   stop.set() (host.py:2605-2608) without joining it. No reader thread is left.
S7 (should-fix; E2, R-7) The evasion line (NET-TOOL.yaml:15) does not say that parent_image is a basename
   only (os_sysmon.py:361: any program named git.exe that starts ssh.exe is left out) nor that git passes ssh
