## Design points settled (each says what the tree does now)
- Q-1 The round at open is `HostProbe`: `host.Worker` over the same reader `raqib watch --host` uses
  (`host.live_reader(catalog, 0.0)`), deadline `DEADLINE_FACTOR x --every` (2 x T). It writes nothing (no
  rounds.jsonl, no inventory.json, no state) and knocks nothing: it is one look, and its trees are listed
  with "listed, not knocked". The host watch's history rule (round 1 = there at the start) is HostWatch's
  own and starts at "Watch this host", not at the look. A reader that never comes back is READER LATE in
  the band with a hole line; when it comes, the trees are shown.
- Q-2 Band words. The look: READING HOST, READER LATE, HOST READER FAILED, NOTHING READ, NO AGENT SEEN
  (level incomplete, never clean: it is not a clearance), "HOST: N TREE(S)", HOST NOT READ (the probe
  could not start). The watch: ui.status of HostWatch's state, with WATCHING turned into WATCHING HOST, and
  into NOTHING READ when the last round read nothing (D-2; ui.status itself says WATCHING there);
  READER LATE and HOST READER FAILED come from ui.status (C-7 order); CRASHED or stuck (N s) from the
  aged heartbeat as M6.4 A-2; STARTING HOST WATCH; HOST WATCH FINISHED with the final report;
  HOST NOT WATCHED for a start refused (C-2/D-6) - the refusal text is a hole line.
- Q-3 The tree table is a fixed-width text in the Text widget (no ttk.Treeview): columns image (22), pid
  (8), named (22), first seen (25), acts (5), endpoints (rest). "named" is named / unknown / benign, with
  what the watch knows in brackets: act-root, history, new (it knocked), gone. "first seen" is the tree's
  first_seen in the watch, and for the look the time the look began. No command line, no cited record
  text, no executable path is shown (trees_of carries cites with text; the window does not show them; the
  page does).
- Q-4 "Watch this host" is one button that becomes "Stop host watch" while the host is watched; the
  project screen keeps its own Start/Stop. The tray's Stop ends every watch of the window; Quit and close
  as M6.4 over both: close hides to the tray while any watch runs and the tray is up, else stops both and
  keeps the report on screen; a second close quits; Quit waits for both workers (A-3).
- Q-5 `raqib app [PROJECT]` opens on the host screen always; PROJECT is preselected in the project field
  of "Watch a project" (and --log still applies to it only, A-10). `--every T` (0.1..86400, as watch
  --host, else exit 2) sets the host rounds; the look's deadline is 2 x T as well.
- Q-6 Exit code of the window: with both watches, 1 if either report is an alarm (or a watch failed to
  start), else the first other non-zero (the host's 3), else 0; both final reports go to stdout/app.log.
  A refused host watch counts as failed: 1, as a project watch that did not start in M6.4.
- Q-7 The tooltip: `tray.tip_text(N, K)` = "Raqib: N trees, K new", N = the host state's `now`, K = its
  `new` (findings of NEW-AGENT and NEW-AGENT-UNKNOWN). `Tray.set_tip` posts WM_RAQIB_TIP to the tray's
  own thread (PostThreadMessageW, as stop()); that thread does NIM_MODIFY of its own icon; a failure is a
  tray hole. The window calls it only when the text changes; back to "Raqib" when the host watch ends.
- Q-8 Ports: the host watch serves its page as `raqib watch --host` does (default port, else any free one
  with a warning badge); with a project watch on the default port too, the second gets another port and
  the warning. The host page's URL is shown read-only on the host screen; there is no "Open page" button
  for the host page (the project screen keeps its own).
- Q-9 The host watch's own lines (round lines, knocks) go to its LogBuffer and its tee (the terminal or
  app.log); the window shows its table, findings and holes, and the final report at Stop. A Log pane on
  the host screen is not built (M6.4's Log pane is the project screen's). Open: should it be?
- Q-10 Session gains `_open/_loop/_conclude/_close` (the four steps of `_work`, unchanged in order and
  holes) so HostSession is a sibling over host.start/loop/conclude/close; M6.4's Session behaves as before.
- Q-11 The window's docstring now names the host's reader beside doctor's `claude --version` as what
  runs (the live reader on Linux runs `ss` by absolute path only when /proc/net/tcp cannot be read, as
  `raqib discover` does); the A-11 sentence is kept.
