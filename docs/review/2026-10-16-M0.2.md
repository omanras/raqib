## 3. Silent assumptions, A3 silences, A5 citations

### A3: silences the new code produces itself
The questions file covers only the missing-session_start case (Q2). Every item below is new.

**S1 [high] An empty log produces no finding.**
- `findings([])` returns `[]`.
- CLAUDE.md rule 4 names "an empty log" as a finding, and A3 names "empty windows".
- The questions file does not raise this.

**S2 [high] Corrupt timestamps are swallowed.**
- Lines whose ts is missing, not a string, has no timezone, or does not parse are dropped from the gap check (silence.py:71-72; trace.py:48-58).
- `trace.parse()` does not count them as bad lines (trace.py:26 checks only session_id and seq), and no finding reports them.
- `test_e1_gap_ignores_lines_without_a_timestamp` (test_silence.py:82-86) asserts that a trace with two corrupted ts yields `[]`. A test now locks this silence in.

**S3 [high] Malformed records are swallowed inside `findings()`.**
- Records without a session_id or with a non-int seq are dropped (silence.py:46).
- `test_e4_malformed_records_are_ignored_not_fatal` (test_silence.py:169-171) asserts `[]`.
- The docstring says "trace.parse() reports them" (silence.py:14-15). That holds only if the caller goes through `parse()`, and no such caller exists.
- The `bad_lines` that `parse()` returns never become a finding anywhere in the tree.

**S4 [high] A session goes quiet after its first `stop`.**
- The first stop or session_end after a start closes the session for good (silence.py:90-91). A later session_start (resume or compact) does not reopen it.
- Claude Code's Stop fires at the end of every turn.
- So the sequence start, turn, stop, more tool calls, log ends produces:
  - no SILENCE-OPEN;
  - no SILENCE-HALF if the posts are present;
  - no SILENCE-GAP, because the function has no clock.
- A3 names "logs that stop". No test covers this.

**S5 [medium] Unknown phase values are silent.** A typo'd or missing phase still counts in the gap check, but it produces no finding and `parse()` does not report it.

**S6 [high] A duplicate seq within a session hides SILENCE-HALF.**
- `pres` and `posts` are keyed by seq with `setdefault` (silence.py:105, 107).
- The builder's own purity-test input shows the effect (gap-negative + half-positive, both session fixture-silence-0001, test_silence.py:149):
  - half-positive alone gives SILENCE-HALF [2], because toolu_s2 has no post;
  - combined, gap-negative's post at seq 2 "matches" it and the finding disappears.
- Capture derives seq from the log file itself (capture.py:122-146). A truncated or rotated log, a changed RAQIB_LOG, or two logs merged for analysis therefore restart seq within one session_id.
- The questions file does not mention this.

**S7 [medium] Time going backwards is not reported.**
- A negative gap (ts moving back in file order) is never a finding. In the same purity input, ts goes from 12:00:31 back to 12:00:00 and nothing is reported.
- A backward step followed by a normal line can also produce a falsely large forward gap.

**S8 [low] SILENCE-HALF matches by seq alone.** It ignores tool, tool_use_id and order. A post that appears before its pre counts as matched. So does a pre and post at one seq with different tool names, which A-2 allows (M0.1b Q4).

### A3: predictable false-positive classes not disclosed (relevant to A6)
**S9 [medium] A tool still running raises SILENCE-HALF.** `half-positive.json` looks exactly like a live trace read while seq 2 is still running, and `findings()` cannot tell the two apart. The questions file does not mention this.

**S10 [medium] Denied or blocked tool calls raise SILENCE-HALF.**
- A PreToolUse denial presumably leaves a captured pre with no post, which becomes a high-severity SILENCE-HALF. Examples: this repo's own `.claude/hooks/scope-guard.sh`, or a user refusing permission.
- I could not verify Claude Code's hook behaviour here.
- Q1 covers only false positives from SILENCE-GAP.

**S11 [low] No fp_budget is declared** for SILENCE-GAP, SILENCE-OPEN or SILENCE-HALF (A6; ADR section 4, lines 36-40).
- The plan defers budgets to M1.3 (DEVELOPMENT_PLAN.md:19-20).
- The rules are Python rather than the ADR section 4 YAML schema, because the HANDOFF directs it.
- Recorded here; not a builder fault.

### A5: citations
**S12 cited_seq does not name exact lines.**
- One seq covers up to two lines (pre and post), and more than two under S6.
- SILENCE-GAP [1,2] in gap-positive means "post of 1 to pre of 2", but the finding does not say so.
- A gap inside one long tool call cites [n, n] ("between seq n and seq n"). No test covers this.
- SILENCE-OPEN cites the seq of the last line in file order. After interleaving (pre1, pre2, post2, post1) that is 1, not the highest seq.
- All of this follows the ADR section 6 format. The builder also added `session_id` to findings (silence.py:63), a local change to that format (questions file lines 30-32).

**S13 [low] `trace.parse()` line numbers can drift, and some corruption is accepted silently.**
- It numbers lines with `str.splitlines()` (trace.py:18), which also splits on \r, \x0b, \x0c, \x1c-\x1e, \x85, U+2028 and U+2029.
- A torn or foreign line containing these characters produces `bad_lines` numbers that do not match newline-delimited line numbers.
- `read()` uses `errors="replace"` (trace.py:44), so invalid UTF-8 inside a JSON string is accepted and never reported.
- capture.py's own output is ASCII-escaped and not affected.

**S14 [low] SILENCE-OPEN can carry `ts: null`.** silence.py:96 uses `.get`, so if the last line has no ts, the finding's ADR section 6 `ts` is empty.

### Other silent assumptions and boundaries
**S15 [medium] `findings()` does not check `gap_seconds`.** No test covers any of these:
- `nan` silently switches SILENCE-GAP off, which is exactly the hazard `gap_seconds_from()` refuses (silence.py:35-37).
- 0 or a negative value flags every pair.
- `None` or a string raises TypeError at silence.py:75.

**S16 [low] The plan and the HANDOFF diverge.**
- DEVELOPMENT_PLAN.md:9-10 sets the M0.2 exit as "a 60 s gap ... yields a SILENCE event with start/end/seq range".
- With `>` (silence.py:75), a gap of exactly 60 s at the default yields nothing.
- The finding carries a single ts (the later line), not start and end.
- HANDOFF E1 (`>`) governs, but the questions file does not raise the divergence.

**S17 [low] The summary text can show the gap equal to the limit.** It rounds to 0.1 s (silence.py:78), so a 60.04 s gap reads "60.0s ... (limit 60s)".
