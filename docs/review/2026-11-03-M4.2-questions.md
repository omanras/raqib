Q1 Demand construct (engine.py). Today the engine judges one line at a time
(match) or counts distinct values per session (aggregate). E3 and E4 need
evidence on another line: before the trigger (E3), or after it and before a
deadline (E4). Proposal: an optional `require:`, allowed on kind demand
only and never together with aggregate:
  - `require: {before: <node>}`: a trigger line fires when no earlier line
    of its session (file order) matches the node. Cites the trigger.
  - `require: {after: <node>, until: <node>}`: each trigger is judged at the
    first later line of its session that matches `until` (the deadline). It
    fires there if no line between it and the deadline matches `after`. One
    finding per deadline, citing the triggers and the deadline line, with
    the deadline's ts.
  - Three-valued: if no evidence line is true but some evidence line cannot
    be judged, the trigger is unknown (a partial note), never a finding. A
    trigger whose deadline has not come (the trace ends first) is unknown.
  - A path op for "under raqib/ or tests/": `under_any: [raqib, tests]`,
    entries placed as outside_any places them (context root, else the
    line's cwd), unknown when the path cannot be placed.
  Accept this, or another shape (for example code rules, as silence.py has)?

Q12 E1 parse limits. These are implementation choices, listed so the Table
can rule on them:
  - `bash -c` / `sh -c` are read one level deep, including clusters (-lc,
    -ec) and options before the string.
  - A -c string holding an expansion ($VAR, $(...)) is code the parser
    cannot see. Is the list then absent (unknown), or is the string parsed
    as text?
  - Evasions that stay: zsh/dash/ksh -c, eval, source, and wrappers (sudo,
    env, xargs, timeout, nohup, exec, command, find -exec).
  - A program word that is not literal ($X, "$(which rm)", a glob such as
    r?, a brace expansion such as {rm,x}) makes the list absent.
  - Control words are skipped (if, then, else, elif, fi, while, until, do,
    done, !, {, }, time). for, case, select, [[ ]], (( )), function
    definitions, and unquoted here-documents with substitutions make the
    list absent.
  - A comment (#) ends the scan of its line.
  - Names are deduplicated in first-seen order, at most 64; more makes the
    list absent.
Accept these, or make them narrower or wider?
