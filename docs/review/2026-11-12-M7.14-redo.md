VERDICT
REDO. AJ-1's property fails in two SILENCE paths: a host-line finding that the watch without Sysmon knocks becomes
  history after a file restart, and a fast-failing follow loses a round of host lines. A MUST NOT TOUCH item is also
  breached: a tree known only from the channel now gets host lines, a changed test (ab10) accepts this, and the test

MUST-FIX (SILENCE)

R-1. host_from does not move when the tree's file restarts. host.py:3216, 3469; Feed.poll at host.py:1033-1035.
- What I read: an os tree's host-line history is `feed.ends.get(ln, 0) <= src.host_from`. host_from is the file size
  at attach and is never updated. At a file restart, Feed.poll resets ends, line numbers and history_bytes to 0, but
  host_from keeps its old value.
- Case: a tree attached again as os in round 5 (gone and back, an os follow that ended, or AG-1's reread), with
  host_from = 4000 bytes. In round 7 the per-tree file is truncated or replaced. In round 8 a HostChild for curl lands
  at bytes 0-400. Since 400 <= 4000, the finding is history: "history: not knocked".
- The watch without Sysmon resets its host Feed's history_bytes to 0, so the same line is live and knocks
  (FIRST-FINDING).
- The source-hole of the restart is still said, but the knock is gone, and "history" falsely tells the person the act
  was there before the watch.
- told_twice's docstring (host.py:698, "a file restarted joins nothing") is also false: the cache at host.py:705 maps
  old line numbers onto the new epoch's records and never checks fkey's epoch.

R-2. A follow that fails inside the round of its attach skips that round's host lines. host.py:3277 (`src.error is not
  None` -> continue), set at host.py:3241-3242.
- What I read: _attach (host.py:1990) runs before _host_lines (host.py:2069) in the same round. If the follow thread
  raises in between, src.error is set and _host_lines skips the tree, including `src.children |= ...`.
- Causes that can land in that window: parse_root rejecting the root, or last_seq/append raising on the first pass.
  The window is longer when the round still has other trees to attach.
- Next round the tree is attached again as host (failed_os). A child that appeared only in that one round's sample is
  never written. The watch without Sysmon writes it.
- The "source-ended" hole says the os source ended. It does not say the host's record skipped the round.
- Likelihood: low. It is still exactly the "whatever the follow missed" case AJ-1 rules on.

SHOULD-FIX

S-1. MUST NOT TOUCH breached: a tree known only from the channel gets HostChild and HostConnection lines (MORE SAID,
  and the words are false).
- Code: host.py:3264-3349 iterates `current`, and brief trees are in it (see host.py:2049, 2217). trees_of builds
  "children" and "remotes" from t["acts"] and t["talks"] (host.py:590-596), and for a brief tree those come only from
  the round's channel records.
- With also_host=True, _host_lines writes them as source "host", "the host's own record".
- Evidence: tests/test_round_channel.py:1286 asserts the msedge tree is unsampled (`not t.get("sampled", True)`), and
  the changed lines 1292-1293 now expect a "host" NET-TOOL note on it.
- The guard test tests/test_host_follow_returns.py:388-396 calls _host_lines with an empty `current`, so it would pass
  whatever the code does.
- The same path puts channel-only children of a sampled os tree into its HostChild lines in any round that reads the
  channel. That is more than the watch without Sysmon writes, under a host label (AJ-3, A5).
- Usually not an extra knock: these trees also have the os line, and the catalog's rules are medium.

S-2. A tree there at the start: its round-1 HostChild is live with Sysmon and history without it (MORE SAID, a knock).
- Without Sysmon, host.py:3345-3349 makes the round-1 lines of a tree there at the start history (`first_round ==
  history_round == n`).
- For an os tree, host.py:3469 uses host_from, the size before round 1's append (0), so the same line is live.
- Every tree is a talker with a child, so every agent there at the start has a round-1 HostChild. If that child
  matches NET-TOOL, DESTRUCT-CMD or a person's rule, the Sysmon watch sends a FIRST-FINDING knock (or a high knock)
  where the watch without Sysmon lists history.
- Likely in practice.
- The builder's question 8 has its premise backwards: the watch without Sysmon judges that line history, not live.
- This also breaks E1's "the findings of the host's record equal". No test covers it, because in rounds() kimi is
  first a tree in round 2.

S-3. A side effect of the same lines on the os feed (MORE SAID).
- host.py:3345-3349 now reaches os trees, because writes_host() is True for them.
- In round 1 it sets the os feed's history_bytes when the host lines are appended, usually before the first pass ends.
  on_pass's `count == 1 and feed.history_bytes is None` (host.py:3228) then never fires.
- Result: the first pass's os lines of a tree there at the start are no longer history. That matters for the silence
  and cross rules (host.py:3470) and for rhythm beats (host.py:2695).
- One act beat each is possible for a child started between the watch's start and round 1, since the sample's first
  round is skipped at host.py:2614.
- A false HOST-RHYTHM (medium): low likelihood.

S-4. R-3 restarts a bound that was right when the record numbers did not restart (said in the hole, but a knock lost
  compared with 2b8b746).
- Code: os_sysmon.py:702-705 resets top=None and since=T at every restart, including Z-5's clock step back
  (os_sysmon.py:935-937), where record numbers continue.
- Case: the follow reads up to record 900 at 10:00:00. A curl's event 1 is record 901 at 10:00:01. The round restarts
  at T=10:00:02. The next pass asks SystemTime>=T, so record 901 is never read. Before AJ-4 it was read by record id.
- Also: events from before the step, with ids <= top and times > T, are read again. That writes duplicate os lines and
  gives two "os" act beats that _once does not join (it requires a different source).
- FOLLOW_RESTART says the follows read from T, so it is not silent. A between-rounds child in that window loses its
  knock.

S-5. A follow attached after a restart starts at T instead of start_eff (question 9), and is not told so.
- Code: os_sysmon.py:696-699. FOLLOW_RESTART is added only when follows > 0 at the restart (host.py:2918-2926). A tree
  attached later has no line saying its follow starts at T.
- After a channel clear, start_eff would have read the events between the clear and T. The new follow never reads
  them.
- Only the round's hole ("what the channel logged from X to T that no round returned is not read") covers it, and it
  speaks of the rounds.
- Covered by AJ-1 for sampled children only.

S-6. R-1 when the old follow is still in a pass (host.py:3203-3222).
- The copy is shallow-correct: top level plus the dicts inside (dict(v)).
- If join(0.5) times out, the copy is taken while the old thread may still be adding top-level keys ("found",
  "by_guid", "by_pid" on its first find). Iterating .items() can then raise RuntimeError in the round thread. This is
  narrow.
- Children the old follow finds after the copy are not in the new tree. The "still in a pass" hole says so.

S-7. An os tree's host lines are judged by the whole catalog, not host_rules (MORE SAID, notes).
- One Feed with src_rules (host.py:3209) judges both line kinds. A host source uses host_rules (host.py:3185); a hooks
  tree uses a separate host_rules feed (host.py:3169).
- No line goes unjudged and none is judged by two feeds.
- No catalog YAML names HostConnection or HostGone, and every aggregate rule reads cwd or paths. So the catalog adds
  at most "could not judge" notes and not-judged counts.
- A person's rule that names HostConnection (and not HostChild) would fire only with Sysmon.
