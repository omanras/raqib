Rulings = ADR-0003 Amendment D.

- D-1 (R1, R2) engine.CLASSES gaining CROSS and cli.run_rules calling
  cross.findings are ratified: C-1 cannot exist without them. Ledger,
  Table: the Scope words contradicted C-1; rule: a new rule class lists
  engine.py (CLASSES) and cli.py (run_rules, check-rules) in Scope.
- D-2 (R3) The handoff Scope header must be exactly `Scope:` (the local
  scope guard parses that line only); the Table's annotated header
  disabled the guard for this task. Fixed in HANDOFF.md now.
- D-3 (R5) os file lines carry `input_meta.path` as hook Edit/Write lines
  do (redacted the same way); E1's "program names only" was about command
  lines. Recorded, no change.
- D-4 (R6, A3) C-5's fallback is read literally: with neither --cwd nor
  event 1's CurrentDirectory for the root, os lines carry NO cwd key and
  the SCOPE-CWD rules give their partial note. os-sysmon's own working
  directory is never written. Tests: --from on another machine (no cwd),
  SCOPE-CWD-MOVED partial not finding.
- D-5 (R8) Root pid reuse: `--root PID[:GUID]`; without a GUID the LATEST
  event-1 holder of PID in the export is the root and earlier holders are
  one silence line ("pid PID had N earlier holders; the latest is the
  root"); README:235 corrected; a two-holder test.
- D-6 (R9) Silence details go to stderr before the append attempt.
- D-7 (R10) An os-only trace whose processes are all depth 0 or 1 gets a
  note "CROSS-SOURCE: nothing to judge (every os process is the agent's
  own)"; README/THREAT_MODEL state both directions of C-2.
- D-8 (R11) Spans: the os side span is per os session; the agent side
  span is the union of hook/proxy sessions; a line is judged only inside
  the INTERSECTION of the two spans; lines before the first os line or
  after the last are not judged and get NO note (history before and after
  os-sysmon is not a gap); lines inside the os span with no agent line
  within W on either side are partial (as now). A long-lived project trace
  does not stay INCOMPLETE after one os-sysmon run. Tests.
- D-9 (R12) "Asked" covers a process AND its descendants: a process is
  asked if it or any ancestor below the shell was named in a shell pre
  within W (npm -> node, git -> sh, a forked bash). The MSYS fork shape is
  a named hole until the field test; THREAT_MODEL lists programs that
  spawn children. The matched negative gains a forked-bash pipeline.
- D-10 (R13, R14) Named holes: name-only matching (a renamed binary); a
  command_unread pre in the window makes the window partial (the note
  names the unread pre); a non-shell tool whose name holds a shell word
  and starts no process is an fp source; "cmd" also matches "command";
  a pre with unknown programs and no process at all stays a finding.
- D-11 (R16, R17, R18) One os line in NET-TOOL's and SECRET-OUTPUT's
  negative fixtures (the guard measured); `raqib check-rules` lists
  CROSS-SOURCE with its measured rate and cross.STATUS (ok | disabled);
  gate.py requires report.CROSS_RULES (no getattr default) with a red
  case; a YAML rule may not declare class CROSS (engine check + test).
- D-12 (R19) Tests for: torn-line repair, a root named only as parent, an
  event with pid but no UtcTime; --cwd validated as the proxy does.
- D-13 (R20, R21, R22, R23) Ruling text corrected to "per export"; the
  default-config claim dropped from synthetic.py and README ("Raqib names
