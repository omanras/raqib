## 3. Threads and locks
Lock order everywhere is `self.lock` -> `status_lock` -> `note_lock` -> `Text._lock`. Nothing takes them in the
  reverse order.
- The raising thread (925-929) gives up `self.lock` and `status_lock` before its `_note` (935-938).
- `_control` takes `self.lock`, then `status_lock`, then calls `_note` only on a failure (747-755).
- The main thread calls `_own_code` at 856, outside the `with self.lock` of 853-855. So the join at 948 holds no lock
  at all.

Answers to (a) to (f):
- **(a) START_PENDING after RUNNING, STOP_PENDING or STOPPED: excluded.**
    - RUNNING (858-860) needs `self.lock`, and the thread reads `checked` again under that lock (926) after 944 has
    set it. A raising still in progress holds the lock, so RUNNING is ordered after it, never before.
  - STOP_PENDING: `stop_asked` is set and told under `self.lock` (750-751) and read under the same lock (926).
    - STOPPED is told only after `done` (711-712, 827), and `stopped` is set under status_lock before it is told
    (721-725). Lines 930-931 then end the thread without counting.
- **(b) Two threads waiting on each other for ever: excluded.** The join holds no lock. A Stop that arrives during the
  join takes `self.lock`, tells STOP_PENDING and releases it. The thread then reads `stop_asked` and returns. The one
  exception is a system call or a write that never returns (finding 2).
- **(c) A check-point that goes down or repeats: excluded.** `point` is a local of the one thread (920-922), and
  `_own_code` runs once per run. After a failure the next number skips one (choice 2).
- **(d) The thread outliving `_own_code`:**
  - It cannot tell a new status: the gates in (a) stop it.
    - It is not excluded from writing a line where the join timed out. It may count and write its first-failure line
    after the check's line and after the count was read (935-938 against 952).
- **(e) An exception in the thread:**
  - It never ends the process.
  - Exceptions within 924-932 are caught and counted (933).
    - One from 921 or 935-938 ends the thread. Python's default hook writes the trace to `sys.stderr`, which in a
    service is the text file (848). But `_end_raising` says nothing of a thread that ended this way (finding 12).
- **(f) Two threads writing at once: excluded.** `_note` runs under `note_lock` (759). Each `Text.write` is whole
  under its own lock (608), and it catches OSError and ValueError (622). The trace at 896 is one write, made after the
  join.

## 4. T-1, T-2, U-3
- **T-1:** RUNNING still comes only after `_own_code()` returns True (856-860). The raisings are START_PENDING with
  nothing accepted (718).
- **T-2:** the wait told stays 60 s.
- **Refusal:** it still ends STOPPED with 15 and its one line (894-900, unchanged).
- **KeyboardInterrupt, SystemExit and GeneratorExit raised inside the check:** the inner `except BaseException`
  catches them (877) and they become the refusal. The `finally` runs normally, and test 1163-1176 still holds.
- **An exception raised by `_end_raising` itself inside the `finally`:** it leaves `_own_code`, and RUNNING and the
  watch still never happen. But the check's answer is never said, and the exit becomes the runner's own 23 (814-819).
  If it is an interrupt and a Stop was asked, the exit becomes 0 (795-799), because `self.code` is set to 15 only at
  894, after the `finally`.
- **U-3's letter:** U-3 says "the number is set before anything is written". The lines `_end_raising` writes (950-955)
  now come before that number on the refusal road (finding 1). No known road reaches this today: the interrupt is
  raised only while the watch runs.

## 5. ZB-3
- **In ZB-3's three cases, nothing changes the exit or the check's answer.** `_own_code` reads nothing of the raising,
  and `points_failed` feeds only the count line.
- **Two ways the raising can still change the outcome:** an exception out of `_end_raising` (finding 1), and a raising
  stuck in the system's call, which holds `self.lock` and status_lock with no bound (finding 2).
- **The number of lines is bounded:** at most three (first failure, did not end, count), or one (not begun).
- **The length of the first-failure line is not bounded or cleaned** when its words come from `_status` (731) (finding
  10).
- **The count excludes the first** (955: `failed - 1`). It can be too low where the bound passed.

## 6. Tests

- "Shorter than a beat" is shown at 1404-1410.
- "Nothing told between the check's end and its line" is shown at 1391-1395, but by the test's hold, not by the code
  (finding 4).
- "A Stop ends the raisings" is shown at 1413-1432.

**Would fail if the code were wrong:** a wrong number or wait, no stop gate, the end coming after the line, no join
  (very likely), a count that includes the first, a line per beat, the first failure not said, an exit changed, the
  check skipped, or the check-point not put in the structure.

**Would not fail:**
- `bound = self.beat` with CHECK_END_MORE ignored (finding 5);
- deleting 926's `self.stopped` or lines 930-931 (finding 6);
- a count of 0 (finding 7).

**Hangs and races:**
- Every new wait has a bound (WAIT = 10).
- An assertion that fails inside `walking` is turned into a refusal by `_own_code`. The asserts that follow still
  fail, so no wrong code passes.
- One check passes by timing: 1504 `not runner.raising.is_alive()` (finding 8).

**Windows:**
- Test 1362 sets `system._api` before the call, so `_win()` returns the stand-in and imports no ctypes. It works the
  same on Windows and Linux.
- The OSError texts and the NotBegun subclass are the same on both systems.
- A 10 ms beat on Windows' timer is about 15 ms, which is harmless.
- Test 1362 ties the field order to its own tuple, not to `_fields_` (finding 11).

## 8. Silent assumptions (A3, A5): for the Table, not the builder
- **The raising runs on a timer, not on the walk's progress, and has no bound of its own.** A check that hangs is now
  told as rising progress for as long as it hangs. A command that waits on the check-point would wait with it, and the
  text file says nothing until the check ends. Not measured, and said nowhere (A3).
- **When the raising works, the text file holds nothing of it.** A raising that never happened (a thread that died, or
  never woke) cannot be told apart in the text file from a check shorter than a beat. Only the system's own reading
  (X55) is evidence for ZB-1 (A5).

  by hand. Findings 1, 2 and 4 need a Table reading or a small fix. The field run (X55) and the gate on Windows are
  still owed.

## Findings
1. **Medium.** winservice.py:881-882, 894, 950-955; ADR-0013:1057-1058.
      - *What is wrong:* on the refusal road, `_end_raising` writes its lines before `self.code = EXIT_NOT_ALONE`.
     That breaks U-3's "the number is set before anything is written". An exception out of `_end_raising` ends the
     check as the runner's own 23 with its answer unsaid. An interrupt there with a Stop asked would tell 0 for a
     refused check, which is the case test 1226 guards for the check's own line. Unreachable today.
      - *To make it right:* set the refusal's number before any line of the raising is written, and make sure nothing
     out of `_end_raising` can replace the check's answer. Or the Table reads U-3's "anything" as the check's own
     lines.
2. **Medium.** winservice.py:950-951 (the line "the start goes on"), 925-929 against 858-860 and 712/721, 935-938
  against 952; test 1490-1509.
      - *What is wrong:* where the join times out because the raising is stuck in the system's call, the thread holds
     `self.lock` and status_lock. RUNNING or STOPPED then waits for it with no bound, so the start does not go on. The
     late thread may also write its first-failure line after the check's line, promising a count that never comes, and
     the count is read too early. The test releases its hold at the very line it waits for (1494, 1499), so it cannot
     show any of this. Its name claims more than it shows.
      - *To make it right:* words that say what is so (for example, "the start goes on once its call returns"), and a
     test comment that says the hold is released by the line. Or the Table rules on ZB-2's sentence as it stands.
3. **Low** (Table). Section 8: the timer-driven check-point over a hung check, and no evidence of the raising in the
  text file. To be named as not measured, or ruled.
4. **Low.** winservice.py:876-882 and 944 against 921-929; test 1329-1330, 1337-1338.
      - *What is wrong:* the code allows one raising that wakes between the check's return and `checked.set()`. ZB-4's
     "nothing is told between the check's end and its line" holds only because the test holds raising 3. What the code
     guarantees is "nothing after the raising is over".
   - *To make it right:* the Table reads the sentence that way, and the test's comment says so.
5. **Low.** Test 1491 and 1507 against winservice.py:947.
   - *What is wrong:* the test patches CHECK_END_MORE to 0.0, so a `bound` that ignores it passes.
   - *To make it right:* patch it to a small nonzero value and assert that the line states the sum.
6. **Low.** winservice.py:926 (`self.stopped`) and 930-931 are untested. Deleting 930-931 passes every test, and would
  write a false first-failure line after STOPPED.
   - *To make it right:* a test that tells STOPPED while a raising is held.
7. **Low.** Choice 1, the count line "after the first: 0", is untested.
   - *To make it right:* a case where exactly one raising fails.
8. **Low.** Test 1504: `not runner.raising.is_alive()` races `run()`'s return, because there the join timed out by
  design.
   - *To make it right:* call `runner.raising.join(WAIT)` before asserting.
9. **Low** (words).
   - 934 "the raising ended by": the thread goes on to its next beat.
      - 65-66 and 916 "one higher than the last": after a failure it is one higher than the last tried, not the last
     taken.
   - 77 "Those numbers are the candidate's": it follows a sentence that also holds the release's 17.7 and 19.8 s.
   - 869-870 "over before the line" and "neither ... depends": not so in findings 1 and 2.
   - *To make it right:* words that say what is so in each place.
10. **Low.** winservice.py:731 into 932 and 937.
        - *What is wrong:* the first-failure line carries `_status`'s raw `str(exc)`, neither cut nor made printable.
      An exception text with a newline breaks "one line".
    - *To make it right:* use `_exc_said` on the raising's road.
11. **Low.** Test 1370-1371 checks the positional order against its own tuple, not against `SERVICE_STATUS._fields_`
  (232-233). A field swap in the structure would pass.
    - *To make it right:* tie it to `_fields_`, as the winmanager structure tests do.
12. **Low** (A3). winservice.py:921 and 935-938 against 949.
        - *What is wrong:* a thread ended by an exception outside its try stops raising and leaves only the default
      hook's trace. `_end_raising` says nothing of how it ended.
    - *To make it right:* one line where the thread ended before `checked` was set.
13. **Nit.** winservice.py:871 against 873: `began` is read before `_begin_raising`, so the check's seconds in its
  line include the thread's start and, where it could not be begun, the writing of that line. To make it right, read
  `began` after `_begin_raising`.
