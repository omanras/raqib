## 6. The count
**MORE SAID**
- Two different (ip, port, protocol) never share a hash. Forms that fold to one server, as intended:
  - an IPv4-mapped IPv6 address and its IPv4;
  - "443", " 443 " and 443;
  - "TCP" and "tcp".
- Edge cases:
  - a bool port gives no key;
  - any non-empty protocol string is accepted;
  - empty fields give no key.
- **One address, many servers (unstated).** With the host name gone, two servers behind one address:port (a CDN edge,
  virtual hosting, a forward proxy) are one os destination. Main kept them apart whenever Sysmon named them. Host
  talks already did this on main. The holes state only the converse (YAML:82 "changes each turn... a CDN"; YAML:89
  "another address of one server"). Likelihood low-medium: an agent whose model API and the site its commands fetch
  share one CDN edge address.
- **One turn, two cycles: no.** rhythm_of is unchanged and counts per destination, and the os and host names stay
  apart. The through-rounds case is identical to main.
  - The (4,5) variant tells AU-3's merge (which gives 2 cycles) from the build (1 on each).
  - The (5,) variant passes under the merge too: it tests where the talks land, not the merge.
  - The streak's "any" rounds are untouched.

**SILENCE**
- Lines with and without the key for one server are two destinations. This is stated, and said, but only for os
  sources (section 5).
- IPv6 zone: str() keeps "%zone" (Python 3.9 and later), so one link-local server on two interfaces is two
  destinations. On earlier Python the address does not parse and the line keeps its old destination, which is said.
  Very low.
- UDP: the protocol is in the hash, so QUIC (udp/443) and tcp/443 of one model server are two os destinations, and the
  host's sample reads TCP only. "(address, port, protocol)" implies it, but no hole says it as a split. Low-medium as
  HTTP/3 spreads.
