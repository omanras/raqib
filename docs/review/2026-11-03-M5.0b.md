## Questions for the Table (not settled here)
- Q-1 An editor's integrated terminal. The benign Windows fixture has VS
  Code installed under `AppData\Local\Programs` with an idle terminal
  (powershell, no child), so act-root does not fire on it. When a command
  runs in that terminal, VS Code's pty host (`Code.exe`, ptyHost) is an
  act-root: user directory, not a shell, powershell -> git below it, no
  connection of its own (its network process is a sibling). The test
  `test_m50b_e3_known_false_positive_a_command_in_an_editor_terminal`
  builds it. Added as a third negative, act-root measures 1 of 3 = 0.333,
  over its 0.25 (`test_m50b_e4_check_fails_over_budget` runs exactly that).
  Should that shape be in the benign set? If it is, A6 disables act-root
  until the class narrows. The ways to narrow it are design choices, for
  example: (a) the act-root's parent is a shell (CLI agents start from a
  terminal; Kimi's parent was cmd), which misses agents inside an IDE;
  (b) no Chromium/Electron helper (`--type=` in argv) is an act-root; (c)
  editor pty hosts in `not_images`; (d) more benign exports, or another
  budget.
- Q-2 Linux places an act-root by argv[0]. A program run through PATH
  (`kimi`, argv[0] relative) and a node or python script under a home
  (`node ~/.npm-global/bin/agent`) are not placed. Both are evasion lines.
  Reading `/proc/PID/exe` changes `snapshot_proc` and the REAL fixture's
  format: M5.3, or a ruling here?
- Q-3 `not_images` includes terminal hosts and multiplexers (mintty,
  tmux, kitty, ...) as "system images" (R-8). Confirm, or narrow it to OS
  images only.
- Q-4 Recent talk raises nothing by itself (R-5). Should recent talk to a
  catalog endpoint with no candidate and no act-root be an alarm (A3: talk
  with no owner seen), and should a DNS row for an IP a known owner talks
  to be listed anyway?
- Q-5 The dashboard's discover tab (`raqib/ui.py`, outside this Scope)
  shows the act-root alarm line and the holes, but not the act-root and
  recent-talk entries. Is that a later Scope?
- Q-6 The Moonshot hosts are in the catalog (R-3): api.moonshot.ai,
  api.moonshot.cn, api.kimi.com, from the vendor's documentation, not
  re-checked offline. Confirm. B-10's blind test is kept by running with a
  `--catalog` copy without them.
- Q-7 The first numbers for the anchor: candidates on 2 of 2 benign
  desktops (explorer talking, as in the field test; the VS Code extension
  host running git; Firefox). B-8 leaves the anchor without a budget. The
  number is printed by `--check` and is not a gate. Record it, or set a
  budget?
