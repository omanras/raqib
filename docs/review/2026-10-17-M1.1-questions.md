# M1.1 — questions for the commander (not answered locally)

Each entry: the question, the most conservative reading taken, where it
shows in the tree. Nothing here changes the exit criteria.

## Q1. Where import and export live
E2 needs per-file inputs, a paste panel, copy and download, but the seven
screens' content belongs to M1.2-M1.4. Reading taken: an eighth entry in
the navigation, **Files** (`#/files`, `src/ui/files.tsx`), with one card
per file (count, problems, import, copy, download), "Import several files"
(matched by exact file name) and the paste panel. The side bar always shows
the five files' counts. Settings (M1.3) still gets "export all".

## Q2. What an import refuses
E2 names the wrong header. Reading taken: refuse what the CLI could not
read at all, with the reason; import everything else and let the engine
judge it. Refused: a CSV whose first line is not exactly its header (the
expected header and the first line are shown), an empty file, a file of
64 MiB or more, bytes that are not UTF-8 (decoded strictly: a byte is never
replaced, since the CLI would report BAD-ENCODING), YAML that does not parse
or has the wrong top level (BAD-YAML, BAD-SHAPE, FILE-EMPTY). Accepted: any
file with row or policy problems; they show as problems and findings. The
paste panel keeps the text, so a refused paste can be fixed and retried.

## Q3. Absent and empty files
A file never imported is absent (`null`, no IndexedDB record); the engine
treats it as FILE-MISSING (rates.csv: an empty table). With no file at all
the app shows the empty state (the five files explained, "Load the sample
household", "Import your files") instead of a red board, and the problem
count is hidden there.

## Q4. Two tabs
Every change writes the whole file at once; the last write wins. After a
successful write the tab announces it on a BroadcastChannel (`qayd`), or,
without one, through a `storage` event on localStorage key `qayd:changed`.
The other tab reloads all five files from IndexedDB and shows a banner
saying another tab changed the household. A memory-only tab announces
nothing (no other tab can read its memory).

## Q5. IndexedDB that fails later
If IndexedDB opens but a write is refused (quota, eviction), the tab keeps
its state in memory from then on and shows the "nothing will persist"
banner; no retry. An open that does not answer within 4 seconds counts as
unavailable.

## Q6. Arabic strings now
E4 allows placeholders. Reading taken: the shell's strings are translated
already (`src/i18n/strings.ts`, the type requires every key in both); M1.3
completes and reviews them. Counts in Arabic are written "label: n"
("الأسطر: 271") so the noun does not have to agree with the number.
