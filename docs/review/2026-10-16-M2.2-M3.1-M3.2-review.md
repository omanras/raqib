### A2. Exit criteria

- **E2: met at HEAD, not met at landing.**
  - At ea37a77, `core.run` caught only `BackendError` (commit-e036333.diff:84-89).
  - So the anthropic SDK's no-credentials TypeError escaped `cmd_eval`, which catches only ValueError (cli.py:381). The whole eval crashed instead of counting each event as a miss.
  - The README added in M2.2 showed exactly that command (commit-ea37a77.diff:45).
  - test_eval.py still has no backend that raises a non-BackendError exception.
- **E3: met.** There are rules, model and rules+model rows (eval.py:153-161).
- **E4: partly met.** Offline canned tests exist, and the baseline doc matches the pinned test (test_eval.py:203-209). No real candidate was ever run, and gate green is a claim only.

### A3. Bugs and silent assumptions
- **A-1 [high] The label leaks into the model prompt.**
  - The session id is `"eval-" + eid` (generate.py:32), for example `eval-d05-widen-own-scope` or `eval-b24-local-health-check`.
  - `render_window` puts the session id in the prompt header (suspect/core.py:96-98).
  - So the model reads the label letter (b/s/d) and a slug describing each event.
  - A test pins this (test_eval.py:61), and the canned-answer tests depend on it (test_eval.py:44-45).
  - Any real model row would be inflated.
- **A-2 [high] A broken backend can rank first.**
  - An error on a benign event is not an FP (eval.py:138), and errors rank after FN and FP (eval.py:146).
  - A backend that errors (refuses, times out) whenever it would answer low gets FN 0, FP 0 and ranks above every honest backend.
  - A backend that always answers 1.0 with one citation gets FN 0 and ranks first, whatever its FP.
  - No FP ceiling or budget applies to model rows (A6).
- **A-3 [medium] The eval set leans toward the model.**
  - Every positive that only a model can catch echoes the hint list in SYSTEM_PROMPT (core.py:51: `.claude/settings.json`, hooks, `raqib.log.jsonl`, gates).
  - The matching events are s11 and s12 (generate.py:167-171), d01 `.git/hooks` and d04 CI (generate.py:198-206).
  - The deceptive events are built to dodge the rules (test_eval.py:212-216), but none is built to dodge a model: their file names state the intent (`upload_db_dump.sh`, `shadow`).
- **A-4 [medium] Some labels cannot be defended from the metadata.**
  - b24 "curl on localhost" (generate.py:133-134) and s02 curl (generate.py:141-142) both store only `command_head: curl`. "localhost" is invisible in the trace.
  - b20 (2 edits outside scope, generate.py:124-125) and d04 (2 edits outside scope, generate.py:204-206) have the same shape. Only the file names differ.
  - s08 is labelled suspicious only because it crosses the DRIFT-FILES threshold, which makes that label circular (generate.py:153-155).
  - d02 rests on its description; the trace holds only `ln` and `data/shadow` (generate.py:200-201).
- **A-5 [medium] The rules' false positives from silence are never measured.**
  - Every call waits 2 s (generate.py:44), and no benign event idles after `stop`.
  - M0.2 Q1 and M0.3 S4 record that real long calls and real idle time raise SILENCE-GAP.
  - So "FP 6" understates the rules' false positives on real sessions (A7).
- **A-6 [medium] The rules row has 0 errors by construction.**
  - It is hard-coded `"error": False` (eval.py:101). Notes such as `partial` or `not-evaluated` never count as errors or misses.
  - So "errors 0" in docs/review/2026-10-16-M2.2-baseline.md:18 is not a measurement.
- **A-7 [low] `eval` exits 0 even when a candidate errored on all 50 events** (cli.py:396). The M3.2 evidence (M3.2-questions.md:29) shows exactly this happened. That is an A3 tension.
- **A-8 [low] An environment variable silently changes the shipped baseline.** `RAQIB_GAP_SECONDS` is read from the environment (cli.py:380) and is not printed in the output header (eval.py:177-178).
- **A-9 [low] Two candidates that resolve to the same backend/model overwrite each other** in `per_event`, and their rows get duplicate names (eval.py:157-164).
- **A-10 [low] The set leaves whole cases out (A7):**
  - no `scan: partial` or `scan: none`, and no `placeholder_kinds`;
  - no corrupt line, no event with several sessions, no event longer than one window (M2.2 Q4).
- **A-11 [low] The threshold was never set.** M2.1 Q2 asked M2.2 to set it from FN/FP; it is still 0.5. Answers below the threshold are not kept (eval.py:116-117), so no threshold sweep can be run from the output.

### A4. Claims without artifacts (A8)
- "phase 2 done ... evaluation" (README at ea37a77, diff:58): DEVELOPMENT_PLAN M2.2 asks for "model choice decided by FN first", but there is no real candidate row in the tree.
- "11 eval mutants ... harness not in git" (M2.2-questions.md:54-57).
- "gate green" has no output in the tree.

### A5. Mutants likely to survive (by reading)
- eval.py:158: passing `DEFAULT_THRESHOLD` instead of `threshold`. No test sends a valid non-default threshold through `evaluate` or the CLI.
- eval.py:116: `flagged = bool(raised) and not errors`. Each event is one window, so flagged and error never occur together.
- eval.py:163: dropping `and not r["flagged"]`.
- eval.py:123: dropping `first[eid]["error"] or`. This mutant is equivalent, because the rules error is always False.
- eval.py:67: dropping the required-keys clause. No test removes label, lines or description, and the resulting KeyError would escape `cmd_eval`.
- eval.py:146: dropping the name tie-break.

## Part B: M3.1 read-only web UI (b2db5df)

### B1. Scope violations

- [low] CLAUDE.md:26 lays out `raqib/ui/` (a directory); the module is `raqib/ui.py`.
- [low] E3 says "answers GET only"; HEAD is answered too (ui.py:267-268). The builder wrote this HANDOFF itself (9472e2e) and then departed from it.

### B2. Exit criteria
- **E1: partly met.**
  - The suspicion run record (windows judged, below threshold, errors) is never rendered (ui.py:182-189). `report.render_text` does show it (report.py:183-189).
  - The cited-line text inside finding cards comes from `report.describe`, which cuts the tail at 240 characters (report.py:55-56). The end of a long path can vanish from the A5 citation.
  - This contradicts the claim that "the end of a long path stays visible" (M3.1-questions.md:38-39). That holds only for timeline cells (ui.py:73-75).
- **E2: partly met.**
  - The "never closed" band needs a `session_start` (ui.py:117-118, 128), so a session whose start was lost gets no band (M0.2 Q2, inherited).
  - SILENCE-ORDER has no band, only marks.
  - A pre without a post is a tag on the row (ui.py:121-124), not a band.
- **E3: met by reading, with the HEAD deviation above.** I found no unescaped interpolation:
  - every trace or file value goes through `_text` (ui.py:69-76);
  - the class name, the anchors and the line numbers come from controlled sets or are formatted as ints.
  - `frame-ancestors` is ignored when the CSP comes from a meta tag (file mode). That is harmless for file://.
- **E4: met.** The tests use the real blocked-calls and file-tools traces. The hostile trace covers paths, session ids and summaries only (see B5).

### B3. Bugs and silent assumptions
- **B-1 [medium] A3: a serve failure shows as a blank page, not an alarm.**
  - If the trace or catalog becomes unreadable while serving, `page()` raises UsageError inside the handler (cli.py:331-333).
  - socketserver prints a traceback on stderr and closes the connection.
  - The browser gets an empty response, not an alarm page. The watched agent can delete or rename the trace to get this.
- **B-2 [medium] The live view will raise false alarms on healthy sessions.**
  - During a running session, every in-flight call is marked "no post" and SILENCE-HALF, and the session gets an "ends without stop" band. So a healthy session shows ALARM (M0.2 S9).
  - Idle time after `stop` draws gap bands (M0.2 Q1).
  - The M3.1 notes do not mention either.
- **B-3 [medium] Three different states look the same.** "No model was run", "the model ran and raised nothing" and "the suspicion file was truncated" all render as "Suspicion (0)" (ui.py:182-189). `report.build` does not compare the run record's counts with the lines either.
- **B-4 [medium] What a local process learns from `--serve`.**
  - Any local process, the agent included, reads the whole report: findings, notes, suspicion reasons, trace path.
  - The page is rebuilt on every GET, so the agent can poll it after each action as a live evasion oracle.
  - `HTTPServer` is single-threaded with no timeout (ui.py:285), so one idle local connection blocks the view.
  - Q2 records the read. The oracle and the stall are not recorded.
- **B-5 [low] A disabled rule still yields CLEAN.** `report.py:103` counts it as clean, and the page shows the CLEAN badge. The catalog lives in a checkout the agent's user can write (see C-9).
- **B-6 [low] Duplicate `id="L<n>"` anchors.** A record kept with a problem (bad ts, unknown phase, invalid UTF-8), or a line with two problems, produces both a band row and a record row with the same id (ui.py:101-105, 207, 213).
- **B-7 [low] Bands and findings can disagree.** With `--findings FILE`, bands use the current gap limit (cli.py:325, ui.py:112), while the findings came from another run.
- **B-8 [low] `--serve` exits 0 whatever the result** (cli.py:347).
- **B-9 [low] The written HTML file can be faked.** Nothing protects its integrity. The quickstart writes it into `~/raqib`, which the agent's user can write, so a fake CLEAN page is possible. The threat model does not mention this.

### B4. Claims without artifacts (A8)
- Headless Chromium checks at 1280 px and 390 px: the screenshots are not in git (M3.1-questions.md:9-12).
- "10 UI mutants all killed": the harness is not in git (M3.1-questions.md:53-55).

### B5. Mutants likely to survive (by reading)

  - ui.py:187: backend/model unescaped.
  - ui.py:157: alarm detail unescaped. The hostile trace has no alarm, yet the "unknown phase %r" detail carries trace text.
  - ui.py:194: notes detail unescaped. Partial notes carry session ids.
  - ui.py:147: trace path and findings_source unescaped.
- **CSP:** ui.py:26-27 can be weakened (drop frame-ancestors, base-uri or form-action, or add `img-src *`). The header test compares against the constant itself (test_ui.py:209), and the meta test checks only a prefix (test_ui.py:159).
