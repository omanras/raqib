M1 [verified] docs/THREAT_MODEL.md:565-570 is outside the builder's Scope, so it is the Table's. It says the helper is
   "started by the watch with the watch's own interpreter, always `-I` ... and the watch's own import path given
   entry for entry". From this commit on that is false wherever sys.frozen is true. Sentences to add after
   "...it is in the watch's record of what it started." (line 570):
   (a) "Where Raqib is packed with its own runtime (`sys.frozen`; ADR-0007 CG-1), the helper is the packed program
       itself with one fixed word as its only argument: no `-I` and no import path are given; it loads Raqib, and
       every module Raqib's entry imports, from the packed program's own folder; its directory is `/` and its
       environment is the watch's. That the packer's runtime reads nothing of that environment was measured once
       (PyInstaller 6.11.1: PYTHONPATH and a working folder's modules not loaded), not proven; what the packer's
       own start reads of it (its own variables, the library search path) was not measured."
   (b) "Every `raqib` and `python -m raqib`, packed or not, on every system, given that word as its first and only
       argument serves the reader on its standard input and output, as `python -m raqib.procevents --serve`
       does, with the rights of whoever runs it: it adds no reach. A packed program given a right of its own
       (file capabilities, set-user-id) would serve the machine's process events to whoever runs it so."
   Two more edits:
   - Lines 587-590 ("Before the helper's fixed program sets its import path ..."): add "Packed, the helper's start
     reads the packed program's folder (its archive and libraries) again at each start: whoever can write that
     folder changes the next helper as he changes the next watch."
   - Lines 605-608: "when the interpreter's file, or a packed program's file, is replaced on disk".
