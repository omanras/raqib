# M0.3 measures, limits, rates - design questions

Readings taken by the builder where ADR-0001 section 5 / A5 or the
handoff left room. Each is the most conservative reading available.

1. **Invalid rows poison their period (ADR section 3) is applied here**,
   in the measures, not later: any loader problem of class `invalid` with
   a date inside the period makes the measure `Unknown`; one without a
   date (bad date, wrong column count, bad encoding, too long, or a
   file-level problem) makes every measure `Unknown`. For holdings the
   same applies to problems dated between the chosen snapshot and the
   as-of date (a broken newer snapshot must not fall back silently to an
   older one). This is the reading announced in the M0.1 questions (item
   2). Question: is "one dateless bad line blanks the whole check" the
   intended severity?

2. **Nothing after as-of is seen.** Every period is cut at `ctx.as_of`
   (`end_of`): a row dated after as-of in the same month is not summed,
   a snapshot dated after as-of is not the current one, and a snapshot's
   age is measured from `min(period end, as-of)`.

3. **Transfers.** Rows tagged `transfer` are excluded from sums over the
   `income` and `expense` groups whatever their category. A row tagged
   `transfer` under an income category is therefore not income. Sums over
   other groups (`invest`, `transfer`) count every row.

4. **Signs.** Sums over the `expense` group are negated so spending reads
   positive and a refund (a positive row in an expense category) lowers
   it; `income` and other groups are summed as recorded.

5. **`months_of: expense`** averages over the complete calendar months in
   the trailing twelve (a month counts only if its last day is on or
   before the cut date) that hold at least one ledger row; fewer months
   than twelve -> those available, their labels in `detail`; none -> the
   limit is `Unknown`. A month with rows but no expense rows counts as a
   zero month. Question: should a month with no rows count as zero
   instead of being skipped?

6. **Staleness** is `age > snapshot_max_age_days` (an age equal to the
   limit still holds); `Stale` carries the value the stale snapshot gives
   when it can be computed. No snapshot at all is `Unknown`, not `Stale`.

7. **Drawdown window** is the last `window_days` calendar days ending at
   the cut date, inclusive (90 days ending 2026-09-30 start 2026-07-03).
   Drawdown on each snapshot date is measured against the running peak
   inside the window; `detail` carries the (date, value, pct) series so
   M1.1 can find the crossing date. A window with no snapshot is
   `Unknown`; a peak that is not positive is `Unknown`. Every position of
   the account counts, debt rows included, at the recorded sign.

8. **Share** divides the class value by the total of every non-`debt` row
   at the recorded sign; a zero total is `Unknown`. A custom class list
   without a class named `debt` excludes nothing.

9. **Rates.** `rates.csv` rows for the base currency are a problem
   (`BASE-RATE`); two different rates for one currency and date are a
   problem (`CONFLICT-RATE`) and `Unknown` for that date; a rate must be
   positive. The rate row used is cited next to the converted row (A4).
   `rates.load_optional` treats a missing file as an empty table, since
   the ADR marks the file optional; `rates.load` reports it missing.

10. **Limits return `Value` (amount + cited rows), not a bare Decimal**, so
    a `pct_of: income` limit cites the income rows and a `months_of`
    limit cites the expense rows it averaged. `.amount` is the Decimal
    the handoff asks for.

11. **Decimal precision.** Divisions (share, drawdown, averages) use the
    default Decimal context (28 significant digits) and are not rounded;
    rounding is for display only.
