# M1.1 rule schema + loader + runner: questions for the commander

M1.1 exit criteria E1-E4 are met and `tools/gate.sh` is green. The HANDOFF was
drafted by the builder (`docs/handoffs/M1.1.md`) under the commander's order
(`docs/review/2026-10-16-commander-order.md`). 21 mutants of the parser, the
engine and the runner were each killed by `tests/test_rules.py` (an ad-hoc run,
not committed).

## What shipped

- **`raqib/rules/yamlite.py`:** a strict YAML subset, stdlib only (A-7). Any
  plain scalar that YAML 1.1 and 1.2 read differently is an error (`yes`,
  `017`, `1e3`, `1:30`, `.inf`, dates). So is everything outside the subset
  (anchors, tags, block scalars, multi-line flow, tabs, duplicate keys).
  Errors give the line number. Every catalog file, and a corpus of test
  documents, parse the same as PyYAML 6.0.1; that cross-check is skipped
  where PyYAML is missing.
- **`raqib/rules/engine.py`:**
  - Schema validation, where every error names the file and the field.
  - Declarative match nodes: `all`, `any`, `not`, and predicates `eq`, `ne`,
    `in`, `not_in`, `exists`, `nonempty`, `regex`, `prefix`, `glob`,
    `outside`, `outside_any`.
  - An optional `aggregate` (distinct values per session).
  - `evaluate(rules, lines, context) -> (findings, notes)`, which is pure.
    `check_finding` rejects a finding with no cited_seq (A5).
- **`raqib/rules/fixtures.py`:**
  - Every positive must fire.
  - A rule's negatives plus a shared benign corpus give a measured fp_rate.
  - An active rule over its fp_budget fails the gate; A6 says it must then be
    set to `status: disabled`, not tuned.
- **Catalog:** three rules, NET-TOOL (network-from-tool), DESTRUCT-CMD
  (destructive-command) and SCOPE-PATH (path-outside-scope). Each has 1 to 3
  positives and 1 negative. The benign corpus is three synthetic sessions
  plus the two real Claude Code traces from M0.3.

## Open questions (not answered)

- **Q1 What counts as a false positive for A6.** NET-TOOL fires on a benign
  docs lookup (WebFetch docs.python.org). DESTRUCT-CMD fires on a benign build
  cleanup (`rm`). Each therefore measures 1/6 = 0.167 against a budget of
  0.25. The budget was set to the measured routine rate, not raised to make a
  test pass, and the YAML says so. Should rules that by design fire on
  routine but risky actions carry budgets like these, or should they become
  `low` severity with a budget of 0?
- **Q2 command_head is too coarse for DESTRUCT-CMD and NET-TOOL.**
  - DESTRUCT-CMD cannot see `git reset --hard`, `git clean -fdx`,
    `find -delete` or `> file`.
  - NET-TOOL cannot see `git push`, `pip install`, `npm install` or
    `python -c "import urllib..."`.
  - Both rules treat command_head as a hint (M0.1b Q1). Should capture also
    store a few more privacy-safe facts, such as a short list of flags or the
    second token for `git`, `pip` and `npm`?
- **Q3 The silence rules are not in the YAML catalog.** SILENCE-GAP, OPEN,
  HALF and ORDER are Python (M0.2) and have no fp_budget (M0.2 review S11).
  Should they get catalog entries, with `match` replaced by a reference to the
  Python rule, so that A6 covers them too?

## Assumptions made (confirm or overrule)

- **Extra optional rule fields** beyond ADR-0001 section 4: `status`
  (`active` or `disabled`; this is A6's "disabled"), `description`, `summary`
  (a template with `{field.path}`, `{seq}` and `{count}`), and `aggregate`.
  Unknown fields are errors.
- **Findings** carry `class` and `session_id` in addition to ADR section 6:
  `{ts, rule_id, class, severity, session_id, cited_seq[], summary}`.
  `ts` is the ts of the cited line (of the last one for an aggregate).
- **Predicates:**
  - A predicate on a missing field is false; `exists: false` is the
    exception.
  - Equality is type-strict: `1` matches `1.0`, but never `true` or `"1"`.
  - Paths are POSIX. A relative path is joined to the line's cwd and
    normalised, `~` paths count as absolute, and a path that cannot be placed
    makes the predicate false.
- **Deduplication and context:**
  - A rule fires at most once per (session, seq), so a pre and its post do
    not double-count. The catalog rules match `phase: pre`.
  - A rule that needs context it was not given is not run. It gets a note
    instead, and a note is never a clean result (A3).
- **Fixture layout:**
  - Paths are relative to the repo root. A fixture is a JSON list, or
    `{context, lines}`, or a raw `.log` trace.
  - Every file in `tests/fixtures/rules/<ID>/` must be referenced by its rule.
- **Rule ids** use `CLASS-NOUN` (SCOPE-PATH), not the plan's kebab names, to
  match SILENCE-GAP.
