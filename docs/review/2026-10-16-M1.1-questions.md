# M1.1 rule schema + loader + runner: questions for the commander

M1.1 exit criteria E1-E4 are met and `tools/gate.sh` is green. The HANDOFF was
drafted by the builder (`docs/handoffs/M1.1.md`) under the commander's order
(`docs/review/2026-10-16-commander-order.md`). 21 mutants of the parser, the
engine and the runner were each killed by `tests/test_rules.py` (an ad-hoc run,
not committed).

## What shipped

- **`raqib/rules/yamlite.py`:** a strict YAML subset, stdlib only (A-7). Any
  plain scalar that YAML 1.1 and 1.2 read differently is an error (`yes`,
  `017`, `1e3`, `1:30`, `.inf`, dates). So is everything outside the subset
  (anchors, tags, block scalars, multi-line flow, tabs, duplicate keys).
  Errors give the line number. Every catalog file, and a corpus of test
  documents, parse the same as PyYAML 6.0.1; that cross-check is skipped
  where PyYAML is missing.
- **`raqib/rules/engine.py`:**
  - Schema validation, where every error names the file and the field.
  - Declarative match nodes: `all`, `any`, `not`, and predicates `eq`, `ne`,
    `in`, `not_in`, `exists`, `nonempty`, `regex`, `prefix`, `glob`,
    `outside`, `outside_any`.
  - An optional `aggregate` (distinct values per session).
  - `evaluate(rules, lines, context) -> (findings, notes)`, which is pure.
    `check_finding` rejects a finding with no cited_seq (A5).
- **`raqib/rules/fixtures.py`:**
  - Every positive must fire.
  - A rule's negatives plus a shared benign corpus give a measured fp_rate.
  - An active rule over its fp_budget fails the gate; A6 says it must then be
    set to `status: disabled`, not tuned.
- **Catalog:** three rules, NET-TOOL (network-from-tool), DESTRUCT-CMD
  (destructive-command) and SCOPE-PATH (path-outside-scope). Each has 1 to 3
  positives and 1 negative. The benign corpus is three synthetic sessions
  plus the two real Claude Code traces from M0.3.

## Open questions (not answered)

- **Q1 What counts as a false positive for A6.** NET-TOOL fires on a benign
  docs lookup (WebFetch docs.python.org). DESTRUCT-CMD fires on a benign build
  cleanup (`rm`). Each therefore measures 1/6 = 0.167 against a budget of
  0.25. The budget was set to the measured routine rate, not raised to make a
  test pass, and the YAML says so. Should rules that by design fire on
  routine but risky actions carry budgets like these, or should they become
  `low` severity with a budget of 0?
- **Q2 command_head is too coarse for DESTRUCT-CMD and NET-TOOL.**
  - DESTRUCT-CMD cannot see `git reset --hard`, `git clean -fdx`,
    `find -delete` or `> file`.
  - NET-TOOL cannot see `git push`, `pip install`, `npm install` or
    `python -c "import urllib..."`.
  - Both rules treat command_head as a hint (M0.1b Q1). Should capture also
    store a few more privacy-safe facts, such as a short list of flags or the
    second token for `git`, `pip` and `npm`?
- **Q3 The silence rules are not in the YAML catalog.** SILENCE-GAP, OPEN,
  HALF and ORDER are Python (M0.2) and have no fp_budget (M0.2 review S11).
  Should they get catalog entries, with `match` replaced by a reference to the
  Python rule, so that A6 covers them too?

## Assumptions made (confirm or overrule)

- **Extra optional rule fields** beyond ADR-0001 section 4: `status`
  (`active` or `disabled`; this is A6's "disabled"), `description`, `summary`
  (a template with `{field.path}`, `{seq}` and `{count}`), and `aggregate`.
  Unknown fields are errors.
- **Findings** carry `class` and `session_id` in addition to ADR section 6:
  `{ts, rule_id, class, severity, session_id, cited_seq[], summary}`.
  `ts` is the ts of the cited line (of the last one for an aggregate).
- **Predicates:**
  - A predicate on a missing field is false; `exists: false` is the
    exception.
  - Equality is type-strict: `1` matches `1.0`, but never `true` or `"1"`.
  - Paths are POSIX. A relative path is joined to the line's cwd and
    normalised, `~` paths count as absolute, and a path that cannot be placed
    makes the predicate false.
- **Deduplication and context:**
  - A rule fires at most once per (session, seq), so a pre and its post do
    not double-count. The catalog rules match `phase: pre`.
  - A rule that needs context it was not given is not run. It gets a note
    instead, and a note is never a clean result (A3).
- **Fixture layout:**
  - Paths are relative to the repo root. A fixture is a JSON list, or
    `{context, lines}`, or a raw `.log` trace.
  - Every file in `tests/fixtures/rules/<ID>/` must be referenced by its rule.
- **Rule ids** use `CLASS-NOUN` (SCOPE-PATH), not the plan's kebab names, to
  match SILENCE-GAP.

## REDO: builder's response to docs/review/2026-10-16-M1.1.md

**Fixed** (commit `landed: M1.1 REDO`)

- **Y1:** a quote opens a quoted scalar only where a scalar can start (line
  start or after `- ` there, after `: `, after an opening `[`/`{`, after `,`
  inside one). `summary: a - "b # c"` now reads `a - "b`, as YAML does.
- **Y2:** plain keys must resolve to strings; `on:`, `true:`, `null:`, `1:`,
  `.5:`, `017:` and dates are errors (block and flow keys).
- **Y3:** lines are split on `\n` only. C0 (except tab), DEL, C1, non-ASCII
  spaces and bidi/zero-width characters are errors, raw or escaped. Only
  ASCII spaces are stripped.
- **Y4:** `1.5_0`, `1._` and any underscore in a number-like scalar are
  errors.
- **Y5:** plain values starting with `]`, `}` or `,`, flow items starting
  with `#` or `?`, and `--- foo` (any document marker except a lone first
  `---`) are errors.
- **MS1, PA3:** logic is three-valued. A predicate that cannot judge a line
  (missing field, unplaceable path) gives "unknown"; `not unknown` is
  unknown; a rule fires only on true. Unjudged lines give a `partial` note.
  `exists` always judges; catalog rules use it as a guard where a missing
  field means "does not apply" (SCOPE-PATH).
- **PA1:** two new rules. SCOPE-CWD-ROOT (high, SCOPE) fires when a session's
  cwd is `/`, `/root`, `/home/<u>` or `/Users/<u>`. SCOPE-CWD-MOVED (medium)
  fires when one session reports more than one distinct cwd, citing the
  first line of each. Fixtures include a real-looking moved session.
  `outside_any` anchors relative scope entries to context `root` (the
  HANDOFF's directory in the CLI, or `--root`) instead of the line's cwd.
- **PA4 (partly):** a leading `//` collapses to `/`. `~` paths still count as
  absolute, so they give a false positive, not a silence.
- **AG1:** a matching line without the `distinct` value is "unknown" and
  noted. **AG4:** DRIFT-FILES and both SCOPE-CWD rules use aggregate, so the
  runner measures it (`as: path`, `cite: first`).
- **SU1:** long values keep their start and end with `...` in the middle, so
  `/../etc/shadow` stays visible. **SU2:** titles may not contain braces, and
  yamlite now rejects control and bidi characters in any scalar.
- **A5-1:** `check_finding` checks `class` and `ts` (string or null); a
  finding's ts falls back to the last valid ts of its session.
- **A6-1, F14:** a rule whose context is missing from a fixture is
  "unmeasured" on it, not clean. `check-rules` shows measured/unmeasured, and
  a rule with no measured negative fails ("unmeasured").
- **A6-2:** every fixture line must be a sound trace record (session_id, int
  seq, valid ts, known phase), else the fixture is an error.
- **A6-5:** `fp_budget` must be `0 <= x < 1`.
- **3h-1, 3h-3, 3h-4, 3h-6:** skipped (uncitable) lines give a `skipped-lines`
  note; a missing catalog directory, an empty catalog and `*.yml` files are
  errors; a context value of the wrong type gives `bad-context`; a SILENCE
  rule must be `high`.
- **3i:** mutants (a)-(e) are covered by tests (quote set rewritten,
  `...` marker, rate equal to budget, unplaceable root, `nonempty` mapping).
  23 REDO mutants were run ad hoc and killed (not committed, as before).
- **Optional expected seqs:** a positive fixture may say `expect_seq`; the
  runner reports `missing_seq` when the rule fires but cites other lines.
- **M0.2 S14, S15:** OPEN, HALF and ORDER fall back to the last valid ts;
  `gap_seconds` above 7 days is an error.
- **Fixtures:** `tests/fixtures/rules/generate.py` regenerates every rule
  fixture and the benign corpus in the current capture shape.

**Recorded, not fixed**

- **PA2:** paths are normalised lexically; symlinks are not resolved (the
  watcher does not touch the watched tree, A4). Now stated in engine.py.
- **PA5:** Glob/Grep patterns, Bash file access and MCP file tools do not
  reach `input_meta.path`. Needs a capture change (Q2 territory).
- **A6-3:** fp_rate stays files-fired / measured files. **A6-4, A6-7:** the
  budgets still rest on a synthetic corpus; the real-trace benign files are
  few and short. **A6-6:** default `benign=()` kept; the CLI and test pass the
  corpus.
- **AG2, AG3:** summary fields come from the last matching line; distinctness
  is compared on JSON text (paths are placed first with `as: path`).
- **A5-2, A5-3:** a citation is not checked against the trace, and the phase
  is not cited.
- **3h-7:** wrappers and compound commands (`sudo rm`, `bash -c`, `cd x &&
  rm`) still hide the program from command_head.
- **MS2:** `prefix` and `glob` remain string operations (documented).
- **M0.3 residuals** (M2, M3, B4) move to the M1.2 REDO commit.
