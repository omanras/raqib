# M1.2 — questions for the commander (not answered locally)

Each entry: the question, the most conservative reading taken, where it
shows in the tree. Nothing here changes the exit criteria.

## Q1. Chip colours
E1 asks for a chip "coloured by verdict". The CLI's green is every policy
`hold`; the other six verdicts are all red. Reading taken: `hold` is green
and breach, kill, missing, stale, invalid and unknown are all red, so a
silence (missing, stale) never looks milder than a breach (A3). Every chip
carries the verdict word, so colour is never the only signal. Amber is
kept for `warn` findings (DUP-ROW), which do not break green.

## Q2. The reversing row
"Reverse" appends the mirror row: the same date (so it nets out in the
same period: the E5 scenario reverses a 2026-09-28 row and judges at
2026-09-30), the amount with its sign flipped as text ("-200" -> "200"),
the same currency, account and category, the original tags plus
`reversal`, and the note `reverses ledger.csv:<line>`. A reversal can
itself be reversed; nothing is edited in place (A6).

## Q3. "Save only when parse has no problems"
Reading taken: Save is blocked while any line is `invalid`; a `warn`
problem (DUP-ROW) does not block it, because the CLI accepts exact
duplicates ("two identical purchases happen") and the Add-row form allows
them too (with a notice). The problems, warnings included, are listed by
line next to the text. Without a readable policies.yml every row's account
and category are undeclared, so nothing can be saved until it is fixed.

## Q4. Dates as text
The as-of date and the forms' dates are ISO text inputs (`YYYY-MM-DD`,
Latin digits), not native date pickers, which display the browser's locale
(and, in Arabic, Arabic-Indic digits), against "dates ISO" (M1.3 E4).
A date is taken as soon as it is a valid calendar date.

## Q5. The engine's texts are not translated
Reasons, "measure vs limit", findings and the summary line are the CLI's
text verbatim (E1 asks for it), in English in both languages, and laid
out left to right inside the Arabic page.

## Q6. A household the CLI cannot read
The dashboard shows the CLI's message ("qayd: cannot read or parse the
household files:") and each problem with its line instead of a board; no
policy is judged (see M0.3 Q5).
