# M1.2 — questions and readings taken

1. **Revoke path.** The handoff says "revoke = POST /invites/:id/revoke".
   Reading taken: `POST /api/circles/:id/invites/:inviteId/revoke`, so the
   organizer check runs on the circle in the one place it runs for every
   circle route (`server/circle-access.ts`); an invite of another circle is
   404. Audit only, no ledger entry (A1: invitations not yet accepted are
   the one thing members do not see).

2. **Preview before accepting.** M2.1's Join screen "shows the circle
   summary", so `GET /api/invites/:token` was added. Reading taken (most
   private): it requires a signed-in user, is rate-limited like accept, and
   answers 404 for any token that is unknown, used, revoked, expired, or
   whose circle no longer accepts members. `GET /api/circles/:id/invites`
   (organizer: status of each invitation, never the token) was added for
   M2.2's invite list. The token exists in clear only in the creation
   response.

3. **Invite rate limits.** ADR §6 asks for per-IP and per-account limits on
   invite endpoints without numbers. Reading taken: 120 per IP and 100 per
   account per 15 minutes over create, preview, accept and revoke, enough
   for an organizer to invite a full circle (100) in one sitting; a first
   setting of 30 per account stopped exactly that in the tests.

4. **Member cap.** "Refused ... at member cap": member_count is only
   fixed at start, so the cap before start is `MAX_MEMBERS` = 100 active
   members (the bound the money arithmetic is sized for).

5. **Who may join, leave, be ordered.** Only in `draft` (shared/state.ts).
   An accept after the draw opened, after start or after cancel is 409
   `circle_closed_to_members` with the reason; the preview of such a link is
   404. The organizer cannot leave (409 `organizer_cannot_leave`; cancel
   instead). A member leaving a draft clears a manual order (the ledger
   entry says `orderCleared: true`), because a permutation without them no
   longer exists.

6. **Start date rules.** A start date may be today (UTC, with one day of
   slack so a user west of UTC is not refused their local "today") up to
   five years ahead; checked on create, on PATCH and again at start (a
   draft can sit for weeks). Earlier is 409 `start_date_past`.

7. **PATCH semantics.** Every field whose value actually changes becomes
   one `circle.rule_changed` entry `{field, from, to}`; the minor unit is
   such a field when the currency changes it. A currency change that
   changes the minor unit requires the contribution in the same request
   (otherwise the same integer would silently mean a different amount).
   The period/due-day combination is checked after merging.

8. **Obligations at start.** Start creates every round (due dates from
   shared/schedule.ts, recipient by position) and one `contributions` row
   per (round, payer) with the expected amount; with `recipient_pays:
   false` the recipient has no row in their own round. Opening round 1 at
   start is M1.4's.

9. **The organizer is a member.** `circle.created` is followed by a
   `member.joined` entry for the organizer, so every member, organizer
   included, appears in the ledger the same way. Member entries carry the
   user id so the client can name the actor of every entry.
