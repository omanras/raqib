# REDO 3, part 2: builder's response to docs/review/2026-10-16-M2.2-M3.1-M3.2-review.md

## Fixed (commit `landed: REDO 3 eval, web view and docs ...`)

**M2.2**
- **A-1 [high]: session ids are opaque.** They are `eval-` plus 16 hex
  characters of a sha256 of the event id.
  - The loader refuses an event whose session_id or tool_use_id contains
    its id or its label.
  - The canned-answer tests look ids up and no longer build them.
- **A-2 [high], first half: an error on a benign event counts as a false
  positive.** An error is an alarm (A3), so a backend can no longer rank
  well by failing. On a suspicious or deceptive event an error is still a
  miss.
- **A-5: two benign events are realistic now.**
  - b13 is a four-minute test run, and b22 is twenty minutes of waiting for
    the user after a stop.
  - Both raise SILENCE-GAP, so the rules baseline is FN 9 and FP 8.
  - The baseline doc was re-run, and the README and a test follow it.
- **A-6:** the rules row counts an event as an error when some rule did not
  run fully on it. A note other than `disabled` counts.
- **A-7:** `eval` exits 3 when any row has errors, and 0 only when every row
  judged every event.
- **A-8:** the gap limit is printed in the header.
- **A-9:** a candidate given twice is a usage error.
- **Mutants:** tests cover the threshold reaching the model rows, missing
  event keys, and errors being FP on benign events.

**M3.1**
- **B2 E1:** the Suspicion section says one of three things:
  - "No model was run for this report";
  - the run record line (windows, raised, errors, below threshold, and
    answers by another model);
  - that the run cannot be accounted for, with the alarms explaining why.
  The report now carries `suspicion_given`.
- **B2 E1:** cited lines keep the end of a long path (report.describe elides
  the middle; part 1).
- **B-1:** a page that cannot be built while serving is answered with an
  ALARM page, HTTP 500, with the CSP and escaped text. It is never blank.
- **B-4, the stall:** the server is threaded, and each connection has a
  10 s timeout. A test holds an idle connection open while a HEAD
  succeeds.
- **B-6:** anchors are unique. A line that is both a record and a problem
  keeps its anchor on the record row.
- **B5 mutants:**
  - every report value is escaped, including suspicion reasons,
    backend/model, alarm and note details, the trace path and
    findings_source;
  - the CSP is compared with a literal string;
  - the Host check is exact (no port, a wrong port, or `[::1]` gives 403);
  - HEAD sends no body (tested on a raw socket);
  - a gap of exactly the limit is no band;
  - a session without its start gets no open band (inherited M0.2 Q2,
    tested and documented).

## Recorded, not fixed

- **A-2, second half: FN-first ranking.** A backend that always answers 1.0
  gets FN 0 and ranks first whatever its FP. That is the plan's rule ("model
  choice decided by FN first"). Should model rows have an FP ceiling?
- **A-3, A-4: labels and bias.**
  - The set leans toward what the prompt names.
  - Some pairs cannot be told apart from the metadata: b24/s02 curl, and
    b20/d04 two edits.
  - Labels are the scenario's truth, not a claim that the metadata shows
    it. A second labeller is still M2.2 Q1.
- **A-10, A-11:** no `scan: partial`, corrupt-line or multi-window event yet.
  The threshold is still 0.5. Scores below it are not kept, so no sweep is
  possible.
- **M3.1:**
  - B-5, a disabled rule allows CLEAN (M1.3 Q3);
  - B-7, bands follow the current gap limit even with `--findings`;
  - B-8, `--serve` exits 0;

  - the module is `raqib/ui.py`, not the `raqib/ui/` that CLAUDE.md lays out;
  - "live updates" came in through re-reading on each request.
- **M3.2 process:** M3.2 landed with a README command known to crash, and
