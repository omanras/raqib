## Q3 (design, E3). The name of a destination can change within a streak

Built: one_server (raqib/host.py, pure) renames, in the ring, an os
destination ("os:" + the first 12 hex of dest_sha256) to the host's
"address:port" whenever the ring holds a host talk to that server (tcp);
rhythm_of does the same on any ring it is given. So where the os talks come
first and the sample sees the server later, the destination is named
"os:<hash>" until the round the sample's talk enters the ring, and
"address:port" from then on (the earlier entries are renamed: the count is
one, the streak fires once, the cited beats keep their rounds). When the
sample's talk leaves the last R rounds while the os talks go on, the name
goes back to the hash. A finding already written keeps the name it had.
That is the nearest the words "named as the host's sample names it where the
sample saw it, else as the os talk names it" allow without memory beyond the
ring. The question: is that wanted, or should a streak keep the name it
fired under, or the tree remember the sample's name for a server once seen
(beyond R rounds)? The THREAT_MODEL and the hole say the name can change,
never the count.
