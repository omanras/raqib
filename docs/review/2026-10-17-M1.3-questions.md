# M1.3 example rule set — design questions and notes (returned, not answered locally)

No engine change was needed for the example set. The points below are the
choices the builder made inside the scope of the task.

## Q1. Budgets of the example rules
E4 asks for at least two rules with a non-zero fp/10k and no budget above
50. Six rules measure non-zero on the 1,000-event corpora (each benign
match is 10/10k): encoded PowerShell 10 (budget 20), whoami 20 (30),
schtasks from Temp 10 (10), sudo root shell 20 (30), SSH from the internet
10 (20), scanner user agent 30 (40). The four others measure 0 with budget
0. One rule sits exactly on its budget (10 = 10) on purpose, so the
inclusive comparison of M1.2 Q6 is exercised by the self-gate.
Question for the commander: should the example budgets be documented as
"measured + headroom" (as here) or set to the measured value exactly, so
that any new benign match in a regenerated corpus turns the gate red?

## Q2. Planted benign matches
`tools/make_corpus.py` plants the benign events that produce those false
positives at fixed indices (an administrator's encoded script, two
`whoami` runs, an installer's scheduled task from `Temp`, two `sudo -i`,
one SSH login from 203.0.113.77, three partner requests with
`python-requests`). Everything else is drawn from a seeded
`random.Random` using only `random()`, `randrange()` and `choice()`,
whose sequences are stable across Python 3 versions; `sample`,
`choices`, `shuffle` and `gauss` were avoided for that reason.

## Q3. Corpus header
The header carries `generator`, `seed` and `events` inside `_mizan`
(allowed by M1.2 Q5), so a reader can tell how the file was made without
opening the script.

## Q4. Originality
The ten rules are written for this set: generic, well-known technique
classes (encoded PowerShell, whoami, LSASS dumping, schtasks persistence,
root password over SSH, sudo root shell, SSH from outside, path
traversal, SQL injection probes, scanner user agents), with their own
field choices, filters, fixtures and descriptions. No rule, fixture or
description was copied from the public Sigma repository or any other
rule set. Hosts are `*.corp.example` / `*.example.test`, users are
numbered, addresses come from RFC 5737 ranges.

## Q5. Near misses
Every negative sidecar has at least one line that equals a positive line
except for exactly one field (`tests/test_examples.py` asserts it): the
encoded flag removed, `NT AUTHORITY\SYSTEM` as the user, another process
dumped, `Program Files` instead of `AppData`, a key instead of a
password, `apt-get` instead of a shell, a failed instead of an accepted
login, an ordinary file name, a plain `id=42`, the same `python-requests`
call from the monitoring range.

## Q6. Features exercised by the self-gate
The set uses `endswith`, `startswith`, `contains`, `contains|all`,
`contains|windash`, `re|i`, `re`, `cidr`, value lists, `1 of selection_*`,
`all of selection_*`, `and not filter_*`, nested-free events of three
schemas. `exists`, `null`, the numeric modifiers and dotted paths are
covered by the unit tests only; a later example could add them.
