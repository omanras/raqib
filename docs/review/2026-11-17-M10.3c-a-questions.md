## Questions
1. `--shape raqib` with `journal:`. The CLI's `--shape` defaults to "raqib" (raqib/cli.py: help strings only in
   scope), so a `--shape raqib` written cannot be told from none: only `--shape hec` is refused (W-6). Should the
   CLI's default become None so that any `--shape` is refused with `journal:`?
2. W-3 against M-3. A batch to the journal is bounded by its lines' own bytes, so every line the forwarder reads
   whole (at most 512 KiB) is sent, never refused for its length. A line over 512 KiB is never read whole by the
   cursor's machine (M-3) and is still refused locally, counted and named, with the words "longer than one
   request may be (J-11)" (pass_unsent unchanged: the cursor's machine is not to be touched). Raise the limit for
   the journal, or keep it and give it its own words?
3. The socket is connected to the journal's path first, and then each entry is sent to that same path. The path
   goes with sendto, and with sendmsg for a memory file, as the Table measured it. connect is the phase that
   says there is no journal (ENOENT, ECONNREFUSED: `connect`). A connected datagram socket waits properly for
   room when the journal's queue is full (an unconnected one would spin on EAGAIN under a timeout). Stop's
   shutdown ends a blocked send. The Table measured an unconnected socket: the field must confirm connect on
   the real socket (X26 does).
4. Failing words. judge and the forwarder take ERRORS (HTTP's) for the journal: `connect` reads "no connection to
   the collector". Choosing another table in judge is outside link.py's allowed parts. Also judge's first line
   says "facility 13, framing none: one datagram a message" for a journal state: it reads facility and framing
   together, and it was not changed. Does the Table want the journal's own words in both?
5. X26's "identifier of its own run". W-2 fixes SYSLOG_IDENTIFIER raqib and the CLI has no option for another.
   The rig reads its run's entries by the journal's trusted _PID of the forwarder's own process (`journalctl -t
   raqib _PID=<pid> -o json`), as W-7 says a reader must. A run-unique identifier would need a keyword the CLI
   does not have. Is the pid the identifier the Table meant?
6. X26's states. check.py's words are MET, MISSED, OPEN and n/a. "NOT MET" is built as MISSED, with what is
   missing (the lines by number). "NOT RUN" is n/a, "not run: <reason>", and --strict never fails on it. No new
   state word was added (X26 only).
7. The rig's own test. Where forward_run's JOURNAL is a stand-in, x26 runs the forwarder through JOURNAL_RUN (a
   `python -c` that sets raqib.forward.JOURNAL and calls cli.main). On the real machine it runs `python -m raqib
   forward ... --to journal:` itself.
8. MESSAGE drops exactly one trailing newline ("the line as written without its newline"): a CR before it stays.
   Syslog's MSG drops a CR too (_bare). Which does the Table want?
9. "No control character" in a RAQIB_ field is taken as C0, DEL and C1 (U+0080 to U+009F). A lone surrogate,
   which UTF-8 cannot hold, is left out too.
10. The pace. Only a taken batch is paced: what is left of count/250 s from the batch's start is waited by
    pause(), the injected wait, with the state once a beat. A failed send waits J-10's waits only.
11. The facility is parsed by syslog's own parse, so its error says "a syslog facility, a whole number from 0
    to 23".
12. The CLI help of `--facility` now says "syslog and journal: only". P-6 says the two help strings are the
    Table's: the Table may want its own words.
