Q1 (Q-A, D-10) "The first literal .py/.sh argument" is not the script.

    command                                    command_programs   Q-A reading
    python3 -c 'pass' gate.py                  [python3]          gate.py
    bash -c 'true' gate.sh                     [bash, true]       gate.sh
    sh -c 'exit 0' tools/gate.sh               [sh, exit]         gate.sh
    python3 -m pytest tests/test_report.py     [python3]          test_report.py
    python3 -m pyflakes raqib/hooks/common.py  [python3]          common.py

In the first three the .py/.sh word is data (sys.argv[1], or $0 of the -c
string) and is never run; in the last two it is an argument of the module.
So the field records arguments that name no program, which the
"program-like name" of D-10 does not cover, and E3 takes
`python3 -c 'pass' gate.py` (exit 0, nothing written) as a gate run:
knowing the demand helps by not complying (ADR-0002:23-26). (A fake gate.sh
anywhere already passes under D-10's basename only; this way needs no file.)
Alternative: the script operand only, i.e. the first non-option word of
python/python3 when no -c or -m came before it (-W, -X and
--check-hash-based-pycs take a value), and of bash/sh when no -c or -s came
before it (-o, -O, --rcfile and --init-file take a value, as
common.py:364-390 already reads them). Also open: in which simple commands
(top level, inside $(...), inside a bash -c string: the reader reads all
three); .py/.sh only, or any script operand (`bash tools/gate`); and
python3.12, `env python3`, `py -3`, `uv run`.
