## Why STOP (superseded: ruled in Amendment 2, Q-1 -> P3)

E1 fixes the Windows command form to "interpreter + script path, quoted,
no shell syntax (Q-7)". The ruling's reason was: "What the shell wrapper
covered on POSIX (interpreter missing, script missing) becomes, on Windows,
a hook error shown by Claude Code rather than a block". That is false for a
missing script:

- CPython exits **2** when the script file cannot be opened
  (`python3 -I /nonexistent/raqib/hooks/capture.py` -> exit 2; the same C
  path runs on Windows). Pinned by
  `tests/test_install.py::test_m51_q1_python_exits_2_when_the_script_is_missing`.
- The tree says exit 2 is "block" for Claude Code (old
  `tools/install-hooks.sh:17-18`; test `test_b1_missing_capture_never_blocks`).
- So with the Q-7 form, a moved or deleted checkout blocks every
  PreToolUse (and Stop) of the watched agent. That breaks A4 ("the watcher
  never touches the watched"). B1 closed exactly this on POSIX.

E5's README line ("hook-error-not-block behaviour") can't be written
truthfully either. The README on this branch states the real behaviour.

Two smaller gaps follow from "nothing else":
- **Trace location.** With no `RAQIB_LOG=` prefix and no argument, the
  Windows hook writes `./raqib.log.jsonl` in whatever directory it runs
  from. The trace stops being absolute and `--log` has nowhere to go.
- **`-I`.** Without it, PYTHONPATH can shadow the stdlib (B2). A shadowing
  module that calls `sys.exit(2)` is a block too.

## Questions

- **Q-1 The Windows command form.** Choose one:
  - **P1 (literal Q-7):** `"<python.exe>" "<capture.py>"`. A missing
    script blocks the agent; no `-I` (B2 open); the trace is relative to
    the cwd and `--log` is impossible.
  - **P2 (on this branch):** `"<python.exe>" -I "<capture.py>" "<log>"`,
    with forward slashes. `capture.py` takes the log as its one argument
    (before `RAQIB_LOG`). B2 stays closed and the trace stays absolute, but
    a missing script still blocks (exit 2). Paths containing
    `" % $ ` !` or control characters are refused, exit 2.
  - **P3 (not implemented):** `"<python.exe>" -I -c "import os,runpy,sys;p=sys.argv[1];os.path.isfile(p) or sys.exit('RAQIB-SILENCE: capture hook failed, missing '+p);sys.argv[:]=sys.argv[1:];runpy.run_path(p,run_name='__main__')" "<capture.py>" "<log>"`.
    There is no shell syntax: the characters inside the quotes are literal
    in cmd.exe and in sh. A missing script gives exit 1 with a
    RAQIB-SILENCE line, so it never blocks. The cost is inline code in the
    command, the "nothing else" that Q-7 ruled out.
  - Or accept the block risk under P1/P2 and say so in the README.
- **Q-2 Hook shell on Windows (Q-7 record).** I could not read Claude
  Code's documentation from this session: the proxy refused
  code.claude.com and further probing was denied. **Unverified, from
  memory:** native Windows Claude Code needs Git for Windows and runs its
  Bash tool through Git Bash. How hooks are spawned is unknown. CI runs
  the installed command through `cmd.exe /d /s /c "..."` (what Node's
  `shell: true` does) and through Git Bash
  (`test_m51_windows_hook_runs_under_cmd_and_git_bash`). On Linux, the
  same form runs identically under `sh -c` and as a plain exec.
- **Q-3 No deadline on Windows.** SIGALRM does not exist there. A capture
  slower than the 10 s hook timeout is killed with no RAQIB-SILENCE line.
  Add a timer, or accept the gap?
- **Q-4 CI vs real Windows clones.** `.gitattributes` is outside Scope.
  CI sets `core.autocrlf false` and `PYTHONUTF8=1`: 115 test call sites
  use the default encoding, though product code under `raqib/` uses
  explicit encodings (checked with `-X warn_default_encoding`). So CI does
  not cover a CRLF checkout or the CLI writing non-ASCII to a cp1252 pipe.
  Add a `.gitattributes` (`* text eol=lf`) in a later task?
- **Q-5 Cross-platform settings.** The installer recognises the POSIX,
  legacy and Windows forms on every platform. Installing from WSL and from
  Windows into one `.claude/settings.json` leaves the last form, which is
  broken for the other side (ruling Q-6 says the two are different cwds).
  Is that acceptable?

failure in either test is a real failure on Windows. On POSIX nothing
changes. M5.1b E6 removes both markers and both classes.

cases: the file gone from an existing directory, and its directory gone.
Each must exit neither 0 nor 2 and print no RAQIB-SILENCE line. The exact
cmd.exe status is not pinned; the test asserts only "not 0, not 2".
