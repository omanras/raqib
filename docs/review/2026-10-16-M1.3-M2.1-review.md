### 3. Bugs and silent assumptions
1. **[high] A3: a findings file is not tied to its trace.**
   - `report TRACE --findings F` runs no rule on TRACE, not even the silence rules (cli.py:241-243). It trusts F.notes.json for which rules ran.
   - The sidecar records `trace` (cli.py:176), but `_read_findings` reads only `notes` (cli.py:204-211).
   - Result: an empty F plus `{"notes": []}` from any quiet trace makes a *different*, non-empty, well-formed TRACE report CLEAN, exit 0 (report.py:101-106). This holds even if TRACE has a gap, an open session or a half call.
   - The agent runs as the same user and can write these files (THREAT_MODEL.md:68-71).
2. **[medium] Control characters from the trace reach the text report.**
   - These are printed raw:
     - session_id, rule_id and summary (report.py:173-176);
     - the details of missing-citation and suspicion-error alarms (report.py:91-94, 128-130).
   - Where the raw text comes from:
     - session_id can be any non-empty string (trace.py:80);
     - a line with an unknown phase is kept (trace.py:71-73), and its phase goes raw into SILENCE summaries through `_label` (silence.py:96-97);
     - `tool` also goes raw into summaries (silence.py:139-140).
   - A forged line with a newline or ANSI escape in session_id can print extra report lines, for example a fake `RESULT: CLEAN`. The exit code is not affected.
3. **[medium] A5: the cited evidence leaves out `cwd`.**
   - `describe()` never renders cwd (report.py:43-57).
   - For SCOPE-CWD-ROOT and SCOPE-CWD-MOVED (later rules; SCOPE-CWD-ROOT.yaml:8,12), the deciding field appears only in the summary, not in the cited lines.
   - The same applies to relative paths, which are placed against cwd.
4. **[low] The notes sidecar's structure is not checked.** `{"notes": "x"}` or `{"notes": [{}]}` passes cli.py:208, then crashes at report.py:103 with a traceback. Exit is 1 and no report is printed.
5. **[low] Options are silently ignored with `--findings`.** `--scope`, `--handoff`, `--gap-seconds` and a bad RAQIB_GAP_SECONDS are all ignored (cli.py:241-243).
6. **[low] A5 wording.**
   - A finding whose citation has no line is still listed and counted under FINDINGS (report.py:85, 171), as well as being an alarm.
   - A5 says such a finding "is not a finding". This path only raises, never clears.
7. **[low] Q1 (rules run in-process, against ADR section 1) was asked for `report` only.** M2.1 `suspect` (cli.py:295) and the later `ui` repeat the pattern without a question.
- **A2, privacy, exit codes:** no A2 path in this code. Rules and report make no network calls. An uncaught exception exits 1, never 0.

### 3. Bugs and silent assumptions
1. **[high] A3/E3: the server-side fallback hides refusals.**
   - backends.py:99-100 sends `fallbacks="default"`. If the fallback works as M2.1-questions.md:42-45 describes, a window that claude-opus-5-5 refuses is re-run on another model.
   - Only a refusal that survives the fallback reaches backends.py:122-125.
   - So a refused window can end as "below threshold": dropped, nothing written, exit 0. No line says the requested model refused.
   - `response.model` is never read. The line and the run record name the *requested* model as the judge (core.py:150-152, 170).
   - This was asked as Q4 but shipped on by default.
2. **[medium] Prompt injection: the header line is outside the frame.**
   - session_id and cwd go on the header line (core.py:97-98), outside `<findings>` and `<trace>`.
   - SYSTEM_PROMPT marks only text inside the tags as untrusted (core.py:47).
   - The agent can steer cwd (THREAT_MODEL.md:38-39; capture.py:401-403). JSON escaping keeps it on one line, but the model reads it as framing, not data.
   - test_suspect.py:60-73 covers only a path inside `<trace>`.
3. **[medium] Privacy and E4: what leaves the machine.**
   - **Sent whole:** each line's input_meta and output_meta (core.py:95), with no allow-list of inner keys and no length limit.
   - **Consequence:** "no raw content" holds only while the trace is honest. The agent can write the trace (THREAT_MODEL.md:40, 116-117), so with `--backend anthropic` a planted input_meta is sent off the machine word for word.
   - **Also sent but missing from the documented list** (THREAT_MODEL.md:44-45, README.md:83):
     - session_id;
     - the absolute cwd, which often contains the OS user name;
     - ts and error_class;
     - scan and placeholder_kinds;
     - each finding's rule_id and summary (core.py:93-94), and summaries embed paths.
4. **[medium] A3: `suspect --findings F` can crash without a record.**
   - Every JSON object in F goes to the model layer unchecked; there is no check_finding call (cli.py:292-293).
   - windows() runs before the try block (core.py:148, try at 153) and iterates `f.get("cited_seq") or []` (core.py:75-77).
   - A finding with an integer cited_seq raises TypeError: traceback, no file, no run record.
   - Also: non-JSON lines are dropped silently (cli.py:293), and F.notes.json is ignored.
5. **[medium] A3: the suspicion run record is never checked.**
   - A missing S.run.json raises nothing (cli.py:228-233, report.py:185), unlike a findings file without notes (report.py:98-100). An empty S with no run record looks the same whether suspect ran and raised nothing or never ran.
   - The run record's `trace` (cli.py:308) and its windows and errors counts are never compared with TRACE or with S's lines.
     - Deleted error lines leave no alarm, while the run line still prints "N errors" (report.py:186-189).
     - A run record that is valid JSON but has missing or mistyped keys crashes render_text at the same place.
6. **[medium] The Anthropic request shape is not proven.**
   - In form it matches the stated target (backends.py:96-105):
     - model claude-opus-5-5;
     - `betas=[server-side-fallback-2026-07-01]` and `fallbacks="default"`;
     - `output_config.format` json_schema, plus effort.
   - But the only test uses a fake client whose `create(**kwargs)` accepts anything (test_suspect.py:267-272), and the one live claim contradicts another doc (section 4).
   - Nothing in the tree shows that the real SDK and API accept `fallbacks` and this output_config on `client.beta.messages`. If they do not, every window becomes an error line.
7. **[low] Exit codes for `suspect` are ambiguous.**
   - It exits 1 for a raised suspicion, for all windows failing, and for a corrupt or empty trace (cli.py:317-321). A traceback also exits 1.
   - A caller cannot tell "the model layer did not run" from "suspicion raised".
   - Exit 0 means "nothing raised", but the module docstring says "0 clean" (cli.py:30).
8. **[low] Soft A2 channel through the reasons text.**
   - Reasons are free model text (core.py:130), printed under SUSPICION (report.py:194-195).
   - A raised answer can argue that a rule finding is a false positive. Only the prompt forbids this (core.py:45).
   - Text planted in the trace can be echoed back this way.
9. **[low] Privacy: the "local" Ollama default can be remote.** OLLAMA_HOST or `--ollama-url` can name a remote host. Data then goes out over plain HTTP with no notice (backends.py:33-35), while the docs call the default local.
10. **[low] Mislabelled errors.** core.py:158-161 also catches exceptions from render_window and validate and records them as "<backend> failed". Example: `math.isfinite` on a huge JSON integer raises OverflowError at core.py:117.
11. **[low] The model sees one cwd per window** (core.py:79, 98). Per-line cwd is dropped (core.py:39), so a `cd` inside a window is invisible unless a finding mentions it.
12. **[low] REDO credential handling.**
    - Any TypeError whose text contains "authentication" is labelled missing credentials (backends.py:117).
    - The `ant auth login` hint (backends.py:107, 118) is not backed by anything in the tree.
- **A2 overall:** I found no code path where a model answer clears, lowers or suppresses a rule finding. core.run never writes findings, and report.build's result can only go up (report.py:101). What remains is the text channel (3.8) and the misrecorded model under fallback (3.1).
