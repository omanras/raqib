## 3. Findings

### Item 1: the machine, as a proof

C is the cursor (on disk), R the reach, q the count in question, P the proof (R, q and P are memory only).

The states:
- S0: q = 0 and no P (R = C).
- S1: q > 0 and no P (C at the first line in question; between C and R only lines in question and lines not sent).
- S2: P set.

The transitions as the code runs them:

Start of a try (attempt 1100-1117):
- alone = 0.
- check_file (1075-1088). Another file means a restart: C = R = q = 0, P and scanned cleared, restarts + 1.
- In S2, settle first.
- In S1, ask_first, then go_on.
- In S0, go_on.

S0, go_on at C (1172-1240):
- A line not sent at C: passed and counted (skipped, or refused locally and named), so C = R moves. tick and Stop at
  each line.
- Batch taken: C passes it, then "moved".
- A batch of one refused: q = 1, R = its end, C stays, and the try goes on at R (now S1).
- A batch of two or more refused: split (1255-1279). Each line alone, in order:
  - taken with q = 0: passed;
  - refused: q + 1, R = its end;
  - taken with q > 0: P = that line, R = P's end, state written, settle;
  - failed or token: the try ends with q and R kept;
  - Stop: ends with nothing moved.
- Cap (alone >= 100 at the top of split, or before a batch at 1205): the try ends. With q > 0 it is failed `refusing`;
  with q = 0 it is "moved".
- Failed send: nothing moves. If `late` while sending and the batch had more than one line, the next batch is half its
  size (940-943).
- End of file, or a partial line of at most 512 KiB: idle, or "moved". More than 512 KiB with no newline (TAIL):
  failed `file`.
- read_at finds another file: "again" (the next pass restarts).

S1:
- ask_first (1119-1153): asks the line at C.
    - Taken: passed, q - 1, walk_to_question passes the lines not sent up to the next line in question, state written,
    and the loop goes on while q > 0. Each counts toward the cap; at the cap the try ends "moved".
  - Refused: it stays in question, and go_on runs at R.
- go_on at R:
  - lines not sent move R only, not counted (1197-1198);
  - a batch at R taken: P = the batch (it begins exactly at R), R = P's end, settle;
  - refused: as in split, or q + 1 for a batch of one;
  - end of file or TAIL: failed `refusing`, C unmoved.

S2, settle (1281-1322):
- From C to P's start, a line not sent is passed and counted.
- Each event line is asked alone. Taken: sent + 1. Refused: counted refused. Either way it is passed, q = max(0, q -
  1), and the state is written.
- Failed, token, Stop or "again": the try ends with P kept.
- Cap: state written, "moved"; the next try settles first.
- At P's start: C = P's end with P's last sha, R = max(R, end), q = 0, P cleared (back to S0).

Stop, anywhere: "stopped" with nothing moved after the last write; run's finally writes the state (1411-1414); P is
  lost.

A restart of the process: C from the disk, R = C, q = 0, no P. The lines in question are asked again as new ones, and
  P is sent again.

What holds (certain from the code, append-only file):
- (a)
    - Every event line that settle passes was refused alone before P was sent. R advances only past lines refused
    alone or lines not sent, and P begins at R.
  - Each such line is asked again after P's take and counted only if refused then.
    - The first refusal is always the line's own alone send: a refused batch adds nothing to q, and a batch of one is
    alone.
  - A take in ask_first (an earlier line) is never a proof (1141-1143).
- (b)
  - settle walks every line from C to P's start; P's lines were all taken.
  - Lines not sent between are passed and counted once: never counted at the reach, counted when C passes them.
- (c) In a run, no line is counted refused twice, or refused and taken. Across a restart, see finding 1.
- (d) check_file runs at every try and read_at at every read, so a changed cursor line resets everything. ask_first
  never runs while P is set.
- (e) q never goes negative (1148 runs only while q > 0; 1318 clamps; 1321 resets). In an append-only file, q > 0
  means the line at C is in question, so the forwarder is never `refusing` for ever with nothing in question.
- (f) With a collector that answers within its bounds:
  - in S0 and S1 each try moves R by 1 to 99 lines until the end of the file, then sends one request a try;
  - a collector put right drains 100 lines a try with no wait;
  - in S2 every send passes a line.
  - No livelock, except finding 3.
- (g) No taken line is sent before an earlier line that is neither taken nor in question. The documented exceptions
  are FORWARD.md:32-36.
- (h) With a collector that takes everything in time: no line is sent twice.
- The docstring's claim (38) has two exceptions outside the machine:
  - `--from end` (J-12);
  - a replaced file the check cannot see (finding 6).
