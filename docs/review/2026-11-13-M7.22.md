## 3. `_give_held` and what changed around it

### a. Lost acts (SILENCE)
- **Q2, the held root's own act** (host.py:2659-2664): when the act's pid is the held root, it is neither kept nor
  given. It disappears from the round. That is harmless when the ancestor already saw it as a child. When the ancestor
  is new, see the arrival case below. No test.
- **Q6, file writes**: these are not lost. Their `via` is [] (discover.py:2184), so they stay with the talking
  ancestor. That is MORE SAID on the ancestor and is a stated hole.
- **Q7, two held keys with one pid**: neither key is in `held` (host.py:2646), so the children stay the ancestor's.
  Nothing is lost; AX-4's false cycles survive in that case. This is a stated hole.
- **A held tree that cannot write a HostChild line** (likelihood low). The child is taken from the ancestor, and the
  AP-2 loop counts it as an act beat and marks it in `self.kids` (host.py:2113-2127, 2733). `_host_lines` then skips
  the HostChild line in these cases:
  - `src.kind == "none"` (writes_host False).
    - A non-os source with `error` set, or any source with `host_error` set. A quiet tree is never attached again,
    because `_attach` runs only for trees of the round (host.py:2046). So this lasts as long as the tree stays quiet.
    The hole at host.py:3595 says "the source is attached again next round", which is false for a quiet tree.
  - `sampled` False: a tree known only from the channel, now matched in the sample through `_same_tree`.

    In each case no rule judges the child, while on main it would have been judged on the ancestor. No hole, no test.
    Q3's "host at least" overlooks the `none` source.
- **A held tree gone this same round**: this cannot happen. `held` uses the same `alive` set as the round's quiet
  test, and `ours` excludes every pid of the round. So every held key lands in quiet_keys or kept. The E4 "gone" test
  would catch a mismatch, because the acts would be dropped at host.py:2113.
- **A `via` with two held roots, or nested held trees**: the nearest root to the child takes it (`reversed(path)`,
  host.py:2659). The THREAT_MODEL says the same. No test has two held roots.
- **Q1, a candidate left with no act** (host.py:2665-2669). If the tree was in a round before, its key is in `left`
  and it becomes quiet or kept:
  - Its source is kept, and so is its ring. The ring gets entries only on AP-2 lines.
  - It gets no HostConnection lines while it talks, and `src.open` stays frozen.
  - It has no HostTree line unless an os or hooks source gains a beat.
  - It gets no new arrival when it is a candidate again (candidate_round is already set).
- **Q1, a new tree never arrives** (SILENCE, likelihood low to medium). This can happen. Construction:
  - Round n-1: agent H is a candidate. Its parent W does not talk, so W is in no tree.
    - Round n: H's connection is closed at the sample, and W has a connection open (an intermittent long-poll worker,
    an IDE host, a supervisor).
  - Discover gives W the acts [H root via [], H's children via [H]]. All of them are taken, so W is dropped.

    W never enters `self.trees`. It gets no line, no source, no NEW-AGENT-UNKNOWN, and it is not even in the round's
    "quiet" list. Its talk appears only in the inventory file. On main, W arrives in round n. A held tree's own
    ancestor cannot be newly started (a parent is older than its child) except through subreaper reparenting, so "W
    started talking" is the realistic form. No test; the Q1 test covers only an ancestor that is already a tree.

### b. Counted twice (MORE SAID)
- **One round**: a child is given to one tree only and removed from the candidate's acts. HostChild dedup is by pid
  against `src.children`; beats dedup by (pid, start) against `self.kids`. I found no double count within one round.
- **Becoming quiet in round n**: when H was a candidate in n-1, its children were already its own (it was the nearest
  talker), so nothing is new again. When H was excluded in n-1 and held in n (Q7 resolved, or a channel candidate with
  H's pid in `ours`), a child that lives through both rounds is W's in n-1 and new on H in n. That is two HostChild
  lines and two NET-TOOLs. Likelihood low. No test.
- **Introduced by this change** (likelihood low to medium, Linux with a subreaper): H is given child X in round n. In
  round n+1, H's root is gone, and X, still alive, is reparented under W. X is then new to W's `kids` and
  `src.children`: a HostChild on W, NET-TOOL on W, and an act beat on W. One process is judged on H and then on W. On
  main, X was W's from round n, so it was counted once. No test.
- **Twin rule on the held tree**: still applied. Beats go through `_once(key, given + fresh)` (host.py:2734).
  `told_twice` pairs by `tree_key`, so H's HostChild and H's os event 1 are joined. No test uses an os source on a
  held tree.
- **A held tree that is a candidate again**: its given children are already in `kids` and `src.children`, so they are
  not new. No test.

### c. Wrong tree
- **Path matching** (host.py:2657-2659): the `alive` check matches the root by (pid, image, start) in the sample, but
  the path is matched by OS pid alone. `via` carries OS pids, because discover's `_os_pids` folds back `pid + REUSE*n`
  (discover.py:2004-2008). In an inventory that holds two instances of one pid (Windows G-6 reuse across samples in
  one window, or guid-apart channel processes), an act whose `via` names the other instance is given to the held tree.
  Likelihood low, Windows only. No test.
- **A pid reused between rounds**: this is caught where starts are read, because the old key is then not alive. Where
  the start is unread on both sides (key[2] None, same image), a stranger is taken for the held tree. That is the same
  as the round's quiet test (R-5), but now acts move to that tree. Likelihood low.
- **The copied `alive` check**: the formula is the same. It runs before the round's loop adds new entries to
  `self.trees`. Those entries have pids in `ours`, so `_same_tree` gives the same answer for every key that can be
  held. The real difference is `k[0] not in ours` (by pid) against `- set(current)` (by key). A held key whose pid is
  also a tree of this round under another key is held quiet by the round but given nothing here, so its children stay
  W's. The hole does not name this case beyond Q7.

### d. Arrivals and state
- The AP-2 road changes no class, history, first_round or candidate_round, and it appends nothing to `new` or `back`.
  The class is quiet or kept, from the tree's state (host.py:2124).
- `was` is "candidate" on the first quiet round (from prev_class), then "quiet". This is correct.
- Tested for quiet (E3) and kept (the partly-read test).

### e. Rhythm
- A given child is an act beat of H at its start time (basis "started" or "stat", otherwise "round"). Host bases are
  not SOURCE_BASES, so it is binned into round n's entry (host.py:2747).
- W's ring never receives a given act.
- **Not covered (MORE SAID, likelihood medium wherever W has an os source):**
    - W's os follow is rooted at W. os_sysmon `_tree` (hooks/os_sysmon.py:397-467) takes every descendant, so H's
    processes are in it too: their Sysmon event 1 at depth 2 or more and their event 3.
    - `_source_beats` (host.py:2905-2920) turns these into W's act beats and talk beats. W, held quiet after Q1, still
    has its AP-2 line from them, so it can still reach K cycles and fire HOST-RHYTHM at high.
  - NET-TOOL also fires from W's os file on H's curl.

    `_give_held` covers only the sample's children. This is the same field case on Windows through the os source, and
    it behaves the same on main and on this code.
