## 1. Scope violations

- **tests/test_readme_top.py:386-391 (rule 1; HANDOFF line 18).** HANDOFF says: "If an exit criterion needs a file
  outside Scope: STOP and say which." E6 adds `events` to the parser. E8 needs the gate green. The gate needs
  README.md (out of Scope) to name every subcommand. That is exactly the STOP case. The builder edited the guard and
  asked a question (Q11) instead of stopping.
    - What the test now allows: `unnamed = {"events"} - <names in the table>`. Then `assert unnamed <= {"events"}`,
    which is true by construction and so checks nothing. Then `named | rest | unnamed == commands`.
    - So exactly one name, `events`, may be missing from the table. Any other missing command, or an extra name, still
    fails. It hides nothing else.
    - The questions file says the test "fails again once the table names it". It does not. Once README names `events`,
    `unnamed` is empty and the test passes. The exception never forces its own removal; it stays silently.
- **Everything else is inside Scope:** raqib/{eventlog,host,event,cli}.py, EVENT.md, THREAT_MODEL.md,
  tools/rig/check.py, rig.yml, tests/ and the questions file. raqib/event.py touches only F-4's and F-5's keys.
- **Two state-shape changes the HANDOFF does not name.** Both come in through host.py, which is in Scope:
  - `knock_rows()` now adds `for` to every knock row (host.py:1838-1840). So the state's `host.knocks` gains a key.
    - The tree entry's `candidate_by` is back (host.py:2150, 2154), so the state's `host.trees[]` carries it again
    (see section 9).

## 4. Can the writer harm the watch?

- **Exceptions.**
    - In host.py, everything is inside `except Exception`: `_events_tick` (1906-1921), `_events_end` (1925-1931), and
    `code_so_far`, which catches itself.
    - In eventlog.py, only the builder call is guarded (97-102) and only open/write/flush, for OSError and ValueError
    (113-122). `event.line(said)` and `core(said)` (105-106) are outside any guard.
    - A TypeError or ValueError there, or a raise in `knock_rows()` / `watch.lost_note()` (evaluated as arguments at
    host.py:1891-1895), escapes to `_events_tick`'s handler.
  - That aborts the whole pass. It also skips the heartbeat that follows it in the same `try` (1915).
  - `next_beat` is not advanced, so `due()` stays true and the pass is retried on every tick, not every round.
    - If the cause is deterministic, no heartbeat is ever written again. Every ledger after the failing point is never
    said. There is only one hole, in the report.
  - SILENCE. Likelihood low.
- **A full disk in the middle of a line.**
    - A flush that fails can leave a fragment without a newline. The next good line is appended onto it, so that line
    is unparseable for any reader.
  - That event is still counted `written` and recorded in `said` (123), so it is never retried.
  - Also, a file left torn by an earlier, killed run glues this run's start event to the fragment.
  - The record already has this guard (`newline_owed`, C-2, host.py:1528). The events file has none.
    - THREAT_MODEL's sentence "A line that cannot be written is a hole of the watch, never a silence" is false for
    this case.
  - SILENCE. Likelihood low (disk full, power loss).
- **A flush that fails after the bytes landed.** The line is counted as not written and retried under a new id with
  the same `rev`. A consumer then sees one `about` at the same `rev` twice. MORE SAID. Likelihood very low.
- **Cost.**
    - Every pass rebuilds every event of every ledger: `check()` plus one or two `json.dumps` each. Nothing is cached
    except the last line's text.
    - `knock_rows()` now runs `_about_of` for every knock. That is a linear identity scan over findings, source
    findings, both hole lists and the trees, so O(knocks x ledger).
  - It runs once or twice per pass (host.py:1890), and also on every tick through `state()` (KNOCKS_KEPT rows).
  - The ledgers only grow, so the per-round cost grows without bound over a watch of hours.
  - All of it runs under `self.lock`. `page()` gives up after 15 s with "not responding" (host.py:4555).
  - `step_seconds` is measured before the pass (1978), so its time is said nowhere.
  - SILENCE (the cost is unmeasured). Likelihood: rises with the watch's length. I did not measure it.
- **The file cannot be written.** Every pass retries every unsaid thing and opens the file once per event. `n` and
  `not_written` grow by the whole ledger each round.
- **In `finish`.**
  - Every events call is guarded, so the report is still printed.
  - An events hole made in the finish's pass is counted in `exit_now`. The exit can move from 0 to 3 (Q4).
    - `events_text()` (4422) has no guard of its own. Any raise there replaces the whole report with "no final report"
    (exit 1). Likelihood negligible.

## 6. id, about, rev (C-1, D-1)

- **`n`.**
  - It is incremented before the write (eventlog.py:112). A failed write skips its number; the number is never reused.
    - Ids include the run (`run_id(started, pid)`), so a resumed watch or a later run appending to the same file never
    repeats an id.
    - Two host watches sharing one home would interleave lines in one file. On Windows, Python's append is not atomic.
    I could not check whether a second host watch is refused.
- **`about`.**
    - Shared only through the `tree:?` fallback, or two keys whose `tree_word` is the same (a start of None and a
    start of ""). Both are unlikely.
  - `knocked.for` can name something never said in the file. Two cases:
    - a finding whose builder refused, in run B-unbuilt; test_e5 checks only the MAIN runs;
    - a knock for a suspicion, which falls back to its tree. Then "the thing it knocked for" is said to be a tree.
    - MORE SAID. Likelihood low.
- **"The same again".** The comparison leaves out `VARY = id, n, rev, time` (eventlog.py:36).
  - Leaving out `time` hides a change of an entry's own time alone. That is rare.
    - Between beats, a blind spot and the lost-words note are held whole without being built (line 94). So any change
    to their kind or detail also waits for the beat.
  - I found no rev made with nothing changed, except the partial-flush retry (section 4).

## 7. The heartbeat (F-3)

- **Clock and timing.** It runs on the monotonic clock and is checked only in `tick`. A late tick makes a late beat;
  several missed beats become one. A skipped beat is never said as skipped (eventlog.py:141).
- **When the pass fails, no beat is written** (section 4).
- **When the reader failed,** the beat says HOST READER FAILED (E-1). If the band has a word outside the list, the
  heartbeat is not built and becomes a hole. That beat is lost, because `next_beat` was already advanced.
- **What is held until a beat:** a tree's evidence, a blind spot's count, the lost-words note.
- **What is said at once:** a tree that is knocked, becomes benign or history, or changes its `by`. All of that is in
  TREE_CORE.
- I saw nothing held that a consumer needs at once, other than what the Table already saw.

## 10. The twelve questions: what the code does now

- **Q1.** At every beat each present tree is said again: one event per tree whose only changes are seqs and cites.
  Between beats the file does not hold a tree's latest line.
- **Q2.** Just before the end, the file gets a burst: every tree whose evidence moved, every blind spot whose count
  changed, the lost note.
- **Q3.** On an unwritable file, "not written" counts attempts. It grows by the whole unsaid ledger each round, so a
  short watch can report thousands. A person cannot tell lines from things; a collector sees `n` gaps of that size.
- **Q4.** Any events hole makes a watch with no finding exit 3, "1 hole(s) of the watch". An events file that cannot
  be written turns CLEAN into INCOMPLETE.
- **Q5.** The default beat is max(60, every). `--every 120` prints "a heartbeat every 120 s". The window gets the same
  value from HostWatch (host.py:1880).
- **Q6.** A later rev carries the entry's first time. A SIEM that takes `time` as the timestamp files rev 2 hours in
  the past.
- **Q7.** Empty file: exit 1, "no event". A repeated id is the second line's problem.
- **Q8.** `for` can name a tree for a suspicion's knock, and a `finding:i` that is never said (section 6).
- **Q9.** As in section 8.
- **Q10.** Confirmed: test_host_sources.py:771 counts docs/GUIDE.md's paragraphs.
- **Q11.** As in section 1. The exception is permanent and silent once README names the command.
- **Q12.** On Linux, `platform.node()` is `os.uname().nodename`. On Windows (no `os.uname`), CPython's `platform`
  module imports `socket` and calls `socket.gethostname()`. So the static guard is sidestepped, not satisfied. Either
  way it is a local call, and HANDOFF E5 allows `socket.gethostname`.
