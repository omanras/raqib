## Q1 (scope) - the gate's count of HOST-RHYTHM lines is not in tools/gate.py

E4 asks that "tools/gate.py's own count of HOST-RHYTHM lines reads the new
level". tools/gate.py has no such count: it does not name HOST-RHYTHM, a
rhythm or a level at all (`grep -n "RHYTHM\|rhythm\|medium\|watch"
tools/gate.py tools/gate.sh`: nothing).

The count is in the CI workflow, .github/workflows/gate.yml, in the
`watch --host` step (line 239):

    rhythm = len(re.findall(r"^  \[medium\] HOST-RHYTHM ", text, re.M))
    assert rhythm == 0, ("HOST-RHYTHM on a 2-round runner watch", text[-3000:])

and its comment (lines 236-238). The test that pins that line is
tests/test_rhythm.py `test_e5_ci_counts_rhythm_zero_on_the_runners`
(line 581), which reads .github/workflows/gate.yml, not tools/gate.py.

.github/workflows/gate.yml is not under Scope. If AT-1 lands without it,
the report says `[high] HOST-RHYTHM`, the workflow still counts
`[medium] HOST-RHYTHM` lines, finds none in every run and asserts 0: the
check passes whatever the runners do. That is a count that can no longer
see what it counts (silence, CLAUDE.md rule 4), and the local gate cannot
show it (the workflow runs only on GitHub's runners). So E4 cannot be met
inside Scope, and landing E1 without E4 would blind the CI check.

Asked: add .github/workflows/gate.yml to M7.18's Scope (line 239 `[medium]`
to `[high]`; tests/test_rhythm.py:581 follows, already in Scope), or say
where the count is to read the new level. A choice for the Table, not
built: the pattern could match the rule id at any level
(`^  \[[a-z]+\] HOST-RHYTHM `), so a later change of level cannot silence
it; that changes what the line pins and is the Table's to decide.
