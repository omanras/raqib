## Questions
- Q1 (E1: a candidate left with no act). Built as discover's own rule (B-6: "a talker with an act is
  a candidate"): it is dropped from the round's candidates. The watch then classes it by its usual
  formula: held before and its root in the sample, so quiet - though it talks (THREAT_MODEL already
  says a root that talks with no child at the sample is quiet). While quiet its own talk is not in its
  host record (no HostConnection lines) and it has no rhythm line unless a source gains a beat.
  Tested (`test_e1_a_candidate_left_with_no_act_is_no_candidate_and_is_held_quiet`). Is that the
  Table's reading, or should such a talker stay a candidate of the round with no act?
- Q2 (the held root's own process). The ancestor's act whose pid IS the held root (the agent's root
  process itself) is taken from the candidate by AY-1's words ("the child itself included") and given
  to no tree: a tree is not its own child (trees_of never lists the root among its children). Left
  with the ancestor it would keep the ancestor a candidate every round. Confirm.
- Q3 (a quiet tree that gains an act but has no os source). Every tree that was ever in a round has a
  source in self.sources (host at least), so it gets its line by the AP-2 road; the line is made only
  when a given child is new to the tree (not yet in its seen children), as AP-2 makes no line without
  a new beat. A given child already seen gives no line and no HostChild. Confirm.
- Q4 (what the line says). AR-3 sets acts 0, no endpoints, no cites on a line of a tree not in the
  round. A held tree given acts of this sample says their count and the cites of the first three (they
  are of now, not of an earlier sample); endpoints stay empty. Is that AR-3's intent?
- Q5 (kept). E1 gives to a kept tree too. A round whose connections were not read at all has no
  talker and so no candidate: nothing is given (tested as not touched). A round whose connections were
  only partly read can have a candidate beside a kept tree; then the kept tree is given its children by
  the same code (tested: `test_e1_a_kept_tree_is_given_its_children_in_a_round_whose_connections_were_partly_read`,
  the agent's lines class kept, its children its own).
- Q6 (file writes). A file-write act carries `via: []` in the inventory, so a write by a process under
  a held root cannot be placed by its path; file-write acts are not moved (also when the writer is the
  held root itself) and stay the talking ancestor's. Said in the rule's hole. Should discover give a
  file write its path (outside this task's scope)?
- Q7 (two held trees of one root pid, e.g. a guid-keyed brief tree and its sampled one): neither is
  given (no guess). Said in the hole.
- Q8 (the agent's quiet lines). In E3's case the agent's ring keeps one cycle (its round-1 talk, its
  round-2 act) on every later line; no later act makes another (AY-3), and it never fires. As built.
- Q9 (footprints). A candidate dropped by Q1 may still be named by a footprint link of the round's
  inventory (discover links a footprint to a candidate id); the footprint code reads the inventory as
  discover gave it. Not tested here.
- Note: the `alive` test is written again in `_give_held` (two lines, the same as the round's quiet

# M7.22 REDO - the builder's notes and questions (ADR-0007 Amendment AZ)

## What was built
- AZ-1: `_give_held` gives a process act only when a held root's pid is in its `via` (strictly above it); the act
  that is the held root stays its candidate's. The code that dropped a candidate left with no act is gone: a
  candidate is always kept (`dict(c, acts=keep)`). AZ-2: one test, `HostWatch._host_unwritable(key, brief)`, read
  by `_host_lines` (its old two skip conditions, unchanged in effect) and by `_give_held`; where it gives a reason,
  the act stays, and a hole of kind `held-not-given` says so once per held tree. AZ-3: `self.given_marks`
  ((pid, started) -> (held key, candidate word)), set at the first giving and pruned when the pid leaves the
  round's process sample; `_given_elsewhere` is read where a child is first taken as new (the AP-2 loop's
  `gained`, `_child_beats`, `_host_lines`' fresh children). AZ-4: `input_meta.inventory_tree` on a held tree's
  HostChild line only; the word is `tree_word(inv_key(candidate))`, where `inv_key` is trees_of's own key formula,
  moved into a function both read. No generated fixture changed (the regenerate-and-compare tests pass unchanged).

## Questions
- R1 (AZ-1: can a candidate still be left with no act?). Not in a discover-shaped inventory: the held root under a
  talker is its act (via []) whenever a child under it is. Only an inventory that lists a child via a held root but
  not the root itself would do it; the candidate then stays with an empty act list (a tree with no child, not
  dropped). Not tested, as no such inventory is built by discover.
- R2 (AZ-2: an os source's host record). `_host_unwritable` is the state before the round. For a host or hooks
  source, a write that fails in this round sets host_error, and the children given in that round are in no record
  (the source-unwritable hole says the lines are not written); from the next round nothing is given. For an os
  source, AL-1 sets no host_error on a failed write, so a held tree with an os source is given children every round
  even while each round's write fails (each round's hole says so). Should a failed host write of an os source stop
  the giving too?
- R3 (AZ-2: once per tree). The `held-not-given` hole is said once per held tree for the life of the watch, with
  the first reason; a later different reason (the source ends after the record failed) is not said again.
- R4 (AZ-3: the mark's life). A mark lives while its pid is in the round's process sample (a round with no sample
  prunes nothing). Where a child's start was not read (started None), a process that reuses its pid between two
  samples is taken for the given child and is not new on another tree. A child that was the held tree's own while
  it was a candidate (never given) and later finds a new parent under the ancestor is new there, as on main: AZ-3
  covers given children only.
- R5 (AZ-4: the key's shape). `inventory_tree` is a string: every child given to one held tree in one round shares
  the path above the held root, so it has one nearest talking ancestor; were there more, the words are joined by
  ", ".
