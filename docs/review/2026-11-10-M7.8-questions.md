## Questions for the Table
- Q-1 (E2) The Windows programs: built as below; the Table rules. Matching is by image name only, so each
  fires on every use of the program, whatever its arguments.
  NET-TOOL, added:
  - bitsadmin: the BITS command line; /transfer downloads and uploads URLs (a known living-off-the-land
    fetcher); rare on a developer machine.
  - tftp: Windows' optional TFTP client; a file transfer program and nothing else.
  - finger: System32\finger.exe, a network client with a documented use for fetching text; no developer use.
  - plink, pscp, psftp: PuTTY's ssh, scp and sftp, the Windows twins of three names already listed.
  - winscp: WinSCP's command line (winscp.com and winscp.exe both normalise to winscp): SFTP/FTP/SCP.
  NET-TOOL, left out (the Table may add them):
  - certutil: `-urlcache` downloads, but developers use `-hashfile` for checksums: by name it would fire
    on every checksum; the download is an argument, unseen.
  - mshta, msiexec, regsvr32, rundll32: execution programs that can fetch a URL only by an argument; most
    uses are local (installers, shell extensions).
  - powershell, pwsh, cmd: shells; Invoke-WebRequest is a cmdlet inside them (an evasion line now).
  - git and git-remote-https: Git for Windows starts git-remote-https.exe for every fetch over HTTPS, so the
    os source would see git fetch, which the hook rule left out on purpose ("git fetch: git is not on the
    list"); kept consistent.
  - nslookup, ping, net, robocopy, wmic: diagnostics or local programs; nslookup and dig are already on the
    evasion list as "not on the list"; ping is a child of Kimi's field tree (DESTRUCT-CMD's negative).
  - putty: the GUI a person opens; an agent drives plink.
  - rclone, gh, docker, npm, pip: network programs on every platform, not Windows ones; the hook rule's
    evasion list names them as "not on the list".
  DESTRUCT-CMD, added:
  - format (format.com): formats a volume.
  - diskpart: partitions and cleans disks.
  - cipher: /w overwrites free space, /e encrypts files in place; rare on a developer machine (flagged:
    `cipher` with no argument only lists).
  - sdelete, sdelete64: Sysinternals' secure delete, the shred of Windows.
  - vssadmin: `delete shadows` destroys the volume shadow copies (backups); `list` is benign and looks the
    same.
  - wbadmin: `delete catalog` / `delete systemstatebackup` destroy backups.
  DESTRUCT-CMD, left out:
  - del, erase, rd, rmdir (cmd), Remove-Item, Clear-Content, Format-Volume, Clear-Disk (PowerShell):
    builtins and cmdlets start no process; they are named in the evasion line. (Git for Windows' usr/bin
    rm.exe, rmdir.exe, dd.exe, shred.exe and truncate.exe are matched already: they normalise to the listed
    names.)
  - wmic (`shadowcopy delete`), fsutil (`setzerodata`), bcdedit, wevtutil (`cl`), robocopy (/MIR, /PURGE),
    forfiles, cleanmgr, takeown, icacls: their destructive use is an argument and most uses are queries; wmic
    is called by developer tools (process listings), wevtutil is the os source's own reader.
