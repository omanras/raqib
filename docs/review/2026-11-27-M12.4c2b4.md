  ProgramData as not measured.
- **The place and every folder inside are named again by path after they were read** (wininstall.py:836, 846-851). A
  place or folder replaced by a link in between would be listed through. ZE-5 records this for the place only, and no
  document of this branch says it (finding 15).

- **The purge erases the watch's own record and leaves no trace but the console lines.** No rule in raqib/rules names
  an agent asking for `remove --purge` (finding 17). This is a suspicion only.
- **Words that say more than was done or known:**
  - RECORD_TAKEN says "removed" before anything is removed (finding 12).
  - RECORD_UNTOUCHED says "the service is not gone" where that is not known (finding 13).
  - The RESULT says "not the place as Raqib's service makes it" for a place that was never read (finding 14).
  - The docstring's measured sentence says "(refused)", which was not measured (finding 16).

## The nine questions

**1. Built as ruled.** Yes, except as noted above. The builder's three choices where ZE is silent:
- (a) The RESULT gets added words where the service is not gone: `<result>; the record NOT removed: not touched`.
  Acceptable, and consistent with Y-4. No ruling needed.
- (b) A bad listed name is never handed to the system and is counted. Acceptable and needed, but incomplete (finding
  1). The Table should record the set of refused forms.
- (c) A file that is a reparse point is not removed either. Acceptable: it is stricter than ZE-2's "a folder inside",
  and the documents already say "a reparse point". The Table should record it in one line.

**2. Nothing outside the place.**
- Every path is built as `"%s\\%s" % (folder, name)` (842). Folder is the place, or a path built the same way.
- The place is `ntpath.join(root, "Raqib")` after `_drive_path(root)` (winservice.py:522-523). That function requires
  a drive letter, a colon and a separator, and rejects any ".." segment.
- The judged string and the removed strings are the same, so the object judged is the object removed, except for ZE-5.
- `_one_name` refuses "", ".", "..", "\\", "/", ":" and NUL. It hands three kinds of name that Windows rewrites:
  - names that end in a dot or a space,
  - names made only of dots and spaces,
  - DOS device names.
- By the system's documented normalisation (relative segments are resolved before trailing dots and spaces are
  trimmed), none of these names the folder above. They can name a sibling ("x." becomes "x"), the folder itself, or a
  device. Deletes of those fail, so I traced no removal outside the place. Not measured.
- A name that differs by case, or a very long path, stays inside the place or fails and is counted.
- A replaced place: the code then lists through the link and removes the target's contents under the same path string.
  This is bounded only by ZE-5's trust, and is not said.

**3. Never through a link.**
- On Windows, `entry.stat(follow_symlinks=False)` is built from the find data: the name's own attributes, with 0x400
  set for any reparse point. No folder is entered before its attributes are known.
- The reparse test comes before the folder and file branches (846).
- If `st_file_attributes` is missing, or the stat raises, the whole listing fails: the folder is counted and left, and
  nothing in it is handed (363-366). This is untested.
- A place that is itself a reparse point is refused by `place_judged`, before any call: `read_place` opens with
  FILE_FLAG_OPEN_REPARSE_POINT, then 467-468, then `_record` at 890-892. The READINGS 0x410 case asserts `paths ==
  []`.

**4. Order with the service's remove.**
- Only two results let the record be touched: (0, "nothing installed") from OpenServiceW 1060 (765-767), and (0,
  "removed") from the name asked again answering 1060 (801-803). In both, `held.failed` must be false.
- A service of the name in any state, one that is not Raqib's, a fault, or "removed by DeleteService, whether it is
  gone NOT KNOWN" all give exit 1, and the record is untouched.
- If the service's remove raises, it is caught at 914-916, the exit is 1, and the record is untouched.

**5. Failure and honesty.**
- Errors are counted by number, or by words where there is no number (`_number`, 385-388).
- The first path is said. A RESULT says "removed" only where `remove_folder(place)` succeeded.
- A fault in the middle gives "NOT KNOWN what of it was removed" with exit 1 (929-931).
- The lines are bounded: there are few distinct error keys, and each path is cut at 300 characters.
- Every path is printable ASCII.

**6. The real calls on Windows.** What I expect, from reading:
- `os.scandir`: denied gives winerror 5.
- `os.unlink` goes through CPython's DeleteFileW wrapper. A read-only file answers 5, and the wrapper does not clear
  the attribute as far as known. Such an error 5 is then said "an administrator is needed", which is untrue for an
  administrator.
- A file held open without share-delete answers 32, said as "error 32".
- `os.rmdir` on a folder that is not empty answers 145. A shell whose current folder is inside answers 32.
- Not known without a run:
  - a read-only folder;
  - delete-pending versus immediate removal (whether a file deleted but still open blocks its folder);
  - long paths when LongPathsEnabled is off (3 or 206 expected);
  - device-name handling on Windows 11.

**7. The tests.**
- Each ZE sentence has a test that fails if the code is wrong, except the ASCII sentence and the per-form name
  refusals (finding 1).
- The stand-in Manager flags a link that is entered or removed, and a folder removed while it still has names. It
  flags a path outside the place by string prefix only, so ".." passes `inside_only`. The ".." test checks that
  separately.
- No test reaches the real file system or the real service manager on the win32 jobs:
  - the helper always hands stand-ins (354);
  - the real System's three calls run against FakeOs (1284);
  - the off-Windows test is skipped on win32 (1227);
  - `cmd_service(remove --purge)`, which would now reach the real objects, was removed from the loop.
- The loosened "os." ban is strict for `os.<attribute>`, but not for a bare `os` name (finding 10).

**8. Documents and help.** True to the code except findings 6, 7, 15 and 16. Nothing claims a real-machine run of this
  branch.

**9. Scope and rule 7.** Clean.

VERDICT: NEXT

1. **medium.** wininstall.py:816-818 `_one_name` hands names that end in "." or " " (including names made only of dots
  and spaces, such as "..."), and DOS device names (CON, NUL, AUX, PRN, COM1-9, LPT1-9, CONIN$, CONOUT$, with or
  without an extension). Windows' normalisation then makes the call name another name than the one listed, the folder
  itself, or a device, which is outside the place. E2 holds only on the strings handed. **Fix:** count these and never
  hand them. Test each refused form on its own: today only ".." and "D:\elsewhere" are tested, so dropping ":" from
  the set fails no test. The Manager's `_path` (tests:221-228) should judge every component after the place, not just
  the prefix.
2. **medium (field, Table).** The runner reports STOPPED after `done` and only flushes service.txt; the process lives
  up to 15 s more (winservice.py:726-727, 838-842). The purge follows the name's 1060 at once, so expect error 32 on
  service.txt and exit 1 at times. That is honest, but X56's "ends with 0" may read 1. Not measured. The Table should
  know before wiring X56.
3. **medium (A3, ZE-3, Table).** The record is touched when no service named RaqibWatch exists, even while a service
  of another name runs the runner on the same place, as the rig's hand-made ones do. ZE-3's own reason ("may still
  write") applies. The Table should rule on it or record it.
4. **medium/low (Y-4, Table).** Error 5 inside the purge is said "an administrator is needed" (wininstall.py:100, via
  878). The caller there is an administrator who has just read the place. A read-only file, a name pending removal or
  a mapped image all answer 5. E3 asked for these words; ZE-4 ties them to the place's own list, which `place_judged`
  already says. The Table should rule the words for error 5 inside the place.
5. **low/medium.** "is gone" (wininstall.py:135, 864, 872) rests on RemoveDirectoryW alone, while X-6 asks the name
  again before saying "removed". **Fix:** read the place again and require absent, or say only what was done.
6. **low (E5).** SERVICE.md:809-810 and wininstall.py:44-45 say the runner's start uses `place_judged`. It runs
  `prepare` (winservice.py:574-586), which is tied to `place_judged` by number in the tests. **Fix:** "place_judged,
  the install's reading, tied by the tests to the runner's prepare". ZE-1's "one function" wording is the Table's.
7. **low (E5).** cli.py:311 "1 left as it is" is untrue after a partial purge. **Fix:** "1 not all removed, what is
  left said".
8. **low (E4).** No printed path in the purge comes from a non-ASCII or non-printable listed name. The non-ASCII link
  at tests:776 is never the first said, so `_error_said` at wininstall.py:876 and 879 could be dropped with nothing
  failing. **Fix:** make such a name the first link and the first error, and assert its escaped form.
9. **low (E4).** tests:1239 replaced `remove(real, io.StringIO()) == 2`, the default road with no stand-ins. **Fix:**
  keep the old line beside the new one.
10. **low.** tests:1022-1027 and 1036: with `os` imported at module level, a bare `os` passes (getattr(os, ...), or
  aliasing `os.unlink` in another function). **Fix:** assert every Name "os" is a scandir/unlink/rmdir call inside its
  own System method. "os.environ" is listed twice, which is harmless.
11. **low.** The ZE-3 tests (tests:843-850) have no case where the service's remove raises, and none for "whether it
  is gone NOT KNOWN". The branch at 922 is generic, so the code holds; a case would pin it.
12. **low (A5).** RECORD_TAKEN (wininstall.py:133-134) says "removed bottom up" before anything is removed. **Fix:**
  "to be removed bottom up".
13. **low (A5).** RECORD_UNTOUCHED (wininstall.py:128) says "the service is not gone" where that is not known: the
  manager not opened, the name not asked again, a fault. **Fix:** say the service's remove did not end gone or none
  installed.
14. **low (A5, Table).** For a place never read (error 5, error 3, ProgramData not a drive), the RESULT says "not the
  place as Raqib's service makes it" (wininstall.py:892). These are ZE-1's words, but nothing of the place was read.
15. **low (A5).** ZE-5's re-naming by path is not said in SERVICE.md or the docstring, for the place or for the
  folders inside (wininstall.py:836, 846-851). **Fix:** one sentence in the ruled paragraph.
16. **low (A5).** wininstall.py:51 has "(refused)" inside the measured sentence; that was not measured. **Fix:** drop
  it, or say "which place_judged refuses".
17. **low (A3, suspicion only).** The purge erases the watcher's own record and leaves no trace but the console lines.
  No rule names an agent asking for it. This is the Table's.
18. **low (ZE-1, recorded).** Anything inside a taken place is removed, whatever made it; for example, a program copy
  an administrator put under ProgramData\Raqib, which passes the check.
