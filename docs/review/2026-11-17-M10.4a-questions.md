# M10.4a - questions for the Table (ADR-0011 Amendment R-1, R-4)

The builder's choices where HANDOFF.md did not rule. None is answered here; each is how the code stands.

1. **check_name stays in raqib/forward.py.** It raises forward's UsageError, and link.py may not import the
   forwarder. `forward.status` calls it before `link.read`, so a bad NAME is the usage error it was.
   `link.read(name=...)` checks the name against NAME itself: a name that is not a forwarder's gives no row
   (no path is built from it, so `../x` reads nothing). Should link have a check of its own that the window
   (M10.4b) uses, and should a bad name there be a row rather than no row?

2. **The further line for more than 64 states**, written after the 64 rows:
   `raqib forward --status: N more state(s) in FOLDER not read: at most 64 are read, in order of name`.
   The exit is `link.worst` of the 64 rows read: a state that is counted and not read does not change it.
   Under CLAUDE.md rule 4 (what is not read is not known), should a count above 0 make the exit 3 instead?
   That would mean a host with 65 calm forwarders always says 3.

3. **A second new output line.** E3 says a state over 1 MiB is UNREADABLE "with that reason". So status says:
   `the state PATH cannot be read: it is longer than 1 MiB, more than a forwarder writes (it is not read
   whole)`. Before this task, such a state was read whole and judged. No earlier test covers this case, so
   every covered output is still byte for byte, but this is a second new line beside the further line.
   It is read as at most 1 MiB + 1 byte, and a state of exactly 1 MiB is read.

4. **Pipes and devices are not waited on.** link opens a state with O_NONBLOCK (where the system has it) and
   reads only a regular file. Anything else - a directory, a pipe, a device - is UNREADABLE with the line a
   directory already had (`the state PATH cannot be read`). Before, `--status` waited for ever on a pipe
   with no writer, and read a link to /dev/zero without end. This is a behaviour change for cases no test
   covered, made under R-4's "never in the way". Is it kept?

5. **The count of the rest.** `read` returns `link.Rows`, a list subclass. Its attribute `rest` is the number
   of states past LINKS_MAX. The other shape would be a `(rows, rest)` pair. Which should M10.4b read?

6. **`state` is None wherever a row is UNREADABLE.** That includes JSON that parsed but that `state_problem`
   refused, so the window gets no field of a file that is not a forwarder's state. `refused` is None in the
   same rows, as `--status` says "unknown" there. Is that right for the panel?

7. **What moved beyond E1's list**, because the moved code needs it and none of it touches the network:
   SHAPES, SCHEMES, DELIVERY, DELIVERIES, DELIVERY_OF, FACILITIES, FRAMINGS, HEAD_MAX, SHA, _count,
   _instant, _state_problem. HEAD_MAX also bounds the forwarder's own head hash (N-3). It now lives in link
   and forward takes it. PLAIN, PORT_OF, FACILITY, UsageError, check_name, iso and events_default stay in
   forward.

8. **raqib.host loads the network modules.** E2 allows raqib.host (for host_dir), but importing raqib.host
   imports raqib.ui, which imports http.server, socket and ssl. So "imports no network" holds for link.py's
   own import statements, which is what the AST test reads, and not for everything Python loads when link
   is imported. The fresh-interpreter test checks raqib.forward, raqib.cli and raqib.app only. Should
   host_dir, or the folder's rule, move somewhere that imports nothing, so the reader loads no socket at all?
   That needs raqib/host.py, which is out of this task's scope.

9. **The clock is called once in every case.** `forward.status` now calls `clock()` once before reading,
   even when there is no state. Before, it was called only when there was a name. No test sees the
   difference.

10. **FORWARD.md says one sentence.** The bounds (64 names, 1 MiB, the further line, pipes not waited on)
    are not in FORWARD.md or the guide. Should they be said there?

11. **No function was kept in forward for a patch.** No test in tests/test_forward.py or
    tests/test_forward_rig.py patches a moved name on `forward`. The tests that patch `forward.os.replace`,
    `forward.os.fsync` and `forward.os.link` patch the os module itself, which both modules share, on the
    forwarder's write path, which did not move.
