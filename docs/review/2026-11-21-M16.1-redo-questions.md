# M16.1 REDO - questions, choices and what was not run (2026-11-21)

The builder's file for the Table (CLAUDE.md rule 6), for HANDOFF's R1 to R9 (ADR-0017 Amendment A). Nothing here
is answered locally.

## What was not run here

- **No engine and no docker here.** Nothing of the pipeline, the templates or the six searches as they now stand
  was run against Elasticsearch or OpenSearch. The rig's job `siem` is their first run. New and unmeasured:
  - The check script: two Painless functions, `typed` and the recursive `walk` (depth, text length, the count of
    keys, an empty key), declared before the statements; `for (def e : map.entrySet())`; `tally.set(0, ...)` on a
    list; a `throw new IllegalArgumentException(...)` per reason. It runs before any field is written.
  - The mapping script: a function `Map obj(Map m, String k)` that makes a part of `ctx` only where it is not a
    map already (so a shipper's `host.*`, `observer.*`, `rule.*`, `process.*` stay); `new ArrayList(map.keySet())`;
    `Collections.sort`; `subList(0, 50)`; dot assignment on maps returned by the function (`h.name = ...`).
  - `on_failure`: a single `remove` of `raqib`, and `set` of `@timestamp` with `override: false`.
  - The template's `priority: 200`, and `raqib.prev` and `raqib.unknown_keys` as keywords.
  - silence.json and runs-no-end.json as written. Amendment A says the engine's own clock was read inside the
    selector on both engines, but not by which expression: the probe (siem_probe3.py) tried
    `System.currentTimeMillis()` first and `new Date().getTime()` second. The searches use the first (Q1).
    The `terms` order by the `deadline` sub-aggregation is the probe's; the `multi_terms` has no order (the
    probe's form).
- **sigma-cli was run here, not against an engine.** In a throwaway virtual environment in the session's scratch
  folder (not in the tree), with exactly the versions the rig's job now pins (sigma-cli 3.1.0, pySigma 1.5.1,
  pysigma-backend-elasticsearch 2.1.1, pysigma-backend-opensearch 2.0.3), every rule converted to `lucene` and
  `opensearch_lucene`; the new rule gives `event.action:heartbeat AND (NOT raqib.state:WATCHING)` in both.
- **The pins are not the rig's printed versions.** I could not see what the rig printed at its run. The pins are
  the set pip resolves today for Python 3.12 (`pip install --dry-run --python-version 3.12` of the three
  packages), the same set used above (Q8).
- **The rig's job itself** (its YAML, `--beat 5`, the pinned install) has not run.
- **tools/rig/siem_run.py** was run only against a stand-in engine with a clock of its own (tests/
  test_siem_content.py): a faithful one, one that judges silence by the event's `time`, one whose arrival is
  an hour late, one that drops a shipper's fields, one that refuses the deep lines, one that miscounts, a Sigma
  conversion that takes its near misses too, a sigma-cli that is missing or fails, refused content, and a closed
  port. Its checks (`check_of`) and mapping (`ecs_of`) mirror the pipeline's text; the rig is what says whether
  the two agree.

## Design questions

- **Q1. Which clock.** The selectors read `System.currentTimeMillis()`. If the rig says that expression is not
  allowed in one engine, the other the probe tried is `new Date().getTime()`. Which one did the Table's
  measurement take?
- **Q2. host.name on an error document.** The pipeline does not set `host.name` on an error document: it leaves
  whatever a shipper set there (the line could not be trusted far enough to read `watch.host` from it). R3 says
  "sets host.name ... on an event and on an error document": should it set `host.name` from the line's
  `watch.host` where that is a text, even on an error document?
- **Q3. message.** On an event with no `summary` the pipeline removes `message` (the line, which a shipper put
  there), as M16.1 did: the line is in `event.original`. Is `message` a field a shipper set, which SA-4 keeps?
- **Q4. FINISHED.** The new Sigma rule takes every heartbeat whose `state` is not WATCHING, as R4 says; that
  includes FINISHED, the heartbeat of a watch that ended its rounds in order (said as a false positive in the
  rule). Should FINISHED be left out?
- **Q5. The bound of runs.** runs-no-end.json keeps the probe's unordered `multi_terms` (by count): past 10000
  runs the cut is the runs with the fewest lines, which are the likeliest killed. Ordering it by the deadline
  as silence.json is was not measured in a `multi_terms`.
- **Q6. What the pipeline checks.** It checks the kind of value of every top-level key the spec knows, of every
  key of `watch` and of `rule`, and of `subject.pid` and `subject.image` (the keys an engine types or the
  pipeline moves out); not the keys inside the other parts kept whole (the engine takes any value there), and
  no closed list of words but `kind` (`severity` outside its five words stays `raqib.severity`, with no
  `event.severity`). Is that the ruling's "a base key ... of another kind of value"?
- **Q7. Unknown keys inside a part.** A key the spec does not know inside a part the spec names (`evidence.zz`,
  `watch.zz`) is removed and listed as `evidence.zz` as a top-level one is. The items of a list (the cites) are
  not looked into.
- **Q8. The pins.** See above: the set pip resolves for Python 3.12 today, not the rig's printed set.
- **Q9. The template's priority.** 200: above Elasticsearch's own templates for logs and metrics, under nothing
  of Raqib's. Any number is a guess about the SOC's other templates.
- **Q10. A shipper's `host` that is not an object** (an old Logstash writes `host` as a text): on an event the
  pipeline replaces it with an object holding `name`; on an error document it is left as it is.
- **Q11. The near misses.** Each rule has one or two (siem_run.NEAR): the alarm rule's is a DRIFT source finding
  with alarm false; the hole rule's is a knock; the class rules' is the DRIFT finding (and for persistence the
  knock that names PERSIST-RUN-KEY); the unnamed agent's is a finding of NEW-AGENT; the watch's INCOMPLETE end's
  are a WATCHING heartbeat that holds an INCOMPLETE result and a CLEAN end; the heartbeat rule's is that
  WATCHING heartbeat.

## Choices the HANDOFF did not make

- The pipeline's lists of known keys and of the kinds of value it checks are made from EVENT.md's Keys table
  (siem_run.known; a test holds the pipeline's text to them), so a key added to the spec fails a test until the
  pipeline is made again.
- The order of processors: the schema (`fail`, as measured), every other check (one script), the date, the
  arrival, then the mapping script, so that no check can fail after a field is written.
- An error document: only `raqib` is removed; `event.kind` pipeline_error, `error.message`, `event.ingested`;
  `@timestamp` the arrival unless a shipper set it; `message` and `event.original` the line.
- The bounds' words in `error.message` begin "not an event:"; the json processor's and the date processor's own
  messages are the engine's.
- Searches: `alarm.json`, `rule.json`, `hole.json`, `watch-not-0.json` now sort by `event.ingested`; both
  searches of silence filter on `raqib.watch.beat` and `event.ingested` existing (an error document has
  neither) and the runs one on `raqib.watch.run`.
- siem_run.py: the made-up events are EVENT.md's examples with a host `made.example`, a run, an id and an n of
  their own; the odd lines are made from the heartbeat example (`odd.example`), each followed by a heartbeat of
  another run; the review's lines beside the Table's twelve (`rule.fp_budget` a text, `rule.attack` of objects, a
  top-level dotted key) and three that are events with unknown keys (one, a dotted one, sixty); the shipper's
  fields are `host.hostname` and `host.name` `shipper.example`, `host.ip` 192.0.2.7, `agent.type`, `log.offset`,
  sent once with an event and once with a line that is not JSON. Silence and the runs with no end are judged by
  the runner's own send times: a host or run is surely silent when the latest of its deadlines by the clock after
  the send is before the clock before the search, surely not when the earliest is after the clock after it; the
  others are said as not sure and not judged. The engine's order of hosts is checked by its own deadlines.
- A Sigma conversion into more than one query is counted as their OR.
- siem_content.py reads the rules as the report does (`report.rule_table(engine.load_catalog(...))`); a kind the
  code does not declare is written `none`.
