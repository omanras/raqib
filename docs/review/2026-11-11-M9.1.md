## Findings

**D1 must-fix: a closed terminal or a dropped ssh does not get E1's result. ADR-0010's FOR case is not met and the README claims it is.**
- Case: run `raqib watch ~/p` in a terminal emulator, then close the window.
  - The tty is hung up, so writes return EIO, and SIGHUP is raised as AskedStop in the nap.
  - watch.py:1397-1398 writes "\nraqib watch: stopped (SIGHUP)\n" inside the `except KeyboardInterrupt` clause. A tty stdout is line-buffered, so the write flushes and raises OSError.
  - That OSError leaves loop() from inside the handler, so conclude() (watch.py:1273-1274) never runs:
    - finish() is skipped: watch.json is never marked finished.
    - unregister() is skipped: the registry row stays `watching`, `finished: null`.
  - close() still runs. The OSError then passes through cmd_watch (cli.py:1185-1190) and main(), which has no handler (cli.py:1305-1313). Python exits 1 from the traceback, or 120 when its final stdout flush fails.
- The host watch fails the same way at host.py:4104-4105 and 4225-4227, and also skips HostWatch.finish and stop_sources.
- README.md:24 lists "a closed terminal, a dropped ssh" with "its exit code 0 / 1 / 3", and cli.py:116-120 says "the registry row finished".
- The builder's Q-5 (questions.md:118-121) says "The registry row is marked and watch.json written before the report is printed". That is false: the "stopped" line comes before conclude.
- test_first_run.py:651-666 sends SIGHUP to a child whose stdout is a file, so it cannot see this.
- This is not a regression from 0e8b007, where SIGHUP killed the watch.

**D2 must-fix (false statement to the person): README.md:24 and cli.py:123-125 say that after SIGKILL or TerminateProcess "`raqib report <trace>` gives the findings", and the sentence covers `raqib watch --host`.**
- The host watch's record is ~/.raqib/host/rounds.jsonl (host.py:69-70). It holds round records, not trace records.
- cmd_report (cli.py:858-865) has no host path.
- NEW-AGENT, AGENT-DARK-LIVE, HOST-UNWATCHED and HOST-RHYTHM are computed by HostWatch from the rounds (host.py:47-51). No command rebuilds them.
- So for a killed host watch, `raqib report <rounds.jsonl>` does not give its findings.
- The words are ADR-0010 decision 1's own, so changing them is the Table's call.

**D3 should-fix: the E7 SIGTERM "second signal" step is a race and can fail the Linux gate at random (test_first_run.py:618-621, 656-657).**
- The child's stdout is a file, so it is block-buffered. For the empty test project nothing flushes between the "stopped" write and cmd_watch's final `out.flush()` (cli.py:1187).
- That flush is followed at once by `stops.restore()` (cli.py:1190).
- So the test first sees "stopped (SIGTERM)" just as the handlers go back to SIG_DFL. The second `send` then either does nothing (the child has exited) or kills the child (`proc.wait()` returns -15), and `assert code in (0, 1, 3)` (:647) fails.
- The step never sends a signal while the report is being written. Only the in-process tests (:508-512) cover that.

**D4 should-fix (A8, Windows):**
- Closing the console window, logoff and shutdown reach Python as SIGBREAK through the CRT console handler.
- The Python handler only records the signal and returns (cli.py:339-346), and Windows then ends the process. Nothing is printed and the row is not finished.
- README.md:24's out-of-reach list names only SIGKILL and TerminateProcess, while "a closed terminal" sits in the same sentence.

**D5 note (Q-4): a host watch stopped while a reader is out ends INCOMPLETE (exit 3).**
- finish() adds the reader-out hole at host.py:3525-3528. Ctrl-C does the same today.
- With `--window S` the reader is out S seconds of every T, so a supervisor's SIGTERM often gives 3.

**D6 note (A3): some of what Stops sees is never reported.**
- Signals left ignored at start (`Stops.ignored`, cli.py:323-325), later signals (`later`, :340-342) and signals install() could not set (:327-328) are kept or dropped silently. None of them appears in the start lines, watch.json or the report.
- README.md:24 does not mention the nohup exception; the help text at cli.py:117-118 does.

**D7 note: narrow windows where the default disposition applies.**
- A stop signal before install (during imports or argument parsing) kills the watch.
- One after restore (cli.py:1190) and before the interpreter exits gives 143 or 129 after a complete report. D3's race hits the second window.

**D8 note (Q-6):** in a watch's final report the ALARMS count also includes Watch.alarms() (watch.py:686ff): watch-crashed, a registry hole and an unwritable state file. These are the watch's alarms, not "the trace's own", and are neither "A3 silence" nor "A5" in the strict sense. no-kind (ADR-0002 B-3) and the suspicion-run alarm are counted there too.

**D9 note:** `{matched:...}` is rendered on the deadline line for an after/until demand (engine.py:999-1000), which usually reads "-", and on the last line only for an aggregate (engine.py:903). This is documented (engine.py:55-56) and no catalog rule uses it.

**D10 note:** ruleform.py:510-511 `SUMMARIES["program"]` still names `{input_meta.command_head}`. A person's program rule made from the form keeps the outsider's wrong-program sentence. ruleform.py is outside Scope.

**D11 note:** a NET-TOOL Bash line that fires on url_host alone (for example head git) now says "program -" beside `programs ["git"]`. 0e8b007 said "program git". This is consistent with decision 4.

## Checked, no finding
- **Where a signal can arrive:**
  - During startup after install: the name is kept and the watch stops at the first nap after one step.
  - During a poll: kept, and the next nap stops.
  - During the nap: AskedStop is raised from the handler.
  - During conclude, close or the report: only counted.
  - After restore: the default applies (D7).
  - Races at the napping flag all end in AskedStop.
  - CPython runs handlers in the main thread only. AskedStop is raised only inside nap, inside the loops' `try` (watch.py:1386-1398, host.py:4082-4105), so it cannot escape an `except Exception` elsewhere.
- **Cleanup on AskedStop is Ctrl-C's line for line:** conclude, finish, stop_sources, helpers and channel closed, then close() shuts the server and the notifier. The report is written once. The handlers are restored on exception paths too.
- **Windows:**
  - SIGHUP is absent and skipped. SIGTERM and SIGBREAK can be set.
  - time.sleep is not woken by Ctrl-Break, so the stop comes when the 0.5 s nap ends.
  - The Ctrl-Break test skips without a console or on OSError. It is bounded by CHILD_TIMEOUT and kills the child in a finally. Its output file is closed. `watch PROJ` has no grandchildren.
  - The in-process tests call the handler directly and run on every platform.
- **Q-1 (keys):**
  - Watch.key (watch.py:491-494) and host fkey (host.py:3203-3207) are in-run dedupe keys. They are also used by the grown hand-over, which compares the first four parts, and written to watch.json findings[].key and the state's source_findings[].fkey.
  - Nothing reads them back. ui reads only the heartbeat. host's _refuse_second (host.py:1466-1493) reads only mode, finished, heartbeat, run and pid.
  - The act registry ((rule_id,) + events), the KNOCKS ledger (host.py:1601-1612) and notification folding (limit_id or event) hold no sentence.
  - A {matched} sentence is a pure function of the cited line. So no act knocks twice or misses a knock within a run, across a restart, or from a 0e8b007 state.
  - If the Table rules to drop the summary from these two keys, that changes B-2's dedupe and grown hand-over in watch.py and host.py, outside decision 4.

  - A bad `{matched:}` is refused at load (engine.py:332-336, test :185). "-" when nothing is named.
