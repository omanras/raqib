# M10.3b - questions for the Table (the forwarder over syslog; ADR-0011 J-6, J-14)

Each is built as the nearest thing J-6's words allow, and said here for a ruling.

1. raqib/cli.py (outside Scope). E1's `--facility N` and E2's `--framing newline` are options of the command
   line, and the parser is cli.py's. As the Table allowed at the start of the session, exactly two options were
   added to the forward subparser (`--facility N`, `--framing {octet,newline}`) and nothing else in cli.py.
   Left as it was, therefore: the `--to` help still says "syslog is not built yet", and the forward
   subparser's help still says "one HTTP collector". Both are now false; the next task that may touch cli.py
   should correct them (two strings).
2. A new failing word, `write` (forward.ERRORS): a syslog send whose bytes or datagram the system did not take
   (the connection ended, no route). None of the HTTP words was true of it ("no-answer" says an answer was
   awaited). The status, the state check and FORWARD.md's table name it; a state holding it is readable.
3. Default ports. udp 514 (RFC 5426) and tls 6514 (RFC 5425) are the RFCs'. RFC 6587 names no port for plain
   tcp; 514 was taken because collectors listen there. Should tcp require an explicit port instead?
4. The state's destination for syslog has `path` "" (no path); the state check refuses, for a syslog scheme, a
   shape other than raqib, a delivery other than the scheme's own word, or a path other than "". The state has
   no key for the facility or the framing: changing either between two runs of one name is allowed (the cursor
   is the line's, not the wire's). Should they be in the state, and part of "another destination" (J-13)?
5. One connection a batch over tcp and tls, closed after the batch, with no TLS close_notify (unwrap could wait
   up to its bound for a collector that never answers it; octet counting tells the collector where each
   message ends). A connection kept open across batches would cost fewer handshakes but would make "written"
   weaker still (a peer that closed is seen only at a later write). Built as one a batch; recorded in
   FORWARD.md's "Not here".
6. `--framing` with a udp destination is a usage error (a datagram is one message, never framed), and so are
   `--facility` and `--framing` with an http(s) destination. J-6 does not say; silence would let a mistyped
   command look accepted.
7. RFC 5424 fields the event cannot fill. Where `watch.host` is not 1 to 255 printable US-ASCII (a name with a
   space, a non-ASCII name written as a JSON escape), the HOSTNAME is `-`; the same for a kind longer than 32
   (MSGID) and a time that is not RFC 5424's (TIMESTAMP). Nothing of the event is changed: the MSG holds it
   whole. A severity the event contract does not have (none today) would be 4, warning, never 6.
8. The MSG has no BOM: the line is ASCII (MSG-ANY), "the line as written". A collector that wants a BOM for
   UTF-8 is not served; none of the event's bytes is outside ASCII.
9. Over udp a batch passes when every sendto returned with no error; one socket a batch, never connected (a
   connected udp socket would report an earlier datagram's ICMP refusal on a later send, which is not that
   send's failure). Each line is still one datagram; a batch is the cursor machine's unit, unchanged.
10. The rig: X23 (tcp, octet counting), X24 (udp, --batch 10 so that a burst stays inside the stand-in's
    receive buffer), X25 (tcp, --framing newline), each also MISSED where the stand-in found a message not in
    J-6's shape, a delivery word not the transport's, a framing not the one asked, or a refused line. The
    stand-in writes the severity map again rather than importing raqib's, so that the rig checks the rule, not
    the code against itself. X24's "every line sent arrived" holds on loopback only; across a network udp loss
    is not a rig fact.
11. tests/test_forward.py: the one HTTP-era test that asserted "a syslog destination is not built yet" was
    renamed (`..._and_a_syslog_usage_error_says_so`) and its two syslog cases now hold two usage errors syslog
    still has (a token file; plain tcp to a documentation address). Its HTTP assertions are as they were.
