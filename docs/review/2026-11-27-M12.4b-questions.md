## Q1. `--service` is X28-X30's already: X48 reads `--service-run RUNFILE`
E4 names `tools/rig/check.py --service RUNFILE --service-events EVENTSFILE`. `--service` is taken: it is the
FACTS.json of X28-X30 (`read_service`), and both rig jobs already give it (`.github/workflows/rig.yml`, the Windows
job's check step and the Linux job's: `--service $env:RUNNER_TEMP\service.json`). A RUNFILE of `key: value` lines
given there would make X28-X30 MISSED on Windows (not JSON), and the Windows job could not give both. Chosen:
`--service-run RUNFILE` and `--service-events EVENTSFILE`; X28-X30 unchanged. The job's wiring (the Table's) gives
those two. A file given and missing is MISSED (its silence), as X47's; X48 is n/a only where neither is given; one
given without the other is MISSED with "not given" for the other.

## Q2. No spec lists the host watch's holes
E5 and the Scope name "docs/specs/HOST.md or the spec that lists the host watch's holes (only the new hole's line,
where such a list is held)". There is no docs/specs/HOST.md, and no spec holds a list of the host watch's hole kinds:
docs/specs/EVENT.md lists the events' kinds ("hole" among them), not the kinds of a hole; ADR-0007 names holes as
they were ruled (an ADR, not mine). raqib/ui.py's J-8 orders some hole kinds and leaves "the rest as they came"
(outside Scope, and not needed). Chosen: the hole's kind and its words are in docs/specs/SERVICE.md alone (the
Windows section's "The watch before", and the Linux unit's paragraph names the kind). Should a list of the host
watch's holes be begun somewhere?

## Q3. The hole: its kind, its words, no knock, no live line
Kind `watch-unended` (host.UNENDED), the noun-then-state shape of the other kinds (rounds-corrupt, reader-late).
Words: "the host watch before this one, run RUN (pid PID), ended without its end: its state PATH was left
unfinished, its last heartbeat HEARTBEAT; nothing was watched from this home for N s, from that heartbeat to this
start (a watch ended from outside, a crash or a power loss)". It takes the road of the other holes of the start
(host-rule, rounds-unreadable, rounds-corrupt): `self._hole(self.t0, ...)`, round None, no knock, not said as a live
line on the watch's output; it is in the final report's HOLES, the state's holes and the events (once, "hole:i",
severity "hole", alarm true), and the result is incomplete ("1 hole(s) of the watch"; exit 3 where nothing makes it
1). Should it knock (HOST-HOLE), or be said live at the start, as a capture gap is a finding (rule 4)?

## Q4. N, the seconds said
N is `int(max(age, 0))` of the age the refusal's own reading took (holder() at `_refuse_second`, the watch's wall
clock a moment after its start), the same number the staleness was decided on. A clock set back between the
heartbeat and the start gives a wrong N, as Amendment H records ("said as read"); with the state's own staleness
negative an N of 0 could be said. Kept as read.

## Q5. A heartbeat that cannot be parsed: no wait in the runner

"held and fresh"); the watch refuses (20) and the service stays stopped until an administrator removes the file,
as the refusal's words say. Should the runner say it in its text file before the watch?

## Q6. One line before the wait, none after it
E3's one line: "another host watch's state still holds the place (run R, pid P, heartbeat A s ago, stale after S
s): it was ended without its end, or it still watches; waiting up to W s for it to go stale, asked again every 1 s,
then the watch" (W with one decimal: 30 - 4 + 1 is "27.0"). After the wait no line is added: where it went stale the
watch's hole says the rest; where it is still fresh the watch's own refusal line is in the same text file. Should

## REDO

### R1. AI-1: the early write says the start's holes so far, not the one hole alone
Before register() writes the state, `HostWatch._before_said()` calls the events log's own `start` and `ledgers`
with `holes=` the watch's holes (nothing else: no tree, note or finding). `ledgers` names a hole by its place in the
list (`hole:j`) and walks a list from its first entry; a host-rule hole (a catalog lacking a rule) or a
rounds-corrupt hole made earlier in `__init__` is therefore written with it, before the first round, on such a start
only. Saying `hole:k` alone would need eventlog.py's own code (not in Scope). On such a start the start line is
written at the watch's start (its clock's t0), and the beat is counted from it, not from the first tick. Every other
start is as it was. Is that within "the order of everything else at the start"?

### R2. The kind and words of AI-2's hole
Kind `watch-state-unreadable` (UNREADABLE_BEFORE), the noun-then-state shape of `watch-unended`. Words: "the state
PATH is there and cannot be read as a state (WHY): whether the host watch before this one ended without its end, and
how long no watch of this home watched, is not known; this watch takes the home". WHY is the error's kind and words
(`JSONDecodeError: Expecting value: line 1 column 1 (char 0)`, `PermissionError: Permission denied`), or "it holds a
JSON list, not an object", cut to 80 (WHY_SAID_MAX). An object that is no host watch's state (another mode, or none)
stays "nothing held", as the reviewer's table has it: E2 names "a JSON that is no object" only.

### R3. A state nested past the parser's limit (finding 2)
`holder()` does not catch RecursionError (nor MemoryError), and its docstring now says so: catching it would change
the refusal (AH-1's MUST NOT TOUCH). The watch then ends with that exception, as before M12.4b; in the runner it is
the runner's own (23), tested with a stand-in. Should holder take it as a state that cannot be read (the watch would
then start and say AI-2's hole, where today it fails)?

### R4. One bound, 40, for the run, the pid and the heartbeat
HELD_SAID_MAX = 40, the heartbeat's bound before; a value cut ends with "...". The unparsed refusal uses the same
constant for its heartbeat (40: its words are the same). The fresh refusal's run and pid are still not bounded: E2
keeps `_refuse_second`'s words as they are, so finding 3's concern stands for that refusal's text (a file another
process wrote, copied whole into the watch's error). Should the refusal's run and pid be cut too? A real run id is
under 32 characters.

### R5. The seconds of a heartbeat ahead of the clock
Said only where holder answered STALE with a negative age (the state's own staleness negative or NaN): "S s ahead of
this start's clock" with S as `%g` of the seconds (0.25, 1e-06: never "0"), and "how long no watch of this home
watched is not known" in place of "for those N s ...". Behind the clock N is the whole seconds (`int`), so 0.75 s is
"0 s before this start".

### R6. The runner's numbers and endings
A staleness or an age that is no number the wait can use (a boolean, a text, NaN, an integer too large for a float)
waits the whole HELD_WAIT_MAX: it is held fresh, and a wait of 0 would start a watch that refuses at once. The line
after a wait that ended on a state of another mode reads "no longer held (none: the state is no host watch's)". The
runner tells "gone" and "finished" by holder()'s words "no state" and "the state is finished" (a test ties them);
the three others by holder()'s own answers (ENDED_SAID, tied by a test). Finding 8 (the first and the last ask lie
outside the 60 s) is not changed.

### R7. X48's new MISSED
An again-pid of 0 or below is MISSED ("again-pid N is no process's"); a negative again-seconds is MISSED
("again-seconds N is before the end from outside"). A byte-order mark is read past at the start of both files, the
RUNFILE and the events. Where the RUNFILE gives no killed-pid or again-pid, the tie's own words are not said (the
RUNFILE's are). killed-pid 0 has no line of its own: no hole of a real watch names pid 0.

### R8. What is still said nowhere (finding 26)
A state removed before the watch starts (not during the runner's wait) is still said nowhere: holder() then answers
"no state", which is also a first watch's. Not changed.
