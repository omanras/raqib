## What was built
- **E1 (S-3, the environment).** `Mentions._file` now follows a name os.environ itself is bound to: by `=` (each name
  of its targets), an annotated `=` or `:=`, with os.environ alone, as a branch of `x if c else y` (not its test) or
  as an operand of `or` / `and` (`_environ_bound`). Every other occurrence of that name in the binding's function
  (its nested defs too) is held in ENVIRON by file, function and its statement's text, as os.environ itself is,
  unless `_read` calls it a read of one name (a subscript read, `.get` given a string written in the code, `in`).
  So a store, a `del`, any method but such a `get`, the name handed on and the name bound again are each held. The
  made-up case (ORDINARY, "S-3 a store through a name os.environ is bound to") puts `environ["PATH"] = "C:\\x"`
  after the binding in a copy of raqib/autostart.py's `default_folders`; it fails at its line, as "E1 (os.environ):
  a statement not held, in default_folders", and for nothing else.
- **E2 (S-3, three small forms).**
  - `_use`: getattr of a library's object given a string written in the code (or a parameter every call gives as
    one) is a function taken by name only when no such string begins with `_`; otherwise the use is held by its
    statement in OTHER_USES, as any other use. Case: `getattr(k32, "_handle")` in a copy of winservice's
    `System._win` fails at its line as "E6 (a library's object used otherwise)", and for nothing else.
  - `named`: a class pattern's keyword names (`MatchClass.kwd_attrs`) are mentions. Case: a `match` with
    `case object(LoadLibraryW=f): pass` at the end of a copy of raqib/wincode.py fails at the case's line for
    "E1: a mention more than held ... 'LoadLibraryW'" (and, as LoadLibraryW is a statement word, its `match` is
    also "E2: a statement not held" at the line above; the case allows that, and nothing outside its lines).
  - `sys.modules`: the detection is unchanged; a case proves it. `loaded = sorted(sys.modules)` at the end of a copy
    of raqib/cli.py (which imports sys) fails at its line, and every problem found names 'sys.modules' - not
    another word of the line.
- **E3 (S-4).** `NARROWED = ("compile", "exec", "eval")`. They are counted where `named()` reads a word (a name, an
  attribute, a parameter, a keyword, an import's part or alias, a def's name, ...) and as a whole word in every str
  and bytes constant, but not in a docstring (the first statement of a module, def or class, when it is a str), and
  not as an attribute of a name that `import re` (or `import re as X`) alone binds in the file (`_bound_otherwise`:
  a name the file also binds by assignment, del, parameter, def, class, except or another import is not set apart).
  The other words are counted as before, docstrings too. Cases, each at the end of a copy of raqib/event.py (which
  imports re): `NEW_RE = re.compile("x")` and a new def whose docstring says exec, eval and compile change nothing
  (no problem at all); `got = eval(x)`, `run = builtins.exec`, `got = obj.compile("x")` and
  `got = getattr(obj, "eval")` each fail at their line for their word.
- **E4.** The file's first lines say S-1 (what the hold is for), that it does not hold code written to get past it,
  and S-2's list of what is therefore not held, with R-3's earlier list kept in it. "anything else fails" (the first
  lines and the comment above WORDS) and "PATH never set" are gone; the first hold "refuses the forms it knows of a
  search mode given, a folder added and the PATH set". `Mentions.faults` was never written (finding 13): it is
  removed, with `problems`' `list(m.faults)` and `dump_held`'s `# faults:` line. `_use`'s docstring says what the
  code does: any other use is held by its statement. The class docstring says the object is followed only in its
  function, a def of its file and an attribute of its file, and that what is not followed is not held.
- **E6.** Every test of the file passes here (133 passed, 1 skipped on Linux): the 30 escapes, the 4 not-vacuous
  cases, the earlier tests, and the 10 ORDINARY cases. Undoing each fix alone (a copy of the file, run here, not

## Questions for the Table
1. **`.get` by a key not written, through a bound name.** E1 says "any method but `get` given a string written in
   the code ... as a use of os.environ itself is" and also "The reads the tree makes through such names stay
   uncounted". The tree reads through such names twice by `.get` given a name (autostart `default_folders`'
   `environ.get(var)`, watch `open_page`'s `environ.get(k)`). Built: the same `_read` as for os.environ itself, so
   those two statements are now ENVIRON rows, as `System.getenv`'s `os.environ.get(name)` already was; the reads
   E1's `_read` names (subscripts, `.get` of a written string, `in`) stay uncounted. If the Table meant every read
   by `.get` to stay uncounted through a bound name, the two rows go and the rule differs from os.environ's own.
2. **Reads by other methods.** `held.items()` in autostart `_sure` is a read, held because it is "any method but
   `get`". Kept as the letter says; is a list of read-only methods (`items`, `keys`, `values`, `copy`) wanted?
3. **The bound forms followed.** Followed: `=`, an annotated `=`, `:=`, through `if`/`else` branches and `or`/`and`.
   Not followed (each still holds os.environ's own statement): a tuple unpacked, `with ... as`, a loop's target, a
   default parameter (`def f(environ=os.environ)` holds the whole def, but its name is not followed in the body),
   and a name the bound name is itself bound to (`x = environ` is held; `x` is not followed further). The follow
   runs over the whole function, uses before the binding and nested defs with a name of the same spelling included.
4. **`re` set apart.** Only where `import re` alone binds the name in the file; `from re import compile` makes
   `compile` a name, counted. Right?
5. **"Counted as names".** Read as every place `named()` reads a word, not only a bare name: a def named `compile`,
   a keyword `eval=`, an import's part `eval` are counted. Right?
6. **getattr through a parameter.** Where getattr's name is a parameter every call gives as a string, one of those
   strings beginning with `_` sends the use to OTHER_USES whole. Right?
7. **The two shorter documents.** docs/GUIDE.md and docs/THREAT_MODEL.md name S-2's list in short ("a library's
   object, a name or a table reached from elsewhere", "the interpreter's own roads to code (its imports by a path,
   sys.path, extension modules)"); docs/specs/SERVICE.md and the test's first lines name it whole. Is the short
   form enough for S-2?
8. **The earlier escape "redo-4b _ctypes by sys.modules".** Unchanged: it still fails only for the string "_ctypes"
   (hostwin.py does not import sys), as the review found. S-3's proof is the new case in cli.py; ESCAPES are not
   among E1 to E6's changes.
9. **Versions (the review's finding 12).** The 11 new ENVIRON rows are `ast.unparse`'s text on Python 3.13.18 here;
   none holds an f-string. Whether 3.11 and 3.12 write them the same is for the gate's matrix, not measured here.
