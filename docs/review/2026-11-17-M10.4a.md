## 3. Silent assumptions, and what a rule should have caught (A3, A5)
- **A3, unread states**: as in section 2. Q2 asks the question, but the code and the test already chose the calm
  answer.
- **A5, the 1 MiB line (link.py:310-311)**: "more than a forwarder writes" is a claim with no evidence behind it.
  - The forwarder keeps 50 refused ids (forward.py:155, :1294) plus `last_id`.
    - Each is an event id, which `event.ID` does not bound (event.py:92), inside a line of up to 512 KiB
    (forward.py:149).
    - So a running forwarder fed long ids by a writer of the events file (N-9) writes a state over 1 MiB. Its own
    `--status` now calls that state UNREADABLE with untrue words.
    - The writer is not bounded, and its restart read is unbounded too (forward.py:1090). Erring toward alarm is
    acceptable; the words are not true.
- **A3, listing failure looks like "no state"**: a folder that cannot be listed, or fails part way, gives `[]` with
  `rest` 0 (link.py:343-346). That is the same as no folder at all. `status` then prints "no forwarder has written a
  state" (this was already so before), and M10.4b's panel would say R-2's "nothing leaves this host" when nothing was
  read.
- **A3, dangling symlink**: a symlink to nothing raises `FileNotFoundError`, which gives SILENT "no state: ... (it
  never ran, or not here)" (link.py:306-308). The window's own doctrine says otherwise (ui.py:218, J-11: "a link to
  nothing is an unreadable file, not an absent one"). This was already so in `status`; it now reaches the panel.
- **A3, partial result dropped**: the outer `except Exception: pass` in `read` (link.py:350-351) returns the rows read
  so far. Names after a failure are neither rows nor counted in `rest`. In practice it cannot be reached (`_row`
  catches everything), but it drops silently by construction.
- **A3, `Rows.rest` defaults to 0 (link.py:258-260)**:
  - A slice, `sorted`, `Rows(x)`, `+` or `json.dumps` loses `rest`.
  - A copy then reads as "nothing unread".
- **A5, the docs claim**: FORWARD.md:339 ("every state in ~/.raqib/forward/ without NAME") and :350 ("Of several
  states, the worst") are untrue past 64. The table at FORWARD.md:356-372 has no row for the new outputs (over 1 MiB,
  not a regular file, more than 64). Q10 flags this; the one-sentence scope blocked a fix.
- **Already in the moved code, not this task's**: a state with beat 1e308 makes `2 * beat` infinite (link.py:235), so
  it is never SILENT. The forwarder's `--beat` has no upper limit (forward.py:775), so a dead forwarder whose state
  says a huge beat reads OK forever.

### 4. Bounds and safety of `link.read`
- **Name bound**: `heapq.nsmallest(64)` over a streamed `scandir`, so the cut keeps the 64 smallest names in the same
  order as `sorted`. The listing is never held whole but is walked whole on every call (link.py:272-279), so time is
  unbounded for a huge folder (it matters at M10.4b's once a second).
- **Size bound**: `STATE_MAX + 1` read, never whole (link.py:295).
- **Directory, FIFO, device**: opened with O_NONBLOCK, then `fstat` checks for a regular file, so each becomes
  UNREADABLE with no wait. On Windows `getattr(..., 0)` stands in for the missing flag and O_BINARY is added. NAME
  admits device names (con, nul, aux, prn, com1-9, lpt1-9); these now open the device and are refused by `fstat`,
  where the old code hung reading them. Not tested on Windows.
- **Open before the type check**: the device is opened before its type is checked, without O_NOCTTY. The project's own
  reader stats first and uses O_NOFOLLOW (raqib/hooks/common.py:1407-1423).
- **Symlinks**: followed (link.py:286), as before.
- **Replace race**: a file renamed over between listing and reading is handled by the atomic rename; a file deleted in
  between gives SILENT.
- **Names and traversal**: a name not matching NAME is no row, and no path is built from it, so `../x` reads nothing.
- **Decoding and nesting**: decoding is ASCII as before. RecursionError is caught (link.py:313).
- **Huge numbers**: an integer over 4300 digits raises ValueError, giving UNREADABLE. For huge floats see the beat
  note in section 3.
- **Nothing raised**: I found no path that raises.
