# M7.26 - questions returned (a reused pid is not a parent; ADR-0007 Amendment BE)

Status: STOP. Nothing of BE-1 to BE-4 is landed; the tree holds only this file.
Base: 9d17741 (claude/M7.26). raqib/discover.py and raqib/hostwin.py are the
same on main (d6ce171) and on the base.

## What was built, measured, and taken out again

BE-1 and BE-2 were written in raqib/discover.py (about 80 lines; not
committed): a start as the module reads it (an ISO UTC text with a "T" by
`_ts`, as raqib/host.py's `utc_time`; a Linux key "boot+N" as its ticks; an
export's local CreationDate not guessed); a verdict per link ("kept": both
starts read and the parent not later; "broken": the parent later, one source
any later start, two sources only above GUID_SAME_SECONDS; "unread"); a
`_parent` that every walk reads (`ancestors`, `_descendants`, the children,
the shell's parent and `launched_by` of `_act_roots`); and the reader's own
tree by `_descendants(..., proven=True)`, links "kept" only. The holes of
BE-3 were not written: Q2 and Q3 came first.

Run on the whole suite (3903 tests), that code failed four existing tests,
all in tests/test_round_channel.py. That is E6's STOP: the pins are not
changed here.

## Q1 (E6, the STOP) - two fixtures of tests/test_round_channel.py hold a child started before its parent

BE-1 reads both as a reused pid and breaks the link. A probe that turned
every "broken" back into "kept" made all four pass again, so the cause is
BE-1 alone, in these two links and no other:

1. `act_root_sample` (tests/test_round_channel.py) appends to
   tests/fixtures/host/quiet/quiet the row of agentx.exe, pid 9216, parent
   pid 5888, CreationDate 2026-11-10T07:49:00.000Z. Pid 5888 is the
   fixture's powershell.exe, CreationDate 2026-11-10T07:50:00.000Z: the
   parent started 60 s after the child. The link breaks (in the round with
   the channel and in the round built without it). agentx then has no
   listed shell for a parent, so it is not an act-root, and the .kimi
   footprint is dark instead of linked. The three tests that fail:
   - test_ad1_b3_an_act_root_that_talks_only_in_the_channel_keeps_its_footprint_linked
     (line 1599: "dark" x4 where "linked" x4 is pinned)
   - test_ad1_a_tree_of_the_round_only_by_the_channel_is_quiet_for_the_footprint_as_without_it
     (line 1619)
   - test_ad1_must_not_touch_a_round_without_the_channel_keeps_its_shape
     (line 1687)
2. test_ae1_ad2_does_not_reach_a_guid_tree_whose_own_start_the_round_read
   copies tests/fixtures/host/quiet/talking and moves the CreationDate of
   powershell.exe, pid 5888, to 2026-11-10T08:00:05.000Z (the pid taken
   again). Its child row stays: conhost.exe, pid 5890, parent pid 5888,
   CreationDate 2026-11-10T07:50:00.100Z. The link breaks, the shell has no

By BE's own words both rows describe a reused pid: a child cannot be
younger than the process it was born of. But BE-1's MUST NOT TOUCH says
every existing fixture gives what it gave, and E6 says do not change the
pin. Asked: may these two test-built samples be corrected in
tests/test_round_channel.py (for example agentx at 07:50:30.000Z under the
shell; in AE-1, a child of the shell started after 08:00:05 beside, or in
place of, the old conhost row), or does the Table want another reading?

## Q2 (E5 against E6 and Scope) - the "reparented acts" hole is pinned outside Scope

"reparented acts: ... (reparented to init; on Windows a dead parent's pid
can be reused), is not attributed" is one of ALWAYS_HOLES. Every inventory
carries it. Its text is pinned in raqib/rules/hostdata/inventories.json
(8 inventories). tests/test_thresholds.py
test_e1_make_py_is_a_thin_writer_over_fixturegen_and_hostdata_is_what_it_makes
asserts that file equals what make.py builds now. raqib/rules/ is not in
Scope, and E6 forbids the change. So E5's last sentence cannot be met by
changing the text.

What is true after BE-1: where both starts are read, a reused pid is broken
and the child is not attributed. The old words are then true, and now
proven. They stop being true only for a link kept with a start unread,
where the child goes to the pid's new holder. Proposed, nearest to BE-3:
keep the always-hole's words, and say the untrue part only on a round that
has such a link (in the BE-3 hole, or by replacing the always-hole's text
on that round only). Asked: which one, or add
raqib/rules/hostdata/inventories.json and its regeneration to Scope.

The Windows exports carry a local CreationDate ("11/2/2026 8:01:02 AM"),
which is not compared. The Linux fixtures carry no start_ticks. So a hole
that "counts the links kept with a start unread" on every round with one
changes all seven discover inventories, the eight pinned ones, and
quiet-unread's rounds. "No such hole where there is none" does not save
them: there are such links. Asked, one of:
- (a) said only on a round where the reader dated at least one link (a
  round of the live reader), counting the links it could not date;
- (b) said only for the links BE-2 kept out of the reader's tree, and the
  links on an act's path or an act-root's chain (the links a judgement
  used);
- (c) said on every such round, with the pins regenerated (Scope gains
  raqib/rules/hostdata and the pins).

## Q4 - Linux's key "boot+N" was decoded to compare

Without the decode, no Linux start is comparable. BE-2 would then put every
helper of a Linux reader out of its tree, and BE-2's MUST NOT TOUCH says
those helpers stay out of every tree. The decode is one regex on the
module's own key (parse_proc writes "boot+%d"), not a time parser. No
existing Linux fixture carries start_ticks, so it changes none of them.
Asked: is that the module's own reading, or "a second parser"?

## Q5 - which start of the channel BE-1 reads

The channel's event 1 time was read only in a channel round (as X-6's
"started" of an act: `started_of(p) or channel_started if channel`). A
Sysmon export read by `raqib discover` (channel off) gives BE-1 no start.
Asked: confirm, or should an export's event 1 date a link too?

## Q6 - which pid the broken-link hole names

Proposed: the reused parent pid (the pid the reader or its launcher can
hold), sorted, at most 20, with the count of links whole: "parent pid 732
(the reader's own pid)". The child's pid would be beside it, or in its
place. Asked: which?

## Q7 - the reader's launcher walk already applies BE-1

raqib/hostwin.py `self_tree` already ends the chain where
`started[ppid] > started[pid]`. Both are the reader's own GetProcessTimes
texts, one fixed format (`filetime`: %Y-%m-%dT%H:%M:%S.%fZ), so the
string order is the time order. A start that was not read keeps the link.
tests/test_hostwin.py test_a7 covers a younger python. Proposed: no code
change there, and E3's test with made-up rows (a younger raqib.exe in the
middle of the chain ends it, nothing above it is a launcher; an unread
start keeps the link). Asked: or does "the same rule" mean BE-2's
strictness for a launcher too (a launcher whose start was not read is not
named)?
