## Choices made locally (each is the Table's to confirm or overturn)

Q-1 The word beside a colour. The band's bracketed word is the level's
C-10 result word: clean, alarm, incomplete (and note). I first used
"nothing found" for green, then saw it beside WATCHING with a high
finding listed: while a watch runs, the band's level is the watch's own
health (ui.status: WATCHING is "clean" whatever the findings; the
findings are in the body), so a word claiming a result would be
contradicted by the screen. The level word claims no more than the
colour. (Whether WATCHING with a settled high finding should itself be
red is a question about ui.status, not about the look: recorded, not
changed.) A green state still says "Not
a clearance." in its detail, as F-7 asks.

Q-2 The tray tip while only a project is watched. The HANDOFF says "while
watching"; M7.3's tip followed the host watch only. "Raqib: idle" while a
project watch runs would be a false word, so the tip now follows any
watch (Controller.watching()): N and K are the host watch's (0 when the
host is not watched), F is the findings of the watches running (the host
view's findings and suspicions plus the project watch's findings, read
from the state the window already holds - Session.last_state - never a new
read). Changing when the tip changes is presentation of the tip, but it is
a change of a condition in Controller.host_tip: the Table may prefer the
host-only condition.

Q-3 The footer and the look's holes (F-3). The first look on a real
machine has 14 holes of a paragraph each; listed in the footer they pushed
every screen past 600 px (the footer is packed first, so the screen was
the one clipped - true before this task too). The footer now lists the
window's own holes and notes in full and the look's holes as ONE counted
line: "round at open: the first look has N hole(s), each listed under
HOLES on the Host screen and written to the log" (`foot_lines`). Every
look hole stays in full on the host screen's HOLES list and in the log
(F-3's log line is unchanged), and the count stands in the footer until
the host watch's first round, as F-3 asks. This is the one place where
the look changes what a footer says rather than how: the Table's to rule.

Q-4 "acts" is not a Treeview column. The HANDOFF lists eight columns
without it; `host_rows` and `HOST_COLUMNS` are unchanged (they are what
look.json's rows hold and what the text table prints), and acts is in the
detail pane. TREE_COLUMNS maps each column to its index in a host_rows row.

Q-5 What the detail pane shows of a tree: image, pid, kind; class,
started, first seen, acts; source and its findings by severity; rhythm /
suspicion; endpoints; cites as src:line only (never the record's text, as
host_rows never shows a command line, a cited record's text or an exe
path); the tree's findings (host findings matched by tree_key, else by the
tree word), its suspicions (by tree word) and its dark notes (by
live_tree). `host_watch_view` and `probe_view` gained a "details" key
(display data, aligned with rows); HostProbe._write picks its keys by
name, so look.json is unchanged (test).

Q-6 Log placement. The header's Log toggles the current screen's log: on
the host screen the log takes the detail pane's place (so the screen
keeps its size at 900x600); on the watching screen it opens below the
body as before. The per-screen "Log" buttons are gone (the header has it);
the Log tab is disabled on the project field and the Rules screen, which
have no log.

Q-7 The ttk theme. Light mode on Windows keeps the native "vista" theme
(its buttons keep the OS colours; frames, labels, tables and texts take
THEME's); dark mode, and Linux, use "clam", which takes every colour of
the theme. Dark mode is only read on Windows (the HANDOFF's "where Tk can
tell"); Linux and macOS are light.

Q-8 Colour of a tree row: alarm (red) when the tree knocked ("new") or its
source has high/medium/low findings; note (grey) when gone; otherwise the
default text colour. History trees are not coloured.

Q-9 The text panes are tagged by section (`text_tags`): lines under
"FINDINGS: n" (n > 0) alarm red, under "HOLES (A3): n" (n > 0) and
"hole: ..." lines amber, under "NOTES" grey; the section line carries the
word. The final reports are tagged the same way (only their "hole:" lines
match). The project watch's body is now set through the tags path; its
text is byte-for-byte body_text / the final report as before.

Q-10 Fonts: UI families Segoe UI, Cantarell, Noto Sans, DejaVu Sans,
Liberation Sans, Helvetica, Arial; mono Cascadia Mono, Consolas, DejaVu
Sans Mono, Liberation Mono, Noto Sans Mono, Courier New, Courier; size 10
(band 15 bold, first-run lines 9). The named Tk fonts are reconfigured for
this process only.
