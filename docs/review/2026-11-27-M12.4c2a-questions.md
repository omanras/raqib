# M12.4c2a - the builder's questions (ADR-0013 Amendment P)

Each question is the Table's to answer; what the code does meanwhile is said with it. Nothing here is answered
locally.

## The drive (P-1)

- **Q1 - where the drives asked are kept.** `wincode.check(system, drives=None)`: the counts dict is left exactly as
  it was (many present tests compare it whole), and the drives asked and taken are put, in the order asked, on a list
  the caller gives - `(letter, device's name)`. `cli_check` gives one and hands it to `checked_words(counts, drives)`
  / `plain_words(counts, drives)`, whose `drives` defaults to none (then nothing is added). Meanwhile: as built.
- **Q2 - the pass's words.** The drives are said at the end of both sentences: `; and the drive asked before any name
  of it was read, each said by the system to be of the fixed kind with a device's name beginning \Device\: C:
  "\Device\HarddiskVolume3"` (plural "the drives ... of them", each `LETTER "DEVICE"`). "to the drive's letter" stays.
  Neither rig pattern (CHECK_COUNTS, CHECK_PLAIN_COUNTS) was changed: both still match, held by
  tests/test_rig_check.py `test_x49_and_x50_still_read_the_pass_with_its_drives` and by test_wincode's
  `test_p1_a_second_drive_that_is_a_disk_is_asked_once_and_said_in_the_pass`.
- **Q3 - a refused drive names no role, and X49 on x64.** A drive refused is said as `X:\, the drive X: (first met by
  PATH), asked before any name of it is read (ADR-0013 P-1): ...` - neither K-2's nor K-3's role, since no name was
  judged. X49 and X50 ask for a role in the refused copy's words. On GitHub's x64 machine the job's own folder is on
  `D:`, which is now asked first; X49 stays MET there only if `D:` reads kind 3 with a device's name under
  `\Device\`. Amendment P names `C:\`'s reading as measured; `D:`'s device's name is not in this tree's measurements.
  Meanwhile: X49's and X50's readers are unchanged; if `D:` is not read so, X49 reads MISSED ("its words name no
  role") and says the words.
- **Q4 - what the real reader gives for a letter that is not there.** `winservice.System.read_drive` reads the kind
  first and then the device's name; where QueryDosDeviceW writes nothing it raises OSError with the system's number,
  and the kind is said only inside those words (`the device's name of Q: was not read (the drive's kind 1)`). So a
  letter that is not there is refused as "its device's name was not read (... (error 2))", never by "kind 1 (no
  root)" as a judged kind. Meanwhile: as built; both refuse.
- **Q5 - a device's name that begins with `\Device\` but holds a character that is not printable.** P-1 as written
  takes it; the pass says it made printable (`?`). `\Device\` is compared with its case (`\device\...` is refused).
  Meanwhile: as written; held by `test_p1_a_second_drive_that_is_a_disk_is_asked_once_and_said_in_the_pass`.
- **Q6 - the stand-in's default for a letter a test does not give.** `Machine` reads `C:` as measured (kind 3,
  `\Device\HarddiskVolume3`) and every other letter as a disk's stand-in (`DISK_STAND_IN`, kind 3,
  `\Device\HarddiskVolume1`, not measured), so that every present test stands. The measured reading of a letter that
  is not there (kind 1, error 2) is given by name where a test asks for it. Meanwhile: as built.
- **Q7 - `_Walk._missing`'s "not there, and neither is its drive".** On a real machine a letter that is not there is
  now refused at its drive before its root is read, so that branch is met only where a drive answered a disk's
  reading and its root was then not there. Kept, untouched (N-4, Q3 of M12.4c1b).
- **Q8 - "used nowhere else" (E1).** Read as: in winservice.py the two calls are declared in `System._win` and called
  only in `System.read_drive`, and QueryDosDeviceW is in no other file of raqib/. raqib/autostart.py has its own
  GetDriveTypeW (AJ-4, declared there, long before); it is out of Scope and was not touched. Held by
  tests/test_winservice.py `test_p1_the_drives_two_calls_are_declared_with_the_others_at_the_first_call_and_used_by_read_drive_alone`.
- **Q9 - small choices.** The letter is asked and said in upper case (`C:\`), the case met not kept; a ValueError
  from the reader (a root not of the form `X:\`, never given by wincode) is refused as not read; the reader's buffer
  is 1024 characters, a local of the method (Scope allowed no new module constant in winservice.py); a reading that
  is not a pair is refused with its own words; kinds 0 to 6 say the words E2 gives (5 "a disc", 6 "a RAM disk"),
  any other number "a number this check knows no word for".

## The libraries loaded by name (P-2)

- **Q10 - what tests/test_libraries.py follows, and what it does not.** It follows a name to strings written in the
  code through: a lambda loader bound to one name in its function (its calls there); a loader def called by its name
  anywhere in raqib/, a `(loader or eventlog_dll)(...)` call included; a `for` over a top-level table of strings (a
  dict's keys by `.items()` or `.keys()`, a tuple's items); and a setter of the environment whose variable's name is
  a parameter (winservice.System.setenv), followed to its callers (`HOME_NAMES`). Anything else is a fault. A loader
  handed in by a caller (`Api(loader=...)`) is not followed: in raqib/ no caller hands one (only tests do), and the
  names at the call sites are held whatever loader is called. Not seen (said in its docstring): a load reached by a
  name bound again, functools.partial, a subclass, a module bound by assignment, exec or importlib. Meanwhile: as
  built; the held sets (RAQIB_LOADS, 13 places; RAQIB_LOADERS, 4 loaders) make a blind scan fail.
- **Q11 - find_library.** Refused outright: on Windows it walks the folders of PATH (read in this interpreter's
  Lib/ctypes/util.py). raqib/ has none.
- **Q12 - the calls that change the search.** SetDllDirectoryW/A, AddDllDirectory, RemoveDllDirectory,
  SetDefaultDllDirectories, LoadLibrary(Ex)W/A, LoadPackagedLibrary and os.add_dll_directory are faults wherever
  named, but SetDllDirectoryW in raqib/cli.py `main.set_dll_directory_w` (ADR-0007 CI-3), allowed as what it is;
  a second test holds that raqib/own.py calls it only as `call(None)` (the folder searched first back to the
  system's own, nothing added). Whether CI-3's call belongs on P-2's words "no folder added to the search" as
  allowed, or should be said apart in the spec as it now is: the Table's.
- **Q13 - "sets PATH".** The scan reads writes to os.environ (a subscript, update, setdefault, `__setitem__`) and
  os.putenv; a deletion or a pop is not read (it adds no folder). The names raqib/ sets are held: HOME and
  USERPROFILE (ENV_NAMES).
- **Q14 - System32 on Windows.** The Windows-only test finds each name of the list under `%SystemRoot%\System32`
  (`C:\Windows` where the variable is not there); not run here (Linux).

## The rig (P-3, X51)

- **Q15 - X51's reading.** `--service-check-drive FILE`, keys `letter-exit` and `letter-words`; MET only where the
  exit is 1, the words hold `kind N (WORD)` and `names its device "DEVICE"` (followed by `,` or `:`), and DEVICE does
  not begin with `\Device\`. It does not ask that the letter or the folder be the job's own. A refusal of another kind
  whose device is a disk's (`\Device\...`) reads MISSED. The job's wiring is the Table's.
