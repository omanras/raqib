# M1.3 findings + report CLI: questions for the commander

M1.3 exit criteria E1-E4 are met and `tools/gate.sh` is green. The HANDOFF was
drafted by the builder (`docs/handoffs/M1.3.md`) under the commander's order.
14 mutants of `raqib/report.py`, `raqib/cli.py` and `raqib/rules/context.py`
were each killed by `tests/test_report.py`.

## What shipped

- **`python -m raqib rules TRACE [-o FILE]`** writes silence and catalog
  findings, one JSON per line. With `-o`, `FILE.notes.json` records which
  rules did not run and why, the rule table, the context and any trace
  problems.
- **`python -m raqib report TRACE [--findings FILE] [--json]`** shows:
  - every finding with the file line numbers and a bounded rendering of each
    cited seq (A5);
  - alarms: an empty trace, corrupt lines, rejected findings, and citations
    with no line;
  - rules that did not run (A3);
  - every rule's class, severity, fp_budget and status (A6).

  Exit codes are 0 clean, 1 alarm, 3 incomplete, 2 usage.
- **`python -m raqib check-rules`** prints the measured fp_rate against
  fp_budget per catalog rule and exits 1 if any active rule is over budget.
- **Scope** comes from `--scope PATH` (repeatable) or `--handoff HANDOFF.md`.
  The Scope: block is read the way `.claude/hooks/scope-guard.sh` reads it.
  `RAQIB_GAP_SECONDS` is now honoured in production, which answers the M0.2
  review's E1 point; `--gap-seconds` overrides it.
- `raqib/__init__.py` is now ASCII. Its em dash broke CLAUDE.md rule 7.

## Open questions (not answered)

- **Q1 `report` runs the rules in-process when `--findings` is not given.**
  ADR-0001 section 1 says no stage calls the next in-process. The
  file-to-file path exists and is tested to give the same result
  (`rules -o F`, then `report --findings F`). The one-command form is there for
  the quickstart and the outside reader (M3.3). Is that acceptable?
- **Q2 Any finding is exit 1, whatever its severity.** A low-severity finding
  gives the same exit code as a SILENCE alarm. Should the exit code follow the
  highest severity instead?
- **Q3 A disabled rule does not make a report incomplete.** It is listed, but
  the result can still be CLEAN. Should a disabled rule be counted as
  incomplete, since a gap in coverage is a kind of silence?

## Assumptions made (confirm or overrule)

- **Silence findings** get `class: SILENCE` when written, so that every line
  of findings.jsonl has the same shape.
- **A findings file without its `.notes.json`** makes the report
  "incomplete": which rules ran is unknown, and that is not clean.
- **A line in a findings file that is not a JSON object** becomes a rejected
  finding, which is an alarm.
- **Cited lines** are rendered without hashes, and cut at 240 characters
  with non-printable characters replaced. They show phase, tool, seq, ts,
  ok, error_class, input_meta and output_meta.
- **The silence rules have no declared fp_budget** and show "-" in the rule
  table (M1.1 Q3).
