## 3. The questions you asked
**R-2 / T-2.** Nothing in the new code starts, stops, signals or configures a forwarder, reads a token or opens a
  connection. Places that decide something from anything other than a row's code or word:
- (a) `_link_rank` and `link_counts` (990-1004) state link.worst's order a second time. For any code outside {0, 1,
  3}, and for any non-int code, they disagree with `worst`.
- (b) T-5's "empty is note" (1010-1011, 1028).
- (c) No read yet means incomplete, "READING LINK" or "LINK NOT READ" (1022-1025, 1071-1072).
- (d) The late override (1012).
- (e) A reader that raises, or returns something other than a list, becomes a problem (3007-3011).
- (f) "ahead of this clock", chosen from the sign of the age (1042-1044).
- (g) The why-line tag (1047).

**T-3.**
- Name: `link_line(,64)` at 1038. It is enforced upstream: link.py:283 matches the file name against NAME, and the
  row's name is the file's name (310, 380). The window's reader is `link.read` (2984).
- Word: 16 characters (1038). Facts and why: 1036-1037.
- `to` is never used anywhere in app.py, although E1 says "Use them". It appears only inside facts[0].
- Rail: 1080, with each word cut at 1001. Detail: 1051-1060, with the problem passed through `link_line` at 1054.
- Nothing of the link reaches "Could not see" or the log.
- `str.isprintable` turns Cc (C0, DEL, C1), Cf (bidi embeddings, overrides and isolates, LRM/RLM/ALM,
  ZWSP/ZWNJ/ZWJ/WJ, BOM, soft hyphen), Zl and Zp (U+2028/9), Zs other than the space (for example NBSP), Cs, Co and Cn
  into "?".
- It lets through RTL letters (implicit bidi reordering still applies), homoglyphs, stacked combining marks, wide CJK
  and astral symbols.
- Tags are constants. State text appears only as `%` arguments, never as the format. There is no `str.format`. Label
  text goes through `configure`, with no Tcl substitution.
- The window does not bound the number of lines; it relies on `judge` (at most 5 facts and 1 why).
- **R3:** `_safe` runs over the whole value before the cut, on the Tk thread, on every tick while the Link screen is
  open (5296). With link.py's bounds, 64 states of just under 1 MiB each, that is about 64M characters per tick. I
  estimate seconds per tick but did not measure it. The writer of the folder can be the watched agent, since it runs
  as the same user. The worker also parses up to 64 MiB a second on every screen, competing with the watch's threads
  for the GIL; also unmeasured.

**T-4 / U-4 / R-4.**
- A new thread is started for each read (3000), named "raqib-app-link", as a daemon. There is no loop and no lock.
- `rows` is assigned once (3012). "Never two at once" holds only because `poll` is called from the Tk thread alone,
  which is not documented.
- A reader that blocks forever: one thread stays, no new read starts, and the view goes late after 10 s. `destroy`
  blocks the Tk thread for 2 s and leaves the daemon thread behind; U-4 accepts this.
- A BaseException leaves the old rows in place, and the next read retries after a second.
- If the clock goes backwards (possible only with an injected clock, not with `monotonic`), reads starve and the age
  is negative, so the view is never late.
- Redraw: covered under E4.
- Window `__init__` starts the thread before `check()` and `_title_bar`. If either raises, the thread is orphaned.

**R-3 / U-2 / U-3 (for the Table to rule; I do not rule).**
- FAILING beside SILENT or UNREADABLE: the rail and the verdict are amber and never say "failing" on any screen but
  Link. One stale state of a retired forwarder, or one planted by the watched agent, is enough to hide every later
  failure. `test_e3` (line 174) pins exactly this masking.
- `rest` or `problem` beside FAILING turns a known failure amber, which is what U-2's FOR forbids for late reads.
- A reader that raises drops the last known FAILING. This cannot happen with `link.read`, which never raises.

**J-1 / E6.** A failure of `LinkJob` never reaches `c.hole`, consistent with R-4. The exception: an exception in the
  link path on the Tk thread, such as a failure to start the thread at 3001 when called from 5097. That one does reach
  `c.hole` through `tick` (4987-4989), and it aborts the rest of every tick: `_first_run`, `host_tip`, `_sync_primary`
  and the screen's own tick (5112-5133). The read touches no watch file and no lock (link.py:80-82, host.py:393-394).
  On Windows, its open can collide with the forwarder's `os.replace`, which already retries (forward.py:963-970).
