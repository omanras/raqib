VERDICT: STOP
This is a recommendation, not an approval. The engines ran the content and every claim was MET. But the search for
silence (S-5) has two weaknesses that are design questions, and the Table must rule them before merge: Q3 (the
longest beat a host ever said) and the blind spot for hosts that never sent a heartbeat (F2). The must-fix items

## MUST FIX BEFORE MERGE
1. siem/elastic/searches/silence.json:54 and siem/opensearch/searches/silence.json:54: the default `now` is
   "1767225600000" (2026-01-01). If a person pastes the request and body as they are, no host whose heartbeat
   arrived after that date is ever listed. Silence then looks like "none".
   Smallest change: no default value (`"params": {}`). A missing `now` then fails loudly at Long.parseLong
   (silence.json:42). siem_run.py:260 still works with an empty params object.
2. siem/README.md, near :100-105: add one paragraph on what the content trusts.
   - It trusts every key of a well-formed line, including `watch.host`, `watch.beat` and `time`.
   - The watched account writes the file (THREAT_MODEL.md:1710-1713). So a forged heartbeat keeps a host off the
     silence list. One heartbeat with a long beat raises that host's limit for as long as it stays in the index.
   - The pipeline replaces any `host.*` a shipper set (pipeline.json:40 `ctx.host = ['name': ...]`). It removes
     `host` from error documents (pipeline.json:52), so an error document names no host.
3. siem/README.md:36-39 says a line that is not an event is "kept, never dropped". That is more than the pipeline
   does:
   (a) It checks only the JSON, the schema string and a list of types (pipeline.json:18, :40). A line that
       event.check refuses for another reason is indexed as a normal event: an unknown `kind`, no `n`, `about` or
       `rev`, or a word outside a closed list.
   (b) Some lines pass the pipeline and are then refused by the template, so they are lost, not kept:
       `watch.run`, `watch.mode`, `watch.platform` or `rule.kind` as an object, `rule.fp_budget` as a string
       that is not a number, or an object inside `rule.attack`. The mapped types are at template.json:132-151
       (and threat.technique.id is keyword).
   Smallest change: say exactly what is checked, and that such lines are refused. Whether to widen the checks is
   Q9, the Table's.
4. siem/README.md:47-51 and :63: say three things.
   - Install the pipeline and the template before any line reaches a `raqib-events*` index. An index created
     earlier, an index under another name, or one matched by a template of higher priority keeps the engine's
     guesses. That is the measured trap again. The template sets no `priority`.
   - A shipper that names its own pipeline skips `index.default_pipeline` (README:44-45 says nothing about it).
5. siem/README.md:76-79 says the agent dedups by `watch.host` and `id`. Neither a stock agent nor this content
   does that: the pipeline sets no `_id`. Delivery is at least once (FORWARD.md), so alarm.json and rule.json
   count duplicates. Correct the sentence.
6. siem/README.md (the searches section): add one sentence. `@timestamp` is the event's `time`: the host's clock,
   and a first saying carries the entry's own older time (EVENT.md:86-88, 142-143). A scheduled rule or a view
   window on `@timestamp` misses a line that arrives late. `event.ingested` is the arrival time.
7. Rig claims that cannot fail:
   (a) tools/rig/siem_run.py: add the runner's own stand-in events (TO MEASURE 1 and 2) so each Sigma rule and
       search is shown to match once and to miss a near miss.
   (b) .github/workflows/rig.yml:179: add `--beat 5`. As it is, the real watch says no heartbeat at all:
       4 rounds of 5 s is shorter than the 60 s default beat (eventlog.py:198). The search for silence was
       proved on one heartbeat of one host.
   (c) siem_run.py:142-143 and :322-331: check `event.ingested` against the runner's own clock around the bulk
       request, and compute silence's expected `last` from the runner's send time, not from the engine's
       `event.ingested`.
