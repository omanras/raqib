# M2.1 export via pySigma — design questions (returned, not answered locally)

Each question names the reading the builder took; each has a test in
`tests/test_export.py`.

## Q1. JSON shape of `export --json`
E1 says `--json` prints `{"target", "query", "backend_version"}`; ADR
section 9 says JSON output is `{"version": 1, "rules": [...], "green"}`.
Reading taken: E1 literally for `export` (exactly those three keys), since
export is not a verdict and has no green/red; the other four commands keep
the ADR shape. The commander may want the ADR amended either way.

## Q2. Which Elasticsearch backend class
`pysigma-backend-elasticsearch` offers Lucene, EQL and ES|QL.
Reading taken: `--target elastic` is the Lucene query string
(`LuceneBackend`), the most widely accepted form. EQL / ES|QL would be new
targets, which E2 puts out of scope.

## Q3. What pySigma receives
Reading taken: the rule mapping as loaded, minus the `x-mizan` key, through
`SigmaRule.from_dict`; no processing pipeline is applied, so field names
pass through unchanged. A pipeline option would be a new feature.

## Q4. `backend_version`
Reading taken: the installed version of the backend distribution
(`importlib.metadata`), `"unknown"` when the package is not installed as a
distribution. The pySigma core version is kept on the adapter but not
printed, to match E1's three keys.

## Q5. Exit codes of `export`
Reading taken: 0 query printed; 1 the rule is invalid or the backend
refused it (one line `mizan: export failed: <error class>: <message>`);
2 unknown target (argparse `choices`); 3 rule file unreadable or a package
missing (one line naming the `pip install` command). A missing core
pySigma names both packages (`pip install pysigma pysigma-backend-splunk`);
a missing backend only names the backend.

## Q6. Lazy import
Reading taken: pySigma is imported through one indirection
(`_import_module`) inside `load_adapter`, so importing `mizan.cli` (which
imports `mizan.export`) never imports `sigma`; a test asserts it, and the
gate's AST check guards the other modules. The verification in this
session used pySigma 1.5.1 with pysigma-backend-splunk 2.1.0 and
pysigma-backend-elasticsearch 2.1.1 (installed by pip resolution);
all ten example rules export on both backends.

## Open item
The Splunk backend expands `windash` into five variants including
non-ASCII dashes; that output is pySigma's and is not stored in the tree.
