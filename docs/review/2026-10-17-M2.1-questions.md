# M2.1 — questions for the commander (not answered locally)

Each entry: the question, the most conservative reading taken, where it
shows in the tree. Nothing here changes the exit criteria.

## Q1. "One spec per screen"
Eight screens have a spec each: `dashboard`, `ledger`, `holdings`,
`decisions`, `policies`, `review`, `settings`, `files`. The specs written
for M1.1-M1.3 (`shell`, `data-screens`, `screens`) were split by screen
without changing a test, except two that moved into stronger ones: "at
400 px wide ..." is now `mobile.spec.ts`, and "without IndexedDB ..." is the
stub "reading the API throws" in `private-mode.spec.ts`. What is not one
screen stays in `shell.spec.ts` (first run and reload, two tabs, the
header's language and theme). The hello spec moved from `tests/e2e/` to
`e2e/`; `playwright.config.ts` now runs `e2e/` only. `vitest.config.ts`
still excludes `tests/e2e` (outside this Scope, harmless).

## Q2. What "no request leaves the page" counts
`offline.spec.ts` routes every request of the browser context. Loading
the page is exactly one request, the document itself (the build is one
file; Chromium asked for no favicon). After the load, a full tour (every
screen, with a row added and reversed, a decision recorded, the review
downloaded, Arabic and dark switched on and off, a file downloaded) makes
no request of any scheme through the router and no http(s) or ws(s)
request seen by `page.on("request")`; downloads are `blob:` URLs, which
are not network. The recorders are shown not to be blind: a `fetch` made
at the end is seen by both. A second test refuses every request but the
document (`internetdisconnected`) and the tour passes.

## Q3. file:// and IndexedDB
In Chromium, `dist/index.html` opened from `file://` has IndexedDB and the
household survives a reload; the spec records which case held as a test
annotation ("available: the household persists") and asserts the other
branch where it does not hold (banner shown, reload empty), since other
browsers may refuse storage to `file://`. The banner path is also forced
on `file://` by removing IndexedDB before the app starts.

## Q4. Private mode is simulated, and one case cannot be seen
The stubs reproduce what browsers do when they refuse: the open request
fails (InvalidStateError), open throws (SecurityError), reading
`window.indexedDB` throws, the API is missing, open never answers (the
app gives up after its 4 s timeout), or a write is refused after a good
open (QuotaExceededError). In each the banner shows, the full tour works,
and a reload indeed starts empty. A browser whose private window offers
IndexedDB that is wiped when the window closes (current Chromium, Firefox
and Safari) cannot be told apart from a normal window: no banner shows
there. That limit belongs in the failure model (M2.2); no test can cover
it.

## Q5. "No horizontal scroll" at 400 x 800
Read as: the page itself never scrolls sideways (`scrollWidth <=
innerWidth`), on every screen, in English and in Arabic, with every form
and raw panel open; wide tables scroll inside their own `.table-wrap`
box, and every control outside such a box lies inside the window. The
navigation (eight links) is visible on every screen. A row is added by
touch alone.

## Q6. What the accessibility smoke checks
A control has a label when a `<label>` gives it text (the label's own
text, not the options of a select inside it), or `aria-label`, or
`aria-labelledby` resolving to text; a placeholder or a title does not
count. Buttons, links and summaries have text; every `.chip` has text and
a verdict chip's text is the verdict itself; every SVG is `role="img"`
with a `<title>`. Focus order: no positive tabindex, and Tab from the skip
link visits elements in strictly increasing DOM order until it comes back
around; the skip link is the first stop after a load and moves focus to
`<main>`. The checks are shown to catch planted faults. Not checked here:
contrast and screen-reader output (contrast is M2.2's).

## Q7. App code changed
None. No test revealed a bug in `src/`. (`src/` is not listed under this
task's Scope; had a fix been needed it would have come back here.)

## Q8. Run time
The suite is 39 tests in 15 specs on one worker, about a minute and a
half; the "open never answers" case waits for the app's 4 s timeout on
purpose.
