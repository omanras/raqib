# M2.1 — questions and readings taken

1. **"A creates an invite" without circle screens.** E5 needs the organizer
   to create an invitation in the UI, while circle screens are M2.2.
   Reading taken: a minimal circle page (`client/screens/circle.tsx`:
   summary, members, and for the organizer of a draft an "Invite members"
   card that creates a one-time link and shows it once with Copy). M2.2
   builds the full circle screens on top of it.

2. **Rate limits in the e2e suite.** The per-IP auth limit (30 per 15 min)
   would trip across the suite from 127.0.0.1. Reading taken: the e2e
   server runs with `TRUST_PROXY=1` (allowed outside production) and every
   simulated person (browser context) sends its own `X-Forwarded-For` from
   the 198.18.0.0/15 benchmarking range, as a reverse proxy would; the
   limit itself is unchanged and is exercised in M3.1.

3. **Date input display.** Dates shown by the app are ISO (YYYY-MM-DD,
   Latin digits). The start-date field is the browser's native date picker
   (comfortable on phones); its value is ISO, but its display follows the
   browser's locale, which the app cannot set. Reading taken: keep the
   native picker and repeat the chosen date in ISO under the field.

4. **Missing-key check.** `client/i18n/keys.test.ts` (run by vitest in the
   gate) fails when en/ar keys differ, a value is empty, placeholders
   differ, an Arabic string has no Arabic script or contains Arabic-Indic
   digits. In addition `ar.ts` is typed `Record<MessageKey, string>`, so a
   missing or extra key is also a TypeScript error.

5. **Server messages in Arabic.** The server answers in English. The client
   translates every error code it knows (`error.<code>` keys) and, in
   Arabic, falls back to a generic Arabic sentence plus the code instead of
   showing English; the request id is always shown in error toasts.

6. **Offline-honest banner (A10).** Any request that cannot reach the
   server (or the browser's `offline` event) shows a banner that says so
   and gives the time of the last answer from the server; it disappears on
   the next successful request. Data already on screen is never relabelled
   as current.

7. **Sign-up codes before the session.** The account exists and its
   session cookie is set when the codes are shown; the app moves on only
   after "I saved these codes somewhere safe" is ticked. Reloading at that
   moment skips the codes (they are never shown again); Account offers a
   new set behind the password.

8. **Open redirect.** `?next=` is honoured only for same-origin paths
   (starting with one `/`, not `//` or `/\`).

9. **No CSS framework, no UI kit, no icon font.** Tokens on `:root`
   (light, dark via prefers-color-scheme, manual switch with
   `html[data-theme]` cycling system/light/dark), one accent, logical CSS
   properties so the layout mirrors for Arabic, inline hand-drawn SVG icons
   (direction-sensitive ones flip in RTL), no inline style attributes (CSP
   `style-src 'self'` holds without `'unsafe-inline'`).

10. **Default currency.** OMR in the create form (the project's home
    region); any of the 33 supported ISO-4217 currencies can be chosen.
